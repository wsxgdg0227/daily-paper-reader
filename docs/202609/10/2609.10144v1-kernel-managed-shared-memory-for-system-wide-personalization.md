## 摘要
AI系统在能够适应其使用者时会变得更有用，但在多智能体系统中，一个智能体学到的有用上下文往往无法被其他智能体使用。我们提出内核管理的共享内存，一种系统级抽象：专用智能体写入结构化、带标签的记忆，而由智能体系统内核（而非单个智能体）来管理检索、隐私执行和提示注入。我们在AIOS上实现并评估该设计，并在三个助手模型（GPT-4o、Llama-3.1:8B、Qwen-2.5:7B）上、总共1,800次试验中，将其与三种替代方案进行比较。与使用相同底层存储的未受管理的外部记忆后端（Mem0）相比，内核管理的检索与注入将个性化得分在5分制上提高2.4–4.0分（例如，GPT-4o上的用户画像使用从1.05提高到4.69），且每次比较均在p < 10^-18水平上显著。与标准检索增强注入相比，增益同样很大，且在三个模型上均保持一致。与完整的、未经过滤的上下文拼接（其是可用上下文而非响应质量上的软上限）相比，内核管理的注入在三个模型中的两个上统计上匹配性能，在第三个上表现出小的、模型特定的不足，同时使用显著更短的提示：三个模型的端到端延迟降低15–61%，并相应减少每次调用的token使用量和推理成本。这些结果表明，将记忆管理集中到智能体系统内核，而不是将检索和隐私执行留给单个智能体，能够以一小部分成本提供无约束上下文的大部分个性化收益。

## Abstract
AI systems become more useful when they can adapt to the people using them, but in multi-agent systems, useful context learned by one agent often remains unavailable to others. We present kernel-managed shared memory, a system-level abstraction in which specialized agents write structured, tagged memories while the agent-system kernel, not individual agents, governs retrieval, privacy enforcement, and prompt injection. We implement and evaluate this design on AIOS and compare it against three alternatives across three assistant models (GPT-4o, Llama-3.1:8B, Qwen-2.5:7B) and 1,800 total trials. Against an unmanaged external memory backend (Mem0) using identical underlying storage, kernel-managed retrieval and injection improve personalization scores by 2.4-4.0 points on a 5-point scale (e.g., 1.05 to 4.69 profile usage on GPT-4o), with every comparison significant at p < 10^-18. Against standard retrieval-augmented injection, gains are similarly large and consistent across all three models. Against full, unfiltered context concatenation, a soft ceiling on available context rather than on response quality, kernel-managed injection statistically matches performance on two of three models and shows a small, model-specific deficit on the third, while using substantially shorter prompts: end-to-end latency is 15-61% lower across all three models, with corresponding reductions in per-call token usage and inference cost. These results indicate that centralizing memory management in the agent-system kernel, rather than leaving retrieval and privacy enforcement to individual agents, delivers most of the personalization benefit of unconstrained context at a fraction of its cost.

## 1. 核心问题与整体含义

- **研究动机**：AI 系统在多智能体场景中会分别学到用户的不同上下文，例如偏好、任务状态、对话历史等；但这些信息通常被隔离在单个智能体内部，导致系统整体无法形成一致、连贯的个性化行为。
- **核心问题**：现有多数记忆系统把检索、过滤、隐私控制和提示注入留在应用层或单个智能体内部，造成逻辑重复、隐私策略易被绕过，并且跨智能体共享困难。
- **整体含义**：论文主张把个性化记忆管理从“智能体应用逻辑”提升为“智能体系统内核能力”。由内核统一负责写顺序、身份解析、隐私过滤、检索排序、格式化和注入，从而以更低成本获得接近“全上下文拼接”的个性化效果。
- **实现背景**：方法在 AIOS 上实例化，但作者强调该抽象不限于 AIOS；任何具备共享记忆后端和可控提示构造路径的多智能体运行时都可实现类似设计。

## 2. 方法论：核心思想与关键技术细节

- **核心思想**：专用智能体写入结构化、带标签的记忆，而“智能体系统内核”集中管理检索、隐私执行和提示注入。面向用户的 AssistantAgent 不直接检索记忆，也不自行构造个性化提示。
- **系统模型**：
  - 多智能体系统 \(A=\{a_1,\dots,a_n\}\)，共享记忆存储 \(M\)。
  - 查询表示为 \(q=(a_i,u,x)\)，其中 \(a_i\) 是请求智能体，\(u\) 是用户标识，\(x\) 是输入提示。
  - 记忆项表示为 \(m=(u,o,t,s,c)\)：用户、所有者智能体、记忆类型、共享策略、内容。
  - 记忆类型包括 `profile`、`task_context`、`conversation`；共享策略包括 `private` 或 `shared`。
- **内核五步个性化流程**：
  1. 对目标用户执行“写后读”顺序保证；
  2. 检索候选记忆 \(R=\text{search}(M,u,x)\)；
  3. 按系统可见性规则过滤；
  4. 按语义相关性和 token 预算排序、截断；
  5. 注入记忆，生成增强提示 \(x'=K(a_i,u,x)\)。
- **身份解析**：内核按优先级解析用户身份：请求附带的标识符、最近注册的会话标识符、历史标识符回退注册表、最后才使用请求智能体自身标识符。该机制用于避免跨用户污染。
- **可见性规则**：  
  \[
  \text{visible}(m,a_i)=
  \begin{cases}
  \text{True}, & o=a_i \\
  \text{True}, & s=\text{shared} \\
  \text{False}, & \text{否则}
  \end{cases}
  \]
  若共享策略缺失、格式错误或显式私有，则默认视为私有。隐私被设计为内核不变式，而非 SDK 约定或提示指令。
- **写顺序保证**：由于 ProfileAgent / TaskAgent 异步写入，而 AssistantAgent 可能同时检索，内核使用按 `user_id` 作用域的写屏障：
  - 每次写入获得单调递增序列号；
  - 检索时对目标用户当前最高序列号做快照；
  - 阻塞直到快照内所有写入确认排空；
  - 默认超时 5000 ms，超时后 fail-open，优先保证活性而非严格一致性。
- **记忆格式化与角色**：
  - 内核将结构化 JSON 记忆渲染为自然语言，避免小模型难以使用原始 JSON。
  - ProfileAgent 提取稳定用户属性；TaskAgent 提取短期任务上下文；AssistantAgent 只基于内核注入的上下文生成回答。
- **实现特征**：推理时运行，无需重新训练；支持可配置的抽取、注入、相关性阈值、记忆预算、写屏障超时和可插拔记忆提供者。

## 3. 实验设计

- **场景与数据**：没有使用公开标准数据集，而是使用合成评估框架。每个试验生成合成用户画像、合成任务上下文和一个刻意模糊的后续查询，例如“What should I focus on next?”，使个性化内容必须来自注入记忆。
- **评分维度**：由 GPT-5.4 作为唯一自动评委，在 1–5 分制上评估：
  - Profile Usage：用户画像使用；
  - Task Usage：任务上下文使用；
  - Integration：画像与任务信息是否被连贯结合。
- **对比方法**：
  - `naive_concat`：完整合成画像/任务上下文直接拼接，不检索、不过滤，是“可用上下文”的软上限，而非响应质量上限。

  - `mem0_default`：使用 Mem0 外部记忆后端，配置为 private-only，无内核编排、写顺序或跨智能体共享。
  - `kernel_shared`：论文提出的内核管理共享记忆方法。
- **模型**：GPT-4o、Llama-3.1:8B、Qwen-2.5:7B。
- **主要配置**：`auto_extract=true`、`auto_inject=true`、相关性阈值 0.3、每次最多注入 10 条记忆、记忆 token 预算 2000、写屏障启用且超时 5000 ms。
