## 摘要
自回归模型解码受带宽限制，因为每个权重以及键/值缓存字节在每个 token 中都要经过一次高带宽内存。Megakernel 是一种理想解决方案，但现有的自动 Megakernel 生成方法无法同时实现跨模型的泛化性和正确性保证。我们提出 ForgeMegakernel，它利用编码智能体为每个模型生成高性能解码 Megakernel。ForgeMegakernel 将包含十个渐进式里程碑的通用知识库与独立的中间状态测试预言机相结合。这些里程碑提供了 Megakernel 的结构特性：为每个 SM 提供细粒度指令流，用依赖计数器取代全局同步，以及使用共享内存缓冲池来实现跨 SM 的工作负载均衡和更高的并行度。测试预言机推导 Megakernel 的中间状态，并在生成过程中检查性能、误差和精度，从而保证锻造出的 Megakernel 正确且可信。我们在涵盖 0.6B-13B 参数的八个模型家族中的 14 个代表性解码操作上评估了 ForgeMegakernel。生成的 Megakernel 实现了 50.5-85.9% 的 MBU，并且在相同配置下，相对于 SGLang 0.5.18 的几何平均加速比为 1.21 倍，相对于 Megakernel 编译器的几何平均加速比为 1.54 倍。在 SGLang 内部，使用不规则提示在 GSM8K 上评估时，所有 14 个 Megakernel 在答案准确率相当的情况下，解码速度均快于 SGLang 引擎。

## Abstract
Auto-regressive model decode is bandwidth-bound, since every weight and key/value-cache byte crosses high-bandwidth memory once per token. A megakernel is an ideal solution, but existing automatic megakernel generation approaches cannot achieve both generalization across models and correctness guarantees.   We present ForgeMegakernel, which generates a per-model high-performance decode megakernel using coding agents. ForgeMegakernel pairs a universal knowledge base of ten progressive milestones with an independent mid-state test oracle. The milestones provide the megakernel's structural properties: a fine-grained instruction stream for each SM, dependency counters replacing the global synchronization, and a shared-memory buffer pool for workload balance across SMs and greater parallelism. The test oracle derives the mid-states of the megakernel and checks the performance, error and precision during the generation process, guaranteeing a correct and trustworthy forged megakernel.   We evaluated ForgeMegakernel on 14 representative decoding operations across eight model families spanning 0.6B-13B parameters. The generated megakernels achieved 50.5-85.9% MBU and geometric mean speedups of 1.21x over SGLang 0.5.18 and 1.54x over a megakernel compiler under identical configurations. Inside SGLang, evaluated on GSM8K with ragged prompts, all 14 megakernels decoded faster than the SGLang engine at comparable answer accuracy.

# ForgeMegakernel 论文结构化总结

## 1. 核心问题与研究动机

- **解码是带宽受限的**：自回归模型每生成一个 token，都要将全部模型权重与 KV 缓存逐字节读一遍 HBM；解码的算术强度约为 1 FLOP/Byte，GPU 算术单元大量闲置，性能瓶颈是显存带宽而非算力。
- **逐算子启动的开销巨大**：vLLM、SGLang 等主流引擎每个解码步需要启动数百个算子内核（H100 上 280–448 次启动/token），每次启动都有 ramp/drain 与网格级同步开销，使单步耗时达到单次持久内核执行的 1.06–1.45 倍。
- **Megakernel 是理想解但难以复用**：把整个解码步融合进一次持久内核启动（megakernel）可消除上述开销，手写实现可达 H100 带宽的 74–78%，但针对单一模型定制、迁移到新模型需数周专家工作。
- **现有自动生成方案的两难**：
  - *编译型*（如 MPK）遵循固定 lowering 规则，在规则未覆盖的 cell 上性能骤降；
  - *智能体型*（naive prompt）生成的内核"能跑但慢"，在 5 个测试 cell 上均慢于 SGLang（利用率仅为其 0.59–0.95 倍）。
- **正确性无法保证**：融合后所有中间值留在寄存器/共享内存中，外部只能看到最终 logits。仅做输出检查无法定位缺陷（如 ragged batch 中位置广播错误）；让智能体自建检查则标准不统一、易被绕过（实验显示自检内核仍损失 1.5–5.0 个 GSM8K 点）。
- **由此引出两大挑战**：C1 如何构建既通用又精确、不含模型特定参数的知识库；C2 如何恢复可验证的中间态并建立标准化正确性门禁。

## 2. 方法论

### 2.1 总体框架
ForgeMegakernel 以"模型配置"为输入，输出可直接被服务引擎加载的解码 megakernel，由三部分构成：
- **C1 通用知识库（十级里程碑阶梯）**——规定"要建成什么结构"；
- **C2 中间态测试预言机（oracle）**——规定"判决依据是什么"；
- **C3 端到端生成框架**——把二者变成带 GPU 反馈的搜索循环，并完成部署。

### 2.2 十级里程碑（M0–M9）
- **功能前缀 M0–M4**：依次验证工具链、单个算子、单层融合、L 层堆栈、真实 checkpoint 上的解码，全部对照 float64 golden。
- **M5 megakernel**：建立单次持久启动，禁止库调用（含 LM head 在内不得有算子留在外部），检查启动次数。
- **M6 每 SM 指令流**：宿主将解码器编译成带操作数描述符的类型化指令，每个 SM 分配一条流，内核内解释器分派。检查：≥5 种指令类型、每层 ≥6 条指令、队列不均衡 ≤1.35×，并设 MBU 下限。
- **M7 无网格栅栏（依赖计数器）**：用计数器信号量记录生产者–消费者边，取代全局同步。检查：网格级栅栏数 = 0、计数器 ≥4L、busy_frac ≥0.85、tail_spread ≤0.05，并设 MBU 下限。
- **M8 共享内存缓冲池**：提供随指令生命周期分配的暂存空间，使第 k+1 条指令的加载与第 k 条指令的存储重叠，避免缓冲区过早回收。检查共享内存缓冲池存在，并设 MBU 下限。
- **M9 稳定性（可选）**：1000 步贪心生成无 NaN/Inf、相对 bf16 参考漂移 ≤5 个位置，并可自由运行至 4000 token，针对索引溢出、缓冲池碎片化和计数器回绕。

三个性能步骤构成结构化分解：**指令流分配工作，计数器为工作排序，缓冲池承载连续指令重叠搬运的操作数**；但阶梯同时要求"结构 + 实测性能"，每个门禁返回统一信封 `{status, suite, summary, metrics, details}`。

### 2.3 中间态测试预言机
- **字节核算性能测量**：宿主从模型配置推导字节数 B(b,S)（式 2，含权重、KV 缓存、嵌入行；不含完整嵌入表以免虚高 1.22×），延迟用两点斜率 `t = min_r{t_r(80) − t_r(16)}/64` 消除 prefill 与长度无关开销；MBU = B(b,S)/(t·β_peak)，并强制 MBU ≤ 100%、MBU ≤ 1/ρ（ρ 为 ncu 实测字节与 B 之比，界定读放大上限）。
- **float64 参考误差测量**：
  - KV 缓存逐层比对（式 4，δ 相对差），要求内核相对 PyTorch 参考的距离 C < 2B（B 为参考相对精确算术的距离），可定位首次分歧；
  - logits 层用 golden 自身 top-64 上的 log-softmax（式 5，ε 与 ε_max），三条界线：ε(K) ≤ 5D、ε(K) ≤ ε(SGLang)、ε_max(K) ≤ 2ε_max(SGLang)，均非人为选定。

- **无容差功能检查（M5 起）**：logits 有限性、KV 越界读取（用 σ=100 噪声污染写游标之后的 KV 区域，要求 logits 逐位不变）、每 lane 使用自己位置而非 lane 0 广播。
- **防篡改**：宿主在生成前固定所有可测量量并加哈希传递，门禁禁止重算；智能体只能写内核源码与笔记，任何改动评估器的轮次被回滚。

### 2.4 生成循环
- 每轮从**全新上下文的 headless 编码智能体**（Claude Code + Claude Opus 5，1M 上下文）开始，只接收里程碑矩阵、当前里程碑、上一轮门禁摘要与规则；编辑内核 → 在 H100 上构建与测量 → 保留或回滚 → 写入 ledger（假设、diff、测量结果、决策），只有实测值跨轮传递。

- **部署**：实现为 SGLang model class，`forward(EXTEND)` 为单 token 循环，`forward(DECODE)` 为批量步，与基线共享 scheduler/sampler/内存管理器/detokenizer。

## 6. 主要结论与发现

- **性能**：14 个锻造 megakernel 达 **50.5–85.9% MBU**（SGLang 为 36.5–78.9%，MPK 为 20.6–75.9%）；相对 SGLang 加速 1.10–1.61×（几何平均 **1.21×**），相对 MPK 加速 1.14–2.51×（几何平均 **1.54×**）。
- **与手写实现相当**：Llama-3.2-1B 上锻造内核达 74.0% MBU，与手写 megakernel 的 74.6%（作者报告 78%）相当，分别比 SGLang/vLLM/MPK/llama.cpp 快 1.37×/1.50×/1.52×/1.84×。
- **精度**：相对 float64 前向，锻造内核在每个配置上都比 SGLang 更接近精确算术，误差比为 0.38–0.72，中位数 0.66。
- **服务级**：SGLang 内 GSM8K 解码加速 1.03–1.28×（几何平均 1.11×），准确率与基线相差在 1.5 个百分点以内，7 个配置持平或更高。
- **性能来源分解**：SGLang 每次 matvec 网格启动的 ramp/drain 常数项约 **4.63 μs**（R²=0.9993），每 token 65–141 次 GEMV 族启动合计 301–653 μ

s 量级的纯启动开销，这一项在 4096 上下文、batch 16 时仍占单步耗时的可观比例。
  - **融合项**：锻造 megakernel 将每步启动次数压到 1 次（M5 门禁强制），并把"每次 matvec 都要重新载入权重"变为"权重在持久内核内跨步驻留"，因此带宽浪费集中在 KV 缓存与激活上，读放大被 M7 的依赖计数器与 M8 的缓冲池进一步压住。
  - **精度代价为零**：加速并未以精度换性能——所有配置上误差比均 ≤ 1（0.38–0.72），说明持久化与融合反而减少了中间态回写与重读引入的舍入机会。
- **结构有效性（消融方向性证据）**：在固定 50 轮预算下，去掉 M6/M7/M8 任一结构都会掉到对应 MBU 下限之下，而完整阶梯达标，说明三项性能结构不是装饰性门禁，而是分别对应"工作分配""工作排序""操作数搬运"三个可分离的带宽来源。作者同时声明这只是方向性证据，非幅度量化。
- **跨智能体可迁移**：换用不同厂商、不同模型（GPT-5.6-sol）的编码智能体重锻造同一 cell，得到 35.7% MBU、约 89.5% 的 cell 上限，成本与默认 harness 相当，表明收益来自 C1 知识库与 C2 预言机，而非某个特定模型的提示技巧或隐性先验。
- **长上下文单调性**：Qwen3-8B b=1 的内核在 S ∈ {64,…,4096} 上上包络 79.6–83.7% MBU，说明性能不随上下文增长而崩塌（KV 缓存读取占比上升时仍维持高带宽利用）。

## 7. 局限性与开放问题

- **硬件单一**：全部结论基于单张 H100 80GB HBM3。共享内存容量、SM 数量、启动开销模型、HBM 带宽比在不同架构（A100、B200、消费级卡、非 NVIDIA 加速器）上差异显著，十级阶梯中的 M6（每 SM 指令流）与 M8（共享内存缓冲池）门禁阈值（如 MBU 下限、队列不均衡 ≤1.35×）是否需要重标定尚不明确。
- **消融覆盖窄**：仅一个模型、一个 shape（Qwen3-0.6B，b1×128）的 4 臂对照，作者自认只能给出方向而非幅度；三项结构之间是否存在交互效应、在 MoE / 多头潜在注意力等结构上是否同样可分离，未被检验。
- **模型规模与形态**：cell 覆盖 0.6B–13B 的稠密解码器，未涉及 MoE 路由、投机解码、多 token 预测、prefix caching 复用、张量并行/流水并行；这些都会改变"每步读多少字节"的核算基础。
- **正确性门禁的边界**：M9 为可选且只做 1000 步稳定性检查；无容差功能检查针对的是已知缺陷类别（越界读、位置广播、logits 有限性），对更隐蔽的数值路径缺陷（如特定 mask 形状下的注意力缩放）是否覆盖充分未做系统性证明。
- **成本与效率**：每块内核中位数 47 轮、14.7 agent-hours、约 177 美元（最贵 414 美元），对单模型部署是可摊销的一次性成本，但对需要频繁跟进上游权重更新的场景仍偏重；论文未给出"权重变更后增量重锻造"的路径。
- **评估口径**：MBU 以字节核算为分母，刻意排除完整嵌入表（避免 1.22× 虚高），因此其绝对值与把嵌入表计入的已发表报告不可直接比较；服务级 GSM8K 差异（1.5 个百分点内）被归入 run-to-run 噪声，缺乏更大规模或多次重复的统计检验。

## 8. 结论与意义

- **核心结论**：把"手写 megakernel 的专家经验"编码为**可验证的十级里程碑 + 字节核算性能指标 + float64 中间态预言机**，可以让编码智能体在无人工干预下，为 8 个模型家族的 14 个配置锻造出解码 megakernel，达到 50.5–85.9% MBU，几何平均比 SGLang 快 1.21×、比 MPK 快 1.54×，且在 Llama-3.2-1B 上追平手写实现（74.0% vs 74.6% MBU）。
- **方法学贡献**：论文把"智能体写内核"这一过程从**不可复现的提示工程**转变为**带门禁的搜索循环**——性能用统一信封报告，正确性用可定位首次分歧的中间态比对判定，评估量在生成前固定并哈希，智能体只能改源码与笔记。这使跨轮、跨智能体、跨 cell 的结果可比。
- **对工程的启示**：M5→M6→M7→M8 的顺序本身就是一份"持久内核优化路线图"：先消灭启动开销，再把工作分给 SM，再用计数器代替栅栏，最后用缓冲池重叠搬运；每一步都有可测量的下限，便于在资源受限时判断"值不值得做下一步"。
- **更广的定位**：该工作把 megakernel 从"一次性手写工艺品"推进到"可批量生产的编译器目标"，同时明确其边界——一种 GPU 架构、稠密解码器、单卡；跨硬件与跨并行策略的自动迁移，是留待后续的直接问题。
