## 摘要
长期语言模型智能体在多次交互中依赖外部记忆。原子记忆尤其有用：其细粒度语义边界能够实现精确检索以及观察之间的直接比较。然而，不断累积的原子不可避免地会变得冗余、重叠或冲突。现有方法通常让 LLM 管理器直接添加、更新、删除或重写记忆，将语义解释、存储决策和内容生成耦合在一个易出错的操作中。我们提出 ROAM，一种关系引导的框架，在管理时利用原子性，同时允许在回答时使用更丰富的表示。ROAM 将传入原子与已存储原子对分类为独立、等价、方向性包含或冲突，然后将观察组织为活跃的 Primary 和支持性的 Evidence 角色。融合随后将互补细节和时间变化组合成紧凑的、可能非原子的视图。回答时仅检索 Primary 视图，防止冗余或过时的原子独立参与竞争。在不同模型和评估设置中，ROAM 将回答准确率最多提升 29.8 个百分点。消融实验表明，不同关系带来互补收益，且融合在角色组织之外带来持续增益。机制分析进一步发现，答案关键来源召回率提高 15.6 个百分点，混杂词元占比降低 11.5 个百分点。ROAM 在不同管理器规模下保持稳健。

## Abstract
Long-term language-model agents rely on external memory across interactions. Atomic memories are particularly useful: their fine-grained semantic boundaries enable precise retrieval and direct comparison between observations. Yet accumulating atoms inevitably become redundant, overlapping, or conflicting. Existing methods often ask an LLM manager to add, update, delete, or rewrite memories directly, coupling semantic interpretation, storage decisions, and content generation in one error-prone operation. We introduce ROAM, a relation-guided framework that uses atomicity for management while allowing richer answer-time representations. ROAM classifies incoming--stored atom pairs as independent, equivalent, directionally subsuming, or conflicting, then organizes observations into active Primary and supporting Evidence roles. Fusion subsequently combines complementary details and temporal changes into compact, potentially non-atomic views. Only Primary views are retrieved for answering, preventing redundant or outdated atoms from competing independently. Across models and evaluation settings, ROAM improves answer accuracy by up to 29.8 percentage points. Ablations show complementary benefits from different relations and consistent gains from fusion beyond role organization. Mechanism analysis further finds 15.6-point higher answer-critical source recall and an 11.5-point lower confounder-token share. ROAM remains robust across manager scales.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：长期运行的 LLM 智能体需要跨会话积累用户偏好、处境与经历，并随现实状态变化持续修正。由于原始对话历史远超工作上下文上限，主流架构维护**外部记忆库**，在查询时检索相关子集。
- **原子记忆的价值**：为在严格上下文预算下最大化检索精度，系统倾向把持久知识表示为**细粒度、原子化的事实或结构化关系**。原子表示能用更少 token 保留关键信息，提供可寻址单元并支持定向更新，已成为长期记忆系统的标准表示基础。
- **核心痛点**：原子化只规定了记忆的*粒度*，并未规定不断累积的原子事实应如何随时间共存。持续流式输入的原子观察必然带来**语义重述、空间/属性细化、时序状态转移**，导致：
  - 直接追加 → 严重冗余与歧义；
  - 不加区分地删除或覆写 → 破坏追溯知识演化所需的历史上下文；
  - 未整理的、重叠的、过时的记录会与答案关键证据**争夺有限检索容量**，拖累下游回答质量。
- **现有方法的缺陷**：以 Mem0 为代表的"指令式直接操作"范式，让 LLM 管理器对每个新旧记忆对直接选择 `ADD/UPDATE/DELETE/NONE`，把**语义关系推断、物理存储变更映射、更新协调**耦合进一次黑盒复合决策，导致操作后果不稳定、历史可追溯性差。
- **整体含义**：有效的原子记忆管理应**解耦显式的语义关系推断与确定性的状态控制**，而不是依赖端到端的存储突变。

## 2. 方法论

### 2.1 核心思想
ROAM（Robust Organization of Atomic Memories）是一个**关系引导的记忆管理框架**，将复合决策分解为「显式关系推断 + 确定性策略执行 + 融合」三部分：

- 对每条新入观察，预测其与既有记忆之间的**五类细粒度语义关系**之一；
- 固定策略据此把记忆分配为结构角色：把信息量最大的事实提升为 **Primary（活跃）**，其余作为 **Evidence（支撑）** 保留溯源；
- 融合模块把互补细节与时间变化合成为**紧凑的读视图**；
- 回答时**仅检索 Primary 视图**，Evidence 保留但不独立参与竞争。

### 2.2 问题设定与流水线
系统采用三阶段流水线（式 1）：

```
Ft = Extract(Dt)            # 从原始交互抽取事实
St = Manage(St-1, Ft)       # 管理器更新结构化记忆状态
Kq = Retrieve(q, St; B)     # 在预算 B 下检索最相关子集
```

原子观察表示为三元组（式 2）：`Ot = (at, τt, ct)`，其中 `at` 为自包含事实陈述，`τt` 为时间戳，`ct` 为来源上下文。

> **Remark**：长期交互中记忆管理不必每条观察后同步执行，可异步或周期性在后台整合，允许管理阶段优先考虑记忆紧凑性而非最小更新延迟。

### 2.3 语义关系（五种）
设 `Pt-1` 为活跃原子记忆，新观察 `Ot` 先经检索得到候选（式 3）：`Ct = ρk(at, Pt-1)`；再由关系模型对每个有序对预测（式 4）：

```
rt(i) = Φ(at, ai) ∈ R,  R = {IND, EQV, OSN, NSO, CON}
```

| 关系 | 含义 |
|---|---|
| **IND** | 独立：两者可同真且互不蕴含 |
| **EQV** | 等价：真值条件相同、互相蕴含 |
| **OSN** | 旧被新包含：新观察严格蕴含旧观察并增加具体性（如"住在 Cambridge, MA"蕴含"住在 MA"） |
| **NSO** | 新被旧包含：反向蕴含方向，不增加具体性 |
| **CON** | 冲突：实体/属性/时间范围对齐后描述不相容状态；显式时间限定符优先用于消解 |

### 2.4 关系条件化的记忆整合

- 每条观察存为**不可变记录**（式 5）：`Mi = (ai, vi, τi, ci, zi)`，其中 `ai` 为原子文本、`vi` 为当前读视图、`zi` 为角色。
- 角色集合（式 6）：`Pt = {Mi : zi = PRIMARY}`，`Et = {Mi : zi = EVIDENCE}`。
- **关系优先级**（式 7）：`CON ≻ OSN ≻ EQV ≻ NSO ≻ IND` —— 优先保护状态区分，其次偏向新引入的具体性，最后才整合冗余观察。
- 选定关系 `r*t` 后，匹配候选集（式 8）：`Ht = {Mi ∈ Ct : rt(i) = r*t}`。
- 读视图更新（式 9）：将 `{M*} ∪ Dt` 按时间排序为 `(S1,...,Sn)`，则
  `vM* ← Fuse(View(S1),...,View(Sn); r*t)`。

**关系→角色/视图映射（Table 1）**：

| 关系 | 角色更新 | 视图更新 |
|---|---|---|
| IND | 将 Mt 插入为新 Primary | `vt ← at` |
| EQV | 最早的匹配 Primary 存活，其余转为 Evidence | 去冗余 |
| OSN | Mt 成为 Primary，旧匹配转为 Evidence | 保留新增具体性 |
| NSO | 最早的匹配 Primary 存活，Mt 转为 Evidence | 保留既有信息 |
| CON | Mt 成为当前 Primary，旧匹配转为 Evidence | 构建时间历史 |

关键点：**融合只改变读视图**；回答时检索 Primary 视图，后续管理仍使用不可变的原子文本。

### 2.5 算法流程（Algorithm 1）
1. 检索候选 `C ← ρ(at, {ai : Mi ∈ P}, k)`；
2. 若 `C = ∅` 则 `r* ← IND`，否则对候选逐对预测关系并取最高优先级；
3. 若 `r* = IND`，插入为新 Primary；
4. 否则匹配 `H ← Matches(C, r*)`，执行 `(M*, D) ← RoleUpdate_{r*}(H, Mt)`；
5. 更新角色与集合（M* 为 Primary，D 为 Evidence）；
6. 将 `{M*} ∪ D` 按时间排序构成 V，融合得到 `vM* ← FuseOrdered(V; r*)`。

- **Append-all 的脆弱性**：N=0 时达 87.0%，N=8 时暴跌至 24.4%，说明"全保留"仅在无竞争时有效。

- **关系消融**：N=8 时 CON-only 32.1%、CON+EQV 62.3%、完整 ROAM 71.9%；从 N=4 起排序稳定为 `CON-only < CON+EQV < ROAM`，说明**矛盾、等价、方向性包含各自贡献互补**。
- **融合的独立价值**：ROAM w/o Fusion 与 RO
