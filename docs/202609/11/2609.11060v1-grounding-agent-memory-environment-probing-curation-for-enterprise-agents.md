## 摘要
持久化记忆正进入面向生产的智能体平台，以帮助长时程智能体跨会话积累经验。然而，仅限于已完成轨迹的任务后策展智能体可能保留错误、过度泛化部分证据或保留过时知识。我们提出环境探测式策展，这是一种与部署兼容的扩展，为现有的异步策展智能体提供最小权限的只读世界工具，以检查、界定范围并刷新候选记忆。它无需重新训练模型，且不改变任务智能体、检索器、记忆表示和生产写入权限。在基于其 SDK 构建的类生产 GitHub Copilot（GHCP）测试框架中，我们在 CLBench 数据库探索和 90 个改编的 APEX 管理咨询任务上比较了无状态执行、完全上下文学习、GHCP + Mem 以及 GHCP + Mem（带环境探测）。在 CLBench 上，环境探测将通过率从 39% 提升至 73%，通过率折扣奖励从 8.60 提升至 22.60，同时将每题查询次数从 8.8 降至 4.7，任务智能体成本从 3.38 美元降至 1.68 美元。在六个 APEX 世界中，全部 18 项记忆与基线的平均奖励比较均为正向，任务智能体工具调用下降 16–75%；在五个世界中，环境探测带来最高的任务智能体每美元奖励增益。在 Sonnet 4.6 和 Opus 4.7 上，环境探测的平均奖励也高于 GHCP + Mem，且无模式漂移。因此，环境探测将现有的智能体记忆策展转变为一种基于环境信息、可审计的过程，同时保持紧凑的任务时接口。

## Abstract
Persistent memory is entering production-oriented agent platforms to help long-horizon agents accumulate experience across sessions. Yet a post-task curator agent restricted to completed trajectories can preserve errors, overgeneralize partial evidence, or retain stale knowledge. We introduce environment-probing curation, a deployment-compatible extension that gives an existing asynchronous curator agent least-privilege, read-only world tools to check, scope, and refresh candidate memories. It requires no model retraining and leaves the task agent, retriever, memory representation, and production write authority unchanged. In a production-like GitHub Copilot (GHCP) harness built on its SDK, we compare stateless execution, full in-context learning, GHCP + Mem, and GHCP + Mem (w/ Env Probing) on CLBench database exploration and 90 adapted APEX management-consulting tasks. On CLBench, probing raises pass rate from 39% to 73% and pass-discounted reward from 8.60 to 22.60 while reducing queries from 8.8 to 4.7 per question and task-agent cost from \$3.38 to \$1.68. Across six APEX worlds, all 18 memory-versus-baseline mean reward comparisons are positive and task-agent tool calls fall by 16--75%; probing gives the best task-agent reward gain per dollar in five worlds. Probing also attains higher mean reward than GHCP + Mem on both Sonnet 4.6 and Opus 4.7 without schema drift. Environment probing therefore turns existing agent-memory curation into an environment-informed, auditable process while preserving a compact task-time interface.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景趋势**：LLM 智能体正从有界任务执行走向跨会话的持续工作（如演进代码库中的功能实现、企业数据分析、客户支持）。成功依赖于跨相关任务积累环境潜在结构的知识。
- **核心痛点**：无状态执行会在会话边界丢弃轨迹、观察、发现与错误；引入外部持久记忆（create–update–recall）是自然补救，但**仅有持久状态并不保证持续学习**。
- **根本局限（retrospective evidence boundary）**：现有事后策展（post-task curation，如 Mem0、Claude Managed Agents Dreams、ACE、ReasoningBank、ReMe）仅基于已完成轨迹、反馈与使用信号。一条轨迹只是环境的单次、片面、常含错误的观察，其引理可能：
  - (i) 记住实例答案而非过程；
  - (ii) 继承低效路径；
  - (iii) 断言无法验证的范围；
  - (iv) 在未访问区域留下盲区；
  - (v) 随世界变化而过时。
- **后果**：把验证推迟到任务时，会迫使响应智能体消耗稀缺工具调用去重新核验不确定记忆，而非直接解题。CLBench 已表明记忆可编码虚假泛化与过时信念；Xiong et al. (2026) 指出错误传播与错位经验回放。
- **整体含义**：论文提出一种**与部署兼容、无需重训练**的增量方案，将改进定位在**写入时的证据质量**，而非任务时智能体能力的扩张。

## 2. 方法论

### 2.1 核心思想

- **环境探测式策展（Environment-Probing Curation）**：在任务结束后，为现有的**异步策展智能体**授予**最小权限、只读**的世界工具（连接器或 MCP 工具的安全子集），使其能在写入长期记忆前**检查、限定范围、刷新**候选记忆。
- 保持不变的要素：任务智能体、检索器、记忆表示、蒸馏设置、策展智能体核心提示、记忆模式与 CRUD 策略、生产写入权限。
- 与认知科学中“情节记忆可重组以模拟反事实事件”及交互学习（行动可获得被动观察无法获得的胜任力）的视角一致。

### 2.2 在线设定与智能体角色

- 任务流 $S=(S_1,\dots,S_N)$，环境状态 $E_i$ 可演化 $E_{i+1}\sim\Delta(E_i)$（含未告知变化）；未来任务隐藏，任务须按序关闭且不可重访；模型参数 $\theta$ 固定，每任务新开会话。
- **任务智能体** $A_\theta$：仅持有环境工具 $TE_i$ 与只读 `memory_read`，无记忆写权限。轨迹 $\tau_i = A_\theta(S_i; TE_i, R(\cdot, M_{i-1}))$，终端反馈 $g_i$ 仅在任务关闭后到达。
- **策展智能体** $C_\phi$：任务后独立实例化，不回答 $S_i$、不见未来任务；拥有 `memory_read/create/update/delete` 四个记忆工具，是唯一可变更 $M$ 的角色。
- 记录契约：每条记录包含 category、confidence、applies_to（检索范围）、lemma（简洁可执行断言）、provenance、utility、usage metadata。

### 2.3 轨迹蒸馏（非写入预处理）

- $d_i = D_\psi(\tau_i)$：蒸馏器保留任务、检索到的记忆、决定性观察、过程、未决假设与答案；**不接收终端反馈，无记忆工具与环境工具，不能写入**。输出带标签的分段证据包（overview/history/work_done/technical_details/important_files/next_steps/checkpoint_title）。

### 2.4 环境探测：propose–probe–commit 流程

- 在提出候选记忆后，进行**有针对性的只读探测调用**，再用观察结果决定 create / revise / narrow / delete / skip。具体可：
  1. 区分偶然答案与可复用关系；
  2. 对比已观察过程与更短路径；
  3. 在另一数据切片上测试声称的关系；
  4. 检查过程的必要前提；
  5. 检查轨迹遗漏的相关状态；
  6. 在怀疑漂移时重新查询当前环境。
- **边界约束**：探测不能改变环境、不进入任务轨迹、不消耗任务智能体预算、不暴露未来任务或标签；若不存在安全只读界面，则退化为纯轨迹策展。
- 提示层面仅增加两个块：`Aaccess`（只读工具访问声明）与 `Averify`（在 Check 与 Reconcile 之间的验证提示），其余完全不变。

### 2.5 评估指标公式

- 通过率折扣奖励：$r_i = p_i\left(1 - \dfrac{q_i}{B}\right)$，其中 $p_i\in\{0,1\}$ 为严格通过（所有 rubric 标准全过才为 1），$q_i$ 为基准统计的任务智能体工具调用数，$B=15$（CLBench SQL 查询）或 $B=100$（APEX Archipelago 工具调用）。记忆管理与框架内部调用不计入 $q_i$；成本不含蒸馏/策展阶段。

## 6. 主要结论与发现

- **CLBench（漂移）**：通过率 39% → 73%，总奖励 8.60 → 22.60（2.3–2.6×），每题查询 8.8 → 4.7，任务智能体成本 \$3.38 → \$1.68。记忆不仅提高正确率，也减少重复环境探索。
- **上下文不随部署时长膨胀**：Full ICL 消耗 5.42M 输入 token，GHCP + Mem 为 2.13M，环境探测仅 1.69M，同时通过率与奖励最高。
- **迁移边界即领先**：环境探测在迁移处累计奖励 0.541 vs 仅轨迹 0.486，终值 0.565 vs 0.500（无记忆 0.215），说明策展侧探测在后续任务检索前即刷新了模式引理。
- **无漂移跨模型**：Sonnet 4.6 上 GHCP + Mem 提升 +0.351，探测 +0.421；Opus 4.7 上分别 +0.252、+0.263；探测在两模型上均取得最高平均奖励（0.748、0.721）。
- **APEX**：全部 18 项记忆–基线奖励增益为正；任务智能体工具调用从 30.0–71.6 降至 13.9–28.4（降幅 16–75%）；探测在 6 个世界中的 5 个取得最佳每美元奖励增益。
- **机制解释**：记忆摊销环境发现；探测使记录从“警告/笼统映射”转为“可执行过程”（明确源表、join 键、过滤条件、聚合粒度、当前模式名）；探测收益大小取决于轨迹遗留的证据缺口。
- **成本–正确性关系**：工具调用减少可**促成正确性**（为最终计算留出预算），而非仅降低

而非仅降低单次调用开销。作者强调这是一个**质变**而非单纯的效率优化：当任务智能体不必反复试探模式、重跑失败 join 或重新发现文件位置时，节省下来的工具调用预算被重新投入到真正的分析计算中，从而在原本"预算耗尽导致答案不完整"的题目上转为通过。

- **记忆内容质量的定性对比**：论文给出的记录对照显示，仅轨迹策展产出的条目多为"警告式"或"笼统映射"（如"注意时间戳字段可能有两种编码"），而经过环境探测的条目为"可执行过程"（明确源表、join 键、过滤条件、聚合粒度与当前模式名）。这一差异解释了为何两者在检索命中率相近时，下游执行成功率仍有差距。
- **增益来源的分解**：作者将总增益拆为两部分——(i) **记忆本身带来的摊销收益**（相比无状态基线）；(ii) **写入时探测带来的增量收益**（相比仅轨迹策展）。后者在任务时接口完全一致的前提下取得，因此可较干净地归因于写入侧证据质量，而非检索或提示工程。
- **探测收益的条件性**：增益大小取决于"轨迹遗留的证据缺口"——即单次轨迹未覆盖、但可被安全只读探测低成本补齐的部分。当轨迹本身已充分、或环境不存在安全只读界面时，探测的边际价值下降。

## 7. 局限性与批判性评估

- **探测的前提约束较强**：方法有效性依赖"存在最小权限、只读、可安全调用的世界工具子集"。若企业环境只能提供写权限接口、或只读接口会触发副作用/审计成本，则方法退化为纯轨迹策展，收益回落到 GHCP + Mem 水平。
- **策展阶段成本未纳入主指标**：论文将蒸馏与策展的 token/调用开销单独追踪，未计入任务智能体成本与奖励。虽然这在"任务时预算"口径下合理，但**总拥有成本（TCO）**视角下，探测调用本身消耗真实资源；若探测频繁或昂贵，端到端性价比可能低于文中"每美元奖励增益"的表观值。
- **探测可能固化错误**：探测是对环境的又一次片面观察，若探测设计不当（如样本切片有偏、查询本身含假设），可能把轨迹中的偶然错误"验证"为可信引理，反而提高错误置信度。论文未系统报告"探测引入的假阳性记忆"案例。
- **统计力度受限**：CLBench 每组仅 5 次配对运行、APEX 有状态 5 次/无状态 3 次，置信区间存在重叠；作者亦明确将子组差异（如探测在 Sonnet 上增益更大、在个别世界为负增量）定位为"机制解释"而非已确立效应，这一自我限定是诚实但削弱了细粒度结论的强度。
- **环境与任务代表性**：两个基准分别为 SQLite 探索与文档分析，均属"结构可探测、变化可观测"的设定。对**不可探测黑箱**（如第三方 SaaS 无只读 API）、**高频漂移**或**对抗性环境变化**，方法未做压力测试。
- **缺少人类或下游效用评估**：指标为 rubric 严格通过与工具调用折扣奖励，未评估记忆质量对企业实际决策、可维护性或审计合规的影响。
- **模型单一性**：主实验统一使用 gpt-5.4，且任务智能体/蒸馏器/策展智能体共享同一基座模型，未检验"策展模型强于任务模型"或跨模型异质组合的情形。

## 8. 理论意义与实践启示

- **理论意义**：
  - 将"持续学习"的瓶颈从**任务时的能力扩张**重新定位到**写入时的证据质量**，提出了一条与部署兼容（无需重训练、无需改任务智能体）的增量路径。
  - 呼应交互学习与认知科学中"情节记忆可重组、可主动查询"的观点，为智能体记忆研究提供了"策展即主动感知"的框架。
  - 明确了**retrospective evidence boundary**：事后策展的天花板是单次轨迹的信息量，突破该边界的唯一途径是引入新的环境观测。
- **实践启示**：
  - 企业部署记忆系统时，应优先为策展角色配置**最小权限只读工具**，而非扩大任务智能体的权限或预算。
  - 记忆记录应优先沉淀**可执行过程**（表名、键、过滤、粒度），而非笼统警告；这要求策展阶段具备验证能力。
  - 成本优化的关键不是"少调用工具"，而是"把调用预算从重复探索转移到最终计算"。
  - 在无法提供安全只读接口的场景，应至少保留纯轨迹策展作为降级路径。

## 9. 总体评价

- **贡献清晰且定位精准**：论文没有提出新模型或新架构，而是以极小的接口改动（两个提示块 + 只读工具）解决了记忆策展中的根本证据缺口问题，工程可行性与可迁移性强。
- **实验设计相对严谨**：跨两个异构基准、三种模型、漂移/无漂移两种动态，配合配对基线与成本调整指标，并将"记忆收益"与"探测增量"分离，因果归因较为干净。
- **结论稳健但边界明确**：主要结论（通过率、奖励、成本、token 效率的全面改善）在多个设置下一致；子组效应作者已主动降级为机制解释，态度审慎。
- **待补强的方向**：策展阶段 TCO 的完整核算、探测假阳性的系统评估、不可探测/高频漂移环境下的压力测试，以及跨模型异质组合的探索。这些将是该方法从"有效"走向"可靠"的关键。
