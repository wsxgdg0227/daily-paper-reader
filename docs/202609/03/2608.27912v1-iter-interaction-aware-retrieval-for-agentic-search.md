## 摘要
深度研究智能体通过一系列迭代的搜索步骤来回答复杂的用户问题，其中智能体自主制定子查询以检索每个阶段所需的证据。然而，现有的检索器训练通常仅依赖当前步骤的子查询及其对应的搜索结果作为训练信号，导致从先前交互中积累的信息在很大程度上未被充分利用。我们引入了ITER，一种使用智能体轨迹学习信号训练的、具备智能体交互感知能力的稠密检索器。ITER不仅整合当前子查询，还整合主问题及先前的子查询来表征每个查询，并使用源自智能体交互的轨迹相对学习信号进行训练。在来自三个模型家族的六个智能体骨干网络上，ITER持续优于现有的基于智能体轨迹训练的稠密检索器LRAT，在InfoSeek-Eval上平均提升7.5%，在BrowseComp-Plus上平均提升13.5%。与深度研究检索器AgentIR相比，ITER还展现出更强的跨智能体鲁棒性，后者依赖于外部LLM评判信号及智能体搜索前的推理。消融实验进一步表明，主问题和先前的子查询提供了最稳健的查询表征，而先前访问过的且有价值的文档在后续搜索中被用作冗余负例，提供了最强的轨迹相对监督。代码可在 https://github.com/ielab/ITER 获取。

## Abstract
Deep-research agents answer complex user questions through an iterative sequence of search steps, where the agent autonomously formulates sub-queries to retrieve the evidence needed at each stage. However, existing retriever training typically relies only on the sub-query and its corresponding search results at the current step as training signals, leaving the information accumulated from previous interactions largely underutilized.   We introduce iter, an agent interaction-aware dense retriever trained using agent trajectory learning signals. iter represents each query by incorporating not only the current sub-query, but also the main question and preceding sub-queries, and is trained using trajectory-relative learning signals derived from the agent's interactions.   Across six agent backbones from three model families, iter consistently outperforms the existing agent-trajectory-trained dense retriever, LRAT, achieving an average improvement of 7.5% on InfoSeek-Eval and 13.5% on BrowseComp-Plus. iter also demonstrates stronger cross-agent robustness than AgentIR, a deep-research retriever that relies on external LLM-judge signals and the agent's pre-search reasoning. Ablations further show that the main question and previous sub-queries provide the most robust query representation, while previously visited and useful documents, used as redundancy negatives in subsequent searches, provide the strongest trajectory-relative supervision. Code is available at https://github.com/ielab/ITER.

### 1. 论文的核心问题与整体含义（研究动机和背景）

- **背景：多步智能体搜索的兴起**。深度研究（Deep-Research）智能体在回答开放式复杂问题时，通常需要经历多轮"子查询生成 → 文档检索 → 浏览判读 → 再次搜索"的迭代循环。这与传统单轮问答检索存在本质差异——检索不是一次性的，而是被嵌入在一个不断演化、证据逐步累积的决策过程中。
- **核心问题**：现有检索器的训练方式与智能体搜索的"交互性"和"累积性"不匹配。当前主流训练方案（如 LRAT）在每个搜索步上只使用**当前子查询**与其对应结果进行监督，忽视了交互历史中非常宝贵的信息，包括：
  - 此前已经发过哪些子查询（反映已探索过的方向）；
  - 此前访问过哪些文档（反映哪些信息缺口已得到满足）。
- **深层矛盾**：在多步搜索场景中，一个文档的价值不应当仅仅取决于它与当前子查询的**主题相关性**，而应取决于它在当前状态下能提供的**边际增益**（marginal gain），即它能带来多少"尚未获取的新信息"。一个此前已被访问且提供过有用信息的文档，即便与当前查询依然高度相关，其边际效用也已大幅下降。
- **总体含义**：论文提出，agentic 检索的目标不应仅是"找到相关证据"，而应是"找到对智能体下一步最有用的证据"，即优化整个搜索轨迹的推进效率，而非孤立步骤的单点相关性。

### 2. 论文提出的方法论：核心思想、关键技术细节

#### 2.1 核心思想
论文提出 **ITER**（Interaction-aware Trajectory-conditioned Embedding Retriever），一种交互感知的稠密检索器。ITER 的设计包含两条核心原则：
1. 检索输入不仅包含当前子查询，还要包含**主问题**和**之前的子查询**，通过历史条件化查询表征将智能体当前所处的搜索状态注入检索过程；
2. 训练监督不是静态的"查询-文档相关性"，而是**轨迹相对（trajectory-relative）监督**——根据文档在轨迹中的交互位置动态判定正负样本。

#### 2.2 查询表征构建
- **默认表示（默认配置）**：将主问题（Main Question）、当前子查询（Current Sub-query）、先前子查询（Previous Sub-queries）序列化拼接作为查询编码器输入。主问题保留任务总体目标；当前子查询表达即时信息需求；先前子查询暗示已探索过的方向，防止重复检索。
- **推理增强变体**：可选地在默认表示中加入搜索前推理（Pre-search Reasoning），即智能体在发出当前子查询之前的思考内容。

#### 2.3 轨迹相对监督信号的构建
- **去重轨迹收集**：为最大化新候选文档覆盖率，团队将搜索接口改为"去重模式"——新结果从不与先前已返回的文档重复，已返回的文档单独列在"returned earlier"区，并可继续通过 get_document 获取。使用 Tongyi-DeepResearch-30B 在 10,000 个 InfoSeek 训练问题上配合 4 种检索后端（BM25 + 3 个 Qwen3-Embedding 规模）收集轨迹，保留 20,893 条最终答案正确的轨迹用于训练。
- **正样本**：将在子查询发出后、下一轮搜索前被访问且被 LLM 判读为提供有用信息的文档作为正样本。值得注意的是，"延迟访问"（文档在之前某轮已被返回但延后到本轮才访问）的样本占 26.7%，说明"首次返回时未被立即访问"不等于无用。
- **分层负样本**：
  - **冗余负样本**（权重最高）：此前已被访问并被判定为有用的文档——它们虽有主题相关性但信息已被消费；
  - **困难负样本**：此前被访问但被判定为无用的文档——其摘要看起来有用但全文无益；
  - **弱负样本**（权重最低）：在当前轮被返回但整个轨迹中从未被访问的文档——因其效用不确定，不宜过度惩罚。

#### 2.4 加权对比学习目标
- **正实例权重**：根据访问后推理文本长度映射为饱和递增的权重（LRAT 的观察结论——推理越长文档越有价值）。原始分数为：āᵢ = 1 − exp(−(ln2/β)·ℓᵢ)，其中 β 为中位推理长度，随后归一化为均值 1。
- **负例分档权重**：(w_red, w_hard, w_weak) = (3.0, 1.0, 0.3)。对负逻辑项乘以权重等价于在其 logit 上加 log 权重。
- **损失函数**：加权 InfoNCE 对比损失，温度为 0.02，批内其他样本也作为额外负样本。最终损失按实例权重 aᵢ 加权聚合。
- **训练参数**：基于 Qwen3-Embedding-0.6B 全参数微调 2 个 epoch，AdamW（lr=1e-6），批量大小 32，bf16 精度，last-token 池化，文档最大长度 512 token，查询最大长度 8,192 token。

### 3. 实验设计：数据集/场景、基准与对比方法

#### 3.3 智能体骨干网络

### 6. 论文的主要结论与发现

1. **轨迹相对训练确实有效**：仅将 LRAT 的训练信号改为 ITER 的轨迹相对信号（查询输入不变），在 InfoSeek-Eval 上将 SR 从 72.7 提升至 76.7，同时减少平均工具调用次数——说明监督信号的构建方式本身就能带来收益。
2. **历史条件化查询带来进一步增益**：加入主问题和历史子查询后，InfoSeek-Eval SR 从 76.7 提升至 80.0，BrowseComp-Plus SR 从 43.7 提升至 46.6。
3. **跨智能体一致性优越**：在所有 12 个（6 骨干 × 2 基准）LRAT 对比中 ITER 全部取得更高 SR，7 项显著；平均增益 InfoSeek-Eval +5.4 点、BrowseComp-Plus +4.3 点。
4. **搜索前推理迁移不稳定**：与匹配智能体（Tongyi）搭配时有效，但在 5 个未见骨干上普遍弱于默认配置——能力迁移受限。
5. **AgentIR 检索到相关文档 ≠ 智能体有效利用**：AgentIR 的证据搜索召回较高，但访问召回和任务成功率不及 ITER，说明仅依赖 LLM 相关性判断无法捕捉"智能体实际上会消费哪些证据"。
6. **冗余负样本是最核心的监督信号**：去除它们导致 BrowseComp-Plus SR 从 46.6 暴跌至 40.8、证据召回从 .636 降至 .561——证明信息已被消费的文档是交互感知检索中最关键的分辨对象。
7. **显式将已访问内容编码到查询中有害**：将访问过的文档或其解读加入查询反而降低性能（可能因为它们既是查询内容又是需要被压低排序的冗余负例，彼此冲突）。

### 7. 方法或实验设计上的亮点

- **概念创新清晰**：将"文档的边际增益"概念形式化为交互相关的效用函数，从理论层面抓住了 agentic 搜索与传统检索的本质区别——检索应当服务于"整条轨迹的推进"，而非"单步的相关性匹配"。
- **负样本设计精巧**：用智能体访问时机来定义"冗余负样本"是自然且新颖的——它直接对应搜索过程中的信息消费行为，而非人工构造的语义相似负例。加权设置（冗余 3.0 > 困难 1.0 > 弱 0.3）反映了证据强度的合理梯度。
- **去重搜索界面的工程设计**：有效扩展了候选文档覆盖面，同时保留对"延迟访问"样本的收集能力（26.7% 的正样本具有延迟访问性质），防止将"未立即访问"误判为"无用"，这是训练数据质量的重要保障。
- **评测强调迁移与鲁棒性**：不满足于单一智能体的匹配评估，覆盖多样化的骨干网络（3 个模型家族 × 多种规模），使结论更有普适价值；且用 4B ITER 与 AgentIR 做规模匹配对比，尽量消除模型规模变量的干扰。
- **检索质量与端到端指标结合**：同时报告 SR（任务是否答对）、证据搜索/访问召回（检索是否命中）与 Steps（效率），避免单指标偏差。

### 8. 不足与局限

- **数据与场景的覆盖边界**：训练数据仅从 Tongyi-DeepResearch-30B 搭配 4 种检索后端收集，且仅保留答案正确的轨迹——无法确定该方法对失败轨迹中可能存在的错误搜索行为模式是否同样有效。评测语料主要为维基类文档，对于需要从非结构化网页、多模态数据或其他格式获取证据的搜索场景缺乏验证。
- **统计功效有限**：InfoSeek-Eval 仅 300 问，多数跨骨干增益虽在数值上为正，但未能达到统计显著（如 4B ITER vs AgentIR 在多个骨干上 SR 差异无显著 p 值）；BrowseComp-Plus 的视觉表格收集较棘手且未逐项给出置信区间。若干 4B 变体在证据搜索召回上显著低于 AgentIR，论文给出的解释（访问信号优于检索信号）虽合理但缺少直接过程性证据。
- **推理增强表征的迁移瓶颈未完全解决**：论文仅指出"推理是自由格式、模型特有的"，但没有提出解决方案（如归一化推理格式或跨模型推理适配），限制了推理增强表征在异构智能体生态中的应用。
- **缺少端到端联合优化的视角**：方法将检索器视为固定组件进行优化，没有与智能体的查询生成策略联合建模——未来的工作如同时调整智能体"问什么"和"怎么检索"可能形成互补增益。
- **算力说明不够透明**：未披露完整评测流程的总计算开销与 4B 模型的训练成本，复现成本估计困难。
- **与真实搜索环境的距离**：实验在固定语料库、受限工具调用次数的封闭环境下进行，与开放互联网搜索相比（如页面动态更新、检索 API 限制、多模态网页等），其结论的可推广性仍需进一步验证。
- **存在潜在的偏差风险**：由于训练集和 InfoSeek-Eval 共享任务分布和信息来源（Wiki-25），域内结果可能高估了方法的实际效果——尽管 BrowseComp-Plus 的域外结果在一定程度上缓解了这一担忧。
