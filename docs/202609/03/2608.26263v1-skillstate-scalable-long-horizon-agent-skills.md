## 摘要
大型语言模型（LLMs）日益作为自主智能体执行复杂、长时间运行的程序性技能。现有的智能体运行时通过不断将观察、动作和中间推理过程附加到不断增长的对话历史中来维持执行，这导致长时程下的延迟退化和上下文污染故障。我们提出了SKILL.state，一种运行时架构，用显式的、可变的执行状态取代仅追加的对话历史。在每个执行步骤中，模型仅接收不可变的技能规范、当前结构化的执行状态以及最新的观察。在产生经过验证的状态更新后，中间推理被立即丢弃，从而防止提示词随执行历史增长。在多种数据集、模型和执行环境中，SKILL.state提高了任务准确率，同时大幅减少了累积的token消耗。我们的结果表明，显式的执行状态是一种有效且与架构无关的抽象，适用于可扩展的长时程智能体技能。

## Abstract
Large Language Models (LLMs) increasingly act as autonomous agents executing complex, long-running procedural skills. Existing agent runtimes maintain execution by continually appending observations, actions, and intermediate reasoning traces to an ever-growing conversation history, causing latency degradation and context-poisoning failures over long horizons. We present SKILL.state, a runtime architecture that replaces append-only conversational history with an explicit, mutable execution state. At each execution step, the model receives only the immutable skill specification, the current structured execution state, and the latest observation. Intermediate reasoning is discarded immediately after producing a validated state update, preventing prompt growth with execution history. Across diverse datasets, models, and execution environments, SKILL.state improves task accuracy while substantially reducing cumulative token consumption. Our results demonstrate that explicit execution state is an effective and architecture-agnostic abstraction for scalable long-horizon agent skills.

## 1. 核心问题与研究动机

论文指出，LLM 智能体在执行长时程程序性技能（long-horizon procedural skills）时，传统运行时普遍采用“对话式（conversational）执行模型”——即把每次的推理、动作、观察和工具输出全部 append 到一个只增不减的对话历史里。这种做法随着执行步数 T 增长会产生三个致命问题：

- **提示词尺寸线性增长**，导致**延迟恶化**和**推理成本上升**；
- **大量历史过程文本**（旧观察、过时推理）残留在上下文中，产生“上下文污染”，模型难以区分哪些事实是**当前有效**的；
- 模型被迫从**累积文本中持续“重建”世界状态**，而不是直接读取当前状态，执行正确性随历史膨胀而退化。

作者由此提出核心假设：应以**显式的、可变的执行状态**取代历史累计，而不是去改进历史压缩或摘要。

## 2. 方法论：SKILL.state 运行时架构

SKILL.state 的核心思想是把技能执行从“对话历史拼接”转变成**显式的状态转移过程**。每步模型仅收到三元组：

```
At = (P, Σt, Ot)
```

- P：不可变的程序性技能规格；
- Σt：当前结构化执行状态（JSON schema）。
- Ot：当前最新的环境观察。

模型输出三元组：

```
(Rt, ΔΣt, at)
```

- Rt：中间思维链推理（只用于当前步内部计算）；
- ΔΣt：结构化状态更新（JSON patch / 字典增量）；
- at：下一步要执行的动作。

状态更新被验证后执行：

```
Σt+1 = Σt ⊕ ΔΣt
```

其中 ⊕ 为运行时字典合并操作（key 置 null 即删除该字段）。验证通过、状态更新后，推理 Rt **立即被永久丢弃**，绝不进入后续 prompt。因此提示词尺寸恒定为 O(1)（不随 t 变化），而累积 token 复杂度为 O(T)；对比传统对话式运行时的提示词 O(t)、累积 token 复杂度 O(T²)。

状态 schema 按领域一次性编写、跨任务复用；例如 InterCode CTF 中 100 个任务共享 5 字段的状态 schema（discovered_flags、tested_hypotheses、active_files、working_dir、cmd_summary）。算法流程见 Algorithm 1（循环接收观察 → 构造 prompt → 生成推理/状态更新/动作 → 校验 → 合并更新 → 执行动作）。

## 6. 主要结论与发现

1. **以显式执行状态替代对话历史能系统性地提升长时程技能执行效果**：在 5 个主要实验与 3 类模型上，SKILL.state 均达到最高的任务成功率/准确率。
2. **token 消耗大幅下降**：Warehouse T=100 时对比 Stateful 降低 16.2×；T=200 时仅消耗 122k token 保持 0.94 准确率。
3. **提示词尺寸恒定（O(1)）**：SKILL.state 在大约 1,736–1,905 tokens 范围内浮动，而 baselines 随 T 膨胀达到 3 万到 8 万+ tokens/step。
4. **抗噪与快速恢复**：在 50 events/step 高噪声下，Prompt 基线崩塌至 0.53，SKILL.state 维持 0.98；环境外漂移时，历史基线需 5–14 步恢复而 SKILL.state 零步恢复。
5. **压缩基线全面崩溃**：滑动窗口与 LLMLingua 这类统计压缩无法保持状态中精确的关系依赖（丢关键变量），说明结构化保持是核心收益来源，而非单纯 token 缩减。
6. **公开非线性真实环境泛化良好**：CTF 上 pass@1 达 54.2%（比最强基线高 7.8 点）；τ-Bench Retail/Airline 均为最优。

## 7. 优点与亮点

- **问题定义精准**：把长时程 agent 问题从“上下文压缩”重构为“状态维护”，切中系统级痛点。
- **架构无关、工程落地简洁**：不需要额外检索、摘要模型或压缩模型，只靠规范化的运行时状态 schema + 丢弃推理。
- **理论复杂度清晰**：给出 O(1) prompt 与 O(T) 累计 token 的解析证据，对比传统 O(T²)。
- **良好的诊断环境设计**：SkillExecBench 用确定性状态转移隔离了“执行机制”和“启发式搜索能力”，能干净地检验状态保持能力；任务使用固定随机种子，确保所有运行时经历完全相同的观察序列，比较公平。预算匹配控制组设计严谨，隔离效果检验到位。
- **明确的失败归因**：对小模型的失败做定量分析（68% 状态误覆盖等），为后续用约束解码提供改进方向。
- **对噪声干扰和突然状态漂移的鲁棒性极为突出**，这在现实环境中很有价值。

## 8. 不足与局限

作者在文中也自述了若干重要局限：

- **状态充分性假设**：SKILL.state 假定一切影响未来动作的信息都能“即时投影”到结构化状态中。三种情况不成立：① 运行时需动态发现 schema；② 早期观察当时未被识别为重要而未提交到状态，后来才需要；③ 任务目标本身定义在历史轨迹上（审计、调试、可解释性需求）——此时历史正是输出而非开销。
- **多智能体未覆盖**：显式状态天然适合多智能体共享状态，但并发写需要确定性的冲突解决语义（⊕ 合并的并发行为在单智能体设置中未打磨）。
- **小模型的结构化输出能力弱**：开放权重小模型在状态 patch 生成上高发键遗漏/类型错误，导致性能大幅折损，有效缓解（如约束解码）在本文只是建议、没有实验验证。
- **基准局限**：SkillExecBench 是模拟环境；真实基准（CTF、τ-Bench）任务数偏少；缺乏对超长真实生产型任务（数小时到数天）的验证；未见跨 schema 风格（粗粒度、细粒度、非嵌套扁平结构）对效果的敏感性研究。
- **计算资源透明性不足**：未报告推理时延绝对数值和算力配置，无法直接判断实际延迟改善幅度。

## 结语

SKILL.state 提出并验证了一个有力的新运行时抽象——以显式结构化状态作为执行真相源，丢弃中间推理，换取了**常数级提示词脚、线性累积 token、更强的抗噪性和 0 步状态恢复**。从方法论提出、理论分析到多环境实验结果均呈现较高的完整度和实证严谨性，对长时程 LLM 智能体系统的设计具有较好的启发性。不过其依赖“状态是高信息充分统计量”的前提，在多智能体、动态 schema 与训练-历史自身的任务中尚未覆盖；未来配合更好的结构化解码约束与小模型校准，是该方向主要的关键落地挑战。
