## 摘要
硬件内核优化需要重复的编译、正确性测试、性能剖析和修改。LLM智能体可以自动化该过程的某些部分，而更强的基座模型、更长的上下文窗口和更长的执行周期已改善了单个任务内的优化效果。但这些进步本身并不能使智能体从已完成的优化运行中学习。现有的内核优化智能体很少保留一个决策、其观测到的执行反馈以及后续利用该证据的决策。保留每一个先前的轨迹也不可行，因为不断增长的历史记录会与当前任务争夺上下文。我们提出了KOPE，一个用于硬件内核优化的经验驱动框架。KOPE在经验图内存中记录带有正确性和性能反馈的优化轨迹，然后在固定的token预算下使用主动上下文管理与注入来检索相关经验。该图保留了决策顺序、观测结果和备选分支，使得在目标硬件上收集的证据能够为后续的优化步骤和任务提供信息。在相同的GLM-5.2设置下，KOPE的每算子加速比几何平均是CANNBot（最强竞争基线）的1.54倍。在完整的53算子消融实验中，主动上下文管理与注入将通过率从60.0%提高到84.6%，将评估器报告的正面字段几何平均值从0.0382提高到0.0661，并将优化token消耗相对于被动智能体主导的上下文构建从159亿token减少到11.13亿token。启用经验图内存将全套通过率从55.2%提高到84.6%，并在有效计时比较上产生了1.43倍的几何平均加速。这些结果支持在基座模型保持固定时，通过外部经验进行持续优化。

## Abstract
Hardware kernel optimization requires repeated compilation, correctness testing, profiling, and revision. LLM agents can automate parts of this process, and stronger foundation models, longer context windows, and longer execution horizons have improved optimization within individual tasks. These advances alone do not enable an agent to learn from completed optimization runs. Existing kernel-optimization agents seldom preserve a decision, its observed execution feedback, and the later decisions that use that evidence. Retaining every prior trajectory is also impractical because an expanding history competes with the current task for context. We present KOPE, an experience-driven framework for hardware kernel optimization. KOPE records optimization trajectories with correctness and performance feedback in Experience Graph Memory, then uses Active Context Management and Injection to retrieve relevant experience under a fixed token budget. The graph retains decision order, observed outcomes, and alternative branches, allowing evidence collected on the target hardware to inform later optimization steps and tasks. Under the same GLM-5.2 setting, the geometric mean of KOPE's per-operator speedups is $1.54\times$ that of CANNBot, the strongest competing baseline. In a complete 53-operator ablation, Active Context Management and Injection raises pass rate from 60.0\% to 84.6\%, increases the evaluator-reported positive-field geometric mean from 0.0382 to 0.0661, and reduces optimization token consumption from 15.9B to 1.113B tokens relative to passive agent-led context construction. Enabling Experience Graph Memory raises full-suite pass rate from 55.2\% to 84.6\% and yields a $1.43\times$ geometric-mean speedup on valid timing comparisons. These results support continual optimization through external experience while the foundation model remains fixed.

## 2. 方法论

### 2.1 整体框架：经验驱动的闭环工作流

KOPE 将每一次优化尝试都视为一次学习事件，循环流程为：

- 根据当前状态 $s_{t,k}$（内核规格、当前最优代码、最近执行反馈、优化目标）从持久化外部记忆 $M_{t,k}$ 中检索相关经验 $z_{t,k}$；
- 在固定上下文预算 $B$ 下组装提示词 $C_{t,k}$；
- LLM 智能体 $\pi_\theta$（参数**固定不变**）生成候选动作 $a_{t,k}$；
- 在目标硬件上执行 $E(a_{t,k})$，得到编译诊断、正确性和性能反馈 $y_{t,k}$；
- 更新外部记忆 $M_{t,k+1}$，供下一步及后续任务使用。

### 2.2 经验图内存（Experience Graph Memory / KOPE-Mem）

- **双重表征**：每个事件同时记录为追加式 Markdown **Journal**（策略、代码变更、验证状态、测量值的自然语言总结）和结构化 JSON **Case**（算子、优化思路、前后代码、编译器反馈、正确性、加速比、置信度、会话/步骤/前驱ID）。
- **决策到结果的图结构**：构建有向无环森林 $G=(V,E)$，节点记录决策及其结果，边 $(u,v)$ 表示 $v$ 的尝试从 $u$ 的状态出发。记录的是**执行谱系而非因果效应**。
- **图感知检索与排序**：
  - 先按精确过滤器（算子、优化层、结果标签）和语义搜索构建相关候选池；
  - 定义**步进比率** $r_v = a_v / a_{prev(v)}$（根节点的 $r_v=1$），据此划分结果标签（effective ≥1.05，partial ≥1，ineffective ≥0.85，negative <0.85）；
  - 使用**折扣下游结果评分** $d(v) = 0.5 \cdot r_v + 0.5 \cdot 0.7 \sum_{u \in succ(v)} d(u)$ 将"后续结果"纳入排序，使检索能区分"短期不错但长期失败"与"当下一般但对后续探索有启发"的决策。

### 2.3 主动上下文管理与注入（Active Context Management and Injection）

- **三级动态上下文**：
  - **Hot**（热）：内核规格、当前最优代码、最近反馈、优化目标——必要时必须包含；
  - **Warm**（温）：从经验图检索到的相关 Case、Journal 摘要、程序性摘要；
  - **Cold**（冷）：更广泛的文档、跨类别经验、旧摘要。
- **预算感知组装**：给定模型窗口 $W$、系统提示 $S$、生成预留 $G$、近期预留 $R$，可得知识预算 $B_k = \max(0, W - S - G - R)$。先满足 Hot 内容，再按图评分依次注入 Warm（上限 $Q_w$）和 Cold 材料（上限 $Q_c$）。
- **明确边界**：该方法在模型调用前选择外部材料，与推理阶段的 KV-cache 淘汰机制互补、可组合，属于不同层级。

## 6. 主要结论与发现

### 系统级结果（Ascend）
- **GLM-5.2 下**：KOPE 全套件通过率 **84.6%**（897/1,060），较 CANNBot 的 57.8% 提高 26.8 个百分点；总分从 1465.93 提升至 2004.49（+36.7%）；算子加速几何均值达 CANNBot 的 **1.54 倍**；53 个算子全部返回。
- **Deepseek-V4-Pro 下**：KOPE 通过率 73.9%，领先 CANNBot（39.3%）34.5 个百分点；但 CANNBot 在"已返回算子交集"上条件得分更高，说明 KOPE 的优势主要在覆盖率而非每个条件统计量上都占优。
- **CUDA-Agent 迁移失败**：即便使用强 GPU 优化工作流，在 Ascend 稀疏语料环境下仅达 9.1%–14.7% 通过率，**未解决任何一个完整算子**——证实"模型能力 + 任务内修正"不足以应对目标特定公开语料稀缺的场景。

### 消融结果
- **主动上下文管理注入**：通过率 60.0%→84.6%（+24.6 pp）；正面字段几何均值 0.0382→0.0661（1.73×）；token 消耗 **15.9B→1.113B（−93.0%）**——证明增益并非来自"放入更大历史"，而是来自选择性注入。
- **经验图内存**：全套通过率 55.2%→84.6%（+29.4 pp）；配对计时几何均值加速 **1.434 倍**；L2/L3/L4 分别加速 1.455/1.501/9.175 倍（L1 无增益甚至微降）。

### 跨硬件泛化（RISC-V）
- Ascend 经验转移可将覆盖率从 60.3% 提至 83.3%（**可行性知识可跨体系结构迁移**），但固定交集性能下降 62.5%（**性能知识不可自动迁移**）；
- 目标端（K3）经验将覆盖率推至 89.2%、性能提至冷启动的 1.325 倍；组合经验达 92.2% 覆盖率和 0.786× 的固定交集几何均值——**"源经验定先验 + 目标反馈修正"**是更强的性能路径。

## 7. 方法亮点与创新

1. **外部记忆而非参数更新的"自我进化"定义**：将基座模型固定，把持续改进的载体放在经验图结构中——这是一种务实且可解释的持续学习路线，规避了参数微调的成本与灾难性遗忘风险。
2. **决策-结果图式的记忆结构**（区分于简单的文本记忆）：同时保留决策顺序、观测结果与备选分支，引入"折扣下游结果评分"，使排序标准从"文本相似"扩展为"决策的长期后果"，更贴近优化的序贯决策本质。
3. **三级预算感知上下文管理**：通过在 token 预算内优先保证 Hot 状态、按图排序注入 Warm 经验，在提升性能的同时将 token 消耗降低 93%——直接回应了长上下文利用率问题。
4. **正确性先于性能的执行纪律**：候选必须通过编译和数值正确性验证才能替换当前最优，失败证据同样被系统记录与复用。
5. **严谨的实验统计口径**：缺失算子计失败、固定交集计时比较、区分"全套件覆盖率"与"条件性能"，避免掩盖覆盖不足的系统。
6. **跨异构硬件体系的迁移实验**（Ascend→RISC-V 同时更换 ISA/内核语言/编译器），分离"可行性知识迁移"与"性能知识迁移"两个不同结论，拓展了系统通用性声明的适用边界。

## 8. 不足与局限

1. **统计效力不足**：每个配置仅一个代表性归档运行，无重复实验、无方差估计、无显著性检验，结论的稳健性存疑。
2. **算力信息不透明**：未披露 GPU 型号、数量、总运行时长，复现所需成本不可估——对学术社区的可复现性和应用者的资源规划构成障碍。
3. **消融粒度不够细**：主动上下文管理的增益无法归因于具体机制（图排序 vs 压缩 vs 注入策略）；经验图内存的实验在第 4 难度级别仅 28 对有效样本，L4 的 9.175 倍加速结论基础薄弱。
4. **检索启发式未经因果验证**：作者明确承认 $d(v)$ 分数和效果标签是检索启发而非因果估计，但未讨论该启发式在何种条件下可能误导后续决策（如错误地将下游成功归因到当前节点）。
5. **性能口径的覆盖局限**：加速比几何均值仅基于正面字段（GLM-5.2 下仅覆盖 52 个算子的部分子集），且非正数值被排除在分母之外，需结合通过率解读。
6. **跨硬件迁移结论边界清晰但保守**：RISC-V 实验中所有配置的平均性能仍低于 PyTorch 原生内核（0.786×），说明"通用工作流"而非"通用性能保障"；且每配置亦为单次运行。
7. **发布状态与时效性**：论文标注为 2026 年预印本（含引用 2026 年文献），引用的模型（GLM-5.2、Deepseek-V4-Pro）与硬件环境（Ascend 910C、CANN Bench v0.4.0）均为特定版本快照，结论的外部时效性需持续跟踪验证。
