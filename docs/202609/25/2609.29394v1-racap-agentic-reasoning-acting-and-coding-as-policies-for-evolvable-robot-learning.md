## 摘要
通用机器人智能体必须从经验中学习、迁移到新任务并高效行动。代码即策略（Code as Policies，CaP）方法在运行时生成并修复程序，这会带来延迟，并将可复用机制与任务特定决策纠缠在一起。我们提出 RACaP，一个智能体框架，它将编码移至演化阶段，并在部署时使用推理—行动（ReAct）循环调用冻结的、带类型的策略 API。一种两阶段策略将能力课程学习与自主自演化相结合，以改进 API、ReAct 执行框架和经验记忆。API 编码了可复用的物理机制，同时暴露参数以支持运行时自适应。ReAct 结合任务特定的工作记忆、长期经验记忆和视觉反馈来选择动作、验证结果并从失败中恢复，而无需修改源代码。RACaP 在 LIBERO-90 上取得 54.4% 的成功率，在零样本 LIBERO-PRO 上取得 45.0%，在 LIBERO-Long 上取得 46.0%，而 CaP 基线在长时程任务上至多为 4.0%。在 LIBERO-PRO 上，其成功率达到 CaP 基线的 2.5 倍，策略中位耗时加速 1.9 倍。为便于在机器人上高效部署，拒绝采样微调将 GPT-5.6 的 ReAct 决策蒸馏到 Qwen3-VL-8B-Instruct 中，实现每次决策推理加速 13.2 倍，并将重复的物理调用从 16 次减少到 4 次。这些结果表明，将可复用代码与运行时决策分离，有助于持续演化、有效迁移以及高效的长时程控制。

## Abstract
General-purpose robot agents must learn from experience, transfer to new tasks, and act efficiently. Code as Policies (CaP) methods generate and repair programs at runtime, incurring latency and entangling reusable mechanisms with task-specific decisions. We introduce RACaP, an agentic framework that moves coding to evolution and uses a Reasoning-and-Acting (ReAct) loop to call frozen, typed Policy APIs at deployment. A two-phase strategy combines capability curriculum learning with autonomous self-evolution to improve the APIs, the ReAct harness, and experience memory. The APIs encode reusable physical mechanisms while exposing arguments for runtime adaptation. ReAct combines task-specific working memory, long-term experience memory, and visual feedback to select actions, verify outcomes, and recover from failures without modifying source code. RACaP achieves 54.4% success on LIBERO-90, 45.0% on zero-shot LIBERO-PRO, and 46.0% on LIBERO-Long, compared with at most 4.0% for CaP baselines on long-horizon tasks. On LIBERO-PRO, it achieves 2.5 times the success rate of CaP baselines and a 1.9-fold speedup in median policy time. For efficient on-robot deployment, rejection-sampled fine-tuning distills GPT-5.6 ReAct decisions into Qwen3-VL-8B-Instruct, yielding a 13.2-fold per-decision inference speedup and reducing repeated physical calls from 16 to 4. These results show that separating reusable code from runtime decisions supports continued evolution, effective transfer, and efficient long-horizon control.

## 1. 核心问题与研究动机

- **背景**：通用机器人智能体需要同时具备三种能力——从经验中学习、把知识迁移到新任务、在物理执行时高效行动。Code as Policies（CaP）通过让 LLM 直接生成可执行机器人程序来提供灵活性，CaP-X 还加入视觉差分与程序修复。
- **核心矛盾（evolution-to-execution problem）**：
  - CaP 把「写代码」放在物理执行路径上。CaP-X 一次编码迭代耗时 6.8–23.8 秒，多轮试验 60.8–113.6 秒；运行期还可能产生语法错误、抓错物体或重复无效动作。
  - 生成出的程序往往**混合了可复用物理机制与任务特定常量**（物体名、坐标、抓取高度、偏移量），换任务就得重写，难以迁移。
- **已有自改进方法的不足**：
  - RATS 用「新奇性 + 可学习性」的 play 目标收集代码，但该目标不保证对下游任务有正收益。论文受控实验显示：LIBERO-90 上的 play 反而使成功率从 21.1% 降到 11.1%，零样本 LIBERO-PRO 从 17.8% 降到 8.3%。
  - ASPIRE 会验证并检索程序修复，但很多修复仍绑定于观测到的固定距离/抓取高度，且**仍然在执行期保留源码生成或修复**。
- **本文要回答的问题**：CaP 系统应如何在「演化期代码」与「运行期决策」之间划分职责，从而既能持续演化、跨任务迁移，又能响应当前物理状态？
- **总体含义**：论文主张——**代码应承载跨任务可复用的物理机制，ReAct 应承载场景相关的选择**（动作顺序、函数参数、恢复、停止）。这是对 CaP 范式从「运行期生成代码」到「演化期演化接口 + 运行期调用接口」的一次定位调整。

## 2. 方法论

### 2.1 核心思想与形式化目标

- 可部署策略分解为三部分：**Π = (Aθ, πφ, M)**
  - Aθ：带类型的策略 API 库（实现参数 θ），承载局部接触几何、运动执行、物理测量、失败报告；
  - πφ：运行期 ReAct 策略（框架参数 φ），负责任务分解、工具与参数选择、失败恢复、停止逻辑；
  - M：长期经验记忆，提供可复用的动作前提与恢复经验，**不存任务答案、绝对坐标或评测器状态**。
- **API 选择目标（式 2）**：在固定 πφ 与 M 时，用配对增益减配对回退在开发集 Ddev 上选择候选 θ′，要求同一任务、同种子、同预算下比较，奖励跨任务泛化性：
  θ* = argmax_θ′ Σ_{τ∈Ddev} [S(τ,Aθ′,πφ,M) − S(τ,Aθ,πφ,M)]
- **ReAct 与记忆选择目标（式 3）**：API 固定后，用**字典序**目标——先比成功率，成功率并列时再比 ReAct 轮数（−ΣT），避免「更快但更差」的智能体获胜。
- 设计张力：API 必须给 ReAct 足够的适应与恢复自由度，同时把抓取、接触控制等底层技能封装在内部。

### 2.2 两阶段演化

- **Phase 1：能力课程学习（S0–S6）**
  - 动机：从只有基础原语出发的自演化会陷入局部最优——单次失败可能混合感知、抓取、放置、路由、停止错误，编码智能体无法归因。
  - 课程层级：S0 直接搬运（pickplace/geometry）→ S1 搬运 ReAct（空抓、偏移恢复）→ S2 有界放置（目标身份与有效内部区域）→ S3a 插入 / S3b 堆叠 / S3c 铰接 / S3d 紧凑控制 → S4 工具路由 → S5 因果组合 → S6 效率（消除冗余检查与无效重试）。
  - 效果：41 任务搬运队列从 13/41（31.7%）提升到 28/41（68.3%）；全 90 任务从 40/90（44.4%）提升到 48/90（53.3%）。
  - 约束：不使用物体坐标等特权数据，只从指令、rollout 视频、工具轨迹与成功信号学习。
- **Phase 2：自主自演化**
  - 对剩余失败聚类 → 选择下一个要攻克的能力 → 视觉评论器对齐前后帧与 API 调用 → 编码智能体提出**单一改动**（API、参数暴露、工具报告、ReAct 路由或记忆）。
  - 候选代码与冻结的父系统在**同任务、同种子、同预算**下配对评估；只有原生成功率严格更高才晋升，平局与回退归档。
  - 规模：596 个开发回合、32 个提案、23 个候选在仿真中测试、9 次晋升获胜，覆盖 transport（T1–T4）、stacking、articulation、紧凑控制、路由、效率。
  - 域内仅从 48/90 提升到 49/90（54.4%），但零样本迁移等指标大幅改善。

### 2.3 冻结的运行期结构

- **两层 ReAct**：Full ReAct（解析整体指令、排序目标、检查语义状态、跨六个 API 路由）+ Transport ReAct（专注单一起点—终点子目标的局部循环，使用 pickplace/insert/push/look/check/done）。
- **六个带类型提示角色**：task_plan、task_plan_review、state_preflight、state_decide（Full ReAct）；transport_decide、transport_reflect（Transport ReAct）。输出为 schema 校验的 JSON，不直接执行环境动作。
- **双结构记忆**：工作记忆（当前指令、剩余子目标、近期 API 调用、视觉结果，每回合重置）+ 长期经验记忆（只读的可复用经验）。
- **API 库**：pickplace、insert、stack、push、articulate、actuate_control，暴露 grasp、clearance、目标解释、yaw、接触模式等参数，返回可读状态、测量值与新 RGB-D 图。
- **闭环机制**：每次物理执行后把控制权交回 ReAct，用视觉工具检查给出建议（除安全/契约违规外不静默覆盖）；评测期严格禁止生成、编译或修复 Python 代码。

### 2.4 拒绝采样微调（RFT）加速运行期

- 把托管 GPT-5.6-sol 教师的 ReAct 决策蒸馏到本地 **Qwen3-VL-8B-Instruct**。
- 数据过滤原则：只保留同时满足**原生执行成功、满足可执行 schema 约束、含有效视觉证据**的教师 rollout；最终保留 54 条、拒绝 40 条。
- 训练角色专属 **LoRA 适配器**，冻结基座模型与视觉编码器，损失只作用于教师回复 token。
