## 摘要
持久记忆使语言模型智能体无需更新模型权重即可改进提示和技能。我们表明，将检索范围与认证范围匹配，可使这些编辑支持在反复出现的任务族上进行可靠的重复适应。我们在 ProcStream-RSI（一个 12 轮代码修复流）上研究冻结模型智能体，使用正交回归控制（ORC）——一种用于持久技能编辑的、基于执行的门控。在一项保持提案和门控决策固定的干预中，仅将每个被接受的技能检索用于其原属任务族，使平均隐藏轨迹效用从全局记忆下的 0.713 提高到 0.816，并将有害部署从八个中的六个变为零个。在 27 个配对的随机顺序流中，Scoped-ORC 相较于 Global-ORC 将平均轨迹效用提高 0.063 [0.037, 0.094]，接受 63 次而非 12 次更新，并在 19/27 个流中产生多次被接受的更新，有害接受为 0/63。全局对照达到 0.713，低于静态智能体的 0.775，因为局部有效的编辑可能干扰无关任务族。这些结果确立了范围匹配作为持久智能体记忆的一种补充控制：认证决定一项编辑是否得到支持，而检索范围决定该证据在何处授权其使用。

## Abstract
Persistent memory lets language-model agents improve prompts and skills without updating model weights. We show that matching retrieval scope to certification scope enables these edits to support reliable repeated adaptation across recurring task families. We study frozen-model agents on ProcStream-RSI, a 12-round code-repair stream, using Orthogonal Regression Control (ORC), an execution-grounded gate for persistent skill edits. In an intervention that holds proposals and gate decisions fixed, retrieving each accepted skill only for its originating family raises mean hidden trajectory utility from 0.713 under global memory to 0.816 and changes harmful deployments from six of eight to none. In 27 paired randomized-order streams, Scoped-ORC improves mean trajectory utility by 0.063 [0.037, 0.094] over Global-ORC, accepts 63 rather than 12 updates, and produces multiple accepted updates in 19/27 streams, with 0/63 harmful acceptances. The global control reaches 0.713, below the static agent's 0.775, because locally valid edits can interfere with unrelated families. These results establish scope matching as a complementary control for persistent agent memory: certification determines whether an edit is supported, while retrieval scope determines where that evidence authorizes its use.

# 论文总结：Scope Before You Persist — Preventing Cross-Family Interference in Agent Memory

## 1. 核心问题与整体含义

- **研究动机**：持久记忆使语言模型智能体无需更新权重即可通过编辑提示、技能来持续改进。但现有自改进系统（如 Gödel Agent、Darwin Gödel Machine）多以"档案最优成员"衡量成功，忽略了**部署谱系**在部分验证下的真实表现。
- **核心问题**：当一条在某个任务族内局部有效的编辑被写入**单一全局技能**并被全局检索时，它可能干扰无关任务族，产生**跨任务族干扰（cross-family interference）**。此时全局记忆甚至不如静态智能体。
- **整体含义**：持久记忆需要两个彼此独立的决策——①更新是否被支持（**认证**），②该证据在何处授权使用（**检索范围**）。论文主张"认证范围"与"检索/部署范围"必须匹配，才能把局部认证转化为**持续适应（continual adaptation）**。

## 2. 方法论

- **总体框架**：冻结 actor $\pi_\theta$ 与持久技能 $K_t$；每轮在 discovery 批次 $D_t$ 上产出修复程序，冻结 editor 生成提案 $K'_t$，门控 $G_t$ 在配对探针任务上决定是否部署：
  $$K_{t+1} = K'_t \text{ if } G_t(K'_t,K_t)=1,\ \text{else } K_t$$
  全程不训练权重，唯一继承状态是 $K_t$。
- **门控漂移命题（Proposition 1）**：设提案有益概率 $\pi$、有益增益 $G$、有害损失 $L$、门控对有益/有害的接受率 $\alpha/\beta$，则期望部署变化为正的条件是 $\pi\alpha G > (1-\pi)\beta L$。对条件独立的 AND 门控，有害接受率为 $\prod_j \beta_j$；若各通道假接受事件相同，增加通道**不改变** $\beta$。该命题只覆盖门控证据中已表示的结果，无法保护尚未出现的任务族免受无范围全局编辑的影响。
- **ORC（Orthogonal Regression Control）门控**：每个任务使用三条在线证据通道——4 个公开样例、4 个私有精确输出测试（不进入 actor/editor 提示）、≥6 个无答案蜕变检查。对任务 $i$ 与通道 $c$ 计算候选减在任的通过率 $d_{i,c}$，按"当前家族 + 各历史家族组"分组，对每组/通道计算**单边 95% 配对 bootstrap 下界** $L_{g,c}$（$n\le 50000$ 精确枚举，否则 2000 次种子抽样，每组 ≥4 任务）。
- **部署条件**：取 $\delta_{new}=0,\delta_{reg}=0.02$，要求 $L_{current,pub}\ge-\delta_{reg}$、$L_{current,priv}>\delta_{new}$、$L_{current,meta}\ge-\delta_{reg}$、所有历史组所有通道 $L_{g,c}\ge-\delta_{reg}$，且无私有/蜕变评估报告不安全程序；合取避免单通道增益"平均掉"另一通道的退化。
- **家族范围检索（Scoped-ORC）**：被接受的候选存入**当前家族 slot**；任务来自家族 $f$ 时，若存在已接受 slot 则用之，否则用初始策略 $K_0$。活动策略仍严格为 360 字符，提案生成与门控完全不变——**只改检索，不改预算、不改决策**。

## 3. 实验设计

- **Benchmark：ProcStream-RSI v3.1**——12 轮代码修复流，含 9 个可复用任务族，家族顺序为 boundary, rotation, ordering, normalization, boundary, rotation, nested, missing, prefix, chunk, tie-breaking, ordering（重复出现使"保留"可观测）。每家族有种子派生的不透明协议 token；发现样例区分家族规则，探针/checkpoint/最终公开样例为中性；每轮 4 个 discovery + 4 个 probe，固定 bank 每家族 1 个 checkpoint + 2 个 final，每流 123 个任务，公开/私有/隐藏输入两两不交。
- **对比方法（7 种配对）**：Static（不提案）、Frozen-compute（同调用但从不部署）、Latest-only（全接受）、Self-judge（actor 自估）、Replay（当前公开增益 + 历史公开非退化）、ORC（完整通道门控）、Batch-ORC（累积发现但仅最终可部署，检验"一次性累积更新"）。
- **三层实验**：
  - 主实验：8 个未见种子 × 全部 12 轮；
  - 固定完成的范围干预：保持提案、门控决策、程序与分数不变，仅改任务到技能的分配；
  - 随机进入扩展：v4 生成器对家族多重集做种子确定性置换，18 流（每首家族 2 流）、每流 1 个更新轮；
  - 全长度扩展：27 流（每首家族恰好 3 流）× 12 轮，配对 Global- 与 Scoped-ORC。
- **外部效度**：32 个 HumanEval+ 任务（固定 SHA-256 排序，事前选定）；GPT-OSS-120B（AkashML BF16）在每流 18 任务 sealed final bank 上做 actor-only 诊断，2000 token 上限。
- **路由器分析**：oracle 路由、stochastic fallback-on-miss 曲线、leave-one-seed-out 字符 3–5-gram 多项式朴素贝叶斯路由。
- **统计**：stream-bootstrap 95% 区间、双侧配对 sign-flip 检验、三个主对比 Holm 校正；独立分析单元为完整流。
