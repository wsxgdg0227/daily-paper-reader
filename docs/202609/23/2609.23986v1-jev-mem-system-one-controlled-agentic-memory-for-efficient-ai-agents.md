## 摘要
智能体记忆对于长时程 AI 智能体正变得至关重要，然而许多现有系统依赖自回归 LLM 来控制记忆的组织、检索和使用方式，从而将昂贵的生成过程置于记忆操作的关键路径上。我们提出 Jev-Mem，一种受系统一/系统二认知启发的新型智能体记忆架构。系统一负责快速、轻量的决策，而系统二执行较慢的审慎推理。Jev-Mem 通过专门的系统一控制平面、结构化的多关系记忆平面和系统二推理平面，将这种分工引入智能体记忆。系统一控制器在构建期间管理记忆类型划分与关系组织，并在检索期间动态执行查询路由、检索预算分配、图遍历、候选评分和自适应停止。系统二仅被调用于复杂推理和答案合成。这一设计同时提升了记忆有效性和系统效率：在 LoCoMo 上，Jev-Mem 取得了 0.777 的 LLM-as-a-Judge 总体得分，相较最强基线相对提升 11.0%；同时将记忆构建时间降至 158 s，相较最快的竞争记忆系统加速 6.6 倍，并将平均查询延迟降至 0.93 s，减少 36.7%。

## Abstract
Agentic memory is becoming essential for long-horizon AI agents, yet many existing systems rely on autoregressive LLMs to control how memories are organized, retrieved, and used, placing expensive generation on the critical path of memory operations. We introduce \textbf{\method}, a new agentic memory architecture inspired by System-One/System-Two cognition. System One captures fast, lightweight decision-making, whereas System Two performs slower, deliberative reasoning. Jev-Mem brings this division of labor to agentic memory through a dedicated System-One control plane, a structured multi-relational memory plane, and a System-Two reasoning plane. The System-One controller governs memory typing and relational organization during construction, and dynamically performs query routing, retrieval-budget allocation, graph traversal, candidate scoring, and adaptive stopping during retrieval. System Two is invoked only for complex reasoning and answer synthesis. This design improves both memory effectiveness and system efficiency: on LoCoMo Jev-Mem achieves an overall LLM-as-a-Judge score of 0.777, an 11.0\% relative improvement over the strongest baseline, while reducing memory construction time to 158\,s, a 6.6$\times$ speedup over the fastest competing memory system, and lowering average query latency to 0.93\,s, a 36.7\% reduction.

## 1. 核心问题与整体含义

- **研究动机**：长时程 AI 智能体需要持续积累用户偏好、任务历史、环境知识等经验，这些信息很快超出固定上下文窗口。因此，智能体需要“智能体记忆”来保存、组织、更新和检索过去经验。
- **现有瓶颈**：许多记忆系统依赖自回归 LLM 控制记忆的组织、检索和使用，例如判断记忆类型、构建关系、路由查询、评分候选、决定何时停止等。这些高频但输出有界的决策被放进生成循环，导致昂贵的 token 生成进入记忆操作关键路径，显著增加构建时间与查询延迟。
- **核心观察**：大量记忆控制操作是“语义的但非生成的”，通常只产生标签、概率或分数，而非自由文本。它们更适合轻量、结构化的 System-One 式计算；复杂证据综合与答案生成才应交给 System-Two。
- **整体含义**：Jev-Mem 将记忆控制本身视为一等系统层，而不是散落在 prompt 或启发式规则中的附属组件。它把 System-One/System-Two 认知分工引入智能体记忆架构，试图同时提升记忆有效性与系统效率。

### 2.1 总体架构

- Jev-Mem 由三部分组成：
  - **System-One 控制面**：轻量结构化决策，负责记忆构建与检索控制。
  - **结构化多关系记忆面**：保存 canonical observation，并维护语义、时间、因果、实体四类关系。
  - **System-Two 推理面**：仅在复杂推理与最终答案合成时调用 LLM。
- 记忆形式可表示为：  
  \(M_t = (V_t, \{E^g_t\}_{g \in G}, I^{vec}_t, I^{lex}_t)\)，其中 \(G = \{\text{semantic}, \text{temporal}, \text{causal}, \text{entity}\}\)。所有关系视图共享同一批记忆节点 \(V_t\)，同一对记忆可同时存在多种类型边。
- System-One 控制器抽象为类型化接口 \(J(S, Q)\)：给定结构化状态 \(S\) 和一批决策问题 \(Q\)，输出独立命题概率或互斥选项分布。决策共享状态时可批量调用。

- 对每个有效观测 \(o_t = (x_t, \tau_t, \mu_t)\) 创建一个 canonical memory node，默认保留原始观测，不在摄入时做不可逆的“存储/丢弃”决策，以避免早期看似不重要的信息永久丢失。
- 控制器预测四个重叠记忆特征：episodic、semantic、procedural、preference。它们只是标注，不是互斥分类。
- **候选发现与关系判断分离**：

- **周期维护**：每若干次写入后，在局部邻域检查冗余、矛盾、过时与新增链接。若需要高层文本抽象，可由结构化控制决策显式升级到 System-Two 生成摘要；生成不是默认维护机制。
