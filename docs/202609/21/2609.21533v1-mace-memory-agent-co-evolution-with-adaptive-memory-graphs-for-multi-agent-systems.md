## 摘要
基于 LLM 的多智能体系统会生成协作轨迹，记录智能体如何规划任务、验证中间结果并修复失败。复用这些过程需要保留动作的前置条件以及后续智能体所需的输出。我们的实证研究表明，将这些依赖关系分组为功能性记忆单元可以提高其保持效果，而连接单元则能提高对任务共同所需的单元和链接的检索。即便每种组合的内容在不同格式下固定不变，偏好的单元组合也会在指令与清单之间发生变化。根据每种组合与格式配对的结果来更新选择，优于分别对组合和格式进行评分。这些发现促成了 MACE，一个通过执行反馈自适应调整记忆组织与智能体记忆使用的记忆-智能体协同演化框架。其 MemGoG 结构将功能单元表示为相关条件、动作和输出的子图，并通过支持、冲突和修复关系将它们连接起来。MACE Loop 在记忆预算内选择与任务相关的单元和关系，并为每个智能体提供用于其当前操作的指令或清单。它记录所选单元、呈现格式、智能体输出和任务结果，以更新用于检索的单元得分和关系，并为后续呈现选择提供依据。在八个基准上，MACE 以 81.11% 的平均得分优于十个基线，而最强基线 SAGE 为 78.97%。

## Abstract
LLM-based multi-agent systems generate collaboration traces that record how agents plan tasks, verify intermediate results, and repair failures. Reusing these procedures requires preserving an action's prerequisites and the outputs needed by subsequent agents. Our empirical studies show that grouping these dependencies into functional memory units improves their retention, while connecting units increases retrieval of the units and links jointly required by a task. The preferred combination of units also changes between instructions and checklists, even when each combination's content is fixed across formats. Updating choices from the outcomes of each combination and format pairing outperforms scoring combinations and formats separately. These findings motivate MACE, a memory-agent co-evolution framework that adapts memory organization and agent memory use through execution feedback. Its MemGoG structure represents functional units as subgraphs of related conditions, actions, and outputs, connecting them through support, conflict, and repair relations. MACE Loop selects task-relevant units and relations within a memory budget and provides each agent with instructions or checklists for its current operation. It records the selected units, presentation formats, agent outputs, and task outcomes to update unit scores and relations for retrieval and inform subsequent presentation choices. Across eight benchmarks, MACE outperforms ten baselines with an average score of 81.11%, compared with 78.97% for the strongest baseline, SAGE.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：基于 LLM 的多智能体系统（MAS）在执行中会产生协作轨迹，记录任务分解、中间结果验证、错误修复等过程。这些轨迹是可复用的经验，但复用一条历史流程时，必须同时保留：动作的**前置条件**（applicability conditions）、**动作本身**、以及**传递给后续智能体的输出**。
- **核心问题**：多智能体记忆系统需要回答两个问题——（i）跨历史执行中，哪些依赖关系应被保留？（ii）检索到的经验应如何交付给不同角色/阶段的智能体？
- **现有方法不足**：已有记忆系统（G-Memory、GraphPlanner、ConMem 等）以关系或层级图组织历史，但检索单元一旦被切分，其内部依赖可能丢失；且不同智能体在同一图上需要不同内容与不同呈现方式，现有方法多未把"记忆组织"与"记忆使用方式"联合优化。
- **整体含义**：论文主张记忆组织与智能体的记忆使用应当**协同演化**——由执行反馈同时驱动"选什么记忆"和"怎么呈现记忆"，而非分别优化。

## 2. 方法论

### 2.1 核心思想
MACE = **MemGoG**（记忆图结构） + **MACE Loop**（记忆使用与演化闭环），核心是"图的图"（graph of graphs）：内部保留功能单元的依赖，外部用类型化关系连接需要共同使用的单元。

### 2.2 关键技术细节

- **MemGoG 构建**
  - 需求识别：对需要记忆的智能体，从其状态与 token 预算抽取需求描述子 `d_t^i = Need(s_t^i, b_t^i)`，指定任务、角色、阶段、当前状态、所需记忆功能与可用预算。
  - 记忆单元（memory graph cell）表示：`g_k = (V_k, E_k, τ_k, f_k, ι_k, o_k, U_t(g_k), p_k)`，即内部节点/边、类型、记忆功能、激活条件、提供内容、历史效用、来源记录。
  - 单元类型：episode（协作片段）、mechanism（风险条件与失败原因）、routine（可复用协作模式）、role projection（角色投影）、source unit（来源溯源）、conflict unit（不兼容记录）。
  - 图组装：候选库 `C_t` 作为外层节点，`G_cand_t = (C_t, ∪_{r∈R} E(r)_t)`；关系集合 `R` 含 support（支持）、abstraction、operationalization、role projection、conflict、repair、feedback。
- **Need-aware Memory Composer（需求感知记忆组合器）**
  - 打分：`S_t(g) = 1₃ᵀ(φ⁺_t(g) − φ⁻_t(g))`；正向项含相关性、历史效用、支持；负向项含冲突、成本（token/工具/延迟）、风险（不当指令迁移）。
  - 预算化组合：过滤冲突/高风险后得候选池，`W_t = Top_Bt(C_adm_t, S_t)`；再取任务相关关系 `E^D_t` 与 `W_t` 求交，得到工作图 `G_work_t = (W_t, E^D_t ∩ (W_t × R × W_t))`。
- **Adaptive Agent-Memory Coupler（自适应记忆-智能体耦合器）**
  - 相关性矩阵 `R_t = [κ_t(g_k, d_t^i, s_t^i)]`，行=工作记忆单元、列=参与智能体；`κ_t` 比较单元激活条件/功能/内容与智能体角色、阶段、待执行操作。
  - 补丁配置 `P_t^i = (c, μ, φ, δ, α, λ, p)`：内容、模式、格式、时机、强度、插入位置、来源记录。
  - 五种模式：相关案例、成功/失败机制、协作流程、执行约束、修复流程；格式如清单或输出 schema；强度区分"提示"与"显式要求"。
  - 渲染：`m_t^i = Render_bti(P_t^i) ∈ L(b_t^i)`，保证不超 token 预算。
- **Feedback Co-Evolver（反馈协同演化器）**
  - 三级反馈：local（当前智能体输出）、downstream（对后续智能体的贡献）、team（最终任务结果）；轨迹回报 `R_ξ = Σ_{h∈H} r_h(ξ) − ‖p_ξ‖₁`，`p_ξ` 为资源消耗与不当记忆使用的非负惩罚。
  - 效用更新：`u⁺_t = u_t + ηD_ξ(R_ξ·1 − u_t)`，`D_ξ` 为对角掩码，仅更新被使用单元；有效组合强化 support 关系，不兼容建议新建/强化 conflict 关系。
  - 算法流程（Alg. 1–3）：任务适配 → 记忆需求检测与组合 → 角色化补丁耦合 → 生成答案 → 解析与评分 → 反馈协同演化提交图更新；**读在预测前、写在评分后**，避免金标泄漏。
  - 不变量：固定任务文件、读写顺序、共享解析器、金标仅评分器可见、记录原始 completion、鲁棒性测试单轴扰动。
