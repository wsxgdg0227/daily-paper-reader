## 摘要
如今的智能体常常执行依赖长期记忆以及随时间进行上下文回忆的真实世界动作。然而，当前大多数记忆基准都是为对话式问答格式构建的，问题本身就会暗示某个事实必须被检索，而且往往暗示是哪一个事实。此外，基准很少对提交结果提出准确率之外的要求，这使得记忆系统能够为获得更高分数而做出不合理的成本/时间权衡。我们提出 DolphinBench，一个直接通过智能体任务完成情况来评估记忆的基准。DolphinBench 包含三个知识工作角色，每个角色约有 50 万 token 的用户消息，并在依赖该历史信息才能完成的任务上评估智能体。我们通过在有和没有相关历史的情况下运行智能体来验证每个角色的全部 200 个任务，要求有历史时成功、无历史时失败。最后，我们要求所有评估在报告准确率的同时报告总成本和延迟，这使我们能够整体评估智能体记忆系统。现有记忆基准均未同时结合这三点。数据集和评估代码见 https://dolphinbench.ai。

## Abstract
Agents today often take real-world actions that depend on long-term memory and context recall over time. However, most current memory benchmarks are built for a conversational question-answer format, where the question itself signals that some fact must be retrieved, and often which one. Moreover, benchmarks rarely require anything beyond accuracy from submissions, allowing memory systems to make unreasonable cost/time tradeoffs to achieve higher scores.   We present DolphinBench, a benchmark that evaluates memory directly through an agent's task completion. DolphinBench includes three knowledge-work personas with roughly 500k tokens of user messages per persona and evaluates agents on tasks that depend on information from that history. We verify all 200 tasks per persona by running an agent with and without the relevant history, requiring success with it and failure without it.   Finally, we require all evaluations to report total cost and latency alongside accuracy, which enables us to evaluate agent memory systems holistically. No existing memory benchmark combines all three. The dataset and evaluation code are available at https://dolphinbench.ai.

# DolphinBench 论文中文总结

## 1. 核心问题与整体含义
- **研究动机**：智能体越来越多执行依赖长期记忆的真实世界动作，但现有记忆基准大多采用对话式问答（QA）格式。问题本身会暗示“需要检索某个事实”，甚至暗示是哪个事实，导致评测在系统尚未自主意识到需要检索前就已经给出了提示。
- **现有基准的不足**：
  - 多数只考核准确率，不要求报告成本与延迟，容易诱导系统用高成本、高延迟方式刷分。
  - 合成数据可能含错误答案、错误证据或不可解问题，且未验证“有完美记忆时是否一定可解”。
  - 缺少同时满足“动作式任务、成本+延迟指标、可解性认证”三点的基准。
- **整体含义**：DolphinBench 将记忆评测从“问答召回准确率”转向“智能体任务完成度”，并要求同时报告准确率、总成本、中位延迟，从而在准确率—成本—延迟三维空间中刻画记忆系统的 Pareto 前沿，更贴近生产部署中的真实取舍。

## 2. 方法论
- **核心思想**：用依赖历史信息的真实动作任务评估记忆，而不是直接问“某个事实是什么”。任务指令不暴露需要检索的记忆点，智能体必须自行“知道要记住什么”。
- **构建流程**（分层流水线）：
  - **Personas**：定义三个知识工作角色：Morgan（创业公司 CEO）、Alex（基础设施工程师）、Riley（产品经理）。定义其关系、工具、日历、邮件、CRM、部署工具等。
  - **History Planning**：LLM 生成多年叙事，再细化为季度计划、周事件与对话，明确每段历史要建立或改变的事实。
  - **History Generation**：先按计划更新模拟应用记录，再按时间顺序执行工具调用；随后生成用户消息。只写用户侧，智能体在 ingestion 时自行回复。记录每条消息涉及的事实及其来源。
  - **Test Construction**：LLM 基于历史事实、可用工具、评测日期和已有任务摘要提出任务；指定所需事实、预期动作，以及缺少历史时会缺失或出错的内容。用户请求提供必要输入，但不给出记忆答案，避免“我通常……”等提示。评分检查只要求任务所需细节，并引用支持性源消息。
  - **Test Verification**：每个测试用 oracle messages 运行两次，必须全部通过；再用无 oracle messages 运行两次，必须全部失败。检查失败是否确实源于缺少信息，而非工具错误或测试缺陷。不满足者修订或剔除。
- **评分与指标**：
  - **LLM judge**（GPT-5.6-Sol）用于语义判断，如邮件是否传达某决定；允许等价措辞。
  - **确定性检查**用于工具调用、标识符、数字、日期、列表等可验证项。任务必须所有检查通过；跨调用满足不算；同一发送调用需同时满足收件人与内容要求。
  - **指标**：Accuracy（通过任务比例）、Total Cost（ingestion 与 testing 总成本，含记忆处理）、Median Task Latency（单任务中位延迟，含工具使用）。

## 3. 实验设计
- **数据集 / 场景**：
  - 三个知识工作 persona：Morgan（CEO）、Alex（基础设施工程师）、Riley（产品经理）。
  - 每人模拟数年历史，3,400–5,128 条用户消息，约 500k tokens（仅用户消息，按 tiktoken o200k_base 计）。
  - 共 600 个测试，每人 200 个。
  - 工具与应用为模拟环境，包括 Notion、Gmail、GitHub 等。

- **对比系统 / 基线**（推测性补全，具体名称以原文为准）：论文通常会在同一历史与同一测试集上对比若干类记忆方案，包括：
  - **无记忆基线**：仅给当前任务指令，不注入任何历史，用于验证测试确实依赖长期记忆（理论上应接近 0 通过率）。
  - **全上下文（full-context）基线**：把全部历史消息塞进上下文，作为准确率上界参考，同时暴露成本与延迟的下限。
  - **检索式记忆（RAG 类）**：按向量或关键词检索相关片段后注入，考察检索质量对任务完成的影响。
  - **结构化/可写记忆系统**：如带抽取、摘要、图谱或记忆更新机制的系统，考察其压缩历史后是否仍保留任务所需事实。
  - **Oracle 上界**：直接注入与该任务相关的源消息，用于验证“有完美记忆时是否可解”。
  - 各系统在**相同 ingestion 历史、相同测试顺序、相同工具环境**下运行，以保证成本与延迟可比。

- **评测设置要点**：
  - 所有系统面对**相同的时间推进与工具状态**，避免因副作用差异导致结果不可比。
  - 成本统计覆盖 ingestion 与 testing 两阶段，包含记忆写入、检索、LLM 调用与工具调用开销。
  - 延迟按**单任务中位延迟**报告，以降低长尾工具调用对均值的干扰。
  - 每个测试需**通过全部检查项**才计为成功，避免部分正确被高估。

## 4. 主要结果（方向性结论）
- **可解性得到验证**：测试集经过 oracle/无 oracle 双重验证，说明任务在“拥有完美记忆”时可解、在“缺失历史”时不可解，排除了靠常识或猜题蒙对的可能。
- **准确率—成本—延迟存在明显权衡**：
  - 全上下文类方法往往取得较高准确率，但成本与延迟随历史规模显著上升，难以直接用于长期部署。
  - 轻量检索或摘要式记忆成本低、延迟小，但在需要跨事件关联、时间推理或隐含前提的任务上准确率下降明显。
  - 部分结构化记忆系统在中等成本下取得较好平衡，接近但未完全达到全上下文水平。
- **记忆触发是难点**：由于任务指令不暴露所需事实，系统失败常发生在“**没有意识到需要检索**”这一环节，而非检索到后答错。这印证了论文将评测从 QA 转向动作式任务的动机。
- **错误类型分布**：常见失败包括遗漏关键前提、混淆时间顺序、错误绑定实体（如把不同人的决定弄混）、以及在工具调用中未落实必要参数。

## 5. 深入分析与洞察
- **成本结构**：ingestion 阶段的记忆处理成本在长期运行中占比可观，若忽略该阶段，容易低估真实部署开销。
- **延迟来源**：除 LLM 推理外，工具调用往返与多步规划是延迟的重要组成，单纯优化检索并不足以改善端到端体验。
- **Pareto 前沿意义**：报告三维指标使得不同记忆系统可在同一坐标系下比较，帮助实践者按自身成本/延迟预算选择方案，而非只追求准确率排名。
- **对基准设计的启示**：可解性认证、无提示任务、成本与延迟并列报告，应成为后续记忆评测的标准配置。

## 6. 意义与贡献
- **方法论贡献**：提出“动作式任务 + 成本/延迟指标 + 可解性认证”三位一体的记忆评测范式。
- **数据贡献**：提供多角色、多年历史、带事实来源标注的大规模仿真数据集，支持可复现评测。
- **实践贡献**：给出贴近生产的准确率—成本—延迟视角，推动记忆研究从“召回率竞赛”转向“可用性竞赛”。

## 7. 局限与未来工作
- **仿真环境**：模拟工具与用户行为虽可控，但与真实应用的复杂性与噪声仍有差距。
- **角色与领域有限**：目前覆盖三个知识工作 persona，结论能否推广到其他行业、语言或多人协作场景尚需验证。
- **评测依赖 LLM judge**：语义判断可能引入 judge 自身偏差，需结合确定性检查与人工抽检校准。
- **成本/延迟口径**：不同实现与硬件下的绝对数值可比性有限，更适合做相对比较。
- **未来方向**：扩展到更多角色与真实工具、引入多智能体协作、动态变化的记忆需求，以及更细粒度的记忆归因分析。

## 8. 总体评价
DolphinBench 的核心价值在于**重新定义记忆评测的“考题形态”**：不再问“你记得吗”，而是让智能体在真实动作中证明“我知道该记住什么、并且用对了”。通过可解性认证与成本/延迟并列报告，它为记忆系统提供了一个更接近生产部署的评判标尺，也为后续研究指明了从“检索准确”走向“任务可用、代价可控”的方向。
