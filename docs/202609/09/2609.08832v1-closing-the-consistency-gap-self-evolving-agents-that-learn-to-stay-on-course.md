## 摘要
大型语言模型（LLM）驱动的智能体在平均水平上可能表现准确，但在生产环境中却不可靠，这种差异已被观察到，但在很大程度上仍未得到解决。当同一任务被给定五次时，在AppWorld基准上使用GPT-4.1的ReAct智能体仅在53%的情况下五次运行全部成功，尽管其单次运行的平均通过率高达77%。我们将这24个百分点的差距称为一致性差距，并认为解决这一差距是可信AI智能体部署的前提。我们提出了一种自我进化的智能体框架，通过识别智能体轨迹中不稳定的、低一致性的步骤，并将其转换为情景记忆，供智能体在未来的运行中利用，从而缩小这一差距。其核心是一个一致性分析器，用于定位轨迹在执行中可能翻转的位置和原因，以及一个指南生成器，将诊断结果转化为有针对性的指南，提交到记忆中，并在类似任务的未来智能体执行中注入。在AppWorld上使用ReAct/GPT-4.1，我们的框架将五次运行全部成功的任务比例在同一任务评估中提高了16个百分点，在类似任务泛化中提高了13个百分点。

## Abstract
Large language model (LLM)-powered agents can be accurate on average yet unreliable in production, a discrepancy that has been observed but remains largely unaddressed. When given the same task five times, a ReAct agent on the AppWorld benchmark using GPT-4.1 succeeds in all five runs only 53% of the time, even though its per-run pass rate averages 77%. We call this 24-point shortfall the consistency gap, and we argue that addressing it is a precondition for trustworthy AI agent deployment. We present a self-evolving agent framework that reduces this gap by identifying unstable, low-consistency steps in agent trajectories and converting them into episodic memory the agent can draw on in future runs. At its core is a Consistency Analyzer that pinpoints where and why a trajectory is likely to flip across executions, and a Guideline Generator that converts the diagnosis into targeted guidelines, committed to memory and injected into future agent executions on similar tasks. On AppWorld with ReAct/GPT-4.1, our framework raises the fraction of tasks that succeed in all five runs by +16 points on same-task evaluation and +13 points on similar-task generalization.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心问题：一致性差距（Consistency Gap）**：论文指出现有 LLM 智能体普遍存在“平均准确但单次运行不稳定”的问题——同一任务、同一智能体、同一模型，多次执行的结果可能不同。例如，在 AppWorld 基准上，基于 GPT-4.1 的 ReAct 智能体单次平均通过率（Mean@5）为 77%，但全部五次运行均成功的比例（Pass^5）仅为 53%，两者相差 24.4 个百分点。
- **该问题的严重性**：大约 32% 的基准任务在多次运行中呈现“有成功有失败”的不稳定状态。在此类场景下，传统平均准确率指标对用户真实体验具有很强的误导性。
- **研究动机**：作者认为，缩小一致性差距是 LLM 智能体在生产环境中获得信任与可靠性的前提条件。然而，该问题在以往研究中被观察到但基本未得到针对性解决。
- **整体含义**：论文主张将“一致性”作为与“准确性”同等重要的第一等级优化目标，通过自我进化的记忆机制逐步缩小这一差距，无需修改模型推理循环或依赖模型内部信息。

## 2. 论文提出的方法论

- **总体架构**：提出一个**两阶段、离线运行的自我进化管道**，由“检测（Detect）”和“生成（Generate）”两个环节构成，构建在 Fang et al. (2026) 的轨迹记忆框架之上。

  - **阶段一（Detect）——一致性分析器（Consistency Analyzer）**：
    - 输入：单条智能体轨迹 \( T = \langle s_1, s_2, \ldots, s_n \rangle \)，即每一推理步骤的记录。
    - 核心机制：对轨迹中的每个推理点，将已记录的提示重新发送给同一 LLM 端点，重复 N 次（默认 N=30，温度 ≤ 0.5），得到一组响应集合，用于估计响应分布的形状。
    - **动机**：一致性问题源于模型令牌概率分布的“平坦性”。当多个令牌概率接近、出现近并列时，平台端浮点噪声、批处理差异等微小扰动即可改变最终选中的令牌——即便在温度为零的贪心解码下也无法消除，因为托管端点的概率本身存在逐次漂移。
    - 步骤级一致性分数计算方式：
      - 自由文本 / 代码响应：使用 SBERT 嵌入的平均成对余弦相似度（语义等价视为一致）；
      - 类别型响应（工具名、枚举参数等）：使用平均成对 Jaccard 相似度（要求精确匹配）；
      - 半结构化响应（如 JSON 中的多字段对象）：按字段分解并加权组合各类型分数。
    - 轨迹级一致性：对步骤级分数取均值，得到 \( C_{mean}(T) \)，并输出一份“一致性记分卡”，标出最可能在后续运行中翻转的步骤。
    - **关键特点**：全程黑盒——不需要模型 logits、内部激活值或智能体源代码，适用于任意基于托管 LLM 端点的智能体。

  - **阶段二（Generate）——指南生成器（Guideline Generator）**：
    - 输入：原始轨迹 + 一致性记分卡。步骤一致性低于阈值（θ_C = 0.85）且位于决策路径上的步骤被标记为“不一致步骤”。
    - 输出：由 LLM 将被标记步骤转化为自然语言形式的“一致性指南（consistency guideline）”，指南被组织为三类：
      - **策略类（strategy）**：强化一个虽正确但波动大的决策模式；
      - **恢复类（recovery）**：绕开一个波动性与失败相关的步骤；
      - **优化类（optimization）**：指示跳过或简化非必要且高度不稳定的步骤。
    - 指南生成后进入双索引情节记忆（嵌入式向量 + 类别/优先级/上下文/来源元数据），经聚类和去重管理，运行时通过余弦相似度或 LLM 引导检索注入未来相似任务的提示中。

- **一致性指标公式**（任务 t，k 次独立运行）：
  - Pass@k——至少一次成功；
  - Mean@k——平均通过率；
  - Pass^k——全部 k 次运行都成功；
  - **一致性差距**：Gap@k(T) = Mean@k(T) − Pass^k(T)（以百分点计）；
  - **归一化一致性**：Consistency@k(T) = Pass^k(T) / Mean@k(T)，用以消除模型自身能力上限对绝对差距的混淆。

## 3. 实验设计

- **基准（Benchmark）**：AppWorld（Trivedi et al., 2024），一个交互式编码智能体基准，智能体通过 Python 工具调用在受控的个人应用模拟环境中执行任务，由标准 AppWorld 评分器自动判定。使用 **test normal 分割，共 168 个任务**。
- **任务难度分层**：Easy（57 任务）、Medium（48 任务）、Hard（63 任务）。
- **智能体架构**：ReAct（Yao et al., 2023）。
- **底层模型**：
  - GPT-4.1（通过 Microsoft Azure 托管）；
  - GPT-OSS-120B（通过 AWS 托管）。
- **多运行设置**：每个任务独立运行 k=5 次，报告 Pass^5、Mean@5、Consistency@5。
- **对比方法**：
  - 基线：无指南注入的标准 ReAct 智能体；
  - 同任务评估：从任务自身的单条基线轨迹生成指南，再对同一任务重复运行测试；
  - 相似任务泛化：利用 AppWorld 场景内三个相似变体（v1、v2、v3）的结构，从 v1 生成指南、注入 v2 和 v3 的运行，共 336 次评估。
- **消融相关性验证**：额外使用 AppWorld test challenge 中 50 个任务来测轨迹一致性分数对任务成败的预测能力（AUROC）。
- **一致性分析器配置**：默认重采样预算 N=30，温度 0.5，步骤一致性阈值 θ_C = 0.85，响应以（API 名，API 参数）类别对提取并按 Jaccard 相似度评分。

## 6. 论文的主要结论与发现

- **一致性差距的量级**：GPT-4.1 的绝对差距为 24.4 pp，GPT-OSS-120B 为 23.8 pp；归一化一致性分别为 0.69 和 0.30，说明较弱模型的成功几乎不可复现。
- **难度分布特征不同**：GPT-4.1 的差距随难度单调增大（易/中/难 17.5/25.0/30.2 pp）；GPT-OSS-120B 的差距在简单任务上最大（38.6 pp），因为困难任务平均通过率本身仅 9.5%，机械地封顶了绝对差距。
- **指南的有效性（GPT-4.1）**：
  - 同任务：Pass^5 提升 **+16.0 pp**（53%→69%，相对增加 30%）；Mean@5 无退化反而上升 +3.6 pp；归一化一致性 +0.17；
  - 相似任务：Pass^5 提升 **+13.0 pp**，仅比同任务低 3 pp，表明提取的更多是可迁移的共性模式。
- **指南的有效性（GPT-OSS-120B）**：同任务 Pass^5 +6.0 pp（相对提升 59%，是 GPT-4.1 的两倍）；相似任务 +8.7 pp；Hard 任务从 0.00 归一化一致性提升至 0.29。
- **一致性分数可以预测成败**：轨迹级平均一致性作为二分类器预测任务通过与否的 AUROC 约 **0.699**，在没有金标准评分的生产环境中可为指南生成器提供替代信号。
- **总体判断**：一致性本身可作为一种独立优化目标，通过离线分析 + 提示级记忆注入实现显著改善，且不牺牲平均精度。

## 7. 优点

- **问题定义清楚且实用**：将“平均表现”与“稳定复现”的形式化区分（Pass@k/Mean@k/Pass^k）概念清晰，指标推导简单有力，实际意义强。
- **方法黑盒且架构无关**：只依赖反复调用 LLM 端点，无需模型内部信息或智能体代码，适用于云托管模型和任意智能体框架，可落地性强。
- **离线分析与在线执行分离**：不影响推理循环，无运行时延迟增量；一次性分析成本换来持久记忆收益。
- **诊断驱动的指南生成**：与以往仅依据结果好坏的记忆框架不同，对“成功但不稳定”的步骤同样标记——抓住了通过率指标掩盖的不确定性源头。
- **自进化闭环设计**：每轮指南的积累逐步缩小不稳定任务群体，形成可持续收敛的反馈动态。
- **评估严谨**：同任务 vs. 非同类任务的对照设计可以分离记忆的机械复现与真正的泛化能力；多难度 × 多模型消解部分能力混淆；提供开源代码（GitHub）支持复现。

## 8. 不足与局限

- **缺少算力详细披露**：未报告 GPU 类型/数量、推理的总调用量等资源数据，难以估算实际部署和调优的总成本。
- **推理成本高**：默认 N=30 使单轨迹令牌成本放大约 30 倍，这对生产环境的大规模任务可能构成显著经济开销；论文提出了自适应重采样方向但未实现验证。
- **指南未经过去验证直接入存储**：生成的指南没有经过前置验证阶段，无法排除含糊、冲突或过拟合个别轨迹细节的“坏指南”进入记忆——论文自己承认这是未来工作。
- **单基准局限性**：仅在 AppWorld 一个基准上量化评估，其他环境仅做定性说明；真实任务分布在多样性和噪音方面与基准差距可能很大。
- **分析器不是验证器**：一致性分数度量的是“稳定性”而非“正确性”，一个自信但方向错误的决策对分析器来说显得“一致”——存在误导风险。
- **平台噪声不可控**：Pass^5 同基线的对比假设云端平台在基线阶段和指南注入阶段的非确定性相当，这一点无法直接测量或控制。
- **跨模型跨架构验证有限**：只展示了 ReAct + GPT-4.1/GPT-OSS-120B；对 CUGA 等其他架构仅提及非正式观察，以及少量模型族，结论的外推性尚需更多实证支持。
