## 摘要
智能体记忆允许LLM智能体在回答新查询时利用先前的交互。现有方法通常将交互历史压缩为摘要或其他由LLM生成的表示。重复生成会增加成本，并可能在系统得知未来查询需求之前丢弃包含答案的细节。我们提出EdgeMem，一种围绕简单原则构建的智能体记忆方法：保留原始交互轮次，并通过互补的内容、时间和情节线索对其进行组织。EdgeMem通过轻量级局部处理构建多锚点超图来实现这一原则。检索直接返回源证据，并将LLM的使用保留给最终答案生成，从而将对多会话历史的结构化访问与对原始对话的忠实保留相结合。在LoCoMo和LongMemEval-S上的实验显示了强大的检索和基于记忆的问答性能；在LoCoMo上，EdgeMem在共享提示下，在七个复现系统中取得了最高的严格评判分数（61.01对58.70），而构建和检索无需生成式LLM调用。总体而言，EdgeMem表明，保留和组织源证据为智能体记忆提供了有效且高效的基础，而无需生成式记忆管理。

## Abstract
Agent memory allows LLM agents to use earlier interactions when answering new queries. Existing methods often compress interaction histories into summaries or other LLM-generated representations. Repeated generation adds cost and can discard answer-bearing details before the system knows what a future query will require. We propose EdgeMem, an agent-memory method built around a simple principle: preserve original interaction turns and organize them through complementary content, temporal, and episodic cues. EdgeMem realizes this principle with a multi-anchor hypergraph constructed by lightweight local processing. Retrieval directly returns source evidence and reserves LLM use for final answer generation, combining structured access to multi-session histories with faithful retention of the original conversation. Experiments on LoCoMo and LongMemEval-S show strong retrieval and memory-grounded question answering; on LoCoMo, EdgeMem achieves the highest strict-judge score among seven reproduced systems under a shared prompt (61.01 versus 58.70), while construction and retrieval require no generative-LLM calls. Overall, EdgeMem shows that preserving and organizing source evidence provides an effective and efficient foundation for agent memory without generative memory management.

## 1. 核心问题与整体含义

- **研究动机**：LLM 智能体需要在多会话长交互中回答查询，但随着历史记录增长，将全部历史喂给模型会超出上下文窗口。现有智能体记忆系统通常将交互历史外部化存储，查询时只检索少量相关证据。
- **现存问题**：主流方法在记忆生命周期中依赖 LLM 推理，存在两大局限：
  - **成本高**：记忆构建、更新和检索中反复调用 LLM，在 LoCoMo 规模下,所有主流基线的记忆构建 token 消耗已超过原始历史本身。
  - **证据丢失**：生成的摘要或提取的记忆单元可能遗漏或扭曲原始轮次中的细节，一旦承载答案的细节在构建阶段丢失，检索阶段无法恢复。
- **核心思路**：借鉴情景记忆（episodic memory）研究（内容 + 时空上下文双维度刻画），提出 EdgeMem——保留原始交互轮次作为原子证据记录，通过内容、时间、情节三类互补锚点组织记忆，将生成式 LLM 仅保留给最终答案生成阶段，实现零生成式 LLM 调用的记忆构建与检索。

## 2. 方法论

### 2.1 问题形式化

- 多会话历史表示为有序源轮次序列 $T=(t_1,\ldots,t_N)$；
- 每个轮次包含原文 $x_t$、说话人 $u_t$、原生会话 $s(t)$、会话内位置 $i(t)$、日期 $\tau_t$；
- 记忆系统为三元组 $(\Phi, \Psi, F)$：$\Phi$ 负责构建存储，$\Psi$ 负责检索，$F$（reader）负责基于证据包生成答案；
- 证据包上限为 $\kappa$ 条源轮次、$B$ 渲染 token。

### 2.2 本地注释（Local Annotation）

- **设计不变量**：$tok_{LLM}(\Phi)=tok_{LLM}(\Psi)=0$——构建与检索阶段零生成式 LLM token。
- 使用轻量本地 NLP 工具（spaCy 实体识别、rank_bm25、dateparser）为每轮提取：
  - 命名实体集 $E_t$（人物、组织、地缘实体/地点、国籍/群体、事件、产品、日期时间）；
  - 关键词集 $K_t$（去除功能词后的词形还原内容词）；
  - 会话日期 $\tau_t$（直接来自转录元数据）；
- 源轮次原始文本逐字保留。

### 2.3 多锚点超图构建

超图 $H=(V,E)$，源轮次为顶点，三类超边：

| 子超图 | 超边定义 | 功能 |
|--------|---------|------|
| 时间子超图 | $e^m_{time}=\{t\mid \tau_t\in m\}$（日历月分组） | 日期跨度访问 |
| 共现子超图 | $e^w_{co}=\{t\mid w\in E_t\cup K_t\}$（共享实体/关键词） | 跨会话共享线索访问 |
| 情节子超图 | $e^s_{epi}=T_s$（每原生会话） | 保留会话成员与顺序 |

- 每个轮次存储一次，可属于多个超边（hub）；
- 构建为追加式（append-only），随交互增长三个访问结构同步扩展。

### 2.4 记忆检索

三个确定性通道并行执行，融合成固定预算证据包：

- **情节通道（Episode Channel）**：构成证据核心。结合轮次级与情节级 BM25 分数：
$$\rho(t)=\lambda\hat{r}_{turn}(q,x_t)+(1-\lambda)\hat{r}_{epi}(q,X_{s(t)})$$
  其中各分数族独立最大归一化。排序后混合全局排名与不同情节的代表轮次，选中的种子轮次连同其前驱/后继一同读出。
- **共现通道（Co-occurrence Channel）**：激活文档频率处于罕见带 $[\delta_{min},\delta_{max}]=[2,10]$ 的查询锚点，从对应 hub 中选择先前未被情节通道选取的高 $\rho$ 轮次，补充跨会话证据。
- **时间通道（Time Channel）**：仅当查询含显式月份 + 四位年份时开启；通过月份 hub 定位情节，加宽规则包含跨度后第一个情节，选取情节开头轮次与高 $\rho$ 轮次。
- **融合策略**：情节核心优先，共现和时间证据填剩余位置（$\kappa=18$：14 情节 + 4 共现 + 2 时间，门开启时替换部分共现名额）;稳定去重保证不重复。

### 2.5 答案生成

- 证据包序列化后连同查询交给唯一 reader 调用——gpt-4o-mini-2024-07-18，温度为零，最多输出 128 tokens；
- 每项证据保留说话人、会话日期与未修改的原文，支持溯源与时间解释；
- 证据不足时返回固定拒绝语句："Not mentioned in the conversation."

## 6. 主要结论与发现

1. **无需付出准确性代价**：LoCoMo 共享提示协议下，EdgeMem 在 SJ、LJ、F1、BLEU-4、ROUGE-L、BERTScore 全部 6 个指标上均超越 6 个复现基线（SJ 61.01 vs 最强基线 CompassMem 58.70），且 7 行 SJ/LJ 排序完全一致，结论不依赖裁判选择。
2. **弃权可靠性显著领先**：对抗性问题上，EdgeMem 精确拒绝率达 92.57%（匹配指令对照中最强基线 A-Mem 84.68%、CAM 仅 38.96%）；弃权行为是"基于保留源证据的只读式回答"的属性，而非单纯指令的效果。
3. **成本数量级降低**：记忆构建零生成式 token（1.8 分钟 CPU 注释 vs 基线 17 分钟–10.1 小时 API 时间）；每问题约 1,000 tokens vs 最接近精度系统 CAM 19,745 / CompassMem 41,348 tokens；质量与花费不挂钩。
4. **跨基准无需调参迁移**：LongMemEval-S 上以最高 R@3（81.49）与 NDCG@3（90.49）取得最佳会话级检索，SJ 60.00 接近最强转录基线 MemGAS 60.20，而 token 仅为约 1/3（3,202 vs 8,829）；30 个不可答问题弃权率 90%。
5. **三锚点各自贡献显著**：平坦 BM25（49.74）→ +情节（+8.44）→ +共现（+2.21）→ +时间（+0.58）到 61.01；所有区间排除零；情节贡献最大，共现与情节有部分重叠（较可加性低约 3.4 分），时间在情节基础上有更大增值。
6. **失败机制审计确认核心洞见**：案例表明基线失败可归因于"记忆忠实但检索不完整"（A-Mem）、"构建阶段丢失关键事实、不可恢复"（CAM）、"存储忠实但导航式检索空转"（CompassMem）三类；EdgeMem 因保留原始轮次并确定性锚定路由，三类问题均可直接命中黄金证据。

## 7. 优点

- **设计理念清晰且从根本上改变成本结构**：明确分离记忆构建/检索与答案生成，以"保留源证据"替代"生成摘要"为第一原则；将生成式 LLM 从记忆生命周期中移除，记忆账单从每次会话的循环成本变为固定本地成本。
- **方法优雅且可解释**：超图多对多结构自然匹配"一个轮次有多个线索、一个线索跨会话连证据"的记忆需求；三类子超图分别对应情景记忆经典理论的内容、时间与情节维度,有认知科学理论支撑。
- **检索策略设计精细**：情节证据核心 + 共现跨会话补充 + 时间显式范围门控的确定性融合策略；罕见带限制（df∈[2,10]）保持锚点特异性；稳定去重、邻居读出等工程细节完备且有明确消融支持。
- **实验严谨性高**：全基线复现 + 计量审计（模型快照锁定、服务端替换检测、逐调用计量）；共享答案提示消除风格变量使指标可比；锚点阶梯消融设计清晰（每个增量含置信区间）；双裁判、多指标、多口径对抗性评估降低评测偏差；案例研究连接统计差距与其机制。
- **效率与效果不矛盾**：最精确的记忆同时最便宜——对"质量追赶花费"现状的有力反驳；LoCoMo 与 LongMemEval-S 跨基准一致表现支持通用性主张。
