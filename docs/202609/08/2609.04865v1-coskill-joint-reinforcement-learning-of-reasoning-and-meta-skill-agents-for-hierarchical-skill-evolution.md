## 摘要
技能库通过使大型语言模型（LLM）智能体重用程序性知识，提高了智能体强化学习（RL）的样本效率。然而，现有范式存在结构性缺陷：它们要么将技能演化与策略优化解耦，要么将元技能实例化为固定工作流。这两种方式都将技能视为待管理的被动对象，限制了技能的灵活演化及其与推理智能体的协同适应。为解决上述局限性，我们提出了CoSkill，一种统一的多智能体RL框架，它将静态的元技能工作流重构为可学习的元技能智能体（Meta-Skill Agent），并在分层技能库上与推理智能体（Reasoning Agent）联合训练。通过将推理智能体和元技能智能体建模为共享单一骨干网络的协作团队，CoSkill实现了端到端的协同适应：推理智能体以检索到的任务技能及其子集中选出的步骤技能为条件生成动作，同时其任务性能指导元技能智能体对这些步骤技能进行细化。在ALFWorld和WebShop上的实验表明，CoSkill显著优于先前的基于技能的方法和RL基线，分别达到了98.4%和90.6%的成功率（相对提升3.5和6.2个百分点）。如图1所示，CoSkill在早期阶段的样本效率、渐近性能和墙钟效率方面均表现出优势。我们的代码可在https://github.com/jinyuan-cookie/CoSkill获取。

## Abstract
Skill libraries improve the sample efficiency of agentic reinforcement learning (RL) by enabling large language model (LLM) agents to reuse procedural knowledge. Yet existing paradigms exhibit structural shortcomings: they either decouple skill evolution from policy optimization or instantiate meta-skills as fixed workflows. Both treat skills as passive objects to be managed, limiting the flexible evolution of skills and their co-adaptation with the reasoning agent. To address the limitations, we propose CoSkill, a unified multi-agent RL framework that recasts the static meta-skill workflow as a learnable Meta-Skill Agent and jointly trains it with a Reasoning Agent over a hierarchical skill library. By modeling the Reasoning and Meta-Skill Agents as a cooperative team sharing a single backbone, CoSkill enables end-to-end co-adaptation: the Reasoning Agent conditions its actions on a retrieved task skill and step skills selected from its child set, while its task performance guides the Meta-Skill Agent in refining those step skills. Experiments on ALFWorld and WebShop show that CoSkill substantially outperforms prior skill-based and RL baselines, achieving success rates of 98.4% and 90.6%, respectively (+3.5 and +6.2 pp). As shown in Figure 1, CoSkill achieves superior early-stage sample efficiency, asymptotic performance, and wall-clock efficiency. Our code is available at https://github.com/jinyuan-cookie/CoSkill.

* **核心洞见**：元技能不应被设计成固定工作流，而应被构建为“可学习的智能体”，与推理策略共享底层模型并通过 RL 共同演化；由此可以实现细粒度的“技能—策略共进化”。
* **论文贡献**：提出 **CoSkill**，一个统一多智能体 RL 框架，将“元技能编辑”本身变成可训练策略，并与使用技能的策略端到端协同优化。实验显示其性能、样本效率和训练效率均优于既有方法。

## 2. 论文提出的方法论

### 2.1 总体思路
CoSkill 以“分层技能库”为共享知识载体，将推理过程和元技能编辑过程建模为**共享同一 LLM 骨干参数、但角色提示不同**的两个协作智能体：  
- **推理智能体（Reasoning Agent）**：依据当前观测和历史，检索任务级技能与步骤级技能后输出环境动作；
- **元技能智能体（Meta-Skill Agent）**：观察推理动作、反馈与当前步骤技能，输出对步骤技能的编辑动作（INSERT/UPDATE/DELETE/KEEP）。

两者通过共享策略网络更新，实现端到端“推理-用技能-改技能”的循环。

### 2.2 分层技能库设计
- 技能库表示为 K 个任务索引的 bundle：`B_k = (stask_k, Sstep_k)`；
- 每轮先全局检索任务技能，再将步骤技能检索范围限制在该任务技能的子集内，即两级层级检索：
  - `k* = argmax sim(f(x), f(q_k))`
  - `j*_t = argmax sim(f(o_t), f(o_{k*,j}))`（仅从 `Sstep_{k*}` 中选）；
- 库的初始版本由离线轨迹经由外部 LLM 归纳得到（ALFWorld：300 task skills + 1 625 step skills；WebShop：300 task skills + 1 406 step skills）。

### 2.3 问题建模：MSMDP
将推理和元技能交互建模为**共享参数多智能体半马尔可夫决策过程**：  
- 全局状态：`g = (x, role, history, B, edited_bundle, pending_edits)`；
- 推理观测 `uR`：任务状态 + 交互历史 + 检索到的 task/step skill；
- 元技能观测 `uS`：推理状态 + 推理动作 + 环境反馈（`r_t, e_t, o_{t+1}`）；
- 元技能动作空间被约束为四种语义编辑操作：
  - `INSERT(bskill)`：在当前任务技能下插入新步骤技能；
  - `UPDATE(skill, bskill)`：替换步骤技能内容；
  - `DELETE(skill)`：删除该步骤技能；
  - `KEEP(skill)`：保持不变。
- 编辑只在基线轨迹（m=0）结束后被批处理应用于“私有副本 bundle”，不直接污染公共技能库。

### 2.4 编辑后验证奖励（Post-Edit Skill Verification）
- 基线尝试返回 `R^(0)_i`；
- 将待验证的编辑序列应用到副本 bundle 后，在同一任务上重新运行 M 次验证轨迹，得 `R^(1)...R^(M)`；
- 选择“编辑后收益”作为元技能体的（延迟、episode 级）奖励：
  `Δskill_i = (1/M) Σ_m (R^(m)_i − R^(0)_i)`；
- 仅当 bundle 包含有效、非平凡且能提升验证成功率的编辑时，才允许被提升(promotion)进公共库；每组只保留 top-Kprom 个候选，并保留原 bundle 谱系。该机制用来抑制库的无限膨胀和低质量编辑。

### 2.5 联合优化：GiGPO
- 作者采用“组内组策略优化”（GiGPO）做角色级信用分配：
  `A_ρ(i,t) = A_ρ(E,i) + ω_ρ A_ρ(S,i,t)`
  - Episode-level advantage：比较同一任务不同尝试的整体回报；
  - Step-level advantage：使用角色特定的锚定状态（推理：`(x,o_t)`；元技能编辑：`(x,o_t,Z_step)`）比较同状态/同目标技能下的替代决策；
- 推理轨迹与元技能编辑轨迹按 rollout 配对，分别构造 batch 后更新同一个 actor，最终 loss 为两种角色的 GiGPO 损失之和。
- 由此：推理智能体学会利用“正在进化的技能”行动，元技能智能体学会做出“经执行验证确实带来收益”的修改。

## 3. 实验设计：数据集 / benchmark / 对比方法

### 3.1 Benchmark
- **ALFWorld**：文本家庭环境，包含 Pick、Clean、Heat、Cool、Pick2 等六类子任务；指标为平均成功率。
- **WebShop**：模拟电商购物，需要搜索、浏览、购买，按任务指令选择匹配商品；指标为任务分数和成功率。

### 3.2 对比基线
CoSkill 与四类方法比较：
- **闭源 LLM 智能体**：Gemini-3-Flash 等，作为强参考而不是主干对齐基线；
- **无训练的提示/经验方法**：原版 Qwen2.5-7B、Zero-Shot、ReAct、Reflexion、Mem0、ExpeL；
- **无技能 RL 方法**：PPO、RLOO、GRPO、GiGPO；
- **技能增强 RL 方法**：EvolveR、Mem0(+RL)、SimpleMem、D2Skill（不同编辑器变体）、Skill1、SkillRL、RetroAgent。

### 3.3 主实验结论（RQ1）
- ALFWorld 平均成功率为 **98.4%**，高出最强先验方法 RetroAgent 3.5 个百分点；5/6 子任务达到 100%。
- WebShop 平均任务分数 **95.9**、成功率 **90.6%**，比最强基线分别高出 4.3 和 6.2 个百分点。
- 对比无技能 GiGPO 基线，ALFWorld 提升 7.6 pp；WebShop 成功率提升 17.8 pp，说明增益不只来自底层优化器；对比“外部大模型当编辑器”的 D2Skill 也有明显优势，说明“随环境奖励对齐技能优化”比单纯更换大容量编辑器更重要。

### 3.4 消融实验（RQ2）
在 ALFWorld 上比较了完整 CoSkill 与四个消融：
- w/o Meta-Skill Agent RL：保留编辑器但去掉其 RL 目标；Step 20 成功率差 12.5%，最终收敛 92.19%（低 3.12%）；
- w/o Hierarchical Skill Library：扁平化技能库；Step 20 差 14.06%，最终 93.75%（低 1.56%）；
- 交替更新（每 10 或 20 步只更新一边）：训练后期差距达到 17.19/14.06 pp。说明高频的跨角色联合更新对稳定收敛至关重要。

### 3.5 元技能学习动力学分析（RQ3）
对比“有无元技能 RL”的编辑行为与库演化：
- 有 RL：元技能动作逐渐收敛为 97%~99% UPDATE，DELETE 几乎消失；
- 无 RL：动作熵高，DELETE 比例从 13% 升至 36%，库累计 promotion 达到 739 个，比有 RL 的 387 个多 47.6%，但下游成功率反而更低；
- 有 RL 的步骤技能检索命中率趋近 100%，无 RL 逐渐退化；训练末期“空步骤技能 bundle”率从 12.4% 降为 0.2%。
论文还用三个 case study（保留延迟清洗约束、补全搜索分支、保留重复子目标流程）定性展示了行为差异。

## 6. 论文的主要结论与发现

- **技能演化应被当作可学习过程，并与推理策略共同优化**，而不能再靠外部 LLM 或静态元技能流程来“遥控”技能库；
- 将“元技能”作为策略（Meta-Skill Agent）并从“后编辑执行成功与否”中学习，是避免“技能库膨胀但无效”以及“策略与技能失配”的有效路径；
- 分层技能组织（任务技能约束步骤技能检索范围）能显著提升样本效率和长程稳定性；
- 细粒度步骤技能编辑比粗粒度“整条技能或进或出”更有价值，且不依赖超大型闭源模型即可超过用强模型编辑技能的方案；
- 联合/高频更新比“交替、稀疏更新”效果更好，说明跨角色信息时效性非常关键。

## 7. 优点

- **框架统一且新颖**：把静态“skill workflow”概念升级为可训练 RL 智能体，同时复用同一策略骨干，避免另起一个编辑器模型带来的工程/参数开销。
- **闭环学习**：用环境任务奖励对“步骤技能内的局部修订”做信用分配，实现细粒度、可验证的技能迭代。
- **严格的门控机制**：post-edit verification、baseline subtraction、top-K promotion、保留原始 bundle 谱系，共同抑制了技能库失控增长和“自嗨式编辑”。
- **训练算法设计合理**：GiGPO 同时考虑 episode 级和 step 级优势，并用角色独立归一化避免推理奖励与技能验证奖励尺度上的相互污染。
- **实验叙事完整**：主实验、消融、动力学分析、case study 相互印证，对“为什么需要 meta-skill RL”给出了很强的证据链。

## 8. 不足与局限

- **实验基线较强依赖外部大模型编辑器**：对比的 D2Skill 变体使用 Gemini-3-Flash 或 O3 做技能编辑，存在编辑器模型规模的不对等；虽然 CoSkill 仍胜出，但对照的“主干一致性”并不干净。
- **算力与可复现性细节缺失**：GPU 型号、内存、vLLM 并行度等训练资源披露不全；仅给了一个环境的 GPU 小时估算。
- **统计报告偏弱**：论文没有给出多次随机种子的均值和方差，成功率的差异是否有统计显著性尚待说明（虽然基线条数多）。
- **验证尝试数过小**：表 3 中 M=1，编辑后验证只用一次随机 rollout，其奖励受环境随机性影响较大；这对“低方差训练”是一个隐患。
- **技能库初始化依赖外部 LLM 离线归纳**：这使最终效果部分取决于离线收集阶段的质量和代表性；若初始库分布偏差大，RL 阶段能否补足未见充分分析。

- **应用场景局限**：仅在 ALFWorld、WebShop 两个文本交互环境中验证，尚未涉及真实环境、视觉语言环境或更广的 open-ended agent 任务；对训练时间开销（验证 rollout 使成本放大数倍）也没有给出与基线的系统化对照，使读者难以评估“换取性能提升所付出的实际训练代价”是否可接受。

- **技能编辑的可行性边界未充分讨论**：论文假设所有可编辑技能都以自然语言步骤文本存储，且编辑动作仅为 INSERT/UPDATE/DELETE/KEEP。但若技能涉及数值参数、外部工具调用或多模态状态，或若编辑不当导致技能语法失效，该框架的泛化能力仍需额外机制支撑，论文未讨论这些边界条件。

- **公共库与私有副本之间的异步性可能引入不一致**：训练中验证发生在私有副本上、promotion 是周期性的，这使推理智能体在某一时刻使用的技能库与元技能智能体正在编辑的库之间存在“时间差”；虽然论文显示该设计在经验上有效，但理论上对 credit assignment 的潜在偏差并未分析。

- **基线公平性细节不足**：部分基线（如 ReAct、Reflexion）在提示词或示例数量上的调优程度未完全披露；同一骨干下的基线是否享有同等计算预算、同等验证 rollout 次数等信息也不够透明，可能让个别对比的实际难度不对等。

- **理论贡献有限**：MSMDP 与 GiGPO 主要是工程性结合与适配，而非全新理论框架；论文并未给出收敛性、样本复杂度或 credit assignment 误差界的理论刻画，理论深度相对薄弱。

## 9. 总体评价与定位

总体而言，CoSkill 是一篇**完成度高、问题意识清晰、工程实现扎实**的 Agentic RL 实证型论文。其核心贡献不在于提出新的 RL 公式，而在于将“元技能编辑”从外部 LLM 的固定工作流，转变成与推理策略**同参数、同优化器、同训练循环**的可学习智能体，并为这一设计配套了分层技能库、编辑后验证门控与组级策略优化等一套完整机制。

在实证层面，它在两个 benchmark 上均明显超越强基线，且清实验、动力学分析与 case study 构成了完整的论证链，使“shared-parameter co-evolution”这一核心主张具有较强的说服力。论文写作结构清晰、术语统一、图表对结论支撑到位，在方法叙述上做到了可复现的细节程度。

其最显著的短板在于**统计严谨性**（无多种子方差、验证次数 M=1）与**规模化证据的缺失**（单一 7B 骨干、双环境验证）。若将其放在“技能库学习”这一快速演进领域的坐标中来看，CoSkill 处于该子领域的第一梯队，但其是否能扩展到更大模型、更长任务、更复杂技能形态（如代码级技能、工具链技能）仍需后续工作验证。整体上，这是一篇值得接收的方法论文，尤其适合作为后续研究在“可演化技能库 + 多智能体共训练”方向上的起点性参考。
