## 摘要
语言生成几乎普遍被视为一个顺序过程：自回归模型一次生成一个词元，而扩散语言模型则用长轨迹的迭代细化取代词元级别的串行性。在这项工作中，我们介绍了PlaidQ，一个用于代码生成的0.7B连续扩散语言模型，并展示了其轨迹可以被积极蒸馏为仅少量去噪步骤——甚至一步，从而实现高效的代码生成。PlaidQ将预训练的自回归模型改造为连续词元嵌入上的双向去噪器。我们通过分布匹配进行少步生成的蒸馏，以及通过成对轨迹监督进行一步生成的蒸馏。在匹配的模型规模下，PlaidQ在代码生成上与离散扩散语言模型具有竞争力。蒸馏随后改变了质量-计算前沿：一个16步的学生模型在HumanEval和MBPP+上分别达到31.78和40.49的pass@10，超过了同一PlaidQ教师模型采样512步的结果。在极端情况下，成对轨迹蒸馏在单步去噪下于HumanEval上达到7.07的pass@1，生成功能正确的程序。这些结果共同确立了连续扩散作为少步和一步代码生成的可行路径。从广义上讲，连续扩散不仅仅是语言的另一种表示：它提供了一个接口，通过该接口语言模型可以继承连续扩散建模的加速和蒸馏机制。训练和推理代码及模型检查点可在https://github.com/pengzhangzhi/plaidq获取。

## Abstract
Language generation is almost universally treated as a sequential process: autoregressive models emit one token at a time, while diffusion language models replace token-level seriality with a long trajectory of iterative refinement. In this work, we introduce PlaidQ, a 0.7B continuous diffusion language model for code generation, and show that its trajectory can be aggressively distilled into only a few denoising steps---or even one, enabling efficient code generation. PlaidQ repurposes a pretrained autoregressive model as a bidirectional denoiser over continuous token embeddings. We distill PlaidQ with distribution matching for few-step generation and paired-trajectory supervision for one-step generation. At matched model scale, PlaidQ is competitive with discrete diffusion language models on code generation. Distillation then shifts the quality--compute frontier: a 16-step student reaches 31.78 and 40.49 pass@10 on HumanEval and MBPP+, surpassing the same PlaidQ teacher sampled for 512 steps. At the extreme, paired-trajectory distillation achieves 7.07 pass@1 on HumanEval with a single denoising step, producing functionally correct programs. Together, these results establish continuous diffusion as a viable path to few-step and one-step code generation. Broadly, continuous diffusion is not merely another representation for language: it provides an interface through which language models can inherit the acceleration and distillation machinery of continuous diffusion modeling. Training and inference code and model checkpoints are available at https://github.com/pengzhangzhi/plaidq.

### 1. 核心问题与研究动机
- **背景**：语言生成长期依赖两类顺序化过程——自回归逐 token 解码（依赖链随输出长度增长）与扩散模型的多步迭代去噪。尽管已有非自回归方案（掩码细化、离散扩散等）可以并行更新多个位置，但它们在更少的去噪步数下难以协调跨位置的决策，导致少数步下的生成质量明显恶化。
- **核心问题**：连续扩散语言模型能否通过蒸馏，实现仅需几步甚至单步的高质量代码生成？
- **潜在意义**：如果可行，连续扩散就不仅仅是一种语言表示方式，而是一个可以继承连续扩散成熟加速与蒸馏机制的接口，为高效语言推理开辟新路径。

### 2. 方法论：核心技术
- **PlaidQ 总体思路**：将预训练自回归语言模型（Qwen3-0.6B，共28层）改造为双向去噪器，在连续 token embedding 空间中执行并行去噪；生成时从高斯噪声出发，多步迭代后一次性做词表 argmax 解码。
- **初始化与对齐**：
  1. 将自回归 transformer trunk 和词汇投影层直接继承，并用双向注意力替换因果注意力；
  2. 通过**identity初始化的AdaLN**向每个 transformer block 注入扩散噪声级别；
  3. 采用**一位偏移策略**：去噪器预测 pθ(yi|xt,t) = softmax(hᵢ₋₁Wᵀ)，使复用头的位置角色与自回归预训练保持一致。
- **记忆瓶颈与 SWVR 内核**：PlaidQ 的干净嵌入重构 x̂₀ = softmax(hWᵀ)E 在152K词表下会产生巨大中间张量。SWVR（Softmax-Weighted Value Readout）是一个受 FlashAttention 启发的流式I/O感知融合内核，通过逐chunk的在线归一化，不物化完整的 B×L×V 概率张量，即可精确计算 codebook expectation、log-normalizer 与目标 token logit。相比密集实现，在序列长度2048时峰值激活内存降低29.6%（40.2GB→28.3GB），且梯度/损失完全一致。
- **混合优化器**：采用 Muon（作用于二维 transformer 主干权重）+ AdamW（应对embedding、偏置、归一化参数与词表头）的混合方案，持续优于 AdamW-only 训练。
- **两阶段蒸馏方案**：
  1. **DMD（分布匹配蒸馏）**——生成4/8/16步学生：学生按推理路径采样以消除训练-推理输入失配，选一个去噪步保留梯度，重加噪后由冻结教师与可训练critic分别去噪，用教师-critic差异作为目标方向更新学生（见文中公式3）。
  2. **配对轨迹蒸馏**——生成1步学生：对相同初始噪声，教师运行多条轨迹得到具体序列目标，学生以交叉熵对齐该点对（见文中公式4），为一劳永逸的映射提供直接监督。
- **步数依赖的温度（score temperature）**：极端少步时，DDIM类更新可能过度膨胀；研究给出稳定条件并对不同 K 设定不同 τ。
- 训练中基于**前缀条件（completion-only）**的 mask 机制，无 cond dropout、无 infilling mask；教师模型训练时伴随 self-conditioning 与 codebook 行列归一化。

### 6. 主要结论与发现
- 连续扩散语言模型可用于一般代码生成：128步教师达到 HumanEval pass@1=19.02、+CFG时 pass@10=39.87 / MBPP+=44.79，与同规模离散扩散模型相当。

### 7. 优点
- **架构简洁而高效地复用预训练权重**：使用已有AR模型作初始化后，只需很小工程量即获得提升（预训练、头对齐、加上控制实验的系统验证）。
- 记忆瓶颈的工程优雅解决——SWVR（类 FlashAttention 思想但用于 vocabulary-attention）严格保持数值精确性而同时大幅节省显存，具备独立可推广价值。
- 专门针对单步生成设计强化监督，配对轨迹比纯粹DMD在极限条件下更有效，且设置步数相关温度解决了少步的稳定性问题。
- 将质量-计算曲线翻转到蒸馏轨道上：在少步下“蒸馏后生成 > 教师采样”不等价于传统 teacher-student 近似，所得16步模型已超越其教师同基准 512 步的最优成绩。
- 训练细节的记录（推文、数据比例、packing、掩码与边界）打磨得完整、易于复现。

### 8. 不足与局限
- **实证覆盖范围较窄**:0.7B规模、代码+部分数学数据，模型是否适用于一般长文文本、复杂推理和更大参数（≥7B）并未展现。
- **蒸馏成本未全面呈现**：需要前置教师训练（大量算力、时间、GPU），且训练D4/D8/D16/单步学生时额外消耗了语料和检索轨迹；论文只报教师训练时间，缺少端到端“教师+蒸馏”与“自回归训练+蒸馏”的成本对照，可能高估快推理的净收益。
- **对比公平性风险**：相比离散扩散模型（Open-dCoder、oDLM 等）与8B级模型，训练数据分配、数据量、蒸馏迭代次数并不完全对齐；表1的比较并不受严格的控制变量约束。

- 缺少人类评价或多样长尾输入的鲁棒性分析，生成输出可能带有隐式重复倾向等隐性问题。
