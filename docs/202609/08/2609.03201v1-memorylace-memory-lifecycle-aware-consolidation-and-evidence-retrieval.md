## 摘要
长期大语言模型代理必须在交互过程中保存信息，同时区分重复证据、历史状态、更新和未解决的矛盾。现有的文本记忆系统能高效检索语义相关的记忆，但往往使这些关系隐含，而更丰富的结构化方法通过全局图、层次抽象或反思来建模这些关系，但复杂度更高。我们引入MemoryLACE（MemLACE），一种轻量级记忆框架，通过稀疏合并、替代和矛盾关系显式建模文本证据的生命周期，同时保留原子自然语言记忆及其来源。MemLACE不是独立检索记忆，而是重构关系感知的证据单元，为下游推理暴露当前、历史、支持和冲突的证据。在BEAM和StructMemEval上，使用开源和专有LLM骨干，MemLACE在同骨干比较中取得了最高整体性能，同时相对于最强反射式记忆基线Hindsight，将BEAM上的端到端运行时间减少了66.6%。消融研究确定生命周期扩展和时间感知是这些增益的主要贡献者。综上所述，结果表明，显式建模文本证据的局部生命周期足以显著改善长期记忆推理，而无需全面的知识图谱或全局反思。

## Abstract
Long-term LLM agents must preserve information across interactions while distinguishing repeated evidence, historical states, updates, and unresolved contradictions. Existing textual memory systems retrieve semantically relevant memories efficiently but often leave these relationships implicit, whereas richer structured approaches model them through global graphs, hierarchical abstractions, or reflection at greater complexity. We introduce MemoryLACE (MemLACE), a lightweight memory framework that explicitly models the lifecycle of textual evidence through sparse merge, supersession, and contradiction relations while preserving atomic natural-language memories and their provenance. Rather than retrieving memories independently, MemLACE reconstructs relation-aware evidence units that expose current, historical, supporting, and conflicting evidence for downstream reasoning. Across BEAM and StructMemEval, using open-weight and proprietary LLM backbones, MemLACE achieves the highest overall performance in same-backbone comparisons while reducing end-to-end runtime on BEAM by 66.6% relative to Hindsight, the strongest reported reflective-memory baseline. Ablation studies identify lifecycle expansion and temporal awareness as the principal contributors to these gains. Together, the results demonstrate that explicitly modeling the local lifecycle of textual evidence is sufficient to substantially improve long-term memory reasoning without requiring comprehensive knowledge graphs or global reflection.

- **核心问题**：长期LLM智能体在与用户进行跨会话、跨任务交互时，需要构建外部记忆机制来保存偏好、计划、修正、约束和既有事实；然而可靠的记忆不只是“检索相关文本”，新证据可能**重复**、**替代**或**矛盾**旧证据，如何显式建模这种文本证据随时间演变的“生命周期”是核心挑战。
- **现有方法的两难处境**：
  - **平面文本记忆系统**（如 Mem0、SimpleMem、SeCom、EMem）存储和检索高效，但将记忆之间的关系隐含化，无法区分当前状态、历史状态、更新和矛盾。
  - **结构化/图式/反思性系统**（如 A-MEM、Zep、Hindsight、MemOS）虽显式建模关系，但依赖全局知识图谱、层次抽象或昂贵的反思阶段，复杂度高。
- **本文提出的问题**：能否在不构建全面全局结构的前提下，保留文本证据的演化状态，并在查询时间**联合检索存在依赖关系的记忆**？
- **解决方案的整体含义**：提出 **MemoryLACE (MemLACE)**，作为平面文本记忆与全面结构化记忆之间的轻量中间地带，仅通过三种稀疏局部关系——合并（merge）、取代（supersede）与矛盾（contradict）——显式建模证据生命周期，即可显著提升长期记忆推理能力，无需全局知识图谱或全局反思。

## 2. 方法论：核心思想、关键技术细节与算法流程

### 2.1 核心思想

- 将长期记忆视为**随证据演变的动态体系**而非平面的摘要集合。
- 保留**原子自然语言记忆 + 来源信息（provenance）**，同时用稀疏的**生命周期关系**将相关记忆显式连接起来。
- 检索时**先找相关记忆锚点，再沿生命周期关系扩展**，将关联记忆组成**证据单元（evidence units）**，使下游LLM能够同时看到“当前状态、历史状态、支持和矛盾证据”。

### 2.2 记忆表示（Memory Representation）

每条记忆被建模为一个元组：

```
mi = (xi, τi, zi, pi, ai, Ri)
```

- **xi**：原子自然语言陈述，表示一条独立可理解的显式证据；
- **τi**：证据支持的时间元数据（如事件发生时间、有效期限），用于区分“有序更新”与“真正矛盾”；
- **zi**：轻量元数据（实体、关键词、话题、地点）；
- **pi**：来源信息，记录支持该记忆的对话轮次ID；
- **ai**：活跃状态标记（1 = 在主动检索范围内，0 = 被替代/废弃）；
- **Ri**：生命周期关系引用集合（包括零或多条 merge、supersession、contradiction 关系）。

记忆存储在形式上构成稀疏关系图 **G = (M, E)**：

- 有向边：**supersession（取代）**，新旧双向指向，形成有序链；
- 无向边：**merge（合并）** 和 **contradiction（矛盾）**。

这种稀疏图只编码对“证据解读”必要的生命周期关系，不追求全面的实体/因果/分类学知识图谱。

### 2.3 阶段一：记忆构建与整合（Memory Construction & Consolidation）

流程包含四步：

1. **记忆构建（Memory Construction）**：
   - 采用类似SimpleMem的轻量滑窗法，将对话窗口（20轮、重叠2轮）转成独立的原子记忆；
   - 每个记忆包含来源轮次信息，不推断未说出的信息；
   - 重叠窗口产生的重复提取被合并，来源累加。

2. **候选与关系选择（Candidate & Relation Selection）**：
   - 对每条新记忆 mnew：通过语义相似性与同实体匹配找相关记忆，再将其**一跳生命周期邻居**一并纳入候选集 C(mnew)；
   - 用cross-encoder对候选重新排序（仅影响是否被考虑，不决定最终关系）；
   - 整合模块从策略集合 **R = {merge, update, contradict, no action}** 中选择**恰好一个策略 r** 和**一个目标记忆 c*​**，由函数 g(mnew, C(mnew)) → (r, c*) 完成；
   - 设计上刻意限制为“单决策-单目标”，降低在多候选间同时判断的不可靠性；
   - 多关系遗漏由后续“局部批量演化”步骤修复。

3. **生命周期状态更新（Lifecycle State Update）**：
   - **update（更新）**：旧记忆被标记为不活跃（a←0），新记忆成为活跃链头（a←1），并建立双向 supersession 边；
   - **contradict（矛盾）**：双方都保持活跃（因为证据未解决冲突），建立对称矛盾边；
   - **merge（合并）**——支持两种策略：
     - **默认 linked-merge**：保留原文和来源，双向建立 merge 引用，每个原始证据仍可单独检索；
     - **compact-merge（备选）**：用一条综合记忆替换多条被合并的记忆，体积更小但丢弃原始独立条目；
   - **no action**：保持独立可检索；
   - 被取代的记忆排除于常规主动检索，但历史和矛盾证据永久保存、不被删除。

4. **局部批量记忆演化（Local Batch Memory Evolution）**：
   - 单个记忆逐条整合后，按**组**对所有新记忆与其候选集做一次有限的联合检查，修复组内才显现的额外 update/contradict/merge 链接；
   - 只修改关系链接和活跃状态，不重写记忆文本、不添加事实。

### 2.4 阶段二：证据检索与上下文构建（Evidence Retrieval & Context Construction）

1. **混合主动记忆检索（Hybrid Active-Memory Retrieval）**：
   - 用四种通道（语义、关键词、结构化模板、话题）在**活跃记忆集 A** 上生成排名列表；
   - 用 **Reciprocal Rank Fusion (RRF)** 融合排名，公式为：

     sRRF(m) = Σ_{c∈C} 1 / (k + rank_c(m))

   - 只对活跃记忆做初始检索，减少被取代记忆的干扰；
   - 非活跃记忆即使未被直接检索到，也能通过已检索锚点的生命周期关系恢复。

2. **生命周期扩展与证据单元（Lifecycle Expansion & Evidence Units）**：
   - 对每个活跃锚点扩展生命周期邻域：Eq = Aq ∪ L(Aq)；
   - 沿 supersession 链恢复历史状态、沿 contradiction 边恢复一跳矛盾证据（有界扩展，不全图遍历）；
   - 将得到的记忆按连通关系组成**证据单元**，supersession 边让组件内按“历史→当前”排列；矛盾证据并列保留；
   - 先分组再重排，让关联记忆作为整体参与评分，而非独立竞争。

3. **链感知重排与上下文打包（Chain-Aware Reranking & Context Packing）**：
   - 重排器对证据单元整体打分；
   - 高分的单元按预算装填上下文，保持链内时间顺序；
   - 单元超出剩余预算时只截断舍弃低优先级记忆，尽量保留完整证据单元。

4. **基于证据的答案生成**：
   - 打包上下文在文中按生命周期顺序展示，显式标记当前/历史/矛盾记忆；
   - 模型能优先使用活跃证据回答当前状态问题、追溯历史状态回答历史问题、并保留下未解决矛盾供决策。

- **合并策略trade-off的诊断**：compact-merge提高矛盾消解（40.3→44.1）但明显降低多跳推理（55.3→43.0），证明默认 linked-merge（保留原始证据和来源）是更优默认。
- **核心理论主张**：显式建模**局部证据生命周期**（稀疏关系）即可获得通常与重量级记忆架构相当的推理收益——“长期记忆的主要挑战不是更丰富的全局结构，而是保留证据随时间推移如何演变。”

## 7. 优点（方法亮点与实验设计亮点）

- **轻量与高效**：三条局部稀疏关系（merge/supersede/contradict）取代全局图谱与反思阶段，将端到端耗时降低近2/3，但精度反而提升；
- **证据保留的完整性与可审计性**：原子自然语言记忆+来源轮次+原始文本保留，即使被取代也不删除，支持追溯“为什么这样回答”；
- **粒度精细**：原子记忆粒度让更新/矛盾只影响被改变的单一claim，整合精准高效；
- **单决策约束设计巧妙**：一次只处理一个关系-目标对，显著降低多候选联合分配的不稳定性；
- **分批演化修复遗漏**：弱化了逐条决策对顺序的敏感性，在不增加全局复杂度的情况下做了局部修复；
- **检索中以“证据单元”而非单记忆为处理对象**：先分组后重排，使依赖关系紧密的记忆不被当作独立片段互相竞争，是一种干净、有效的创新；
- **模型规模无关的增益**：4B小模型上增益大，说明收益来自结构化上下文（而非仅靠更大模型的力量）；
- **消融设计精细且具诊断性**：能判断每个组件影响了哪些认知能力，而非仅报告整体分数；
- **时间感知与连接扩展的对比**揭示了两种不同失效模式的本质差异。

  - 与LIGHT/SimpleMem只在BEAM上对比，未验证它们在StructMemEval上的表现，可比矩阵不完整。
- **特定能力短板**：
  - **计数推理**：Mem-Agent与MemLACE均为0%解决率——框架缺乏聚合/统计类算子；
  - **推荐任务**：仅8.33%场景级通过（个人问题级仅约32.2%），难以处理涉及全局排名/分布式偏好聚合的任务；
  - 时间推理和信息抽取在9B下仍落后Hindsight（分别为−8.7和−5.2个百分点），摘要也不及Hindsight（−4.9），说明“轻量不重建全局”策略在需要穷尽/全局综合的任务上有局限。
- **消融验证范围窄**：只在Qwen3.5-9B上做消融，未确认4B/专有模型上组件贡献是否一致；已折叠多轮复杂对话跨时间窗口的信息读写可靠性在更大规模上缺乏验证；
- **评估与实现中的潜在偏差风险**：组合消融各组件间存在重叠，净效应小于分项加总，削弱了对“可加性”的清晰解读；“时间感知”的具体实现细节在系统描述中着墨较少，复现难度略高；
- **检索配置与嵌入模型为固定选择**，未检验不同嵌入/重排模型替换后的稳定性；语义相关性候选与实体候选的预算、窗口长度等超参数敏感性未做系统诊断；
- **缺乏真实应用场景的端到端验证**：所有测试都来自合成benchmark（对话+QA），未见现实世界多用户/长期交互环境中噪音、话题漂移与隐私约束的影响研究。
