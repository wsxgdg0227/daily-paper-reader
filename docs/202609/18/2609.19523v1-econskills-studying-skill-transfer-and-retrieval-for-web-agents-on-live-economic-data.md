## 摘要
网页智能体经常重复访问相同的网站，然而大多数评估会丢弃在先前成功交互中学到的操作流程。我们提出 EconSkills，一个技能库与评估框架，它将经过验证的 EconWebArena 轨迹提炼为参数化的标准操作流程，用于检索实时经济数据。每个技能记录其适用范围、导航流程、站点特定指南、验证检查与恢复步骤，同时将源实例中的取值替换为占位符。EconSkills 区分两个问题：已知的相关流程能否迁移到留出任务，以及智能体在从技能库中进行选择时能否保留这种收益。在受控迁移中，匹配的技能相比无技能提示提高了成功率，并在配对成功案例上需要更少步骤，而抽象化比回放原始轨迹要有效得多。在技能库规模下，检索总体上与无技能基线相当，并在直接覆盖的任务上表现最佳；按覆盖度分层的结果显示，未覆盖任务上的近似匹配会抵消这些增益。浏览器轨迹进一步识别出，程序性指导何时能缩短特定门户的导航，以及何时仍需要语义验证。这些结果表明，可复用的经济网页流程可以跨任务实例迁移，并为覆盖感知的选择与上下文传递提供了具体的设计目标。

## Abstract
Web agents often revisit the same sites, yet most evaluations discard the procedures learned in earlier successful interactions. We introduce EconSkills, a skill library and evaluation framework that distills verified EconWebArena trajectories into parameterized standard operating procedures for retrieving live economic data. Each skill records its scope, navigation procedure, site-specific guidance, verification checks, and recovery steps while replacing source-instance values with placeholders. EconSkills separates two questions: whether a known relevant procedure transfers to a held-out task, and whether an agent can retain that benefit when selecting from a library. In controlled transfer, matched skills improve success over no-skill prompting and require fewer steps on paired successes, while abstraction is substantially more effective than replaying raw trajectories. At library scale, retrieval is competitive with the no-skill baseline overall and performs best on directly covered tasks; coverage-stratified outcomes show that approximate matches on uncovered tasks offset these gains. Browser trajectories further identify when procedural guidance shortens portal-specific navigation and when semantic verification remains necessary. These results establish that reusable economic web procedures can transfer across task instances and provide a concrete design target for coverage-aware selection and context delivery.

## 1. 核心问题与研究动机

- **背景问题**：基于 LLM 的网页智能体已能在真实网站上读页面、填表单、跟链接并给出答案，但主流评测把每个任务当作孤立任务处理——同一个门户上结构相似的任务（例如只换了年份、国家或数据序列）都要从零重做，先前成功交互中学到的流程在下一个任务前被丢弃。
- **经济学场景的特殊性**：分析师需要从央行、国家统计局、国际组织等官方门户抓取具体数值（通胀数据、政策利率、汇率、国别指标等）。EconWebArena 正是为这一设定构建的基准。
- **关键观察**：在同一个门户内，"到达答案的路径"比"答案本身"稳定得多——国际组织指标的路径、央行统计页的选择器序列、统计局的数据导出控件，都是可复用的结构。
- **核心痛点**：经济学门户常在相邻位置暴露标签相似但单位、季调方式、地理覆盖、发布版本或生效日期不同的序列，因此有用的技能不能只编码"点哪里"，还必须编码"请求的是哪个序列"以及"如何校验其口径与来源"。
- **论文要区分的两个问题**（此前工作常混为一谈）：
  1. 当任务有已知的对应技能时，该技能能否迁移到新实例？
  2. 当智能体必须从整个技能库中自行选择时，这种收益能否保留？
- **整体含义**：EconSkills 既是技能库也是评测框架，把"技能复用"拆解为**流程迁移**与**覆盖感知选择**两个可度量的维度。

## 2. 方法论

### 2.1 核心思想
- 从**已验证成功**的种子轨迹中蒸馏出**抽象化、无实例**的经济网页技能，作为可注入智能体提示的标准操作流程（SOP），并在新任务上复用。
- 技能构建与应用分三阶段：**任务执行 → 技能抽取 → 技能应用**。

### 2.2 关键技术细节

**（a）任务执行（种子求解）**
- 智能体驱动真实门户浏览器，每步观测：当前页面的无障碍树（AXTree）、截图、上下文元数据（焦点元素、动作历史）。
- 动作来自 EconWebArena 的 BrowserGym 高层动作集（元素/坐标交互、键盘输入、滚动、导航、标签页管理）。
- 只有任务被解出且通过基准自动校验（**答案含金标值 + 最终 URL 落在权威域名**）才保留为种子，共 50 个，覆盖 9 个经济类别、37 个权威网站。

**（b）技能抽取（七段式 SOP）**
- 抽取器模型读取完整轨迹（URL、AXTree、动作、确认答案），改写为可供**不同智能体在新实例上执行**的流程，含七个字段：
  1. **Name** 技能名
  2. **Purpose** 可回答的问题类型
  3. **Preconditions** 前置条件（门户/数据集可达等）
  4. **Procedure** 有序的导航与交互步骤
  5. **Website Guidance** 门户特定菜单、选择器与坑点
  6. **Verification** 如何确认取到的数值就是任务所求
  7. **Recovery** 步骤失败时的回退策略（搜索、表格视图、归档、下载视图等）
- **抽象化是复用性的来源**：把实例特定取值（年份、国家、指标、数值目标）替换为具名占位符（`<year>`、`<country>`、`<indicator>` 等），使步骤在新实例填充后依然有效。
- **验证与恢复是技能区别于"脆弱点击录制"的关键**：官方门户常在同页放置名义/实际值、季调/未季调、初值/修订值或多个生效日期，因此技能记录实体、期间、单位、序列定义、来源域名的检查，以及门户特定回退。
- 每个技能序列化为 JSON（七字段），渲染为 Markdown 注入提示；每个种子任务抽取恰好一个技能，共 50 个独立技能。

**（c）技能应用（两级评测设计）**
- **受控匹配迁移**：50 个源技能各配对 2 个同流程族的留出变体 → 100 个"源—变体"对；变体只改实例字段（日期、实体、序列、类别）而保留网站工作流。每变体每条件跑 3 次（种子 0/1/2），三种条件：
  - `BASE`：仅任务
  - `TRAJ1`：任务 + 一条匹配的原始成功轨迹（去掉最终答案）
  - `MATCH1`：任务 + 一个直接匹配的抽取技能
- **库规模部署**：全部 360 个任务各跑一次，条件变化所供给的库上下文：
  - `BASE`（无技能）、`ALL50`（全库）、`RETR5`（按名称与用途排序取前 5）、`RAND5`（任务种子随机 5 个）、`HINT30`（注入 1 个技能，并明确告知其**可选、可能过时、不匹配时可忽略**）。
  - HINT30 中 150 个被直接覆盖的任务给对应族技能，其余 210 个给 top-1 检索技能，并**分组分析**以避免把技能质量与库覆盖率混淆。

**（d）度量与统计**
- 任务 t、条件 c 的奖励 $r_c(t)\in\{0,1\}$（答案含金标值且最终 URL 在权威域名），成功率 $SR_c = N^{-1}\sum_t r_c(t)$，并报告交互步数。
- 配对结果用 **McNemar 精确检验**；步数比较**仅限两条件都成功的运行**，避免把早期失败误判为高效。

## 3. 实验设计

- **数据集 / 场景**：EconWebArena，360 个实时任务，覆盖政府、银行、市场、劳工、金融、能源、教育、健康、贸易等类别，全部通过公开可达页面的浏览器交互完成，无需 API 凭证。
- **Benchmark 性质**：原生奖励要求"答案含金标值 + 落在权威域名"，不从失败检查后的智能体文本中"抢救"答案。
- **受控研究**：100 个被 50 个技能族直接覆盖的留出变体，条件为 BASE / TRAJ1 / MATCH1，每条件 3 次独立运行 → 100 × 3 × 3 = **900 个浏览器智能体 episode**。
- **部署研究**：全部 360 任务 × 5 个条件（BASE、ALL50、RETR5、RAND5、HINT30）。
- **智能体配置**：`gpt-5-mini`，运行于 BrowserGym + AgentLab 生态；每步输入 AXTree、截图、焦点元素与近期动作历史；30 步预算；所有条件仅在被加入提示的轨迹/技能文本上不同。
- **对比方法（基线）**：无技能提示（BASE）、原始轨迹回放（TRAJ1）、随机技能（RAND5）、全库投递（ALL50）、可选单技能提示（HINT30）、检索式投递（RETR5）。
- **辅助分析**：配对单元级结果分析、按库覆盖度分层分析（源任务 / 留出变体 / 无直接匹配）、代表性浏览器轨迹定性对比（ONS、USCIS、美国财政部、SBA 等）。
- **数据修正处理**：4 个在权威来源已变更的基准值，通过**不参考条件结果**构造的固定修正表处理。

## 5. 实验数量与充分性

- **实验组数**：受控迁移 1 组（3 条件 × 100 变体 × 3 种子 = 900 episode）；库规模部署 1 组（5 条件 × 360 任务）；另加配对单元分析、覆盖度分层分析、HINT30 三子集拆分（源任务 50 / 留出变体 100 / 无匹配 210）、以及多组浏览器轨迹定性案例。
- **充分性方面**：
  - 优点：做了**配对级**而非仅平均值的分析（McNemar 精确检验、符号检验），并明确区分"已知匹配"与"需自选"两种情形，还专门构造 HINT30 来检验"可选提示 + 拒绝近似匹配"的能力。
  - 局限：部署研究**每任务仅 1 次运行**，只能做配对比较，无法给出跨种子误差棒；受控研究仅 3 个种子；只有 1 个基准、1 个骨干模型、固定 30 步预算；50 个技能来自单一抽取 schema。
- **客观与公平性**：条件间模型、浏览器环境、观测空间、动作预算、提示注入通道（同一 extra-instructions 通道）均保持一致，只有注入的技能/轨迹文本不同，控制较严谨；RETR5 与 RAND5 保持上下文数量一致，属于合理的控制变量设计；但 HINT30 同时改变了**呈现方式与运行协议**（技能被标为可选、每任务只跑一次），因此其与 MATCH1 的差异不能纯归因于技能呈现。

## 6. 主要结论与发现

- **匹配技能确实迁移**：MATCH1 成功率 41.0% → 49.3%（+8.3pp）；在 300 个配对种子级结果中，46 次由失败转成功、21 次反向，McNemar 精确检验 p = 0.0031，说明增益来自分布式的配对改善而非平均值掩盖。
- **抽象优于回放**：同族的原始成功轨迹 TRAJ1 仅 7.0%，其短平均步长源于**提前终止**而非高效完成——仅删掉源答案、保留实例化动作与观测，对新实例无用。
- **配对成功上更省步**：在 BASE 与 MATCH1 均成功的 102 个单元中，MATCH1 平均少 2.37 步（中位数少 2 步）；59 个单元更短、15 个持平、28 个更长（符号检验 p = 0.0012）。
- **库规模下检索可与基线持平并在覆盖任务上领先**：RETR5 总体 28.3% vs BASE 28.1%（p = 1.0）；直接覆盖的 150 个任务上 RETR5 达 48.0%（BASE 44.0%，HINT30 46.0%）。
- **全库投递造成严重上下文干扰**：ALL50 仅 11.4%（p < 10⁻¹²）；RAND5 为 24.4%（p = 0.085）。
- **覆盖度是解释总体持平的关键**：在 210 个无直接匹配的任务上 BASE 最高（16.7%），RETR5 14.3%、RAND5 12.4%、HINT30 11.4%、ALL50 6.7%。
- **允许忽略不足以消除干扰**：HINT30 在无匹配任务上把成功率从 16.7% 降到 11.4%（p = 0.043）；在 150 个覆盖任务上 +2.0pp 不显著（p = 0.711），在 100 个留出变体上与 BASE 各解出 45/100（Δ = 0，p = 1.000）。
- **配对模式**：100 对中 27 对（27%）匹配技能改善均值、12 对（12%）下降、29 对（29%）至少一个条件成功且无变化、32 对（32%）所有条件与运行均失败。改善多出现在门户有稳定序列页或选择器序列时（ONS 通胀时间序列、财政部收益率表、CoinMarketCap 历史快照）；边界情形是"邻近但语义不同"的选择（特定表单的费用类别、close 与 adjusted close 之别）。
- **轨迹层面的两类复用边界**：① 动态选择器、下载控件或页面改版使智能体无法沿记录路径走；② 智能体到达了相关页面但读错了单位、日期、序列或申报类别；还有近似相关技能在进展停滞时把智能体"锚定"在错误页面上。
- **定性案例**：ONS 任务 225 中 BASE 在通用下载界面耗尽 30 步，HINT30 直达 MM23 时间序列表并在 14 步成功；美国财政部任务 274 中 BASE 困于站内搜索并终止于死链，提示版在 15 步到达历史收益率表；USCIS 任务 264 中提示版虽到达 I-140 费用区块但 30 步内未给出经校验的答案——说明"到达正确页面"与"正确抽取并验证"是两件独立的事。

## 7. 优点

- **问题切分清晰**：把"技能是否可迁移"与"能否从库中选对"显式解耦，用两级实验设计分别度量，避免把存储、检索、呈现三者的效果混为一谈。
- **技能表示具备工程实用性**：七段式 SOP 中显式包含 **Verification 与 Recovery**，并要求占位符抽象，使技能不是脆弱的点击录制，而是可跨实例、可校验、可回退的流程。
- **评测规范性强**：采用原生二值奖励、配对 McNemar 精确检验、仅在双成功子集上比较步数（防止把早退误当高效）、按覆盖度分层报告，避免了"总体平均值掩盖检索失败"的常见陷阱。
