## 摘要
长期与用户交互的智能体必须从不断增长的交互历史中回忆事实、偏好、事件和变化。现有记忆系统通常将交互压缩为通用摘要，或检索匿名文本片段，使智能体难以识别正确的实体、属性与支撑证据。我们提出 EnSIMem，一种面向智能体的实体结构化长期记忆架构。在离线构建阶段，系统将交互组织为主题连贯的片段，并构建以对话为根基的索引条目，形式为 [实体][实体类型][属性:值]。每个条目保留其源对话轮次、时间信息以及可用的多模态字段。在在线交互阶段，智能体的请求被分解为证据需求，其属性与记忆索引对齐。随后，实体-属性查找与自适应检索会收集点推理、时间推理、组合推理和聚合推理所需的证据。智能体基于保留的源证据而非有损的记忆摘要生成回复。在长期智能体记忆基准上，EnSIMem 实现了高回答准确率，同时保持紧凑上下文和良好的在线效率。这些结果表明，实体结构化索引与片段级溯源为智能体的长期记忆提供了可靠基础。我们模型的代码可在 https://github.com/RamonMeng/EnSIMem 获取。

## Abstract
An agent that interacts with users over long periods must recall facts, preferences, events, and changes from a continuously growing interaction history. Existing memory systems often compress interactions into generic summaries or retrieve anonymous text chunks, making it difficult for an agent to identify the correct entity, property, and supporting evidence. We present EnSIMem, an entity-structured long-term memory architecture for an agent. During offline construction, the system organizes interactions into theme-coherent episodes and builds dialogue-grounded index entries of the form [entity][entity type][property:value]. Each entry preserves its source turns, temporal information, and available multimodal fields. During online interaction, the agent's request is decomposed into evidence requirements whose properties are aligned with the memory index. Entity-property lookup and adaptive retrieval then collect the evidence needed for point, temporal, compositional, and aggregation reasoning. The agent generates its response from the preserved source evidence rather than from lossy memory summaries. On long-term agent-memory benchmarks, EnSIMem achieves high answer accuracy while maintaining compact contexts and favorable online efficiency. These results show that entity-structured indexing and episode-level provenance provide a reliable foundation for long-term memory in agents. The code of our model is available at https://github.com/RamonMeng/EnSIMem.

## 1. 核心问题与整体含义（研究动机与背景）

- **核心问题**：长期运行的智能体必须从持续增长的交互历史中回忆事实、偏好、事件与变化，但现有记忆系统难以同时做到"可扩展"与"高特异"。
- **现有方案的张力**：
  - 传入完整交互历史：证据齐全，但上下文膨胀、延迟升高、注意力分散（lost-in-the-middle 效应）。
  - 摘要压缩：上下文小，但丢失细节、时间限定词与溯源。
  - 传统 RAG / 向量最近邻检索：返回匿名文本块，**不显式指示哪个实体、属性或事件使该记忆相关**。
- **关键难点**：相关信息分散在多次交互中，可能以代词、相对时间、相关性或多模态观测形式出现；例如同一事件先以"乘直升机去芝加哥"具体表述，后被笼统地问"如何前往芝加哥"。系统既要连接不同表述，又不能把事件坍缩为"activity/travel"这类无信息类别，同时须保留原始证据以区分显式事实与推断。
- **整体含义**：论文主张将长期记忆重构为"短上下文推理问题"——用结构做**寻址系统**定位证据，用**原始对话**解释证据，而非用有损结构替代原始交互。

## 2. 方法论：核心思想与关键技术

- **核心设计原则**：索引结构是证据的"地址系统"，不是原始交互的有损替代。系统分为查询无关的离线记忆构建与查询相关的在线访问：
  - M = F_memory(D)（持久、查询无关的记忆表示）
  - ŷ = G(q, R(q, M))（检索 + 生成）

### 离线记忆构建（查询无关）

- **主题连贯片段（Theme-Coherent Episodes）**：
  - 将相邻对话轮次分组成连续、主题连贯的片段，介于"每轮"与"整会话"之间。
  - 分片策略：共享实体、事件、目标或未解决的指代时保持在一起；仅当出现新的持久主题/任务时切分；**说话人变化本身不触发切分**；多模态字段附着于引入它的轮次。
  - 形式化：Π(S_n) = (e_{n,1}, ..., e_{n,m_n})，覆盖完整且互不重叠；主题是轮次"共同关于什么"的简短描述，而非固定本体。
- **对话根基的实体–属性索引**：
  - 提取显式提及的实体与显著事件（人物、物体、地点、活动、命名事件），生成记录 r = ⟨x, t, p, v, e, π⟩（实体、类型、属性/关系、可选具体值、所属片段、溯源链接）。
  - 索引形式：**[x][t][p:v] → {episode id}**，例如 [Caroline][person][research: adoption agencies] → {e}。
  - 记录只是"地址"，值在无具体实现时留空；答案仍从保留的源上下文读取。
- **粒度控制的属性对齐**：
  - 属性须**足够宽以支持释义匹配，又足够具体以保留底层关系/事件身份**。
  - 过窄导致召回低；过宽（如把 research、attending a class、playing football 都归为 activity）则丧失区分度。
  - 语料属性与请求属性在"兼容语义粒度"原则下生成，通过兼容性而非精确字符串匹配比较；如"乘直升机去芝加哥"与"去芝加哥旅行"共享 travel 类属性，同时保留具体交通方式于 value 中。

### 在线记忆访问（查询相关）

- **需求感知查询规划**：
  - 将请求分解为原子检索需求集合 H(q) = {h₁,...,h_K}，每个 h_i = (x_i, t_i, p_i, v_i, c_i, ρ_i)（目标实体、类型、中间粒度属性、可选值/条件、证据角色）。
  - 分类推理类型并据此确定证据预算：**点式**（少量片段）、**时序**（按时间排序/比较）、**组合**（多个相关属性/实体）、**聚合/频率**（须收集全部相关片段再计数）。
- **需求覆盖检索**：
  - E(q) = Dedup(Structured(I, H(q)) ∪ Dense(T, H(q)))——结构化实体/类型/属性匹配为主，稠密检索作召回回退；按片段身份合并去重。
  - 跟踪哪些需求已被覆盖，采用**自适应停止条件**（由证据需求决定，而非固定相似度阈值或固定 top-k）：点式问题少量即可停；时序/组合持续到比较或推理桥被支持；聚合/频率须穷尽。
- **证据根基的智能体回复**：
  - 将选中片段展开回源证据（轮次文本、说话人、时间、多模态字段），ŷ = G(q, H(q), Γ(E(q)))。
  - 答案从源证据生成而非仅凭索引记录；显式事实直接作答，证据不足时承认不确定，时间表述保留源精度，聚合跨片段计算。
