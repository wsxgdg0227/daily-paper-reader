## 摘要
智能体记忆系统通过复用过往经验来提升未来表现，然而现有大多数设计都在写入时进行记忆策展：一旦任务完成，其轨迹便被蒸馏为固定的产物，如反思、工作流、技能或推理策略，之后通过相似度进行检索。这迫使系统在尚不知晓未来查询的情况下就决定什么值得记住，从而不可逆地丢弃信息，并产生一个必须服务于许多可能下游任务的、与查询无关的摘要。学习这样的写入时策展器也很困难，因为某项存储决策的价值可能只有在相关查询到来时才会显现，而这可能发生在许多任务之后，从而形成一个长时程的信用分配问题。我们转而保留原始轨迹，并将策展推迟到读取时，即当前任务已知之时。给定检索到的轨迹和新任务，记忆策展器会合成一个紧凑、任务自适应且针对当前需求定制的内容。由于该内容在同一任务上被消费，策展器可以直接根据即时任务成功进行训练，从而避免延迟的效用信号，也无需人为地将相关任务分组。在 ALFWorld、WebShop 和 τ²-bench 上，我们的即时记忆（JitMem）始终优于无记忆智能体以及启发式和已学习的写入时记忆方法，相较最强基线分别提升了 16.2、16.3 和 3.9 个绝对成功率百分点。值得注意的是，即使未经训练的策展器也已能与这些基线相媲美或超越它们，这表明任务自适应的读取时策展本身就是增益的主要来源；而训练策展器则进一步叠加了改进。

## Abstract
Agentic memory systems reuse past experience to improve future performance, yet most existing designs curate memory at write time: once a task is completed, its trajectory is distilled into a fixed artifact, such as a reflection, workflow, skill, or reasoning strategy, that is later retrieved by similarity. This forces the system to decide what is worth remembering before the future query is known, irreversibly discarding information and producing a query-independent summary that must serve many possible downstream tasks. Learning such a write-time curator is also difficult because the value of a storage decision may only become apparent when a relevant query arrives, potentially many tasks later, creating a long-horizon credit-assignment problem. We instead retain raw trajectories and defer curation until read time, when the current task is known. Given the retrieved traces and the new task, a memory curator synthesizes a compact, task-adaptive payload tailored to the immediate need. Because this payload is consumed on the same task, the curator can be trained directly from immediate task success, avoiding delayed utility signals and the need to artificially group related tasks. Across ALFWorld, WebShop, and $τ^2$-bench, our Just-in-Time Memory (JitMem) consistently outperforms no-memory agents as well as heuristic and learned write-time memory methods, improving over the strongest baseline by 16.2, 16.3, and 3.9 absolute success-rate points, respectively. Notably, even an untrained curator is already competitive with or surpasses these baselines, showing that task-adaptive read-time curation itself is a major source of the gain; training the curator further compounds the improvement.

# JitMem（Just-in-Time Memory）论文中文总结

## 1. 核心问题与研究动机

- **背景**：LLM 智能体越来越多地被要求连续求解一系列随时间展开的任务，而非孤立问题。从零开始处理每个任务会浪费智能体最宝贵的资源——自身过往经验，因此催生了"智能体记忆"研究。
- **现有范式的问题**：主流方法在**写入时（write time）**策展记忆——任务完成后立刻把轨迹蒸馏为固定产物（反思、洞见、工作流、可执行技能、推理策略等），推理时通过相似度检索使用。这带来两个根本代价：
  - **信息丢失是过早且不可逆的**：细节一旦被丢弃，后续依赖它的任务无法恢复。
  - **单一固定产物须服务多种未来查询**：同一条轨迹对不同任务可能包含不同的"教训"（如一次家务交互既可教状态转移模式，也可教物体放置策略），但写入时并不知道下游任务，无从取舍。
- **学习层面的困难**：写入时策展器的存储决策价值只有在未来相关查询到来时才显现，可能相隔许多任务，形成**长时程信用分配问题**；因此已有工作（如 SkillOS）不得不人为把相关任务分组以制造延迟信号。
- **核心主张**：把策展推迟到**读取时（read time）**，即"just in time"，此时当前任务已知。记忆库只被动存储原始轨迹，不做任何信息丢弃；检索后由策展器结合当前任务合成紧凑、任务自适应的记忆载荷。这一设计类比认知科学中"情节记忆是重构性的而非回放的"观点。
- **整体含义**：该工作把问题从"存什么"转向"何时、为哪个任务策展经验"，并因载荷在同一任务上被消费，把信用分配压缩为单步，无需任务分组脚手架。

## 2. 方法论

### 核心思想
分离**存储**与**策展**：写入时无损保留原始轨迹，读取时按当前任务条件化蒸馏。策展器是唯一可训练组件，执行器冻结。

### 系统组成与流程
四个组件：记忆库 `M`（存原始轨迹）、检索器 `R`、记忆策展器 `π_φ`、冻结的执行器 `π_L`。每个任务四步：

1. **Retrieve**：`ξ̂_t = R(x_t, M_t)`，从记忆库取 top-k 原始轨迹（用 BM25，仅对任务描述检索，不使用轨迹内容，轻量且与轨迹长度解耦；k=3）。
2. **Curate**：`p_t = π_φ(x_t, ξ̂_t)`，合成任务自适应载荷——识别最相关经验、抽取有效策略、给出针对当前任务的具体指引。
3. **Execute**：`(ξ_t, r_t) = π_L(x_t, p_t)`，冻结执行器在上下文中使用该载荷（而非直接消费原始轨迹）。
4. **Update**：`M_{t+1} = UPDATE(M_t, ξ_t, r_t)`，仅当 LLM-as-judge 判定任务成功时把轨迹追加进库。

- 关键细节：策展载荷 `p_t` 是**临时的，不存入记忆库**；只有执行产生的轨迹才可能入库。轨迹条目为 `ξ = (x, o_1, a_1, …, o_n, a_n)`，不做摘要、反思或技能抽象。
- 同一检索到的轨迹因当前任务不同而产生不同载荷，这是写入时方法无法提供的"任务自适应"属性。

### 训练（GRPO）
- 对每个采样训练任务，策展器生成 G 个候选载荷 `{p_t^(i)}`，冻结执行器分别尝试任务并返回原生任务奖励 `r_t^(i) ∈ [0,1]`（ALFWorld/τ²-bench 为二值成功，WebShop 为连续分数）。
- 组内优势：`Â_i = r_t^(i) − mean_j r_t^(j)`（按 Liu et al. 2025 省略标准差归一化）。
- 目标：`L_GRPO = −(1/G) Σ_i Â_i · log π_φ(p_t^(i) | x_t, ξ̂_t)`，无价值网络。
- **关键性质**：奖励是同一任务上载荷的直接函数，策展动作与奖励之间的时间间隔为零，信用分配即时，无需任务分组或延迟回报机制。
- **固定训练记忆库**：为让奖励只反映载荷质量而非可用轨迹的随机性，先用基础执行器（无策展器）在训练集跑一遍，用**真值成功标签**保留成功轨迹，构造固定训练库贯穿训练，保证稳定可复现。这带来轻微训练/测试分布偏移（测试库随策展器增强的轨迹增长）。
- 训练超参：策展器由 Qwen3-8B（关闭 thinking）初始化，GRPO 训练 100 步，学习率 1×10⁻⁶，batch size 32，group size 8；训练期间执行器为 Qwen3-8B（效率考虑）。

### 评估流程
- 默认测试记忆库从**空**开始（训练库不迁移），随任务求解在线增长，早期任务受益更少（自然冷启动效应）。
- 采用**批量流式协议**：同一批内任务共享同一记忆库状态，每批结束后更新，以提升评估效率。
- 任务成功由 benchmark 真值验证器判定；记忆更新策略用 LLM-as-judge，避免真值标签泄漏进记忆库。
- 由于任务顺序与批次组成会影响性能，报告多次不同随机顺序运行的平均值。

## 6. 主要结论与发现

- **读取时策展优于写入时策展**：JitMem 相比最强基线在 ALFWorld、WebShop、τ²-bench 分别提升 **16.2 / 16.3 / 3.9** 个绝对成功率百分点。
- **任务自适应的读取时策展本身就是主要增益来源**：即使未训练的策展器也已与写入时基线相当或更好。例如 WebShop 上 JitMem-gemini 达 61.0 SR，而 SkillOS 为 41.0（同为 Gemini-2.5-Pro 作策展器与执行器）；ALFWorld 上用 GPT-5.4 执行器时，JitMem-base（Qwen3-8B 策展器，79.3）胜过用 GPT-5.4 的 ReasoningBank（77.9）和 SkillOS-gpt（70.0）——说明增益来自策展时机而非策展模型强度。
- **RL 训练进一步叠加提升**：同基座模型下 JitMem 大幅超过 SkillOS（ALFWorld 77.4 vs 61.2；WebShop 32.8 vs 16.5 SR），且训练设置更简单（只用任务奖励，无需额外内容质量评判模型，也无需任务分组）。
- **策展器可跨执行器迁移**：用 Qwen3-8B 训练一次，迁移到 GPT-5.4 时距直接用 GPT-5.4 训练的策展器仅差 **1.4 SR**，说明学到的是可泛化的策展策略而非执行器特定模式。
- **上下文更紧凑、更高效**：JitMem 相比写入时方法减少输入 token **50.3%–56.3%**、执行步数 **28.4%–31.4%**；JitMem-base 仅比无记忆多 1.9K 输入 token（ReasoningBank 为 10.7K，SkillOS-base 为 13.4K）。
- **消融结论**：任务条件化、成功轨迹质量过滤、保留原始轨迹三者各自独立贡献；去掉检索轨迹后性能大幅下降（ALFWorld 最多 −14.8、WebShop −15.2 SR），证明 RL 增益确实来自"学会蒸馏检索到的经验"，而非单纯调用参数化知识；staged bank refresh 增益有限（最多 +2.8 SR），测试库预热几乎无影响。
- **定性发现**：同一过去经验对"把热土豆放进冰箱"和"把报纸放在沙发上"产生不同载荷（前者突出状态转移，后者突出放置策略）；RL 训练能诱导出环境特定的程序性语义（如"先移动到台灯，再用台灯检查碗"），这些未在提示中指定。

## 7. 局限与批判性分析

- **训练/测试记忆库分布偏移**：为保证训练奖励稳定，训练库由基础执行器的成功轨迹构成且固定不变；而测试库随策展器增强而在线演化，两者分布存在系统性差异。虽然 staged bank refresh 消融显示影响有限（≤2.8 SR），但这一近似并未被彻底消除。
- **τ²-bench 缺少训练侧实验**：该 benchmark 无标准训练划分，因此只能评估免训练变体，削弱了"学习式读取时策展"在对话式工具使用场景下的结论强度。JitMem 的核心训练主张主要依赖 ALFWorld 与 WebShop 两个域支撑。
- **依赖 LLM-as-judge 做记忆写入决策**：与使用真值成功标签相比，judge 可能引入假阳性/假阴性轨迹，长期在线运行时误差可能累积。论文用真值验证器评估性能、用 judge 管理记忆，二者不一致带来的偏差未被专门量化。
- **检索器较为朴素**：仅用 BM25 对任务描述检索，未探索基于轨迹语义、状态相似性或学习式检索的改进。若检索质量成为瓶颈，读取时策展的上限会受制约。
- **评估协议引入的顺序依赖**：批量流式协议使性能依赖任务顺序与批次组成，作者以多次随机顺序取平均缓解，但真实部署中的任务分布未必与 benchmark 一致，冷启动阶段的收益衰减也未被单独刻画。
- **策展器与执行器同源/异构的耦合**：跨执行器迁移虽表现良好，但策展器始终由 Qwen3-8B 初始化，是否依赖特定基座规模或家族仍有待验证；更大或更小的策展器模型未被系统比较。

## 8. 启示与未来方向

- **范式层面的贡献**：论文最核心的洞见是把"何时策展"本身当作设计变量。写入时策展把长时程信用分配强加给学习问题，读取时策展则将其压缩为单步决策，从而既避免了信息过早丢失，又绕开了任务分组等工程脚手架。这一"推迟到信息充分时再做不可逆决策"的原则，可能迁移到更广泛的智能体学习问题（如工具选择、上下文压缩、计划生成）。
- **可延展的研究点**：
  - 把检索器也纳入学习（端到端优化检索与策展的联合策略）；
  - 探索轨迹的层次化/多粒度索引，以支撑更精细的读取时条件化；
  - 将写入决策（是否入库、以何形式入库）与读取策展统一为一个学习目标；
  - 在更长时程、更多域的连续任务流上验证冷启动与分布偏移的影响；
  - 用真值验证器与 judge 的一致性分析，量化记忆库噪声的长期影响。
- **工程意义**：读取时策展在减少 50% 以上输入 token 与约 30% 执行步数的同时提升成功率，说明"存原始轨迹 + 按需蒸馏"在成本—效果权衡上具有实际部署价值，尤其适合上下文预算受限的长期运行智能体。

## 9. 总体评价

JitMem 针对智能体记忆的一个关键盲点——**策展时机**——给出了清晰、可复现且经过充分消融的解决方案。其贡献不只是性能提升，更在于重新形式化了问题：记忆策展是一个**任务条件化**的决策，而当前任务只有在读取时才可知。通过将存储与策展解耦、把策展器作为唯一可训练组件、并利用同任务即时奖励实现单步信用分配，论文在方法简洁性与实证强度之间取得了良好平衡。主要保留意见集中在 τ²-bench 训练侧缺失、训练/测试记忆库分布偏移，以及检索器与 judge 的朴素设计上；但这些问题多为可后续改进的边界，而非对核心主张的实质性反驳。
