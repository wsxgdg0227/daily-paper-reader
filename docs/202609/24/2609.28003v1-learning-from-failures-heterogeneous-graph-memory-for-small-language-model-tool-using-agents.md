## 摘要
中小型语言模型为工具使用智能体提供了具有成本效益的执行器，使其在本地和大规模部署中颇具吸引力。然而，在长时程和有状态环境中，它们常常产生结构性错误，如遗漏必需观察、过早写入、重复失败调用以及违反动作前置条件。这些错误可能导致错误的状态更新、策略违规以及代价高昂或不可逆的后果，从而使可靠的工具执行成为关键部署挑战。现有微调方法需要大量数据和计算，而扁平记忆可能检索到失败动作，却无法保留其因果上下文或安全条件。本文提出 FRESH，一种基于经验结构化异构图的失败感知检索框架，将历史成功与失败转化为工具使用智能体的结构化外部经验。通过显式建模任务、动作、错误、修复与执行条件之间的依赖关系，FRESH 帮助冻结语言模型复用可靠策略、避免重复失败，并在有状态工具交互中做出更安全的决策。在 $τ$-Bench 和 AppWorld 上使用多个开源模型进行的实验表明，与无记忆智能体和代表性基于记忆的基线相比，FRESH 持续提升任务成功率和工具使用可靠性。

## Abstract
Small and medium-sized language models offer cost-effective executors for tool-using agents, making them attractive for local and large-scale deployment. However, in long-horizon and stateful environments, they often make structural errors such as missing required observations, performing premature writes, repeating failed calls, and violating action preconditions. These errors can lead to incorrect state updates, policy violations, and costly or irreversible consequences, making reliable tool execution a critical deployment challenge. Existing fine-tuning approaches require substantial data and computation, while flat memory may retrieve failed actions without preserving their causal context or safety conditions. In this paper, we propose FRESH, a Failure-aware Retrieval framework over Experience-Structured Heterogeneous graphs, which transforms historical successes and failures into structured external experience for tool-using agents. By explicitly modeling the dependencies among tasks, actions, errors, repairs, and execution conditions, FRESH helps frozen language models reuse reliable strategies, avoid recurring failures, and make safer decisions in stateful tool interactions. Experiments on $τ$-Bench and AppWorld with multiple open-source models show that FRESH consistently improves task success and tool-use reliability over no-memory agents and representative memory-based baselines.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：中小型语言模型（SLM）作为工具调用智能体的执行器，推理与部署成本低，适合本地化、大规模服务；但现实任务往往需要多轮、有状态地与外部工具（搜索、数据库、API）交互，仅靠语言生成无法完成。
- **核心痛点**：SLM 在长时程、有状态环境中易犯**结构性错误**——遗漏必需观察（missing read）、过早写入（premature write）、重复失败调用（repeated call）、违反动作前置条件（precondition violation）。这些错误会造成数据库状态错误、策略违规，甚至不可逆后果。
- **现有方案不足**：
  - 微调需要大量数据与算力，且参数化知识难以随工具/策略变化而检查与更新；
  - 增加交互轮数只会让模型重复无效策略；
  - 扁平记忆（flat memory）或完整轨迹记忆虽保留历史内容，却未显式表达动作依赖、失败原因与写入前置条件，可能把**失败动作当作可复用示例检索出来**，或复制一个"曾经成功但当前条件不成立"的写入动作。
- **论文主张**：可靠的经验复用应回答"什么成功了、什么失败了、为什么失败、如何修复、在何种条件下安全"。为此提出 **FRESH**——在**经验结构化异构图**上的**失败感知检索**框架，在不修改语言模型参数的前提下，把历史成功与失败转化为可检查、可更新的外部执行支架。

## 2. 方法论

### 2.1 核心思想
- 将成功与失败轨迹组织为**带类型的有向异构图**，显式区分"已验证策略"与"不安全行为"；
- 用训练好的**异构图检索器（HG-Retriever）**在稀疏召回的候选子图上重排序，把检索结果压缩为四类操作指引（Do / Avoid / Check / Repair）；
- 在执行前用轻量**策略与前置条件门（Policy/Precondition Gate）**拦截高风险写入动作；
- 执行器语言模型**全程冻结**，仅检索器被训练。

### 2.2 失败感知经验图归纳
- 轨迹表示为 τᵢ = (xᵢ, aᵢ,₁, oᵢ,₁, …, aᵢ,Tᵢ, oᵢ,Tᵢ, Fᵢ)，Fᵢ 含任务奖励、状态/动作检查、工具错误、重复调用、终止状态等反馈。
- **经验挖掘器**：归一化工具名、参数、实体与观察；进行**动作级信用分配**——失败轨迹中的成功读动作仍保留为"已验证证据"，仅把失败写入标为负例。
- 对每个失败动作抽取三类知识：**错误（error）**、**缺失前置条件（precondition）**、**修复（repair）**。
- 图为 G = (V, E, τ_V, τ_E, X)：节点含 task / subtask / tool / action / observation / error / precondition / repair / reasoning_memory / successful_trajectory / failed_trajectory；关系含 `calls`、`requires`、`guards`、`verified_by`、`fails_because`、`fixed_by`、`supports`、`contains`、`leads_to`、`similar_to`、`conflicts_with` 等。
- 典型例子：过早取消预订的失败 → 保留 `GetBooking` 为已验证读；`CancelBooking` 经 `fails_because` 连到"资格未验证"错误节点；错误经 `fixed_by` 连到"读—检查—确认—写"的修复序列。

### 2.3 HG-Retriever 训练
- **查询构造**：qᵢ = f_q(xᵢ, hᵢ)，包含领域/意图线索、实体与槽位类型、可用工具、策略约束、近期错误信息。
- **稀疏召回**：按文本相关性、节点类型、历史效用取 Top-K₀ 节点，并扩展 H 跳类型化邻居，构成紧凑候选子图，避免对全图做 GNN 编码。
- **反馈驱动的监督信号**（无需人工标注）：正例 = 已验证动作、成功推理记忆、有效修复、支撑成功写入的前置条件；负例 = 失败动作、重复调用、策略违规、无关记忆、不安全模式。注意"退款前先检查资格"这类反思是正例，而原始过早退款动作是负例。
- **节点初始表示**：拼接文本嵌入、节点类型嵌入、历史成功/失败统计、查询匹配特征后线性投影。
- **关系感知消息传递**：对每种关系 r 使用独立变换矩阵，聚合 r 邻居信息并残差式更新节点表示（ℓ 层）。

### 2.4 测试时图条件化执行
- 图与检索器冻结，执行同样流程后取 Top-K 节点，归入四类：
  - **Do**：已验证动作/工具使用模式；
  - **Avoid**：失败动作、重复调用、不安全模式；
  - **Check**：必需观察、校验与策略条件；
  - **Repair**：修正、备选工具、替代执行路径。
- 在固定上下文预算下序列化为紧凑记忆 M_t（去除任务特定标识与无关观察），执行器据此生成候选动作：â_t ∼ π_θ(a | h_t, M_t, T)，θ 冻结。低风险读动作直接执行。
