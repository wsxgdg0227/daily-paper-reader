## 摘要
递归自我改进（RSI）在长时程任务中仍然困难，因为不断增长的历史记录会模糊任务状态，并导致技能调用错位。我们提出了Recuris，一种用于长时程智能体框架的递归经验-工作记忆架构，其中工作记忆跟踪任务进度并引导从经验记忆中选择技能，将技能使用扎根于当前需求而非完整历史。这种耦合还将执行转化为结构化证据，可将失败定位到特定的记忆组件。在各种任务中，一个固定的元智能体将这些证据转化为对技能记忆的局部化、经过验证门控的更新，从而重塑执行并产生新证据，形成有界的递归记忆演化循环。在四个长时程基准和十个模型上，Recuris在37个已完成的模型-基准组合中改善了35个的任务成功率，将前沿模型提升至SOTA级任务成功率：在tau-bench上，它为GPT-5.6 Sol增加了+17.8个百分点，为Claude Opus 5增加了+15.6个百分点，使Opus 5达到87.9%；在SkillFlow上，为Qwen3.6-27B/35B分别增加了+16.6/+13.5个百分点。随着交互时程增长，优势进一步扩大，在最长任务上达到+32.2个百分点，常见的长时程失败最多减少80%。这些结果将递归演化记忆定位为RSI的可扩展基础，使智能体能够持续将累积经验转化为日益有效的长时程行为。代码：https://github.com/Gen-Verse/Recuris

## Abstract
Recursive self-improvement (RSI) remains hard in long-horizon tasks, where growing histories obscure the task state and misalign skill invocation. We introduce Recuris, a recursive Experiential-Working Memory architecture for long-horizon agent harnesses, in which Working Memory tracks task progress and guides skill selection from Experiential Memory, grounding skill use in current needs rather than the full history. This coupling also turns execution into structured evidence that localizes failures to specific memory components. Across tasks, a fixed Meta-Agent turns that evidence into localized, validation-gated updates to Skill Memory that reshape execution and yield new evidence, forming a bounded recursive memory-evolution loop. Across four long-horizon benchmarks and ten models, Recuris improves task success in 35 of the 37 completed model-benchmark pairs, carrying frontier models to SOTA-level task success: on tau-bench it adds +17.8 points to GPT-5.6 Sol and +15.6 to Claude Opus 5, taking Opus 5 to 87.9%, and +16.6/+13.5 points on Qwen3.6-27B/35B on SkillFlow. The advantage widens as the interaction horizon grows, to +32.2 points on the longest tasks, and common long-horizon failures fall by up to 80%. These results position recursively evolving memory as a scalable foundation for RSI, enabling agents to continuously transform accumulated experience into increasingly effective long-horizon behavior. ## 1. 核心问题与研究动机

- 递归自改进（RSI）是智能体迈向长期自主性的关键目标，但在**长时程（long-horizon）任务**中难以实现。
- 主要障碍在于：
  - 随交互进行，完整历史不断增长，任务状态容易被噪声、已完成步骤和过期信息淹没，导致智能体丢失未完成目标；
  - 技能（skill）回忆与调用与当前执行需求错位：基于初始指令或完整历史的检索越来越不可靠；
  - 现有记忆型智能体框架虽然强调“存储经验”，却较少关注何时、如何调用经验，以及如何从失败中精准改进。
- 论文的核心主张是：**需要一种状态化的“工作记忆”来持续追踪已验证的进度和未解决目标，并作为经验记忆调用的接口**，从而支持可扩展、可定位、有边界的递归自我改进。

## 2. 方法论：Recuris 架构

### 2.1 核心思想

- 将 Working Memory（WM，工作记忆）与 Experiential Memory（EM，经验记忆）耦合：
  - WM 维护一个**被验证过的任务状态**（每个目标的状态、证据、阻塞项），跟踪已完成与未完成内容；
  - 该状态在具体执行事件（如草拟状态更改的调用或回合边界）驱动下，从 EM 中选择与当前需求匹配的技能；
  - 执行反馈（工具返回结果）经 checker 验证后才更新 WM，形成闭环：  
    `Task State → Skill Selection → Execution Feedback → Updated Task State`。

- 这一耦合使执行过程能输出**结构化轨迹**，记录每一步的状态、检索到的技能、动作、观察、状态提案与 checker 决策，从而将失败归因到具体的记忆组件，为记忆演化提供精细证据。

### 2.2 记忆组件与公式

- 记忆被建模为四元组：  
  `M_k = (E_k, W_k, ρ_k, C_k)`
  - `E_k`：可复用的技能记忆；
  - `W_k`：工作记忆规范，定义状态模式与更新规则；
  - `ρ_k`：技能调用策略，决定触发时机与检索键；
  - `C_k`：用于验证状态更新的检查器集合。
- 任务内执行（within-task）：
  - 状态 `w_t` 在有向执行事件下通过策略 `ρ_k` 检索技能子集 `E_t`；
  - LLM 在给定 `(x, h_t, w_t, E_t)` 下生成动作 `a_t`，环境返回 `o_t`；
  - 状态更新由 `U_Wk` 提出，`C_k` 检查，固定内核 `K` 仅提交由观察支持的变化：  
    `w_{t+1} = K(w_t, Proposed_w_{t+1}, checker_decisions)`。
- 任务间演化（cross-task）：
  - 固定元智能体读取失败任务的结构化轨迹 `Γ_k`，将诊断出的每个失败归因到组件 `{E, W, ρ, C}`；
  - 针对被牵涉组件做局部修补（component-specific patching），未牵涉组件保持不变；
  - 通过固定验证门控 `G_fixed`：候选记忆必须修复源任务且不使 held-out 开发集发生回归，才被接纳；
  - 被接纳的记忆改变后续行为，产生新证据，从而构成**有界递归循环**：  
    `M_k → Γ_k → D_k → M+_k → G_fixed → M_{k+1} → ...`。

### 2.3 关键技术细节

- **状态落地的技能调用（state-grounded invocation）**：
  - Call-time invocation：在起草状态更改工具调用时触发，不执行原调用，而是先注入对应技能；
  - Boundary invocation：在回合边界（如首回合）按状态谓词注入技能。
- **证据落地的状态更新**：目标从 pending 到 done 必须由 checker 基于工具/环境结果确认，模型自述成功不算完成证据。
- **两类失败定位与修复**：结构化轨迹使归因可作用于“缺少/损坏的技能”“状态规范误用”“调用时机错误”或“验证器误判”，实现组分级修复。
- **测试时适应模式**：针对孤立任务，在多次尝试间只利用当前任务的失败轨迹和一位验证位，重写任务专用技能；无 verifier 敏感信息传入。

- 在 37 个已完成的模型-基准对中，Recuris 在 **35 个**上提升任务成功率。

- **执行缺口而非理解缺口**：所有变体的 read-action recall 都极高，差距集中在 required-write recall；Recuris 通过状态驱动调用让智能体实际发出正确的写入动作。
- **工作记忆比经验记忆单独加入更关键**：仅加 EM 约提升 +2 点，而加入已认证 WM 后提升约 +24 点；EM 带来的价值取决于是否有机制判断“何时需要技能”。
- **结构化轨迹显著改善故障定位**：组件注入故障的回溯定位准确率从“仅看结果”的 13.0%、“原始轨迹”的 37.0% 提升到结构化轨迹的 64.8%；对调用策略这类“非事件型”故障，原始轨迹完全无法定位。
- **递归演化稳定可迭代**：演化后记忆在 86 个未见任务上获得 +9.0 至 +17.4 点的已决增益；接受的门控不会显著破坏已有能力（锚点任务破坏率低于重跑噪声）。
- **演化记忆可跨模型使用**：一个由中型模型演化出的记忆包可回馈给前沿大模型并获得高于自身基线的最好成绩；但跨模型/跨任务迁移的幅度取决于目标模型是否仍有同类型失败空间。
- **记忆控制层是冻结模型的可训练面**：所有改进都不改变基座权重，而是通过外部、有界、门控的记忆演化实现。

## 7. 优点

- **概念创新清晰**：将“工作记忆”作为经验记忆调用界面的做法，将长时程问题从“检索更多历史”转变为“追踪当前需要什么”。
- **组件级可诊断性**：结构化轨迹同时记录状态、调用决策、动作与验证结果，对应不同类型失败提供了可操作归因，突破只依赖单一成功/失败信号的自改进局限。
- **递归被限定在外部记忆控制层**：基座 LLM 与外部改进过程完全固定，增强了安全性、可解释性与可复现性。
- **验证门控与 held-out 开发集**：候选修补须通过修复源任务且不回归锚点任务的门控，避免盲目接受；同时报告门控自身噪声，提供重要谨慎意识。

## 8. 不足与局限性

- **验证器（checker/verifier）依赖较重**：Recuris 的“状态更新必须由 checker 基于观察证据确认”依赖可用且可靠的验证信号。τ2-Bench 的用户模拟器、SkillFlow 的二进制 verifier 都提供了较为干净的结果判定；在真实开放环境中，验证器常常缺失、昂贵或本身不可信，这会削弱 WM 更新闭环和记忆演化的根基。
- **对“哪些事件值得更新状态”依赖人工/元智能体设计**：状态提案 `U_Wk`、状态模式和更新规则都是由外部元智能体以 prompt 形式书写；论文没有对这些 prompt 的结构、稳健性或跨任务泛化做深入讨论。若任务类型变化过大，状态模式的适配仍需大量人工干预。
- **递归改进的“自举”程度有限**：虽然论文称“递归自改进”，但实际的改进对象是外部记忆与控制策略，而非模型本身；元智能体的诊断和修补能力仍依赖固定的基础 LLM。论文对此有如实说明，但若读者期望看到“模型通过自身输出持续提升自身能力”的自举式递归，其范围仍较窄。
- **故障定位实验规模有限且部分依赖人工定义**：结构化轨迹提升定位召回的结果来自注入式故障模拟（每条件 54 个判定），且故障类型由作者预设（如技能缺失、状态误用等），不代表自然演化过程中真实失败类型的分布。
- **Terminal-Bench 测试时适应的证据较弱**：作者本人也在表 8 中承认最终正向增量与 retry-only 存在混淆，逐次尝试的边际增益置信区间包含零；这使“测试时记忆学习优于多试几次”这一结论的说服力打折。
- **跨任务迁移评估存在选择偏差风险**：在 SkillFlow 上从同一任务族内选择已知可用的记忆模板用于测试时门控，相当于对演化记忆做了 in-sample 挑选；论文对此有声明，但用户仍应谨慎理解“迁移增益”的含金量。
- **未提供充足的计算资源与运行成本明细**：论文有意强调“不更新权重”，却没有报告元智能体运行次数、token 总量、API 调用次数或 GPU/CPU 资源；对外部记忆层递归演化引入的隐性计算开销缺少总账。
- **对记忆演化何时终止、如何防止记忆库无限膨胀讨论不足**：虽然设置了验证门控与锚点任务，但随着任务数量增加，候选记忆、技能库和状态模式规模如何管理，仍然缺乏可扩展性讨论。
- **模型命名与时间戳的可证伪性存疑**：文中出现虚构/未知模型名（GPT-5.6 Sol、Claude Opus 5、Qwen3.6 系列）与 2026 年日期，这种“未来设定”使外部读者难以独立复现或核实模型版本差异带来的影响。

## 9. 总结与个人评价

总体而言，Recuris 的核心贡献并不在于提出一个新的模型或新的推理算法，而在于**重新理解 agent 的长时程失败来源**：失败往往不是“不知道做什么”，而是“不知道当前做到哪了、还需要什么”，也就是执行状态和技能调用时机的脱节。该论文通过引入由证据验证的工作记忆作为任务状态的可信载体，并将经验记忆的调用策略从“模型自选”改为“状态驱动”，从而把“何时调用技能”这一模糊的语义问题转化为具体的状态谓词匹配问题——这一抽象是优雅且实用的。

同时，论文的实验设计在记忆类 agent 研究中属于较高水准：跨模型、跨任务、跨组件的多维验证，对门控噪声与重复运行漂移的敏感性分析，以及对执行缺口（action gap）而非理解缺口（understanding gap）的归因，都体现出较强的严谨意识。它明确区分了“记忆带来的增益”与“控制机制本身带来的增益”，并通过“M0 净贡献为零”的对照消除了一批混淆因素。

不过，该工作离“通用递归自改进智能体”仍有一段距离：它依赖相对可靠的外部验证信号，依赖元智能体对状态规范和检查器的设计，记忆的迁移与适应也主要集中在同族任务上。真正开放的、无 verifier 的、充满噪声与长尾状态的真实世界任务，仍未被完全覆盖。此外，论文对计算资源和记忆演化的横向规模（大量任务、多轮迭代）缺少成本账目，限制了其实用性判断。
