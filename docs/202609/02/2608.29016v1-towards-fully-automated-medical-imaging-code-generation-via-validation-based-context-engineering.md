## 摘要
大语言模型（LLMs）在小规模和常规应用开发的程序生成方面展现出巨大潜力；然而，在应用于医学影像处理等复杂的领域特定任务时，它们仍然存在局限性。通用模型缺乏明确的领域知识和确保正确性的稳健验证机制，通常需要大量人工干预才能生成可靠的处理流程。为解决这些局限，我们提出了AutoMedImg，一个用于全自动医学影像处理代码生成的多智能体框架。AutoMedImg在两个阶段中编排专门的智能体：规划阶段执行数据集分析和架构设计，并进行语义与形式化验证；编码阶段并行生成模块，并进行静态检查、执行测试和组装验证。这种多阶段验证减轻了生成过程中的错误传播，同时，结合特定领域知识库、共享内存和验证反馈的综合自动上下文工程，无需手动提示即可实现上下文构建自动化。跨项目自适应流水线综合机制进一步积累已验证的流水线，并根据项目相似性为新任务检索经过验证的组件，通过跨项目学习提高生成效率。在六个多样且成熟的医学影像数据集上，使用五种骨干LLM进行的广泛评估表明，AutoMedImg实现了零人工干预，分割任务的Dice分数高达0.90，分类任务准确率达99%。

## Abstract
Large language models (LLMs) have demonstrated considerable promise in program generation for small-scale and conventional application development; however, they remain limited when applied to complex, domain-specific tasks such as medical image processing. General-purpose models lack explicit domain knowledge and robust validation mechanisms to ensure correctness, often requiring substantial human intervention to produce reliable processing pipelines. To address these limitations, we propose AutoMedImg, a multi-agent framework for fully automated medical image processing code generation. AutoMedImg orchestrates specialised agents across two phases: a Planning Phase that performs dataset analysis and architecture design with semantic and formal verification, and a Coding Phase that generates modules in parallel with static checking, execution testing, and assembly validation. This multi-stage validation mitigates error propagation throughout generation, while comprehensive auto-context engineering combining domain-specific knowledge bases, shared memory, and validation feedback automates context construction without manual prompting. A cross-project adaptive pipeline synthesis mechanism further accumulates validated pipelines and retrieves proven components for new tasks based on project similarity, enhancing generation efficiency through cross-project learning. Extensive evaluation across six diverse and well-established medical imaging datasets with five backbone LLMs demonstrates that AutoMedImg achieves zero human intervention, with Dice scores of up to 0.90 for segmentation tasks and 99% accuracy for classification.

- **具体困境**：医学图像处理是上述问题的典型代表——医学图像具备多模态（CT、MRI）、2D/3D 体数据、复杂强度范围、专用文件格式（DICOM、NIfTI）等特性；生成过程中的预处理幻觉或架构误选不可被接受（有临床可靠性要求）；完整流程涉及数据加载、预处理、训练、推理等多个相互依赖的阶段；不同项目之间存在大量可迁移模式，但普通 LLM 不具备跨项目记忆。
- **现有工作的不足**：通用代码生成工具（如 Copilot、Cursor、Antigravity）缺少领域知识和系统化验证，在医学图像任务上仍需大量人工干预；多智能体框架（如 ChatDev、MetaGPT、AgentCoder）主要局限于函数/模块级生成；AutoML 类方法（如 AutoML-Agent、M³Builder）虽能自动化流程，但对新数据集需要人工提供骨架、数据集卡或模板，无法做到真正的从零全面自动化；医学影像自动化方法（如 NAS、nnU-Net、MedSAM）只覆盖个别管线段，无法生成完整流水线。
- **研究目标**：提出 **AutoMedImg**，一个能在医学图像处理领域实现**从任意给定数据集中完全自动生成、验证并交付完整代码管线**的多智能体框架，实现“零人工干预”且保持有竞争力的模型性能。

## 2. 方法论与核心技术思想

AutoMedImg 将代码生成组织为**两阶段多智能体流水线**，并通过“验证驱动的上下文工程”在环节之间传递正确信息、阻止错误传播。

### 2.1 总体流程概述：两阶段架构

1. **规划阶段（Planning Phase）**
   - 由 Planning Router 调度 Dataset Analyser 子代理对给定数据集进行探索性分析（模态、尺寸、spacing、强度范围、病例数等元数据）；
   - 输出通过验证后，Architect 子代理基于已验证的数据集属性合成完整管线设计（网络结构、预处理、训练、推理）；
   - 架构设计接受**规划语义验证**：先做上下文级检查（架构与数据集特征是否兼容、是否符合医学影像惯例、模块化与IEC 62304规范），再将 CSP# 规格交给 PAT 工具做**形式化验证**（检查死锁、竞态、活跃性/安全性时序性质）；
   - 只有通过全部验证的架构设计才进入编码阶段，存入共享内存（shared memory）。

2. **编码阶段（Coding Phase）**
   - Coding Router 按架构设计将模块拆分为 Dataset/NN/Training/Inference 等若干子模块，由多个 Coder 子代理**并行生成**；
   - Tester Agent 依次执行**三种验证**：
     - **静态检查**：使用 Pylint 检查语法与依赖有效性，使用 Radon 计算循环复杂度与可维护性指数，阈值设定为 80；
     - **执行验证**：Tester 利用 Pytest 运行 30~40 个由 LLM 生成的测试用例，覆盖假设测试（输入约束）、功能测试（计算正确性）和集成测试（接口兼容性）；
     - **组装验证**：把通过单模块验证的代码装配为端到端脚本后，再进行系统级验证，捕获模块间键名/维度/流程不匹配等问题；
   - 验证失败时，诊断反馈被回灌至编码代理，形成修复循环；通过验证的全流程若性能达标，则写入“自适应管线合成知识库”供后续项目复用。

### 2.2 验证驱动的上下文工程（核心亮点）

- 上下文定义为 `C_Ai = <Pi, M, K_D, K_Ada, Hi, Vi>`，包括任务提示、共享内存、领域知识库、自适应合成知识库、历史执行记录、验证反馈；
- 提出**上下文演进机制**：代理输出先由验证函数评估，只有通过的结果才写入共享内存并传给下一代理；失败则产生诊断反馈并让当前代理基于更丰富的上下文重试。该机制保证上下文由验证结果动态填充，而非靠用户提示词灌输。
- 领域知识被建成**知识图谱**（使用 Cognee 框架），按代理角色配置：Dataset Analyser 使用 nnU-Net 数据集规范知识库；Architect 使用 Grand Challenge 中领先架构模式库及 CSP# 建模技能；Coder 使用 MONAI API 官方文档；Verification/Tester 使用 ISO/IEC 25023、IEC 62304 标准与测试模式库等。

### 2.3 跨项目自适应管线合成

- 新的医学图像处理任务首先按照**硬约束**（模态、任务类型必须精确匹配）和**软约束**（维度、架构特性等按相似程度）在自适应合成知识库中检索相似历史项目；
- 若检索到相似项目，代理将把已验证的组件复制并依据特征差异（类别数、图像尺寸、预处理等）进行适配；如果没有相似项目则从头生成；
- 检索到的方案仍需经过主流程中的所有验证，以保证适配后的正确性——该机制避免了“零起点生成”的低效，同时不会因复用不正确组件而降低质量。

## 6. 主要结论与发现

- **现有工具无法独立完成医学影像代码生成**——所有 IDE 工具和基座 LLM 在六个任务上至少需要 1–17 次人工干预；出错根因多为缺乏领域知识、无法自主选择正确架构/预处理和无法自主修复执行失败；
- **开源的 GPT-oss 甚至出现 0.0067 Dice（FLARE22）的近乎完全失效**，因错误使用普通 Resize 破坏体素物理间隔而不自知——这直接证明了“仅能生成跑得起来的代码”远不能满足医学影像域的要求；
- **AutoMedImg 实现零人类干预**（所有版本在所有数据集上 HI=0），且在多数任务上取得最高的 Dice/accuracy，分割任务最高约 0.90，分类任务最高约 0.99，与完全人工参与的管线相当甚至更好；
- **验证机制是最关键的自动化保障**：在执行测试、规划验证、组装验证被移除时，人工干预分别增加 3.50、0.57 与 2.50 次，证明“只有执行反馈驱动的系统修正”才能实现真正的自治；
- **领域知识库对性能影响最大**：将其移除造成平均 13.7% 的性能衰减，说明合理架构选择强烈依赖于内置医学知识，而非单纯的 LLM 编码能力；
- **跨项目复用（自适应合成）非常重要**：移除后性能降低 8.4%，生成时间增加超过 37 分钟，证明跨项目知识积累对生成效率和质量的提升显著；
- **多智能体架构不可缺少**：替换为单智能体平均性能下降 10.2%，额外引入 1.33 次人工干预，主因是“自验证偏倚”、上下文超限压缩以及无法并行执行。

- **问题定义准确且有真实价值**：抓住 LLM 自动生成 “从零完成的完整医学影像流程” 这一尚未被现有工作解决的关键空白，目标明确、应用场景具体且存在客观评估指标。

- **跨项目知识库设计与隐私/数据泄漏控制考虑严谨**：要求每个新项目只能引用“历史上已通过验证的管线”，并从已处理数据集中获取组件，检索策略明确分为硬约束匹配与软约束匹配，机制清晰可复用；
- **消融设计覆盖度高、粒度细**：论文明确区分了规划阶段、编码阶段、记忆/知识组件和系统架构等不同层面的各自贡献，有助于后续研究者定位所需组件。
- **通用性潜力明确说明**：虽然框架聚焦医学影像领域，但其上下文传播、验证网关、共享记忆等核心架构可以在其他需要“数据集分析→架构设计→编码→验证”的自动管线构建场景中沿用。

## 8. 不足与局限性

- **领域限定**：论文的核心设计（知识图谱、验证语义、CSP# 模板等）只针对医学图像分割与分类等成像任务，没有提供将其扩展到自然语言/通用软件工程等任务的实际证据，“框架域无关”虽在文本中进行了论证但缺乏实验；
- **成本开销与实时性并未详测**：生成一条完整流程需 20–40 美元且平均32分钟/次（若每次生成需要多轮即更高），若要引入开发过程中的反复探索可能进一步放大 API 依赖，论文未系统评估不同骨干模型的价格/延迟差异、输入输出量增长等问题；
- **无法保证“真实临床/生产环境”可部署性**：Dice/Accuracy 与数据科学质量不直接等价于医疗软件合规性，尽管使用了 IEC 62304 等标准规约部分语义，论文并未做真实临床落地、多中心数据迁移、伦理与监管评估；
- **Pass@3 与“取最优”评价规则可能夸大稳定性**：以最佳实验估计系统的稳定水平存在偏差，未报告方差、置信区间或重试次数变化带来的性能分布；
- **验证维度无法捕获所有“错误类型”**：测试用例仅由 LLM 自己生成，缺乏独立第三方测试基准验证语义

……正确性，以及解剖结构、体素间距等医学语义是否符合临床先验；这些错误可能无法被当前验证集合暴露，仍需人工抽查兜底。

- **对测试质量的自我依赖**：Pytest 测试用例本身由 LLM “自产自测”，尽管有静态与集成验证作为辅助，但若同一骨干模型在“实现代码”和“生成测试”上存在一致的系统性盲区（如对某种预处理操作的理解有误），执行测试环节将不易察觉，形成同源验证盲区。
- **知识库构建与维护的外部依赖**：领域知识图谱、MONAI 文档、Grand Challenge 领先方案等均需外部专家与工程人员预先整理和持续更新；若目标领域过新或相关文档不足，知识库可能失效，AutoMedImg 也会随之退化为普通多智能体框架。
- **跨中心与数据异质性泛化不足**：评测数据集虽覆盖多模态与多难度，但均为同一采集标准下的公开基准，缺少对数据分布漂移、中心效应、标注噪声和罕见病变的测试，掩盖了真实医学场景中常出现的“训练时分布与部署时分布不一致”问题。
- **人工干预（HI）的粒度较粗**：HI=0 只说明不需要“外部纠正性交互”，但未记录代理内部重试次数、验证失败的类型分布、各阶段调用 Token 成本等，难以直观区分“一次通过”与“尝试多次最终收敛”之间的质量差异。
- **与临床合规/监管的衔接仍属模拟**：论文使用 IEC 62304、ISO/IEC 25023 作为验证语义的参照，但并未产出软件需求规格、设计描述、验证与确认报告等合规章件；形式化验证与静态分析可作为质量佐证，但与实际临床软件上市审批所需的证据链仍有明显差距。

## 9. 总结与总评

AutoMedImg 是一篇针对“LLM 自主完成医学图像领域从数据到完整代码管线”问题的系统性方案论文，其核心贡献不在于提出某个更强的医学图像模型，而在于构造了一套以验证为核心的自动化工程框架：

- **在自动化代码生成领域**，它明确区分了“能生成单个函数”与“能交付整个可复现流程”之间的差距，用多级验证和跨项目知识解决了多层级的错误传播；
- **在医学图像领域**，它不使用 NAS 式的结构搜索或固定 nnU-Net 模板，而是通过对数据集特性的自动理解、知识库驱动的架构决策与端到端执行反馈，实现对不同任务的完整自适应；
- **在方法可信度上**，其消融实验不仅验证了各个模块的收益，还量化了多智能体架构与单智能体、基线 LLM 之间的性能差距，证明了“验证墙”和“角色隔离”的本质价值。

当然，本文的通用性主张仍需在更多领域、更多骨干模型与真实临床协作场景中进一步验证，且运行成本与测试自生成问题也制约着直接大规模落地。但就现状而言，AutoMedImg 为该研究子方向提供了堪称“完整度最高的参考实现”：研究者既可借鉴其验证网关设计思路来增强现有开发框架，也可按需抽取其中某项组件（如规划语义验证或自适应知识库）嵌入自建系统。它在“如何让大模型从回答问题到安全地补全复杂任务”这一重要演进而非模型的整体能力上迈出了扎实的一步。
