## 摘要
自我进化智能体通过优化其“装备”（提示、技能、工具和执行逻辑）并基于环境反馈来推进自主性。然而，这一范式受到三个挑战的阻碍：信用分配失败，即最终的成败反馈使得哪个步骤导致错误变得模糊；捷径学习，即智能体记忆任务特定模式而非获得泛化能力；以及灾难性遗忘，即无保护的更新会降低先前获得的能力。本文中，我们提出了HarnessEvolve，一个从参考轨迹中学习以实现可靠智能体自我进化的自我进化框架。HarnessEvolve将执行智能体与进化流程解耦，将执行、评估、优化和门控分配给独立的智能体模块，从而实现通用且稳定的装备改进。具体而言，HarnessEvolve通过生成参考轨迹（在给定真实答案时产生的执行路径）并将失败执行与参考轨迹对齐以提取错误信号，从而克服信用分配失败；这些错误信号被聚类以揭示系统性的失败模式。为防止捷径学习和灾难性遗忘，候选装备更新必须通过两道门控：质量门控，用于过滤数据泄漏和提示膨胀；性能门控，仅当更新在当前批次上有所改进且不降低近期批次性能时才接受该更新，并在保留集上进行期末验证以选择表现最佳的已接受智能体快照。我们在涵盖开放域和企业场景的多个基准上进行了广泛实验，使用了不同的模型和智能体框架。结果表明，HarnessEvolve在所有基准和设置中持续优于最先进的基线，证实了其跨任务领域的可靠性。

## Abstract
Self-evolving agents advance toward autonomy by optimizing their harness---prompts, skills, tools, and execution logic---based on environmental feedback. This paradigm, however, is hampered by three challenges: \textit{credit assignment failure}, where terminal success/failure feedback makes it ambiguous which step caused the error; \textit{shortcut learning}, where agents memorize task-specific patterns rather than acquire generalizable capabilities; and \textit{catastrophic forgetting}, where unguarded updates degrade previously acquired competence. In this paper, we introduce HarnessEvolve, a self-evolving framework that learns from reference trajectories to achieve reliable agent self-evolution. HarnessEvolve decouples the execution agent from the evolutionary pipeline, assigning execution, evaluation, optimization, and gating to independent agent modules, enabling generalizable and stable harness improvements. Specifically, HarnessEvolve overcomes credit assignment failure by generating reference trajectories (execution paths produced when given the ground-truth answers) and aligning failed executions against them to extract error signals, which are clustered to reveal systematic failure patterns. To prevent shortcut learning and catastrophic forgetting, candidate harness updates must pass two gates: a quality gate that filters data leakage and prompt bloat, and a performance gate that accepts each update if it improves on the current batch without degrading recent batches, with epoch-end validation on a held-out set selecting the best-performing accepted agent snapshot. We conduct extensive experiments on several benchmarks spanning open-domain and enterprise scenarios, using different models and agent frameworks. Results demonstrate that HarnessEvolve consistently outperforms state-of-the-art baselines across all benchmarks and settings, confirming reliability across task domains.

## 1. 论文的核心问题与整体含义

自进化智能体通过环境反馈来持续优化自身的“harness”——即提示词、技能、工具和执行逻辑——以降低对人类先验知识的依赖。但该范式目前存在三个阻碍可靠进化的关键问题：

- **信用分配失败**：长程任务中智能体往往只在终点收到二进制成功/失败信号，无法判断失败究竟源于哪一步；后续错误又常是早期错误的连锁反应，因此基于整条轨迹反思容易定位错根因。
- **捷径学习**：智能体为了提升当前训练集上的得分，可能将具体题目答案写入 harness，或注入大量任务相关的上下文示例，造成数据泄漏和提示膨胀，虚增训练精度但不带来真实泛化能力。
- **灾难性遗忘**：每个更新只基于当前一小批轨迹，可能与先前已获得的能力冲突，在多次迭代中逐步退化已有技能。

论文主张单纯改进“迭代式提示优化”不足以解决上述问题，需要系统级的架构改变，因此提出 **HarnessEvolve**：将执行智能体与进化流水线解耦，通过参考轨迹、错误聚类、质量门和性能门共同实现可靠、持续、可审计的自我进化。

## 2. 论文提出的方法论

### 核心思想

HarnessEvolve 将智能体系统拆分为四个独立模块：执行智能体、评估智能体、优化智能体和门控智能体。

- 执行与优化分离：执行智能体不能直接修改自身；
- 所有候选更新必须先通过“质量门”和“性能门”双重检查；
- 利用“给定真实答案时生成的参考轨迹”来进行细粒度根因定位。

### 关键技术细节

1. **参考轨迹生成**
   - 优化开始前，对每个训练问题 `qi`，将问题和真实答案一同交给执行智能体尝试运行，最多尝试 `Tatt=5` 次。
   - 评估智能体验证生成的轨迹是“真实的执行路径”，即智能体确实调用了工具、处理中间结果，而非直接输出已知答案。
   - 通过验证的参考轨迹存入全局缓存 `C`，无法生成参考轨迹的任务则退化为单轨迹分析。

2. **评估模块**
   - 判断当前批次中执行智能体输出的最终答案是否与 ground-truth 一致，收集失败轨迹集合 `Fj`；
   - 同时负责验证参考轨迹的合理性，防止“带答案生成”导致的捷径式假轨迹。

3. **优化模块**
   - **轨迹比较**：将失败轨迹 `τ⁻` 与参考轨迹 `τ⁺` 对齐，找出第一个动作分叉点 `t*`，认为这是根因而非后续连锁错误；输出结构化错误信号 `Fi=(si, mi, hi)`，分别表示严重度、错误原因和修复提示。
   - **错误聚类**：按错误原因 `mi` 聚类，而不是按文本相似度；优先处理根因而非下游症状；保留单例簇以避免罕见关键错误被大簇吞没。
   - **候选生成**：根据聚类得到的系统化错误模式，对 harness 中的提示、技能、工具描述、脚本或执行逻辑提出定向修改，生成候选更新集合 `Δharness`。

4. **门控模块**
   - **质量门**：
     - 用 LLM-as-judge 判断候选更新是否直接“泄漏”了失败问题和答案，得分超过阈值 `η_leak=0.8` 则拒绝；
     - 统计新增注入的上下文示例数量，超过 `η_blo=5` 则拒绝；
     - 被拒绝的更新会带拒绝原因返回优化智能体修改，最多重试 `Trev=3` 次，否则放弃。
   - **性能门**：
     - 候选智能体必须在当前批次 `Bj` 上比旧版本精度提升至少 `δ=0.0`；
     - 同时在最近 `R=2` 个批次上的精度下降不能超过容忍度 `ϵ=0.025`；
     - 若满足则被接受并加入快照池 `V`，随即成为新的当前智能体；若连续拒绝次数达到 `Pbatch=10`，提前结束当前 epoch。
     - 接受条件的核心公式为：
       `Acc(Acandidate, Bj) - Acc(Acurrent, Bj) ≥ δ`
       且
       `max over recent batches l [Acc(Acurrent, Bl) - Acc(Acandidate, Bl)] ≤ ϵ`

5. **Epoch 末验证与早停**
   - 每个 epoch 结束后，从快照池 `V` 中选出在验证集 `Tval` 上表现最好的智能体作为当前和最优质模型；
   - 最多运行 `E=20` 个 epoch；若验证精度连续 `Pep=5` 个 epoch 无提升则提前停止。

6. **优化范围**
   - 不像 SkillOpt 只优化 `skill.md`，HarnessEvolve 可同时修改技能描述、Python 脚本、系统提示、工具参数说明以及执行逻辑代码，即完整 harness。

## 4. 论文的主要贡献与可能引发的争议

### 贡献点

1. 明确指出现有“迭代式提示优化”范式的三大通病——信用分配失败、捷径学习、灾难性遗忘，并逐一给出对应机制（参考轨迹比较、质量门、性能门+快照池），问题与方法之间有清晰的一一映射。
2. 提出“执行与进化分离”的架构：执行智能体无权修改自身，所有变更必须由评估与门控模块审查后才能落地。这为自进化系统的可靠性、可审计性提供了工程范式，比单纯改进优化算法走得更远。
3. 将优化对象从“提示词/技能文档”扩展到脚本、系统提示、工具描述与执行逻辑的完整 harness，实验显示修改确实分布在多个组件上，而非仅文本层。
4. 首次在华为真实企业级云核心网/无线网数据集上做自进化智能体评测，并验证优化所得技能的跨框架迁移性，具有较强的工业落地参考价值。

### 可能引发的争议

- **“参考轨迹”是否变相依赖金标准**：优化过程中每个训练问题都要结合 ground-truth 答案生成参考轨迹。虽然实验剥离了“直接写答案”的捷径，但在监督信号的使用强度上，HarnessEvolve 比纯强化/反思式方法吃了更多“标签红利”。论文称这是“用真实答案做根因定位”，但批评者会认为这相当于在优化阶段引入了测试时才能获得的 oracle 信息，其与下游“无标签部署”之间的差距需要更严谨的论证。
- **门控指标的同源性问题**：质量门使用 LLM-as-judge 判断泄漏，性能门使用同一评估智能体打分，若评估智能体存在系统性偏差，门控可能共同放大偏差而非校正偏差。
- “早期分叉点即根因”的假设：轨迹比较假设第一个动作分叉是错误根源，但对某些多步累积型错误（每一步都微偏，最后叠加成大错）并不成立，此时首分叉点反而不是真正根因。

## 5. 局限性与未来方向

论文自身承认或隐含的局限包括：

1. 进化成本较高：每个候选更新都要经历参考轨迹生成、双重门控、历史批次回测，且被拒绝的更新最多重试 3 次。论文未给出完整的时间/算力开销对比，这可能是工业化采纳的主要障碍。
2. 对批量划分的敏感性：性能门依赖于批次内精度与最近 R 个批次的回测，批次大小、批次分布的改变可能影响更新接受率与进化稳定性。
3. 灾难性遗忘的缓解依赖“近期批次回测+快照池回溯”，本质是一种保守策略而非真正克服遗忘；长期多次迭代后的能力上界是否会因保守而受限仍待观察。
4. 单实例错误聚类簇的处理略显粗糙——论文提及保留单例簇，但未说明数量庞大的单例簇如何计算优化优先级。

未来方向可能包括：将参考轨迹中的金标准信号替换为自生成置信信号；引入在线流式批次以摆脱离线批次依赖；将质量门升级为“行为验证”而非“文本泄漏检测”；以及在更多开源数据集上补齐完整的消融。

## 6. 总结性评价

总体而言，这是一篇系统工程味道很重的自进化智能体论文。它真正的增量不在“更好的反思提示词”，而在“一套可以约束自进化过程可靠性的系统架构”：把执行与优化解耦、用参考轨迹做细粒度信用分配、用双重门控抑制捷径与遗忘、用快照池保证可回退。实验设计与工业数据集选择都较为扎实，主要结论可信。

对读者而言，最有借鉴意义的三点是：其一，自进化系统的瓶颈往往不在“生成修改”而在“判断修改是否真的更好”，门控机制比优化算法更决定成败；其二，用带答案的参考轨迹对齐来做信用分配，是一种简单且有效的根因定位手段，代价是需要小心处理标签依赖；其三，跨框架迁移实验表明，真正学到“技能”而非“框架捷径”的进化才具备持久价值。论文在消融完整性与理论深度上仍有提升空间，但其提出的问题框架——进化不仅是优化 harness，更是构建可信的进化闭环——值得后续研究认真对待。

（完）
