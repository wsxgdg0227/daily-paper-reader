## 摘要
硬件内核优化需要反复进行编译、正确性测试、性能剖析和修改。LLM智能体可以自动化这一过程中的部分环节，而更强的基座模型、更长的上下文窗口以及更长的执行周期已经提升了单个任务内的优化效果。然而，仅凭这些进展并不能使智能体从已完成的优化运行中学习。现有的内核优化智能体很少保留某个决策、其观测到的执行反馈以及后续利用该证据所做的决策。保留所有先前的轨迹也不现实，因为不断增长的历史记录会与当前任务争夺上下文。我们提出了KOPE，一种用于硬件内核优化的经验驱动框架。KOPE将带有正确性和性能反馈的优化轨迹记录到经验图内存中，然后通过主动上下文管理与注入，在固定token预算下检索相关经验。该图保留了决策顺序、观测结果和备选分支，使得在目标硬件上收集的证据能够为后续的优化步骤和任务提供参考。在相同的GLM-5.2设置下，KOPE的每算子加速比几何平均是CANNBot（最强竞争基线）的1.54倍。在包含53个算子的完整消融实验中，主动上下文管理与注入将通过率从60.0%提升至84.6%，将评估器报告的正向字段几何均值从0.0382提升至0.0661，并将优化token消耗从159亿token降至11.13亿token（相对于被动智能体主导的上下文构建）。启用经验图内存可将全套件通过率从55.2%提升至84.6%，并在有效计时比较中带来1.43倍的几何平均加速。这些结果表明，在基座模型保持不变的情况下，可以通过外部经验实现持续优化。

## Abstract
Hardware kernel optimization requires repeated compilation, correctness testing, profiling, and revision. LLM agents can automate parts of this process, and stronger foundation models, longer context windows, and longer execution horizons have improved optimization within individual tasks. These advances alone do not enable an agent to learn from completed optimization runs. Existing kernel-optimization agents seldom preserve a decision, its observed execution feedback, and the later decisions that use that evidence. Retaining every prior trajectory is also impractical because an expanding history competes with the current task for context. We present KOPE, an experience-driven framework for hardware kernel optimization. KOPE records optimization trajectories with correctness and performance feedback in Experience Graph Memory, then uses Active Context Management and Injection to retrieve relevant experience under a fixed token budget. The graph retains decision order, observed outcomes, and alternative branches, allowing evidence collected on the target hardware to inform later optimization steps and tasks. Under the same GLM-5.2 setting, the geometric mean of KOPE's per-operator speedups is $1.54\times$ that of CANNBot, the strongest competing baseline. In a complete 53-operator ablation, Active Context Management and Injection raises pass rate from 60.0\% to 84.6\%, increases the evaluator-reported positive-field geometric mean from 0.0382 to 0.0661, and reduces optimization token consumption from 15.9B to 1.113B tokens relative to passive agent-led context construction. Enabling Experience Graph Memory raises full-suite pass rate from 55.2\% to 84.6\% and yields a $1.43\times$ geometric-mean speedup on valid timing comparisons. These results support continual optimization through external experience while the foundation model remains fixed.

## 2. 方法：核心思想、关键技术、算法流程

### 核心思想
- **自进化不改变模型参数**：论文中的“self-evolving”指外部经验与注入上下文的动态演化，基座模型保持固定。
- **经验驱动闭环**：每次编译/运行/评测都被视为一次学习事件，其结果（正确性、性能、诊断信息）被持久化并用于后续决策。

### 技术模块
1. **经验驱动优化工作流（Experience-Driven Workflow）**
   - 对任务 xt、迭代 k，状态 st,k 包含内核规格、当前最佳代码、最新执行反馈与优化目标。
   - 每轮迭代：检索经验 → 组装上下文 → LLM 生成候选 → 目标硬件执行（编译、正确性测试、性能分析）→ 将结果写入记忆。
   - 遵循“先正确性、后性能”原则：仅当候选通过正确性测试且性能更优时替换现有最优代码；失败/校正轨迹也保留为负向经验。
   - 迭代的通用表达式（文中公式）：
     - $z_{t,k} = R(s_{t,k}, M_{t,k})$（检索）
     - $C_{t,k} = I(s_{t,k}, z_{t,k}; B)$（上下文组装）
     - $a_{t,k} = \pi_\theta(C_{t,k})$（固定参数 LLM）
     - $y_{t,k} = E(a_{t,k})$（执行反馈）
     - $M_{t,k+1} = U(M_{t,k}, s_{t,k}, a_{t,k}, y_{t,k})$（记忆更新）

2. **经验图内存（Experience Graph Memory, KOPE-Mem）**
   - **双重表征**：每个事件同时以 `Journal`（追加式 Markdown 叙述）和 `Case`（结构化 JSON，含算子/输入场景、优化思路、前后代码、编译反馈、正确性、加速比、置信度、会话/步骤/前驱 ID）存储。
   - **决策-结果有向图**：节点表示一次决策+结果，边表示尝试从某优化状态出发；为有向无环森林（每个节点最多一个前驱、多个后继），记录分支与顺序但不做因果识别。
   - **图感知检索与排序**：
     - 先做精确过滤（算子、优化层、想法 ID、结果标签）与语义搜索构建候选池；
     - 定义节点 v 的步进比值 $r_v = a_v / a_{prev(v)}$（根节点或无前驱正值时为 1），按阈值将结果分为 effective / partial / ineffective / negative；
     - 为考虑下游效果，计算折扣下游得分 $d(v) = w_{self}r_v + w_{succ}\gamma \sum_{u \in succ(v)} d(u)$，其中 $w_{self}=w_{succ}=0.5, \gamma=0.7$；
     - 排序时在同一结果标签桶内按 $d(v) \cdot c_v$（置信度）排列。
   - 该得分为检索启发式，不作因果估计；不正确的 Case 不能提升当前最优候选。

3. **主动上下文管理与注入（Active Context Management and Injection）**
   - **三级动态上下文分层**：Hot（当前任务必需：规格、现源码、最新反馈、目标）；Warm（检索到的相关历史经验）；Cold（更宽泛的领域文档/跨类别经验）。分层表示注入优先级而非物理存放位置。
   - **预算控制**：给定模型窗口 $W$、系统提示 $S$、生成预留 $G$、近期预留 $R$，可得知识预算 $B_k = \max(0, W - S - G - R)$；如果 Hot 载荷 H 不超过 $B_k$，则 Warm 和 Cold 按各自上限 $Q_w$、$Q_c$ 填充。
   - 注入格式包括紧凑的 Case 字段、前后变换、Journal 摘要或程序性摘要；上下文在每次迭代前重建，使得上一轮的新事件可以在下一轮影响模型。
   - **与 KV-cache 淘汰区别**：KOPE 在模型调用之前选择外部材料，KV-cache 淘汰是在解码期间选择内部状态，二者互补。

## 6. 主要结论与发现

- **系统级结果（GLM-5.2）**：KOPE 全套件通过率 84.6%（897/1,060），CANNBot 为 57.8%，CUDA-Agent 仅 14.7%；KOPE 得分 2004.49 vs CANNBot 1465.93；KOPE 的每算子加速比几何均值是 CANNBot 的 **1.54 倍**。
- **系统级结果（Deepseek-V4-Pro）**：KOPE 通过率 73.9%（783/1,060），CANNBot 39.3%，CUDA-Agent 9.1%；KOPE 得分 1242.90 vs CANNBot 1015.38。
- **CUDA-Agent 在稀疏语料 Ascend 场景中失败**：即使它能返回所有 53 个算子，GLM-5.2/Deepseek-V4-Pro 下通过率仅 14.7%/9.1%，且没有一个完整算子全部 20 例通过；GLM-5.2 下的加速比全部低于 parity（0.1x）。说明仅靠强模型和任务内细化不足以克服目标硬件语料稀缺问题。
- **消融 A（主动上下文）**：主动上下文管理将全套件通过率从 60.0% 提至 84.6%（+24.6 pp），分数从 636 提升至 2004.49，正字段几何均值从 0.0382 升至 0.0661（1.73×），同时优化 token 消耗从 **15.9B 降至 1.113B（减少 93%）**——证明性能提升并非靠堆历史上下文。
- **消融 B（经验图内存）**：开启图内存通过率从 55.2% 提至 84.6%（+29.4 pp）；在 412 个配对有效计时上几何平均加速比为 **1.434×**（L2/L3/L4 分别为 1.455×/1.501×/9.175×；L1 基本持平 0.993×）。说明经验图内存对困难算子的加速更显著。
- **跨硬件（RISC-V Triton）**：KOPE 可在第二个异构工具链上运行；Ascend 源经验能提升通过率（60.3%→83.3%，+23pp），但不提升性能（固定交集加速比从 0.388×降至 0.145×）；K3 本地经验及其与 Ascend 经验组合能同时提升覆盖率与性能（最高 92.2% 通过率、0.786× 固定交集几何均值）；再次支持“跨硬件接口可移植、性能需目标侧调适”的结论。
- **总体结论**：在公共数据稀疏的硬件上，**保留并选择性地再注入目标侧经验是提升内核优化的有效路径**，即便基座模型固定。

## 7. 优点与亮点

- **问题定位精准**：抓住了现有 LLM 内核优化代理的盲区——无法跨任务/跨步骤积累经验，且提出长上下文会稀释有效信息的问题。
- **方法有清晰结构**：将经验存储设计为“文本日志 + 结构化 Case”双重表征，并将优化路径建模为“决策-结果”有向无环图，支持按结果标签和贴现下游得分排序，思想新颖且工程可实现。
- **上下文预算显式刻画**：用公式定义 token 预算与动态三层上下文，避免无限制历史堆叠，与应用层 KV-cache 工作形成清晰分工。
- **实验纪律良好**：统一基准、完整套件、保守缺失算子计数、配对时序比较、区分“全套件指标”和“条件统计量”，并报告 token 消耗，能够较公正地比较不同系统。
- **跨硬件验证**：附录的 RISC-V 实验显著提升了“通用工作流”而非“Ascend 专用工具”的可信度；而且结果揭示了知识迁移的双面性（覆盖率迁移 vs 性能迁移），体现科学诚实度。
- **“自进化”定义严谨**：明确指出模型参数固定，进化发生在外部经验库和注入上下文中，避免了概念混淆。

## 8. 不足与局限

- **实验重复性有限**：每个主配置仅有单个归档运行，缺少重复试验、置信区间和误差估计，无法量化运行波动。
- **系统对比混淆因素**：KOPE、CANNBot 与 CUDA-Agent 在实现上有很多差异，系统级增益不一定完全归因于经验记忆/上下文机制。
- **消融粒度不细**：主动上下文消融只对完整机制做整体比较，未单独分出“检索重排、压缩、注入”各自的独立贡献；图记忆消融也没有单独考察图结构 vs 文本检索本身的效果。
- **性能指标受选择偏差影响**：正速度比字段的“几何均值”基于不同系统各自的正子集，小覆盖率系统可能显得更强；论文自身已尽量避免误读，但读者仍需注意这些数值不代表全套件加速。
- **L4 性能结论样本极少**：图内存消融中 L4 仅 28 个配对用例，9.175× 的估计置信度低。
- **跨硬件实验的抽象程度**：RISC-V 实验本身也只做了单次归档结果，无重复时序采样；且“Ascend memory”导致性能下降，说明源知识不可盲目迁移，作者未展开解释哪些类型知识会迁移失灵。
- **算力成本未披露**：没有报告运行这些智能体工作流所需的实际计算资源与时间，复现成本难以估算。
- **无法回答“何时经验足够”/“如何自适应预算”**：论文把分层上下文的容量上限作为固定超参，未学习在线调整策略，也未讨论经验库无限增长后检索性能/存储的长期问题。
