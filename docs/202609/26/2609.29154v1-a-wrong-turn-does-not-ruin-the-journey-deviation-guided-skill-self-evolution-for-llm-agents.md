## 摘要
大语言模型智能体日益依赖自然语言技能来解决复杂的工具使用任务。然而，此类任务通常存在多条有效的解决路径，因此通过强制失败轨迹与固定的成功轨迹对齐来改进技能并不合适。此外，失败轨迹很少完全错误：智能体可能先收集到有用证据并取得实质性进展，但随后偏离至错误的后续片段。因此，我们认为技能自演化应识别富有成效的问题求解在何处开始失效，而非对整个失败过程进行粗粒度反思。基于这一洞见，我们提出 SkillPivot，一种由偏差点引导的技能自演化框架。SkillPivot 利用执行有效性、目标进展和动作多样性来检测从有用前缀到错误后缀的转变。随后，一个更强的教师模型从相同前缀继续，并在相同交互历史下生成一条成功的替代路径。通过对比学生的失败后缀与教师的成功后缀，SkillPivot 生成局部化的技能更新，同时保留已有效的指导。在 ToolQA、LogicBench 和 WildClawBench 上的实验表明，SkillPivot 持续优于同类技能演化方法，可提升多种智能体模型，并产生紧凑、可迁移的技能更新。

## Abstract
Large language model agents increasingly rely on natural-language skills to solve complex tool-use tasks. However, such tasks often admit multiple valid solution paths, making it inappropriate to improve skills by forcing failed trajectories to match a fixed successful trajectory. Moreover, failed trajectories are rarely entirely wrong: an agent may first collect useful evidence and make meaningful progress, but later deviate into an erroneous suffix. We therefore argue that skill self-evolution should identify where productive problem solving begins to break down, rather than reflect coarsely over the entire failure. Based on this insight, we propose SkillPivot, a deviation-point-guided framework for skill self-evolution. SkillPivot detects the transition from a useful prefix to an erroneous suffix using execution validity, goal progress, and action diversity. A stronger teacher then continues from the same prefix and produces a successful alternative under the same interaction history. By contrasting the student's failed suffix with the teacher's successful suffix, SkillPivot generates localized skill updates while preserving already effective guidance. Experiments on ToolQA, LogicBench, and WildClawBench show that SkillPivot consistently outperforms competing skill-evolution methods, improves multiple agent models, and produces compact, transferable skill updates.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体通过 ReAct 式「推理—行动」循环调用工具完成复杂任务，其可靠性不仅取决于选对工具，还依赖大量任务特定的**程序性知识**（何时查询、如何构造参数、如何解读观察、何时验证、如何从异常反馈中恢复）。
- **常用手段**：为智能体配备自然语言「技能库」（skill corpus），每条技能编码可复用的求解与工具使用指导。但人工技能往往不完整——覆盖主流程而遗漏边界情况、恢复策略、工具约束。
- **核心问题**：**技能自演化（skill self-evolution）**——能否让智能体从自身的交互失败中改进既有技能库？
- **现有方法的缺陷**：
  - 全轨迹反思（whole-trajectory reflection）、成功轨迹模仿、开放式技能重写；
  - 这些做法隐含假设「失败轨迹整体是错的」，但工具任务常有多条有效路径，强制对齐单条成功轨迹并不合理；
  - 更关键的是，**失败轨迹很少全错**：智能体往往先做有用的探索、收集证据、缩小解空间，之后才陷入重复无效调用、过早停止或误读观察。
  - 把整条轨迹当作单一失败信号，会把「有用前缀」与「有害后缀」混在一起，导致更新噪声大、过于宽泛或过拟合单例。
- **核心洞察与含义**：技能自演化应定位「有成效的求解从哪一步开始崩坏」，把失败转化为**局部化、条件化、可审计**的技能维护信号，而非无约束的技能重写。

## 2. 方法论：SkillPivot

### 2.1 问题形式化

- 技能库 $S^r=\{s^r_1,\dots,s^r_M\}$，每轮任务集 $D^r=\{x_i\}_{i=1}^N$。
- 学生智能体 $A_s$ 生成 ReAct 轨迹 $\tau_i=(x_i,h_{i,1},a_{i,1},o_{i,1},\dots,h_{i,T_i},a_{i,T_i},o_{i,T_i},y_i)$，评估器给出 $E(\tau_i,x_i)\in\{0,1\}$。
- 轨迹划分为成功集 $T^+$ 与失败集 $T^-$；目标是学习更新算子 $\Phi$，产出技能增量 $\Delta S^r=\Phi(S^r,T^+,T^-)$，并 $S^{r+1}=\text{Update}(S^r,\Delta S^r)$。
- 优化目标：最大化未来任务成功率 $\mathbb{E}_{x\sim D_{future}}[E(A_s(x;\text{Update}(S^r,\Delta S^r)),x)]$，**同时约束在 $S^r$ 下已可解任务上的回退**。因此技能演化被建模为「带约束的维护问题」，而非单纯的失败修补。

### 2.2 五阶段流程

**（1）学生 rollout**
- 学生带当前技能库执行一批任务，保留完整交互轨迹（因为技能级失败常无法从最终答案看出，如命令层级错误、参数来源错误、忽略空响应、未验证环境状态）。
- 成功轨迹入**成功池**（用于回归测试）；失败轨迹入**失败池**（用于诊断缺失的程序性知识）。

**（2）偏差点检测（Deviation Point Detection）**
- 对每步 $t$ 计算进展潜力分数：
  $$\hat V_t = 0.4\,Exec_t + 0.3\,Prog_t + 0.3\,Div_t$$
- **执行有效性 $Exec_t$**：基于动作有效性、工具执行状态、返回观察可用性的确定性规则打分；无效调用、执行错误、空观察得低分。
- **目标进展 $Prog_t$**：以 ground-truth 作为任务目标的语义表示，用 all-MiniLM-L6-v2 编码当前观察与标准答案并计算余弦相似度；为避免重复证据被反复计分，只保留相对历史最优的**增量**：
  $$Prog_t=\max\big(0,\ \text{sim}(o_t,y)-\max_{j<t}\text{sim}(o_j,y)\big)$$
- **动作多样性 $Div_t$**：编码动作，$Div_t=1-\max_{j<t}\text{sim}(a_t,a_j)$；低值表示重复此前策略。
- **确认机制**：先取 $\hat V_t$ 最低步为候选偏差点，再检查其后各步是否持续低于此前整体水平（形成明显「低谷」），只有确认后才作为真正的偏差点 $t^*$，防止把单次偶然低分误判为偏差、过早截断仍含有用探索的前缀。

**（3）教师 rollout（Teacher Rollout）**
- 更强的教师智能体**从同一前缀继续**（而非从头重做），输入包括任务、当前技能库、学生偏差前轨迹前缀、学生完整失败轨迹（作为需避免的反面参考），沿用相同步号继续 ReAct 循环。
- 使用 **inline reflector**：每次工具调用后分析最新动作与观察，生成简短提示附加到教师 scratchpad，但**不写入保存的原始教师轨迹**，避免污染后续用于对比的后缀。
- 教师续写只有通过任务评估器才被接受；失败则丢弃或从同一偏差点最多重试 3 次。
- 成功后构造配对案例：共享前缀 + 学生失败后缀 + 教师成功后缀。

**（4）配对后缀对比与技能生成**
- **单案例轨迹摘要器**：逐个分析教师纠正成功的配对案例，识别学生错误、教师纠正、当前技能中缺失/不完整的指导、总体演化方向，产出**结构化案例分析**（而非直接改写技能）。
- **技能增量生成器**：聚合多个结构化分析，提出候选 delta，可选三种动作：`improve_skill`（更新技能内容）、`optimize_description`（精炼描述或触发条件）、`skip`（证据不足时不编辑）。

**（5）回归门控技能更新（Regression-Gated Skill Update）**
- 先由 LLM 编辑器把候选 delta 应用到原技能，得到暂定技能 $s'$。
- 再由 **LLM 审查器**按两条标准打分（各在 [0,1]）：
  - **no regression**：$s'$ 是否保留 $s$ 的有用规则，未在无理由情况下删除、削弱、覆盖或矛盾；
  - **generalizable rule**：新增指导是否为可复用的程序性原则，而非针对触发失败的一次性补丁。
  - 仅当 $r_{reg}\ge\theta$ 且 $r_{gen}\ge\theta$（实现中 $\theta=0.5$）时接受，$s'$ 才写入部署技能库并用于下一轮；否则保留原技能，delta 仅作为候选记录。该门控使演化保持保守：每次部署的更新必须修复已观察失败而不牺牲原有有效行为。
