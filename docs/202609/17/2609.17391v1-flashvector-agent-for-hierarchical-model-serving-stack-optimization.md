## 摘要
模型服务是生产推荐系统中最大的成本驱动因素之一。最大化其吞吐量需要驾驭一个深度分层的层级体系：GPU 内核、机器学习框架计算图、模型服务器和按需特征处理——每一层都需要专门的领域专业知识。这种跨层专业知识本身很难获得，且无法随持续增长和演进的工作负载而扩展，导致大量成本效率收益未能实现。尽管近期 AI 智能体在独立 GPU 内核优化中已展现出人类专家级效率，但针对服务栈其余部分的自动调优与优化在很大程度上仍未得到探索。我们提出 FlashVector，一个可优化模型服务栈所有层性能的智能体系统。关键贡献是一个可扩展框架，用于将单内核优化智能体范式推广到异构技术栈，并从整体上带来性能提升。在 Unity 的 Vector 广告平台部署后，FlashVector 在模型服务器上实现了最高 2 倍的吞吐量提升和最高 1.98 倍的延迟加速，并在特征存储上实现了最高 1.6 倍的吞吐量提升。这些优化不仅在 GPU 内核和计算图层面被发现，还遍及模型服务栈的其他组件，例如模型服务器（NVIDIA Triton 的 C++ 代码库）和按需特征转换服务（Python 代码库），证明了该框架对更复杂系统架构的可扩展性。

## Abstract
Model serving is one of the largest cost drivers in production recommender systems. Maximizing its throughput requires navigating a deeply layered hierarchy: GPU kernels, the ML framework computation graph, the model server, and on-demand feature processing -- each demanding specialized domain expertise. Such cross-layer expertise is inherently difficult to acquire, and does not scale with a workload that continuously grows and evolves, leaving significant cost efficiency gains unrealized. While recent AI agents have demonstrated human expert level efficiency in standalone GPU kernel optimization, automated tuning and optimization for the rest of the serving stack remain largely unexplored. We present FlashVector, an agentic system that optimizes performance across all layers of the model serving stack. The key contribution is an extensible framework to generalize the single kernel optimization agent paradigm to heterogeneous technical stacks, and to deliver performance improvements holistically. After deployment in Unity's Vector advertising platform, FlashVector achieved up to 2x throughput increase and up to 1.98x latency speedup on model server, and up to 1.6x throughput increase on feature store. These optimizations were discovered not only at the GPU kernel and computation graph levels, but also across the other components of the model serving stack, such as the model server (NVIDIA Triton's C++ codebase) and the on-demand feature transformation service (Python codebase), demonstrating the extensibility of the framework to more complex system architectures.

## 1. 核心问题与研究动机

- **背景**：模型服务（model serving）是生产推荐系统最大的成本驱动之一。在 Unity 的 Vector 广告平台，DNN 模型贯穿召回、转化率预估、长期价值预测全漏斗，管理数百个模型，生产环境每秒处理数十万次推理请求，横跨数万 GPU/CPU 节点。
- **核心难题**：最大化吞吐需要同时驾驭**深度分层**的异构体系：
  - GPU 内核层（kernel fusion、显存带宽、Tensor Core 利用）
  - ML 框架计算图层（PyTorch 模块结构、张量布局、算子选择、host-device 同步）
  - 模型服务器层（NVIDIA Triton，动态 batching、多进程并行推理，C++ 代码库）
  - 按需特征处理层（Python 代码库，CPU 密集）
- **痛点**：
  - 每层语言（Go/C++/Python/CUDA）、profiling 工具（eBPF、Kineto、Nsight）与"优化方言"完全割裂，跨层专家知识稀缺且**不随持续演进的工作负载扩展**，导致大量成本效率收益未被兑现。
  - 已有的 LLM 智能体仅在**单内核优化**上达到人类专家水平，服务栈其余部分（服务器 C++ 请求路径、Python 特征服务、纯运行时配置）基本未被探索。
  - 优化是**持续移动的目标**：模型重训、流量昼夜变化、硬件/驱动/框架升级都会使手工优化迅速失效（"optimization decay"）。
- **核心研究问题**：能否把 LLM 驱动的优化从独立 GPU 内核推广到**整个模型服务栈**？

## 2. 方法论

### 2.1 核心思想
将"profile–diagnose–optimize–verify"单内核优化范式抽象为**可插拔的分层智能体框架**，让任意服务层通过统一接口接入同一优化闭环，并做到"局部优化、全局验证、持续自触发"。

### 2.2 三大设计原则（论文自述贡献）
1. **Layer agent abstraction（层智能体抽象）**：每层实现统一四阶段接口 + 一个运行后的 Refine：
   - **Profile**：域专用工具（GPU 用 Nsight Systems/Compute，模型服务器用 eBPF，特征服务用生产 eBPF + 自定义解析脚本）
   - **Diagnose**：对照层专属知识库定位瓶颈
   - **Optimize**：生成并应用代码或配置改动（Plan & Apply）
   - **Verify**：用生产证据校验
   - **Refine**：运行结束后把结论写回知识库
2. **Optimize locally, verify globally（局部优化、全局验证）**：各层独立提出候选优化，但只有在**回放生产流量、在固定生产延迟 SLO 下测得端到端收益超过测量噪声**时才被接受。
3. **Always-on optimization loop（常开优化循环）**：每次运行从模型的历史（已接受/已拒绝改动）出发，写回结果，并**自动重新触发**，而非等待人工调用。

### 2.3 三阶段工作流
知识库加载 → 迭代优化 → 知识精炼（Refine）。

### 2.4 知识库内容
业务逻辑（候选数、请求级 vs 候选级特征）、模型服务器架构与运行时参数、特征存储的数据类型与血缘、ML 模型实现细节（架构、参数清单、服务配置）、硬件（NVIDIA GPU profiling 规范）、人工专家提炼的**优化 cookbook**（约束智能体在有限上下文内做出有理据的决策）。

### 2.5 优化循环（Algorithm 1 文字化）
- 输入：服务栈 S、层集合 L（GPU 内核/计算图/模型服务器/按需特征处理）、工作负载 W、评估 harness H、知识库 K、由重复基线运行估计的噪声底 ε。
- 循环体：
  1. `SampleLayer(L)`：**每次迭代随机采样一层**（而非一次性扫全栈）
  2. `Profile(ℓ, C, W)`：只 profile 该层
  3. `Diagnose(r, K_S[ℓ])`：对该层瓶颈假设排序——**候选打分 = 该瓶颈占总时间的比例 × 预期收益**；若最佳可能收益小于噪声底则跳过；把 top-1 交给 Optimize
  4. `Plan(d)` → `Apply(C, Δ)`：生成并应用改动
  5. `Verify(H, C')`：校验正确性 + 延迟/吞吐/成本
  6. 若通过且收益 > 噪声底 ε，再执行 `FullStackLoadTest`；全栈无回退才接受，否则丢弃回滚
  7. 迭代至最大次数或满足优化准则
- 结束：`RefineContext` 把本次改动脉络与结果写回知识库，输出 C*、K*。

### 2.6 正确性门槛（分层设定）
- **确定性重写**（保持算子顺序与累加精度）：输出必须**逐元素完全相等**
- **浮点重排重写**：端到端预测偏差需在 10⁻³ 元素级绝对误差内，且超限元素 ≤ 0.1%（FP16 单位尺度 1 ULP；FP32 为 10⁻⁴）；非有限值直接判失败。per-kernel 验证器用 dtype 缩放界限（FP32 10⁻³、FP16 10⁻²），只能收紧不能放宽，接受阈值写回 model card
- **有意近似**：以业务指标门控（而非输出相等）
- **配置变更**：由固定 SLO 下的影子流量金丝雀门控

### 2.7 噪声与统计控制
- 端到端噪声底约 **±6%**（由未修改基线的重复 no-op 运行估计）
- 2%–6% 区间的改进以最多 **8× 样本量**重测，噪声底按 1/√k 收紧至约 **2.1%**

### 2.8 触发机制
新版本进入集群时优化；或某服务虽在承载流量但**长时间未被分析、配置不再可信**时自动重新触发。
