## 摘要
稀疏矩阵-稀疏向量乘法（SpMSpV）是图遍历、稀疏线性代数和稀疏模型推理中的核心原语。其输入向量通常是动态稀疏的，因此最佳GPU执行路径取决于全局稀疏性和局部向量块分布。现有的GPU SpMSpV方法通常将存储布局、拉取/推送遍历和内核绑定在一起，使得在没有额外存储或调度开销的情况下难以进行细粒度自适应。本文提出了DB-SpMSpV，一个用于动态GPU工作负载的双视图分块SpMSpV框架。DB-SpMSpV将矩阵划分为固定大小的二维块，在高层维护块级CSR/CSC视图，并复用单个低层块负载以支持行驱动拉取和列驱动推送。在运行时，它根据输入块稀疏性选择全局遍历路径，根据局部矩阵/向量块结构选择块微内核，并使用负载均衡、异步预取和分级写回以减少不规则内存访问、写回冲突和负载不平衡。我们进一步将该框架集成到DB-BFS和DB-Decoding中。我们在NVIDIA A100和RTX 4090上使用SuiteSparse矩阵、对称图和三个开源LLM评估了DB-SpMSpV。在各种输入稀疏度下，DB-SpMSpV在A100上相比cuSPARSE实现了平均5.48倍至64.34倍的加速，相比TileSpMSpV实现了2.36倍至14.01倍的加速，在RTX 4090上也有类似提升。DB-BFS在A100上相比TileBFS平均将端到端图遍历提升了2.66倍，在RTX 4090上提升了3.60倍，而DB-Decoding将单token线性层加速最高达4.50倍。

## Abstract
Sparse Matrix-Sparse Vector Multiplication (SpMSpV) is a core primitive in graph traversal, sparse linear algebra, and sparse model inference. Its input vector is often dynamically sparse, so the best GPU execution path depends on both global sparsity and the local vector-block distribution. Existing GPU SpMSpV methods often bind storage layouts, push/pull traversal, and kernels together, making fine-grained adaptation difficult without extra storage or scheduling overhead.   This paper presents DB-SpMSpV, a dual-view blocked SpMSpV framework for dynamic GPU workloads. DB-SpMSpV partitions the matrix into fixed-size 2D blocks, maintains block-level CSR/CSC views at the high level, and reuses a single low-level block payload to support both row-driven pull and column-driven push. At runtime, it selects the global traversal path based on input block sparsity, chooses block microkernels from the local matrix/vector block structure, and uses load balancing, asynchronous prefetching, and hierarchical writeback to reduce irregular memory accesses, writeback conflicts, and load imbalance. We further integrate the framework into DB-BFS and DB-Decoding.   We evaluate DB-SpMSpV on NVIDIA A100 and RTX 4090 using SuiteSparse matrices, symmetric graphs, and three open-source LLMs. Across input sparsities, DB-SpMSpV achieves average speedups of 5.48$\times$--64.34$\times$ over cuSPARSE and 2.36$\times$--14.01$\times$ over TileSpMSpV on A100, with similar gains on RTX 4090. DB-BFS further improves end-to-end graph traversal by 2.66$\times$ over TileBFS on A100 and 3.60$\times$ on RTX 4090 on average, while DB-Decoding accelerates single-token linear layers by up to 4.50$\times$.

## DB-SpMSpV 论文深度解析与总结

### 1. 核心问题与研究动机

- **核心问题**：稀疏矩阵-稀疏向量乘法（SpMSpV）是图遍历、稀疏线性代数及稀疏大语言模型推理等动态工作负载的核心原语。与假设输入向量稠密的 SpMV 不同，SpMSpV 的输入向量通常是**动态稀疏**的，即其非零元素的位置和数量在多次计算中不断变化。这使得计算的最优执行路径既取决于**全局稀疏度**，又受制于**局部向量块的分布情况**。
- **现有挑战**：当前 GPU SpMSpV 方法通常将**存储布局**与**遍历方向（push/pull）**以及**内核实现**强耦合。例如，CSR 格式天然适配行驱动的 Pull 遍历，而 CSC 格式适配列驱动的 Push 遍历。这种耦合使得系统难以根据动态变化的输入向量进行细粒度的运行时应变，若同时维护两套格式又会带来**接近双倍的内存开销**和复杂的索引同步问题。
- **物理意义**：Push 遍历（列驱动）在处理高度稀疏的输入时能大幅跳过无效计算，但面临严重的写回冲突（原子操作）；Pull 遍历（行驱动）内存访问更规整，避免了写冲突，但当输入极度稀疏时会做大量无效扫描。全局最优策略在两者间动态切换，且切换点依矩阵结构而异。同时，全局稀疏的输入向量在局部区域可能非常稠密（如图3热力图所示），仅靠全局层面的决策过于粗糙。

### 2. 方法论：DB-SpMSpV 框架

DB-SpMSpV 的核心设计思想是**通过二维分块来解耦高层全局遍历顺序与低层块内数据组织**，从而实现三级自适应：**存储格式自适应、全局路径自适应、局部微内核自适应**。

- **双视图分块存储格式**
    - **高层索引**：将矩阵划分为 16x16 的固定块。高层只维护**块级 CSR**（用于 Pull 遍历）和**块级 CSC**（用于 Push 遍历）索引，这两种视图仅存储指向物理块 ID 的指针。
    - **低层共享负载**：矩阵块的**数据负载（值、坐标）仅物理存储一份**。通过一个 `csc2csr` 映射数组将高层两种视图关联到同一个块 ID 和块元数据（`blocks_type`, `blocks_nnz` 等），巧妙避免了 CSR+CSC 双重存储的开销。
    - **低层块内自适应格式**：根据块内稀疏度与行列倾斜度，微内核自动选择最经济的存储格式：
        - **COO**：非零元数量少于阈值 th0（如 <32）。
        - **Dense**：非零元数量超过阈值 th1（如 >128）。
        - **ForceCSR / ForceCSC**：存在明显行/列倾斜时采用。
        - **Patched-CSR**：用于前述格式之外的常规块，通过打包数据结构支持 Push 路径使用相同的数值数组。
- **向量元数据**：将输入向量划分为对齐的 16 元素块，生成 16-bit 的 `blk_x_mask` 掩码。全零块可直接跳过；掩码用于块内活动元素的快速计数和定位。
- **两级运行时自适应**
    - **全局路径选择**：通过扫描向量掩码统计非空向量块比例 `xb_sparsity`，与阈值 th3（0.01）比较。若比例很低则走**高层 CSC Push 路径**，否则走**高层 CSR Pull 路径**。
    - **局部微内核选择**：路径确定后，每个矩阵块根据自身的 `blocks_type` 和对应向量块的 `blk_x_mask` 动态选择计算范式。稠密向量块使用 Pull 微内核，稀疏向量块使用 Push 微内核，实现块级的最优计算。
- **GPU 内核优化**
    - **路径感知的负载均衡**：Push 模式将任务扁平化为矩阵块级任务，由 warp 以 grid-stride 方式获取；Pull 模式将行分块按估算计算权重（Dense 为4，CSR 为2，COO 为1）进一步切分为段，保证 warp 间负载均匀。
    - **内存延迟隐藏**：利用 `__pipeline_memcpy_async` 实现共享内存双缓冲和异步预取，隐藏全局内存访问延迟。
    - **分级写回**：首先在 warp 内通过 `__shfl_xor_sync` 等指令进行寄存器级归约，再写入共享内存，最终才写回全局内存，大幅降低原子操作和写冲突。
- **算法流程**：框架在运行时根据输入向量生成掩码和统计信息，若全局稀疏度低于阈值则从块级 CSC 视图出发枚举活跃输入列块，否则从块级 CSR 视图出发，对访问到的块按照其内部格式执行分配合适的微内核计算。
