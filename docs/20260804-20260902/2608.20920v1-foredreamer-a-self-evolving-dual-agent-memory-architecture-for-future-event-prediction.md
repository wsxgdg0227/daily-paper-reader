## 摘要
开放互联网上的未来事件预测要求智能体从嘈杂、冗余且不完整的证据中提炼出可靠信号。现有的检索/记忆机制要么直接将检索到的信息输入智能体，要么依赖简单的记忆功能（如存储和重用先前信息）进行预测，这使得它们不足以应对开放网络预测。我们建议在预测之前将原始网络证据转化为结构化记忆，从而使智能体能够基于提炼后的、针对特定问题的证据进行推理，而非嘈杂的检索结果。本文提出了ForeDreamer，一种用于管理开放网络证据记忆的自进化双智能体框架。ForeDreamer将事实性记忆（当前预测的特定问题证据状态）与经验性记忆（跨预测情节积累的持久智能体经验）分离。它使用一个主智能体进行搜索和预测，并利用一个记忆处理子智能体通过专用工具将搜索结果转化为事实性记忆。ForeDreamer进一步通过两条路径进化经验性记忆，同时改进预测决策和事实性记忆构建。在Prophet Arena和FutureX上的实验证明了ForeDreamer的有效性。项目页面：https://zhongzero.github.io/ForeDreamer

## Abstract
Open-web future event prediction requires agents to distill reliable signals from noisy, redundant, and incomplete evidence. Existing retrieval/memory mechanisms directly feed retrieved information to agents or rely on simple memory functions such as storing and reusing prior information for prediction, leaving them insufficient for open-web forecasting. We propose to transform raw web evidence into structured memory before prediction, enabling agents to reason over distilled, question-specific evidence rather than noisy retrieval results. This paper presents ForeDreamer, a self-evolving dual-agent framework for managing memory over open-web evidence. ForeDreamer separates factual memory, a question-specific evidence state for the current forecast, from experiential memory, persistent agent experience accumulated across forecasting episodes. It uses a main agent for search and prediction, and a memory-processing subagent to convert search results into factual memory with dedicated tools. ForeDreamer further evolves experiential memory through two tracks, improving both forecasting decisions and factual-memory construction. Experiments on Prophet Arena and FutureX demonstrate the effectiveness of ForeDreamer. Project page: https://zhongzero.github.io/ForeDreamer

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 总体架构（ForeDreamer）

- 采用**双智能体**架构，分离“预测主体”与“证据加工主体”：
  - **主智能体**：负责搜索规划、整合已处理的事实性记忆并输出最终预测（含推理性文字）。
  - **记忆处理子智能体**：按照 MemGuide（记忆指引）并调用 MemTools（可执行记忆工具），在工件工作区（Artifact Workspace）中将每条搜索结果转成条目级的事实性记忆。
- 将记忆区分为两类：
  - **事实性记忆（Factual Memory）**：当前问题专属、由搜索证据加工而来的中间证据状态，是原始网页与最终预测之间的可审计接口。
  - **经验性记忆（Experiential Memory）**：跨预测情节积累的、持续指导未来行为的持久化经验。

### 2.2 推理（Forecasting Workflow）

- 输入为（预测问题 q，时间截止线 τq）。
- 主智能体在预算 T 轮内、每轮至多发起一次搜索，使用截止时间受限的检索：Rt = Search(st, E≤τq)。
- 每条检索结果 rt,k 归一化后写入工件工作区，由子智能体按当前选定的 MemGuide g 与 MemTools 集合 Tg 产生处理结果：mt,k = Pg,Tg(rt,k, q)。
- 产生的若干条结构化事实性记忆汇总为 M1:K，供主智能体在最终回合（不再调用工具）做出预测与理由说明：y, ρ = A(q, B, M1:K)（B 为经验库）。
- 记录完整 Rollout，包括交互日志、中间工件、预测结果、真值与评测指标，留作后续进化反馈。

### 2.3 双轨经验进化（Dual-Track Self-Evolution）

- **轨道一：文本型预测经验进化**——更新 Experience Bank（B(v) = {ei}）。
  - 编辑器根据 rollout 反馈对经验库提出 ADD / MODIFY / REMOVE 三类操作。
  - 候选经验需在小规模进化验证池 Devo 上全量通过，且只在验证分数严格优于当前版本时被采纳，否则保持原版本：B(v+1)=B，当且仅当 B优于 B(v)。
- **轨道二：程序性证据处理经验进化**——更新 MemGuide 树与 MemTools 集。
  - 以 MemGuide 树记录演进路径；先根据 rollout 反馈提炼设计需求（Design Requirement），再为该需求生成候选 MemGuide 及配套 MemTools。
  - 候选资产须通过“接口检查 + Devo 全量验证”的双重门槛，只有全部验证成功才被纳入活动记忆。
  - 父级选择遵循基于验证排名的 Zipf 采样，既倾向高质量指引，又保留低排名指引被探索的可能性。

### 2.4 两项关键优化

1. **组合式工具复用（Compositional Tool Reuse）**
   - 动机：对 vanilla 进化在 FutureX 上自动生成的 201 个 MemTools 做源码 Token-Jaccard 聚类，在阈值 0.5 下仅形成 98 个簇（压缩率 48.8%），说明大量代码近乎重复，进化预算被浪费在重复造工具上。
   - 做法：给定新设计需求时，先由“工具复用选择器”从已验证工具集中挑 ≤3 个兼容工具复用（Treuse ⊆ Tactive），只为仍未覆盖的操作新写工具，T = Treuse ∪ Tnew；新生成资产仍需通过同一验证门槛。
2. **多样性引导探索（Diversity-Guided Exploration）**
   - 动机：vanilla 展开始终挂在某个父 MemGuide 上做局部微调，10 个 evolved FutureX MemGuide 全部属于同一“工具编排式处理”流水线原型（图 5），缺少对替代管线的全局探索。
   - 做法：引入“进化调度器（Evolution Scheduler）”——保留原始 rollout 驱动路径，同时增加一条“无需新 rollout”的探索路径：先对当前 MemGuide 分类，归纳各分类摘要并挑选代表性指引，再生成与既有流水线在阶段数量、状态转移、中间产物结构上明显不同的候选；通过同一验证门槛后进入指引树，实现类别多样化的程序性记忆进化。

## 6. 主要结论与发现

- 将“原始网络证据 → 结构化事实性记忆 → 预测”的处理路径，明确优于直接投喂上下文或使用现有记忆系统处理检索结果。
- 双轨进化各自独立有功，且体验库 + 进化指引是互补关系，两者必须同时进化才能取得最佳成绩。
- 两条程序性进化优化都有效：组合式工具复用显著降低工具冗余（如上文提到聚类比率在各档相似度下始终提高）；多样性引导探索将 MemGuide 从单原型集中式扩展到四种流水线原型。
- 鲁棒性实验指出：ForeDreamer 的提升在不同检索器、不同搜索预算、不同上下文预算之下均保持稳定。
- No Information 基线表现明显偏弱，说明模型依靠的是外部检索证据而非预训练背题。
- 总结认为：开放网络预测中，记忆更应被看作**不断进化的证据处理工程与预测经验**，而不只是“存—取”的静态信息库。

## 7. 优点

- 任务定位清晰：锐化“干净的用户记忆任务”与“嘈杂开放网页预测”之间的本质不同，论证充分。
- 双智能体解耦可控：预测与证据加工分离，MemGuide/MemTools 使每一步证据处理都可审计、可复现、可版本化。
- 程序性记忆不只做自然语言反思，而是落到可执行工具之上，并用 MemTool 接口与沙箱执行来保证安全边界。
- 对“经验进化”中常见的工具冗余和探索过度集中问题做了量化诊断（源码相似聚类、Pipeline 原型分布），并有针对性优化，体现了较高的工程与实证质量。
- 实验设计考究：多视角鲁棒性扫描、逐类别消融报告、泄漏检测与后盾对比，验证链条比较完整。

## 8. 不足与局限

- 评估范围窄：主要面向未来预测，传统长期记忆基准（对话个性化、信息重用等）未纳入，故无法说明该框架在通用任务上的泛化性。作者在 Limitations 中已坦诚这是设计边界。
- 验证池规模小、复用反馈与验证：更严格地说，未来事件已解决真值稀少，所以进化与验证都发生在 Devo（每类 5 题或 20 题）上。这面临 validation-set overfitting 的风险，作者虽然用 held-out 实题外表现来回应，但没有做跨随机种子、不同池子大小与重复进化实验来说明鲁棒性，也没有汇报置信区间。
- 报告不透明：
  - 无算力/API 调用量/成本/时延数据——无法评估方法效率与部署门槛；
  - 图与主表中部分数值以截图形式存在，OCR 后可能丢失，不利于复现；
  - 未给出统计显著性检验（如 bootstrap、配对 t 检验等），个别表格差距很小，结论稳健性存疑。
- 公平性之外，注意基线接入方式对结果的影响。已有记忆系统被当作“处理检索结果后再给预测模型”的中间层，未必使用了各系统官方设定的长记忆工作模式。另外主智能体是否有自己的自省/纠错回路未能透明呈现，因此可能真正起作用的只是“把证据处理外包给固定子智能体”，而不是完整的双轨进化——尽管作者用逐轨消融部分实验说明了这一点。
- 模型版本与时效：文中多处被引日期设在 2025–2026 年及以后，虽强调时间截止搜证，但若评测公开题库或后盾模型在预训练中见过类似题目，仍存在残余污染风险，需谨慎对待。
- 缺乏社会影响分析：没有讨论恶意使用预测市场、错误预测造成的公共损失，也无安全评估报告。
