## 摘要
稀疏矩阵内核是科学计算、图分析和机器学习的基础。其GPU性能在很大程度上取决于输入的稀疏模式和执行策略。对于同一矩阵上的相同SpMM操作，cuSPARSE在CSR和Blocked-ELL之间表现出350倍的性能差距。我们对多种数据格式、专用系统和稀疏编译器的研究表明，没有任何单一实现能在所有稀疏模式和算子中持续占优。这促使我们构建一个能够针对每个工作负载和目标GPU自适应调整其表示、执行策略和硬件映射的系统。我们提出SparseDitto，一个基于LLM的系统，为每个矩阵、算子和目标GPU构造GPU内核。SparseDitto在统一设计框架内支持SpMV、SpMM和SpGEMM。一个轻量级加性模型利用输入矩阵的结构特征对既定策略进行排序。然后，一个架构感知规划器提出若干候选设计。编码和验证代理使用目标GPU上的测量结果来实现并优化这些设计。在三种稀疏算子和多样化的矩阵集合上，SparseDitto在NVIDIA RTX PRO 6000 GPU上相对于cuSPARSE实现了2.68倍的几何平均加速，最大加速比为146.61倍。在NVIDIA H200 GPU上，其加速比为2.79倍，最大为78.5倍。其生成的SpMM内核还可将全批量GCN训练加速高达3.39倍。

## Abstract
Sparse matrix kernels are fundamental to scientific computing, graph analytics, and machine learning. Their GPU performance depends strongly on the input sparsity pattern and execution strategy. For the same SpMM on the same matrix, cuSPARSE exhibits a 350x performance gap between CSR and Blocked-ELL. Our study of multiple data formats, specialized systems, and sparse compilers shows that no single implementation consistently dominates across sparsity patterns and operators. This motivates a system that can adapt its representation, execution strategy, and hardware mapping to each workload and target GPU.   We present SparseDitto, an LLM-based system that constructs a GPU kernel for each matrix, operator, and target GPU. SparseDitto supports SpMV, SpMM, and SpGEMM within a unified design framework. A lightweight additive model ranks established strategies using structural features of the input matrix. An architecture-aware planner then proposes several candidate designs. Coding and verification agents implement and refine them using measurements from the target GPU. Across three sparse operators and a diverse set of matrices, SparseDitto achieves a geometric-mean speedup of 2.68x over cuSPARSE on an NVIDIA RTX PRO 6000 GPU, with a maximum of 146.61x. On an NVIDIA H200 GPU, it achieves 2.79x, with a maximum of 78.5x. Its generated SpMM kernels also accelerate full-batch GCN training by up to 3.39x.

## 2. 方法论：SparseDitto

### 2.1 统一设计框架

论文将稀疏内核构建形式化为三元组配置：

- Π = ⟨R, S, θ_H⟩
  - R = ⟨L, I⟩：表示层，其中 L 为数据布局（分组、重排、填充、值放置），I 为稀疏元数据（对行指针、列索引、切片/块信息的遍历方式）。
  - S = ⟨P, D⟩：执行调度，P 为并行分解（将稀疏迭代空间映射到 CTA/warp/线程），D 为数据流（操作数移动与累加方式）。
  - θ_H：目标 GPU 的硬件特定参数，如 tile 尺寸、线程/块配置、共享内存用量、寄存器限制等。

该框架统一覆盖 SpMV、SpMM 和 SpGEMM，三类算子的主要区别体现在算子诱导的中间工作形态与累加器需求上。

### 2.2 结构分析与特征体系

SparseDitto 共计算 **36 个连续结构特征**，外加类别特征，分为四组：

- **输入内在特征**：行长度分布（均值、最大值、变异系数、分位数）、空行占比、列度统计、局部性度量（行跨度、对角线系数）、16×16 分块覆盖率等 18 个特征，反映负载均衡、访存局部性与 tile 结构。
- **表示诱导特征**：针对 ELL/SELL/BSR 等格式计算值槽扩张率 ρ（填充/分块膨胀系数），并与原非零数归一化，反映格式带来的存储与计算浪费。
- **算子诱导特征**（主要针对 SpGEMM）：中间乘积分布的总量、最大值、p95、变异系数，累加器容量适配度 F_h（行内中间值低于阈值 h 的比例），输出行压缩比 γ_B 等。
- **硬件与任务上下文**：SM 数、缓存容量、线程/寄存器/共享内存上限、算子类型、SpMM 稠密宽度 K。

所有特征从有界扫描中计算，无需事先运行 GPU 内核，开销极低。

### 2.3 基于能量的策略选择器

该选择器采用**可解释的加性能量模型**，在离线测量语料上训练。核心公式为：

- 对每个特征坐标 x_j，共享的非线性基：h_j(x_j) = tanh(x_j w_{1j} + b_{1j}) ∈ R^16；
- 对每个算子 o 下的策略 s，能量：E_o(s|x) = β_{o,s} + Σ_j h_j(x_j)^T w_{2,o,j,s}。

能量越低代表推荐度越高。训练目标融合 Listwise 似然与带间隔的 Pairwise 排序损失，并引入 softmax 化的实测加速比作为软标签，按实测性能对策略排序。模型解释性强，可分解出每个特征对策略排名的贡献。词汇表覆盖 SpMV（CSR/COO/SELL/BSR/自适应二维分块）、SpMM（额外含 Blocked-ELL、Tensor-Core 策略）、SpGEMM（CSR-hash、共享内存哈希累加、混合累加）。

### 2.4 层次化架构感知规划器

规划器接收结构特征与策略排名，按照三个层次构建候选配置：

1. **第一层**：比较工作负载规模与 GPU 物理容量（SM 数、缓存、线程/寄存器限制），计算静态工作集与存储开销；
2. **第二层**：选择数据表示、并行分解与数据流算法；
3. **第三层**：确定目标 GPU 上的具体内核启动参数（线程数、共享内存、tile 尺寸等），并做资源合法性检查（式 13）。

规划器将表示与执行调度绑定为一个整体，避免分离优化导致的失配，同时保留多个独立搜索分支以维持多样性。

### 2.5 智能体驱动的迭代码生成与优化

系统包含三类 LLM 智能体（均调用 GPT-5.6-terra）：

- **编码智能体**：基于规划器给定配置，将已验证的稀疏机制（CSR/COO/ELL/SELL/BSR 转换工具、自适应分块、packed column windows、row binning 等）实例化为完整 CUDA 内核；
- **验证智能体**：编译、运行数值校验（与 cuSPARSE 对比，采用绝对+相对混合误差界限）、使用 CUDA events 测延迟，并使用 Nsight Compute 分析缓存命中率、L1/L2 请求、DRAM 带宽、占用率等指标；
- **迭代优化闭环**：将诊断反馈映射到 Π 的对应部分——如填充过多则改布局、负载不均则改并行分解、资源压力过大则改 θ_H，直至预算耗尽，取最快且数值合法的候选。

- **跨算子、跨 GPU 生成能力**：同一套流程无需人工干预即可在另一架构生成高效内核，具备较强的工程实用型。
- **系统成本低**：训练几乎免费，单矩阵生成约 30 分钟、约 20 美元成本，相比 AlphaSparse 的 9 小时/矩阵明显高效。
- 数值校验严格，并与缓存剖析分析结合，深入解释了“命中率不是终点、有效工作量才是”的现象，具有较强的说服力。

## 8. 不足与局限

- **LLM 依赖与成本不确定性**：GPT-5.6-terra 的模型选择固定，作者没有分析不同 LLM（更强的推理模型或开源模型）对生成质量的影响；$20/矩阵的 API 成本虽然低于 AlphaSparse，但对大规模批量使用仍构成实际门槛；论文中称 30 分钟主要受 LLM 推理限制，未给出在推理加速或本地部署场景下的数据。
- **泛化性验证存在边界**：虽然在第 60 个矩阵上做了跨架构验证，但全部组合仍集中在 SuiteSparse 可得的静态矩阵范围，缺少对动态/不规则稀疏结构、多 GPU 系统、矩阵维度极大 K（如 K>256）的验证。
- **对比基线存在代际偏差**：对 DTC-SpMM 与 HSMU-SpGEMM 的复测是在它们未设计目标的新 GPU/CUDA 上进行的，可能使对比结果偏向 SparseDitto；虽然论文如实报道了这一点，但读者仍需谨慎解读其绝对加速倍数。
- **SpGEMM 评测缺失部分任务**：7 个最大矩阵因 cuSPARSE 无法在其上完成 SpGEMM 而被排除，这些通常正是最需要高速内核的大规模场景，可能使 SpGEMM 平均加速比较乐观。
- **一次生成时间较长**：30 分钟每矩阵（即使是小矩阵）在大规模生产运维中仍可能显得昂贵；搜索效率的论文只给平均值，未给出迭代次数、分支数、失败率等详细的方差分析。
- **存在选择性报告风险**：论文报告几何平均而非中位数等其它指标，且未说明 60 个矩阵中有多少任务属于“失败”（在全部案例上是否都找到合法内核），建议关注其对 94% 之外 6% 失败案例的处理。
- **对 GCN 端到端实验只用了 Reddit 单一数据集**，且只替换了稀疏聚合内核，未证明在多数据集/多种模型结构上的普遍有效性。
