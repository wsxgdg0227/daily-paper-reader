## 摘要
稀疏矩阵内核对科学计算、图分析和机器学习至关重要。它们在GPU上的性能在很大程度上取决于输入的稀疏模式和执行策略。对于同一矩阵上的相同SpMM，cuSPARSE在CSR与Blocked-ELL之间的性能差距可达350倍。我们对多种数据格式、专用系统和稀疏编译器的研究表明，没有一种单一实现能在不同的稀疏模式和算子间始终占据优势。这促使我们构建一个能够针对每种工作负载和目标GPU自适应调整其表示、执行策略和硬件映射的系统。我们提出了SparseDitto，一个基于LLM的系统，可为每个矩阵、算子和目标GPU构建GPU内核。SparseDitto在统一设计框架内支持SpMV、SpMM和SpGEMM。轻量级可加模型利用输入矩阵的结构特征对既有策略进行排序。然后，架构感知规划器提出几种候选设计。编码和验证智能体利用目标GPU上的测量结果来实现并改进这些设计。在三种稀疏算子和多样化的矩阵集上，SparseDitto在NVIDIA RTX PRO 6000 GPU上相比cuSPARSE实现了2.68倍的几何平均加速，最高达146.61倍。在NVIDIA H200 GPU上达到2.79倍，最高78.5倍。其生成的SpMM内核还将全批次GCN训练加速最多3.39倍。

## Abstract
Sparse matrix kernels are fundamental to scientific computing, graph analytics, and machine learning. Their GPU performance depends strongly on the input sparsity pattern and execution strategy. For the same SpMM on the same matrix, cuSPARSE exhibits a 350x performance gap between CSR and Blocked-ELL. Our study of multiple data formats, specialized systems, and sparse compilers shows that no single implementation consistently dominates across sparsity patterns and operators. This motivates a system that can adapt its representation, execution strategy, and hardware mapping to each workload and target GPU.   We present SparseDitto, an LLM-based system that constructs a GPU kernel for each matrix, operator, and target GPU. SparseDitto supports SpMV, SpMM, and SpGEMM within a unified design framework. A lightweight additive model ranks established strategies using structural features of the input matrix. An architecture-aware planner then proposes several candidate designs. Coding and verification agents implement and refine them using measurements from the target GPU. Across three sparse operators and a diverse set of matrices, SparseDitto achieves a geometric-mean speedup of 2.68x over cuSPARSE on an NVIDIA RTX PRO 6000 GPU, with a maximum of 146.61x. On an NVIDIA H200 GPU, it achieves 2.79x, with a maximum of 78.5x. Its generated SpMM kernels also accelerate full-batch GCN training by up to 3.39x.

## 2. 方法论

### 核心思想
SparseDitto将稀疏内核构建定义为一个联合设计问题，通过**结构化特征分析 + 可解释的能量排序模型 + 架构感知分层规划 + LLM多智能体生成与实测反馈迭代**，为具体工作负载定制CUDA内核。

### 统一设计框架
每个候选配置表示为：
- Π = ⟨R, S, θ_H⟩；
- R = ⟨L, I⟩：数据表示（布局L + 稀疏元数据I）；
- S = ⟨P, D⟩：执行调度（并行分解P + 数据流D）；
- θ_H：硬件映射参数（tile尺寸、线程/共享内存配置等）。

### 关键技术细节
1. **结构特征提取（36个特征）**：
   - 内在特征（18个）：行/列非零分布、均值/最大值/CV、四分位数、空行占比、行跨度与局部性、16×16占用块覆盖率等；
   - 表示引入特征（8个）：ELL、SELL（3种切片高度）、BSR（b=4/8/16）的填充与存储扩张率（ρ_ELL、ρ_SELL、ρ_BSR）；
   - 算子引入特征（10个）：SpGEMM中间工作量（u_B(i)）、累加器适配统计（F_h）、输出压缩率（γ_B）等，用分层抽样估计。
2. **可解释能量模型（策略选择）**：
   - 加性结构：E_o(s|x) = β_o,s + Σ_j h_j(x_j)ᵀ w_{2,o,j,s}，其中h_j用tanh非线性基函数，跨算子共享；
   - 训练目标 = listwise似然损失 + 按速度差加权的pairwise margin损失；
   - 模型仅15.9K参数，在400矩阵语料上训练仅需约2秒（单GPU），推理耗时亚微秒。
3. **架构感知分层规划**：
   - 第1层：工作负载规模 vs 硬件容量（SM数、内存层级、线程/寄存器/共享内存上限）；
   - 第2层：选择算法、数据表示与执行调度；
   - 第3层：确定合法的launch配置（满足 B_t ≤ T_max、r_t·B_t ≤ R_max、S_t ≤ S_max）；
   - 维护静态存储与资源界：M_rep、M_R、M_T。
4. **LLM智能体迭代优化**：
   - 规划器（planner）、编码智能体（coding agent）、验证智能体（verification agent）共同协作；
   - 编码智能体将候选策略实例化为CUDA实现，验证智能体负责编译、数值正确性校验和NCU实测；
   - 针对padding过高、负载不均、缓存/工作集压力、资源占用等诊断，分层回溯修改Π中对应部分；
   - 搜索预算：3个策略分支×各5轮迭代，之后最优先2个分支再各5轮。
5. **支持的算子与策略**：SpMV（CSR/COO/SELL/BSR/自适应2D）、SpMM（增加了分块Tensor-Core策略）、SpGEMM（CSR-hash/共享内存哈希累加/混合累加）。
