## 摘要
记忆正在成为长周期LLM代理的核心基础设施，然而现有的评估对于在不同操作机制下应使用哪种记忆体（即记忆表示和存储的底层介质）提供的指导有限。我们提出了一种对记忆增强代理的记忆体进行受控测试评估，涵盖密集和稀疏索引、文本记录、结构存储、分层存储、基于细化的记忆、参数更新以及与激活兼容的上下文机制。在三个骨干模型和四个基准套件（涵盖以用户为中心的事实问答和以代理为中心的决策制定）中，我们在统一测试框架下测量了26项性能和效率指标。我们的结果表明，没有一种单一记忆体始终占优：广泛检索有利于长上下文事实问答，而过度的检索可能通过将注意力从行动关键上下文转移而损害顺序决策。可扩展性引入了进一步的路由轴，因为在中等因素的历史长度下表现良好的记忆体在更长的时间跨度下可能变得昂贵或脆弱。这些发现促使记忆体路由成为自适应代理记忆系统的必要组成部分，并为设计高效、可靠且感知机制的LLM代理长期记忆提供了经验指导。代码将在接受后提供。

## Abstract
Memory is becoming core infrastructure for long-horizon LLM agents, yet existing evaluations offer limited guidance on which memory substrate, namely the underlying medium in which memory is represented and stored, should be used under different operating regimes. We present a controlled harness evaluation of memory substrates for memory-augmented agents, covering dense and sparse indices, text records, structural stores, hierarchical stores, refinement-based memories, parametric updates, and activation-compatible context mechanisms. Across three backbone models and four benchmark suites spanning user-centric question answering and agent-centric decision-making, we instrument 26 performance and efficiency metrics under a unified harness. Our results show that no single substrate consistently dominates: broad retrieval benefits long-context factual QA, while excessive retrieval can harm sequential decision-making by shifting attention away from action-critical context. Scalability introduces a further routing axis, as substrates that perform well at moderate history lengths can become costly or brittle at longer horizons. These findings motivate substrate routing as a necessary component of adaptive agent memory systems and provide empirical guidance for designing efficient, reliable, and regime-aware long-term memory for LLM agents. ## 1. 论文核心问题与整体含义

### 1.1 研究背景
- 基础模型智能体正从单轮助手向**长程多轮场景**演进：编程助手跨PR积累项目上下文、网页智能体跨导航学习浏览模式、个人助手跨数百会话追踪用户偏好、科研智能体跨多轮迭代优化假设。
- 这些场景都面临共同挑战：**将新经验写入持久存储，在决策时读取相关知识，并在有限计算与存储预算下管理不断增长的记忆**。
- 不同记忆设计在准确性、效率、成本三个维度上存在根本权衡：
  - 向量索引写入成本低，但多跳检索能力弱；
  - 知识图谱关系推理能力强，但构建需比向量索引多出数量级的LLM调用；
  - KV缓存与模型集成紧密度高，但可扩展性差。

### 1.2 现有评测的三大缺陷
论文对2023—2026年间**52个记忆增强LLM系统**进行了全景分析（Fig. 1），揭示三个核心局限：
- **基准集中**：62%的"基准-系统"配对来自仅两个以对话为中心的数据集LoCoMo和LongMemEval；智能体任务几乎未被考察。
- **指标与骨干覆盖窄**：所有系统报告准确性，但仅21%报告任何效率维度；管理成本和压缩率完全未报告；81%的系统仅用GPT族作为骨干，无法区分记忆体效应与模型特有行为。
- **评估深度浅**：半数系统仅在单个基准上测试且零效率指标；没有系统能同时实现广泛覆盖与全面效率报告。

### 1.3 研究问题与核心主张
- 核心问题：**在不同任务场景和运行机制（regime）下，应选择何种记忆基板？**
- 主张：由于没有单一记忆体在所有场景中占优，**通用智能体记忆必须通过"记忆体路由"——在异构记忆体之间按场景动态选择或组合——来实现**。

## 2. 方法论

### 2.1 记忆体分类框架
论文采用已有工作的外部/内部记忆分类法：
- **外部记忆**（External Memory）：信息存储在模型外部的数据结构中，通过显式操作写入和检索，包括向量、文本记录、图、树和蒸馏抽象；
- **内部记忆**（Internal Memory）：信息编码在模型权重或KV缓存激活中，在生成时隐式访问，无独立检索步骤。

### 2.2 11种记忆方法（M1–M11）
| 家族 | 方法 | 技术要点 |
|---|---|---|
| 平面索引 (Flat Index) | **M1 Dense Vector** | 1536维OpenAI embedding编码，余弦相似度top-k检索；零LLM调用 |
| 平面索引 | **M2 Sparse Vector** | BM25倒排索引；零LLM调用 |
| 文本记录 (Text Record) | **M3 Gist Index** | 实现ReadAgent；LLM生成gist摘要，两级流水线（gist筛选→页面展开） |
| 结构化 (Structural) | **M4 Evolving Notes** | 实现A-Mem；带语义链接的结构化笔记，演化触发邻接重写 |
| 结构化 | **M5 Dual-Level Graph** | 实现LightRAG；实体-关系知识图谱+块级向量索引的混合检索 |
| 层次化 (Hierarchical) | **M6 Hierarchical Tree** | 实现RAPTOR；递归聚类+摘要生成多级树，折叠树密度检索 |
| 细化 (Refinement) | **M7 Distilled Strategies** | 实现ReasoningBank；LLM判断轨迹→蒸馏可复用策略→MaTTS索引 |
| 细化 | **M8 Skill Bundles** | 实现MemSkill（改：PPO控制器替换为零样本LLM，预填充所有skill bundle） |
| 权重 (Weight) | **M9 Adapter Tuning** | 实现LoRA-FA；LLM合成QA对→LoRA（r=8）基于答案损失微调 |
| 激活 (Activation) | **M10 Full Context** | 全文缓冲拼接基线；截断管理 |
| 激活 | **M11 Episode-Clustered Re-prefill** | 实现EpiCache（改：按utterance级重预填充而非in-place KV编辑）；聚类分集+25% token预算 |

### 2.3 受控评估原则
- **隔离实验变量**：仅将"记忆体"设为变量，保持骨干模型、提示模板、辅助LLM设置固定。
- **辅助LLM统一为GPT-4O-MINI**，LLM-as-judge使用共享评判模板。
- 三类配置被排除：M7仅适用于带轨迹的代理任务；M9与Gemma-4的A4B MoE路由不兼容；M10因超上下文窗口而排除于ALFWorld和BigCodeBench。

### 2.4 消融设计
- **Top-k检索广度扫描**：LoCoMo上k∈{1,2,5,10,20}；ALFWorld上k∈{1,2,3,4,5}；含无记忆基线。
- **上下文窗口压力测试**：MAB CR上三个长度档位（6K、32K、262K token）。
- **注意力探针**：从响应token观测四个区域（系统、检索块、任务上下文、线索提示）的注意力质量分布。

## 3. 实验设计

### 3.1 基准套件（4个）
**以用户为中心（User-Centric）**：
- **LoCoMo**：10个多会话对话、1986个问题、五大类别；
- **MemoryAgentBench (MAB)**：四种能力——准确检索（AR，具体化为LongMemEval-S，300条查询，每条约355K token）、长程理解（LRU）、测试时学习（TTL）、冲突消解（CR）。

**以智能体为中心（Agent-Centric）**：
- **ALFWorld**：134个valid-unseen具身规划任务，报告任务成功率（TSR）、目标条件成功率（GC success）、步数等；
- **BigCodeBench-Hard**：148个代码任务，PYTEST执行评分，跨任务成功/失败池构建检索库。

### 3.2 模型与资源
- 骨干模型：Qwen3-8B、Qwen3-32B-AWQ（GPTQ量化，AWQ）、Gemma-4-26B-A4B-IT（激活4B的MoE模型）——三个模型覆盖密集和MoE架构，参数量从8B到26B。
- 推理引擎：vLLM，部署在**4×H200 GPU**上。
- 辅助LLM（用于写入、管理、输入组织）：GPT-4O-MINI。

### 3.3 对比系统
- 主实验：M1–M11共11种记忆体（覆盖7大记忆体家族），加无记忆NoMem基线；
- 辅助成本分析（附录B.3）：Zep、Mem0、MemGPT三个生产级系统；因单次LoCoMo运行需2700–9000次辅助LLM调用（11–23小时），故排除于主对比之外。

### 3.4 指标（26项）
- **性能指标（P1–P6, P8–P12）**：精确匹配（EM）、Token F1、BLEU-1、LLM judge评分、压缩比（Compression Ratio）、Recall@k、任务成功率（Task Success）、GC Success、Steps-to-Goal、Pass@1、SubEM；
- **效率指标（E1–E15）**：记忆体大小、推理时间、写入延迟、检索延迟、写入tokens、写入调用、检索tokens、读取tokens、读取调用、管理tokens、管理调用、聚合总tokens、聚合总调用、总墙钟时间、每查询延迟。

### 3.5 分析
- **银行-测试语义对齐验证**（附录C.2）：验证ALFWorld和BigCodeBench评估池与离线库的语义相关性——通过text-embedding-3-small计算最近邻余弦相似度，与i.i.d.高斯随机向量对照，ALFWorld均值为0.879（随机基线0.068），BCB均值为0.594（随机基线0.061），排除了"检索无关文本导致排名退化为基础模型噪声"的威胁。

### 3.6 权衡
- 排除生产级系统（MemGPT、Mem0、Zep）的理由：辅助LLM成本过高，会主导运行时间和token计数列。
- 将MemSkill的PPO控制器改为零样本LLM，原因是RL训练会混淆跨记忆体对比。

- 消融研究：（i）LoCoMo上top-k扫描k∈{1,2,5,10,20}；（ii）ALFWorld上k∈{1,2,3,4,5}；（iii）MAB CR内容长度6K→32K→262K；（iv）注意力质量/分布探针分析；
- 对齐验证实验（附录C.2）：银行-测试语义相似性。

### 5.2 充分性与客观性
- **优点**：
  - 覆盖广，跨越用户中心和代理中心两类场景；
  - 同类控制严格，单一变量隔离，所有记忆体共享相同的交互历史；
  - 统一测量26项指标，首次使部署关键成本可见；
  - 跨三个骨干模型，包括不同架构和规模，探测模型间一致性 vs 差异；
  - 有银行-测试语义对齐验证。
- **局限性**：
  - 单个测试模型的规模范围有限（3个LLM），无ChatGPT-4o/GPT-5、Claude等更大非GPT制造模型；
  - 辅助LLM固定（GPT-4O-MINI），评估仅一个辅助模型，未探索辅助LLM变化对结果的影响；
  - M10（full-context）在ALFWorld和BigCodeBench中缺失——这是结构性缺席，但它作为一个重要基线被用于很多记忆体研究中；
  - M9权重微调完全不适用于Gemma-4-26B-A4B，M7仅针对轨迹任务评估；
  - 22项对比（M5 vs M4）中，单个数据集方差可能很大但没有置信区间报告——结果按点估计报告，无显著性检验。

## 6. 主要结论与发现

### 6.1 三大核心发现
1. **最优记忆体随场景反转** —— 结构化图（结构图谱）主导对话QA但无法在代理任务中占优，而细化记忆体主导具身规划但在QA上表现不佳。
2. **检索扩展方向相反** —— 深度top-k检索（LoCoMo ↑，ALFWorld ↓）会改变注意力分配：当答案位于检索记忆中时（QA）有用；当需要关注任务上下文（ALFWorld：观察+合法行动）时受害。注意机制显示："检索量"不是通用超参数，而是受记忆体限制的。
3. **可扩展性是第三路由轴** —— 在中等上下文规模上优秀的结构化记忆体（M4、M5）和全文激活记忆体（M10）在较长历史下变得不可行，而细化型记忆体（M7、M8）将写入成本摊销为固定大小的bundle，随历史增长保持质量/秒率高。

### 6.2 附加发现
- **记忆体成本呈重尾分布且常无回报** —— M5在LoCoMo上增加0.15至0.19 P4，但每查询延迟高10至30×；由于M4、M9、M11等在延迟上付出的代价无质量提升，效率成本反映的是"机制复杂度"而非"预期收益"。
- **记忆体家族无法预测端到端表现** —— 在同一家族内"Flat/Refinement"的范围比跨家族的范围更大，因此需要在记忆体级别而非家族级别做路由决策。
- **自主行动策略** —— 在ALFWorld上，M11（episodic clustering）和M7（strategy distillation）胜过其他方法，因为它们抑制了任务不相关的token，压缩了原始轨迹。

## 7. 优点（续）

- **评估范围和深度是论文最强亮点**：据作者所知，这是首个对LLM智能体内记忆体进行的完整测试，覆盖11种方法、7大记忆体家族、3个骨干模型、4个基准套件、26项指标——首次将"计算量—延迟"复杂度与"准确性—质量"表现纳入同一框架加以比较，使此前被忽视的部署成本维度变得可见、可审计。
- **受控实验设计严谨**：严格隔离记忆体作为唯一变量，固定骨干模型、提示模板与辅助LLM，保证跨方法可比性；对比辅以银行—测试语义对齐验证（附录C.2），排除"检索无关文本导致排名退化为噪声"的混淆威胁。
- **结论具有反直觉的实践洞察**：揭示"检索越多越好"这一默认假设的场景依赖性，并明确指出可扩展性是独立于准确率的第三路由轴，为系统设计者提供了超越benchmark排名的可操作知识。
- **跨架构测试提升了结论稳健性**：使用密集（Qwen3-8B/32B）与MoE（Gemma-4-26B-A4B）三类骨干，使观察到的记忆体效应更可能归因于记忆机制本身而非特定模型的归纳偏置。
- **开放性披露充分**：对生产级系统（MemGPT/Mem0/Zep）单独报告成本分析而非简单排除，保留了对规模效应的参考价值；排障理由（辅助LLM调用将主导时间列）透明清晰，便于读者判断可复现实验的边界。

---

## 8. 缺点与局限性

- **骨干模型覆盖面仍受限**：三个测试模型参数范围为8B–26B，未纳入GPT-4o/GPT-5、Claude等前沿大模型，也未测试更小的边缘部署模型（如1B级）；记忆体与骨干尺度之间的交互作用尚不清楚。
- **辅助LLM单一化**：所有写入/管理/组织操作都依赖GPT-4O-MINI，未探索使用更强或更弱的辅助模型如何改变记忆体间的相对排名——而实践中辅助模型的选择往往由成本驱动，是用户真正关心的变量。
- **关键基线缺失破坏矩阵完整性**：M10（Full Context）在ALFWorld与BigCodeBench中结构性缺席（受上下文窗口限制），而全文拼接恰是大量已有工作的对照基线，缺席弱化了代理场景中对比结论的说服力。
- **点估计缺乏不确定性量化**：22项两两对比未报告置信区间或显著性检验；鉴于单条LoCoMo轨迹可能引入大方差（如成本呈重尾分布），点估计排名可能不稳定，读者无从判断差异是否在噪声范围内。
- **记忆体内部超参数未充分扫描**：top-k消融仅覆盖检索广度这一单一超参数，而向量维度、聚类数、摘要比例、LoRA秩（固定r=8）等同样影响机制行为；部分方法（如M1的retriever与embedding模型）与所测骨干耦合较深，混入了检索器质量因素。
- **运行机制维度仅部分覆盖**：论文声称以"运行机制（regime）"为路由依据，但操作化主要体现为上下文长度档位变化；尚未系统操纵写入频率、错误率、记忆规模增长速率、多智能体并发等其他机制维度。

## 9. 对未来研究的启示

- **记忆体路由应被作为一等公民设计**：既然不存在普适最优记忆体，通用智能体架构不应将记忆实现固化，而应内置轻量、可学习的路由模块，依据任务类型（问答 vs 决策）、检索范围（short vs long）、成本预算（延迟敏感 vs 非敏感）动态选择记忆体家族乃至实例，并可借鉴MoE的路由思路进行端到端优化。
- **"检索量×任务上下文结构"值得更深建模**：ALFWorld的注意力探针表明，检索注入的token会稀释对任务上下文的注意力分配；这提示未来工作应当建模"记忆token的边际注意力价值"，设计显式的注意力预算分配机制，而非简单的top-k计数。
- **可扩展性应当成为标准报告指标**：在上下文长度6K→262K的压力测试下，记忆体排名发生明显翻转（M4/M5/M10在长历史下失效，M7/M8维持质量/秒率）。这意味着任何记忆体论文都应报告不同历史规模下的成本曲线，而非单一规模下的快照分数。
- **统一评测框架本身有开源价值**：本文构建的受控管线——同历史、同骨干、同辅助模型、同评判模板——如果随实现代码发布，可成为社区后续记忆工作的事实标准"测试台"，用于快速判定新方法与M1–M11基线集合的相对位置。
- **成本列应纳入主对照而非附录**：当前多数记忆研究仅在准确率上比较，导致高成本复杂机制（如M5图构建）看似"提升"实则相对于成本不可取；未来评估应默认呈现每查询延迟与调用数，让读者自行审视性价比。

---

## 10. 总体评价

这是一项工作量庞大、控制严谨、视角切中时弊的实证研究。它不试图提出新的记忆算法，而是充当"裁判"，在高同质化的记忆评测生态中首次亮出完整、多维、跨场景的比对矩阵。其最大理论贡献在于将"记忆体选择"从架构细节上升为需要显式路由策略的系统级问题；其最大实践贡献在于给出了成本—质量—可扩展性的经验法则，直接服务于研究者与工程师的记忆系统选型。受限于骨干规模、辅助模型单一性与点估计报告方式，结论的统计置信度仍有提升空间，但论文通过透明披露与受控对照，已为其核心主张提供了目前最高质量的实证支撑。

---

**一句话总结**：没有任何单一记忆体在所有场景中胜出——结构化记忆利于长上下文问答、细化记忆利于顺序决策、激活式记忆受制于可扩展性——因此自适应智能体必须在异构记忆体间进行动态路由，"记忆体路由"是构建可靠长期记忆的必要组件。
