## 摘要
稀疏矩阵内核是科学计算、图分析和机器学习的基础。其GPU性能在很大程度上取决于输入的稀疏模式和执行策略。对于同一矩阵上的相同SpMM操作，cuSPARSE在CSR和Blocked-ELL之间的性能差距可达350倍。我们对多种数据格式、专用系统和稀疏编译器的研究表明，没有任何单一实现在不同稀疏模式和运算符上始终占据优势。这促使我们开发一个能够针对每个工作负载和目标GPU自适应调整其表示、执行策略和硬件映射的系统。我们提出了SparseDitto，一个基于LLM的系统，为每个矩阵、运算符和目标GPU构建GPU内核。SparseDitto在统一设计框架内支持SpMV、SpMM和SpGEMM。一个轻量级加性模型利用输入矩阵的结构特征对既定策略进行排序。随后，一个架构感知规划器提出若干候选设计。编码和验证智能体利用目标GPU上的测量结果实现并改进这些设计。在三种稀疏运算符和多种矩阵上，SparseDitto在NVIDIA RTX PRO 6000 GPU上相对cuSPARSE实现了2.68倍的几何平均加速比，最高达到146.61倍。在NVIDIA H200 GPU上，实现了2.79倍的平均加速比，最高为78.5倍。其生成的SpMM内核还将全批次GCN训练加速了最多3.39倍。

## Abstract
Sparse matrix kernels are fundamental to scientific computing, graph analytics, and machine learning. Their GPU performance depends strongly on the input sparsity pattern and execution strategy. For the same SpMM on the same matrix, cuSPARSE exhibits a 350x performance gap between CSR and Blocked-ELL. Our study of multiple data formats, specialized systems, and sparse compilers shows that no single implementation consistently dominates across sparsity patterns and operators. This motivates a system that can adapt its representation, execution strategy, and hardware mapping to each workload and target GPU.   We present SparseDitto, an LLM-based system that constructs a GPU kernel for each matrix, operator, and target GPU. SparseDitto supports SpMV, SpMM, and SpGEMM within a unified design framework. A lightweight additive model ranks established strategies using structural features of the input matrix. An architecture-aware planner then proposes several candidate designs. Coding and verification agents implement and refine them using measurements from the target GPU. Across three sparse operators and a diverse set of matrices, SparseDitto achieves a geometric-mean speedup of 2.68x over cuSPARSE on an NVIDIA RTX PRO 6000 GPU, with a maximum of 146.61x. On an NVIDIA H200 GPU, it achieves 2.79x, with a maximum of 78.5x. Its generated SpMM kernels also accelerate full-batch GCN training by up to 3.39x.

### 2. 论文提出的方法论

**SparseDitto** 是一个基于 LLM 的智能体系统，核心思想是将"工作量本身作为数据"——通过结构分析指导 LLM 聚焦搜索，再通过目标 GPU 的实测结果解决架构相关的未知性。

#### 统一设计框架
每个候选配置表示为 **Π = ⟨R, S, θ_H⟩**，其中：
- **R = ⟨L, I⟩**（表示）：L 为数据布局（分组、重排序、填充、值放置），I 为稀疏元数据（内核如何遍历矩阵）。
- **S = ⟨P, D⟩**（执行计划）：P 为并行分解（将稀疏迭代空间映射至 CTA/线程），D 为数据流（操作数移动与累积策略）。
- **θ_H**：硬件特定参数（块大小、启动配置、共享内存用量）。

该框架统一覆盖了 SpMV、SpMM 和 SpGEMM 三种算子。

#### ① 结构分析与特征提取（§3.1）
计算 **36 个结构特征**，分为三类：
- **18 个固有模式特征**：行/列长度分布（均值、最大值、变异系数 CV、分位数）、空行比例、行跨度与局部性、对角线邻接度、16×16 块覆盖率等，外加行分布的五类汇总（均匀、中等、偏斜、幂律、双峰）。
- **8 个表示诱导特征**：计算各类格式带来的值槽扩张率，如 ELL 的 ρ_ELL = m·max_i r_i / nnz(X)、SELL-c 的切片局部填充、BSR-b 的块填充因子等，评估存储开销。
- **10 个算子诱导特征**：针对 SpGEMM 推导每行中间产物数 u_B(i)，包括其总量/最大值/p95/CV、累加器适配统计 F_h（行数低于容量 h 的占比）和输出压缩比 γ_B。

#### ② 能量模型策略选择（§3.2）
- 用一个**可解释的加性排序模型**对已知优化策略排序，策略词汇表 V_o 按算子区分（SpMV 含 CSR/COO/SELL/BSR/自适应2D块等；SpMM 在其上增加 Blocked-ELL 和 Tensor-Core 策略；SpGEMM 含 CSR-hash、共享内存哈希、混合累计）。
- 模型数学形式：
  - 每个标量特征 x_j 经共享非线性基映射：h_j(x_j) = tanh(x_j·w₁ⱼ + b₁ⱼ) ∈ R¹⁶；
  - 各算子独立读出头：E_o(s|x) = β_{o,s} + Σⱼ h_j(x_j)ᵀw₂,ₒ,ⱼ,ₛ；
  - 能量越低表示策略推荐度越高。
- 训练目标融合 listwise 似然（对实测 log 加速比做软目标）和 gap-weighted pairwise margin 损失（按实测加速差惩罚排序错误），直接基于实测运行时间训练。
- 加性结构使每个推荐均可分解为逐特征解释，供规划器使用。

#### ③ 分层架构感知规划器（§3.3）
- **Level 1（规模评估）**：计算静态工作负载界限（表示占用 M_rep、读侧工作集 M_R、总工作集 M_T），与 GPU 缓存能力、SM 数量等物理资源比较。
- **Level 2（算法+表示选择）**：从策略排序结果出发，将表示、元数据、并行分解和数据流绑定成具体候选配置。
- **Level 3（硬件配置约束）**：验证块大小和线程数满足硬件上限（B_t ≤ T_max, r_t·B_t ≤ R_max, S_t ≤ S_max），绑定启动几何与可用资源。
- 初始迭代均匀分配搜索分支以保持多样性，后期聚焦最快分支。

#### ④ 迭代编码与验证（§3.4）
- 提供 CSR/COO/ELL/SELL/BSR 格式转换与元数据构建工具，以及自适应 16×16 块、打包列窗（SpMM）、上限分析和行分箱（SpGEMM）等构建模块。
- **编码智能体**将方案实现为 CUDA 内核；**验证智能体**执行编译、数值正确性校验（混合绝对/相对误差界）以及目标 GPU 实测延迟 + NCU 剖析。
- 剖析反馈（填充过多→改布局、负载不均→改并行分解、资源压力→改硬件参数）进入下一轮规划迭代，直至选出最快的合法内核并缓存复用。

### 6. 论文的主要结论与发现

- **跨算子总加速**：相比 cuSPARSE，在 RTX PRO 6000 上几何平均加速 **2.68×**（95% CI [2.48, 2.89]）；在 H200 上 **2.79×**（95% CI [2.61, 2.99]），两者区间有重叠。最大单任务加速达 **146.61×**（RTX）和 **78.5×**（H200）。
- **SpMV**：RTX 2.53× / H200 2.68×；在相同输入上比 CB-SpMV 快 **1.91×/1.57×**；比 AlphaSparse（限 13 个成功矩阵）快 5.34×。
- **SpMM**：RTX 上 K=8 时 4.46×，K=256 时缩小至 1.68×（增益随稠密宽度增大而收窄）；比 SparseTIR 快 **1.57×**、比 DTC-SpMM 快 **3.99×**（DTC-SpMM 在 Blackwell 上全部宽度均慢于 cuSPARSE）。
- **SpGEMM**：RTX 3.70× / H200 4.09×，中位数 4.82×，最大 146.61×；比 HSMU-SpGEMM 在匹配输入上快 **5.37×**（RTX）/ 13.60×（H200），且支持 HSMU-SpGEMM 不支持的矩形输入。
- **速度来源剖析**：快的原因不是更高的缓存命中率，而是**发起了更少的无谓请求、保持接近 2 倍的驻留线程数、达到约 2 倍 DRAM 带宽**。相对的，SparseTIR/HSMU-SpGEMM 的高 L1 命中率只是"重复读取已存数据"，并没减少有效工作量；DTC-SpMM 的 Tensor Core 管线利用率仅 1.5%（块中位数占用率仅 10.1%），硬件空转导致其反而更慢。
- **消融结论**：任务仅描述→模式特征→架构感知规划逐级可提升性能（如 SpGEMM 从 1.22×→2.24×→3.70×），说明结构分析和架构意识均提供了实际帮助。
- **先验之外的有效探索
