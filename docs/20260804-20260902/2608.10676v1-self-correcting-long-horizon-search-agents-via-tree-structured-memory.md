## 摘要
大语言模型（LLM）为基础的搜索代理通过与外部环境的多步交互来回答问题。然而，将完整执行轨迹提供给LLM会导致上下文无界增长并引入噪声。现有压缩方法以牺牲重要细节为代价减少上下文，且经常替换错误事实而不修复由它们推导出的下游推理。为解决此问题，我们提出ReTree，一种用于搜索代理的自我修正树结构记忆机制。ReTree构建有界的逐步推理上下文，同时保留源链接证据。它将搜索建模为证据树，其节点存储有界摘要、证据和修订历史。当新检索到的证据与早期声明矛盾时，ReTree回溯到引入该声明的节点，替换过时证据，重新生成摘要，修剪受影响的分支，并恢复搜索。基于源的证据溯源支持可靠的冲突定位，并最终使声明可追溯至检索到的段落。在四个公开问答和搜索基准上的实验表明，ReTree始终优于完整轨迹ReAct，将答案准确率提高最多25.6个百分点（pp）；完整轨迹ReAct的平均最大每步推理上下文是ReTree的$1.27$--$1.51$倍。这些结果使ReTree成为长程搜索的有效自我修正记忆抽象。

## Abstract
Large language model (LLM)-based search agents answer questions through multi-step interactions with external environments. However, providing complete execution trajectories to the LLM causes unbounded context growth and introduces noise. Existing compression methods reduce context at the cost of important details and often replace erroneous facts without repairing downstream reasoning derived from them. To address this problem, we propose ReTree, a self-correcting tree-structured memory mechanism for search agents. ReTree constructs a bounded per-step reasoning context while preserving source-linked evidence. It models search as an evidence tree whose nodes store bounded summaries, evidence, and revision histories. When newly retrieved evidence contradicts an earlier claim, ReTree traces back to the node where the claim was introduced, replaces outdated evidence, regenerates summaries, prunes affected branches, and resumes search. Source-grounded evidence provenance supports reliable conflict localization and keeps final claims traceable to retrieved passages. Experiments on four public question-answering and search benchmarks show that ReTree consistently outperforms Full-Trajectory ReAct, improving answer accuracy by up to 25.6 percentage points (pp); the average maximum per-step reasoning context of Full-Trajectory ReAct is $1.27$--$1.51\times$ that of ReTree. These results establish ReTree as an effective self-correcting memory abstraction for long-horizon search.

*   **研究动机与问题背景**：LLM 搜索代理需要通过与外部环境的多步交互来回答跨文档、多跳的知识密集型问题。然而,标准的"完整轨迹"状态管理存在两个互相关联的缺陷：

    2.  **错误级联难以修复**：检索本身不可靠（可能引入陈旧或冲突信息）。如果早期一个错误前提被采纳，它会误导后续检索和推理，造成"错误级联"。已有压缩方法仅做扁平汇总，在精炼时丢失事实级溯源信息，错误事实即便被替换，也无法主动使依赖它的下游结论失效。
*   **整体含义**：本文把长程搜索中的记忆管理定义为一个"结构化状态修复"问题——既需要**有界的逐步推理上下文**，又需要**声明到证据源的溯源**，还需要**依赖一致的修订（dependency-consistent revision）**。作者提出的 ReTree 通过树状工作记忆实现自我修正的搜索代理，在提高答案准确度同时大幅压缩策略的上下文负担。

## 2. 论文提出的方法论

*   **核心思想**：与常见用树来组织"备选推理路径"或"候选思想"不同，ReTree 的证据树是**状态演化和修订历史之上的依赖树**，记录证据进入状态的位置和由它推导出的后续状态。策略只接触活跃路径上的有界摘要和 top-k 证据，外部树结构保存完整证据谱系和修订记录。
*   **节点结构**：每个节点 $n=(s_n, E_n, H_n, p_n)$ 由 4 部分组成：
    *   $s_n$：紧凑任务状态摘要（最多 140 词），记录请求的答案槽位、已解决/待解决的中间槽位、未解决候选；
    *   $E_n$：在该节点本地引入的证据对象集合（原子事实 + 稳定 ID + 源 URL）；
    *   $H_n$：修订历史；
    *   $p_n$：指向父节点的指针。
*   **上下文构建公式**：$C_k(M_t, q)=s_{n_t} \,\|\, \text{TopK}_k(A(n_t), q\|s_{n_t})$，其中 $A(n)=\bigcup_{v\in \text{path}(r,n)} E_v$，$k=5$。由于摘要和证据数量均有固定上限，逐步推理上下文复杂度可视为 $O(1)$，不随轨迹长度增长。
*   **检索与展开**：每次搜索最多返回 5 段，提取器生成不超过 6 条原子事实，以"段落序号绑定"而非要求模型复述 URL 的方式关联来源（避免不可验证的引用错误）。若新事实与当前路径兼容，则创建子节点并压缩摘要，结构上呈追加式增长（保留事实进入轨迹的位置）。
*   **冲突判定与回溯修复**：
    *   冲突检测要求新证据与既有事实对同一 "实体-属性-范围-时间" 给出不相容取值，才允许回溯；不同实体含义、细化或竞争但兼容的候选会扩展树而非回滚。
    *   二次确认调用要参考分支摘要、目标事实、新证据与目标变更历史，减少震荡（避免在已经拒绝过的取值间反复跳动）。
    *   一旦冲突确认，回溯至引入被否证证据的节点：替换证据原文与来源 → 向修订历史追加记录 → 仅基于修正后的累积证据重新生成节点摘要 → 裁掉所有后代分支 → 以修复节点为当前节点恢复搜索。
*   **形式化保证（公式 4）**：$Dep_{t-1}(j) \subseteq I_t \cup G_t(e'_j)$。含义是记忆更新时需要将每个依赖被修订证据的状态分量，要么置为无效（invalidation），要么在纠正后证据下重新生成（regeneration）。
*   **Claim 级归因链路**：$c_i \to j \to (x_j, u_j) \to \text{Passage}(u_j)$——答案生成器将推理拆为原子声明，给每个声明绑定证据 ID；运行时的证据映射可解析到最新证据文本与 URL，再由 NLI 判断声明的引文能否由原始段落蕴含。
*   **算法流程**（Algorithm 1）：初始化带有根节点的树 → 循环（构建上下文 → 策略选择 query 或 stop → 若条件满足则停止；否则检索、提取、冲突建议、修订确认）：冲突确认后修复更新；否则展开子节点 → 输出支持引用的答案。

## 7. 优点

*   **问题定位新**：把检索引入的错误级联形式化为"状态修复问题"，提出三个联合需求（有界上下文、声明溯源、依赖一致修订），并将老式真值维护系统（TMS）思想适配到现代 LLM 搜索循环中。
*   **可验证的证据锚定**：来源按检索段落序号绑定而非要求 LLM 输出 URL，显著降低"幻觉引用"风险；更新后仍可用证据 ID → 最新证据文本 → 原始段落的链路解析到真实检索内容。
*   **有界且可控的上下文设计**：策略只见固定宽度摘要 + top-k 证据，使其逐步推理复杂度与轨迹长度解耦，同时保留完整证据在外存中的可查性。
*   **结构性修复明确**：不必逐句比对诊断、修完一个事实再修另一个，而是通过祖先关系直接把"由被否证前提推导出的全部后续状态"定位为不可信并剪除，避免错误传播；同域冲突规则及两次确认机制降低破坏性修复风险。
*   **对比设计干净**：Full-Trajectory ReAct / FlatUpdate / ReportMemory 三个对照从不同方向将问题拆开——无界保留、扁平修订、纯浓缩报告分别对应历史日志式、记录式与报告式内存，为"树状内存 + 依赖剪枝"的增量价值给出量化边界。
*   **多维度评估**：除准确率/EM 外还测引文精度与召回、每步上下文增长率、调用次数与 token 开销，归因不用孤立声明而按被引段落做 NLI 蕴含验证，模型评估比通常做法更严格。

## 8. 不足与局限

*   **硬剪枝（over-invalidation）**：把祖先关系当作语义依赖的保守代理，会导致实际上与修订前提无关的存留事实被误删，保守但浪费冗余检索与再生成本。作者指出没有显式依赖图时，这个设计是主动向"修复安全"妥协。
*   **冲突判定质量是上限瓶颈**：误报（false negative）会让污染继续留在状态中，误报（false positive）会剪掉有用证据，同域规则只能缓解而非消除风险；论文未附冲突分类的端到端精确率/召回率分析。
*   **运行成本与规模**：扩展时外部证据库存量线性增长，证据选择与树遍历逐步使变慢；修复包本身需要更多模型查询（ReTree 比 FlatUpdate 多用 7–11% 调用和 10–13% token），在大规模部署中可观。
*   **适用范围窄**：面向"单次长程搜索任务"的工作记忆机制，假设目标是对某一问题的主动搜索分支进行修复，不合适需要无约束回忆一切历史陈述的被动记录场景。
*   **实验覆盖有限**：只有 Qwen3-8B 一个主干模型；没有检验更大/更小的 LLM、不同检索后端或不同预算 k；没有参数敏感性分析；归因诊断只局限于 600 题 FRAMES 子集；4 个数据集都是英文问答为主，缺少其他语言与任务形态；由于"实时检索导致的网络方差"，未报告实际墙钟时间也无高质量错误案例讨论。
*   **评测依赖 LLM 判断**：Judge Accuracy 依赖 GPT-5 自动评分；即便设有类型约束，裁判偏差对排名影响的敏感性验证有所缺失。论文未披露可重复性细节（检索日志快照、Prompt 模板、随机种子敏感性差异），进一步复现存在落地门槛。
