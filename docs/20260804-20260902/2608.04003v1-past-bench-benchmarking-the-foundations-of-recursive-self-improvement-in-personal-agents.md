## 摘要
递归自我改进要求智能体将积累的经验转化为更好的未来行为。个人AI智能体为研究这一能力提供了一个具体场景，因为它们会在会话之间保留偏好、任务历史、工具例程和学习到的技能。然而，保留的经验是否真正随着时间的推移改善它们，尚未被系统性地测试。我们引入了PAST-Bench，一个旨在隔离这一问题的基准。每个智能体在匹配条件下运行一系列有序的全新会话任务，这些条件会打开或关闭保留的经验。它涵盖了26个场景和204个情节，涉及记忆、程序复用、信息收集和更新。我们报告了后续任务的收益，以及这些收益是否遵循预期的保存、检索和更新路径。在七个基础模型和四个智能体框架中，改进是真实的，但在能力上并不均衡。具有相同总体收益的智能体，在收益是否得到预期路径证据支持方面可能存在显著差异。在这些发现的指导下，我们开发了Hermes+，它通过跨越智能体循环各阶段的五项针对性干预扩展了Hermes。Hermes+提高了从保留经验中获得的平均收益，并提供了更清晰的路径证据，其最大的改进出现在需要替换过时状态的任务上，尽管效果仍然依赖于能力和模型。总的来说，PAST-Bench和Hermes+为研究持久智能体如何从保留经验进步到通过经验系统性改进提供了一个评估和诊断基础。代码：https://github.com/Gen-Verse/PAST-Bench

## Abstract
Recursive self-improvement requires agents to turn accumulated experience into better future behavior. Personal AI agents offer a concrete setting for studying this capability because they retain preferences, task histories, tool routines, and learned skills across sessions. Yet whether retained experience actually improves them over time has not been systematically tested. We introduce PAST-Bench, a benchmark designed to isolate this question. Each agent runs through ordered sequences of fresh-session tasks under matched conditions that turn retained experience on and off. It spans 26 scenarios and 204 episodes across memory, procedural reuse, information gathering, and update. We report both later-task gains and whether those gains follow the intended save, retrieve, and update pathway. Across seven base models and four agent frameworks, improvement is real but uneven across capabilities. Agents with the same headline gain can differ markedly in whether that gain is supported by evidence of the intended pathway. Guided by these findings, we develop Hermes+, which extends Hermes with five targeted interventions across stages of the agent loop. Hermes+ raises the average gain from retained experience and provides clearer pathway evidence, with its strongest improvement on tasks requiring outdated state to be replaced, although the effect remains capability- and model-dependent. Together, PAST-Bench and Hermes+ provide an evaluation and diagnostic foundation for studying how persistent agents can progress from retaining experience to systematically improving through it. ## 1. 核心问题与研究背景

- 论文聚焦 **递归自我改进（Recursive Self-Improvement, RSI）** 中一个更基础、可操作的问题——**在线自我演化（online self-evolution）**，即个人 AI 智能体能否将在过往会话中积累的经验（偏好、任务历史、流程技能、会话记录等）真正用于改善未来全新会话中的任务表现。
- 现有智能体评测通常只评估单次会话、单任务得分，无法区分性能提升究竟来自保留经验，还是来自基座模型能力、运行时设计、提示词捷径或任务难度波动。记忆/技能评测则往往只测试孤立组件，缺少能分离“保留经验贡献”的匹配对照。
- 作者提出一种 **性能归因（performance-attribution）问题**：如果后续任务表现提升，这种提升是否真的源于持久化经验，并且是否沿用了预期的“保存→检索→应用→更新”通路？
- 该问题为更强形式的递归自我改进提供了行为与基础设施层面的评估基础，同时避免将效果混同于上下文传播或一次性任务得分。

## 2. 方法论

### 核心思想

- 以 **任务族（task family）** 为基本评测单元，而非单次任务：
  - **早期情节（episodes）** 给智能体提供保存可复用经验的机会；
  - **后期情节** 测试是否实际复用了这些经验；
  - **匹配对照组**关闭持久化，使后期增益相对“无持久化基线”可解释；
  - 每次新情节都刷新会话语境，确保任何跨情节改进必须通过持久化基底（记忆、技能、会话历史）流动。

### 覆盖四种核心能力与任务设计

- **Memory（记忆）**：5 个场景 / 41 个情节——保留用户偏好、约束、例外清单等声明性事实，要求“一次性查找并应用”。
- **Procedural Reuse（程序复用）**：8 个场景 / 64 个情节——保存多步骤工程的 SOP/playbook，要求按顺序执行正确的工具组合。
- **Information Gathering（信息收集）**：6 个场景 / 48 个情节——将答案预置于持久层，测试智能体是否能在干扰信息存在时主动检索而非猜答。
- **Update（更新）**：7 个场景 / 51 个情节——用新的权威写入覆盖旧状态，并测试旧状态不会泄漏。

### 对照与角色设计

- 单个家庭内角色包括：冷启动（cold）、学习（learn）、评测（evaluation）、控制（control）。
- 控制组类型包括：无保留控制、干扰控制、过期状态控制、错误机制控制，用于排除“提示捷径、表面记忆、过期复用、写入错误基底”等替代解释。
- 评测条件：**persistence-off（无经验）与 persistence-on（有经验）配对对照**，两者使用相同提示、评分器、工具栈和随机种子；差距 Δ 用于度量自演化的真实效果。

### 报告指标

- 任务分（task score，每个情节在[0,1]范围，综合完成度、鲁棒性和安全门控）；
- 自演化差距 Δ = S^w/-evolve − S^w/o-evolve（任务族内求平均后宏平均）；
- 机制证据分（Mech）：基于跟踪日志判断 `write-precision, recall-accuracy, update-correctness, retention-horizon, pollution-rate` 五要素，确认收益是否来自预期持久化路径，而不是仅凭任务分提高。

## 3. 实验设计与基准

- **基准**：PAST-Bench，共 26 个场景 / 204 个情节任务。所有任务为合成数据，不包含真实用户数据；任务和评分器由两种模型-代理组合（Codex+GPT-5.4、Claude Code+Claude Opus 4.6）生成，并经过至少一位作者人工检查。
- **对比方法**：
  - 七个基座模型：GLM-5.1、Kimi K2.6、DeepSeek-V4-Pro、MiniMax-M2.7、GPT-5.4、Claude Sonnet 4.6、Claude Opus 4.6。
  - 四类个人智能体框架：Hermes、nanobot、ZeroClaw、Agent-Zero。
  - 另测试两个通用代理（Codex CLI、Claude Code）。
- **Hermes+**：在 Hermes 的五个 agent loop 阶段（Plan、Render、Route、Gate、Close）加入五种机制：
  - E1（Plan）：规划前咨询持久化状态；
  - E2（Render）：记忆绑定类型化渲染，只露出当前有效值；
  - E3（Route）：将技能保存为可检索、可补丁的技能库并排序；
  - E4（Gate）：在动作前强制检索相关持久化渠道；
  - E5（Close）：会话结束同步提取更新后的绑定，写为权威状态并刷盘。

## 6. 主要结论与发现

1. **保留经验确实带来改善，但具备能力特异性和模型特异性**：所有七种基座模型在总体 Δ 上均为正（+0.13 ~ +0.24），但各模型在四种能力上的增益分布差异很大（有的强于 Update，有的强于 Memory）。
2. **相同“总体增益”可能掩盖完全不同的质量**：
   - Hermes 与 nanobot 的 Overall Δ 均为 +0.13，但 Mech 分数分别为 0.64 vs 0.57；说明 nanobot 更多地依赖单一能力提升，缺少统一的“写入再读出”路径，机制证据不足。
   - Agent-Zero 甚至在三个能力上退化（Overall Δ = −0.08），说明单一架构并不总是受益于持久化。
3. **诊断出的共性故障点驱动了 Hermes+ 的设计**：在每条会话循环的对应阶段加入五种干预后，Hermes+在 Update 能力上提升最明显（Δ = +0.24，显著优于任何单一机制），Overall Δ 从 +0.13 提高到 +0.15，Mech 从 0.64 提升至 0.73，但其 Procedural 增益略有下降。
4. **跨模型迁移效果不完全一致**：Hermes+（在 MiniMax-M2.7 上调优）对比 Hermes 基线，在 MiniMax-M2.7、Claude Sonnet 4.6 上增益提升；在 GPT-5.4 上持平；在 DeepSeek-V4-Pro 与 Claude Opus 4.6 上略有倒退。
5. **Mech 与 Δ 应同时汇报**：机制证据分数揭示了任务得分无法识别的路径差异，且对关键词过重等变化具有一定敏感性，但仍可作为稳定的路径信号。

## 7. 主要优点与创新

- **方法视角新颖**：将自演化评测从“单次任务分”前移到“跨会话的保留经验归因”，用匹配的持久化 on/off 控制清晰剥离了模型、任务难度、运行时与持久化本身的作用。
- **实验设计严谨**：严格控制上下文清除、保留状态开关、固定种子/提示词/工具栈，确保 with/without 差距具有可比性。
- **双轴报告机制**：同时提供行为结果（Task score / Δ）和路径证据（Mech），使“确实变好”与“按预期方式变好”这两个问题被单独考察，避免对伪提升的误判。
- **诊断驱动的改进路径**：Hermes+ 的五项修改在 agent loop 的独立阶段实现，支持逐个开关和机制消融，便于研究机制与能力的因果关系。
- 附带了人工验证的 LLM 评分器、机制证据敏感性分析、运行方差与成本报告，提升了鲁棒性和透明度；人类评分与 LLM 一致性较好（within 0.25 约 92%）。

## 8. 不足与局限

- 数据缺少真实用户、人类编写任务和跨任务族的长程干扰，限制了对现实应用中经验长期保持、冲突、冗余等问题的解释力。
- 能力覆盖仍局限于记忆、程序复用、信息收集与更新，尚未覆盖更强形式的递归改进，如策略自优化、元认知机制更新、多代理经验共享等。
- 机制证据分数（Mech）只表明行为与预期持久化路径一致，而无法证明因果必要性；建议未来加入删改伪造工件的反事实干预。
- 主要调试与改进验证基于单个框架（Hermes）与单一基座模型（MiniMax-M2.7），在其它框架中的可迁移性未得到完整证明，Agent-Zero/nanobot 等框架由于自带持久化栈不适合做干净的机制消融。
- 合成任务可能造成“高分”不等于现实鲁棒性，且生成任务中存在模型偏差；OpenAI/Anthropic 等 API 的内部上下文策略也可能影响绝对分数差异。
