## 摘要
尽管大语言模型（LLM）智能体日益依赖长期记忆进行持久交互，但控制这种记忆的检索机制却很少被视为可进化的组件。这种静态方法在异构记忆查询上限制了性能，因为这些查询往往需要多样化的证据构建策略。为解决这一问题，我们提出了**ERSkill**，一个以检索为中心、用于自进化技能引导记忆访问的框架。ERSkill将交互历史编译为结构化记忆存储，并将检索行为表示为由基本原语组成的可执行技能。在推理时，训练好的路由器动态地将每个查询匹配到最优技能，以构建针对性的证据用于答案生成。为了实现持续改进，ERSkill在训练过程中共同进化技能集和路由器。它利用经验字典树（experience trie）高效记录已探索的检索路径，并采用双前沿机制，将新技能能力的扩展与面向路由器的稳定部署安全解耦。跨多个智能体记忆基准的实验表明，ERSkill显著优于强大的非进化和自进化基线。值得注意的是，在使用Qwen3-Next-80B-A3B-Instruct时，它在F1、BLEU-1和LLM-judge分数的整体平均值上提高了31.3%，在使用GPT-5.4-nano时提高了28.1%。

## Abstract
While Large Language Model (LLM) agents increasingly rely on long-term memory for persistent interactions, the retrieval mechanisms governing this memory are rarely treated as evolvable components. This static approach limits performance on heterogeneous memory queries, which often demand diverse evidence construction strategies. To address this, we introduce \textbf{ERSkill}, a retrieval-centric framework for self-evolving, skill-guided memory access. ERSkill compiles interaction histories into a structured memory store and represents retrieval behaviors as executable skills composed of fundamental primitives. At inference time, a trained router dynamically matches each query to the optimal skill to construct tailored evidence for answer generation. To enable continuous improvement, ERSkill co-evolves the skill set and the router during training. It employs an experience trie to efficiently record explored retrieval paths, alongside a double-frontier mechanism that safely decouples the expansion of new skill capabilities from stable, router-facing deployment. Experiments across multiple agent memory benchmarks demonstrate that ERSkill substantially outperforms strong non-evolving and self-evolving baselines. Notably, it improves the overall average across F1, BLEU-1, and LLM-judge scores by 31.3\% with Qwen3-Next-80B-A3B-Instruct and by 28.1\% with GPT-5.4-nano.

## 2. 方法：ERSkill 的核心思想与关键技术

### 2.1 总体框架
- ERSkill 把“记忆访问”建模为**技能引导的证据构建**。它先将交互历史编译成结构化记忆存储；在训练阶段让**技能库与路由器协同进化**；在推理阶段由路由器为每个查询选择最匹配的检索技能，执行该技能构造证据片段，再交给 LLM 生成答案。

### 2.2 结构化记忆与检索原语
- **记忆存储**`M(D)=(A, I, G)`：
  - `A`：原子级记忆记录（atom），每个原子存储文本、元数据、时间戳和实体集合。
  - `I`：多种索引（如向量索引、实体-原子索引、BM25统计），用于从不同入口检索原子。
  - `G`：图结构（相似度图、带类型的关联图与时间相邻关系），用于从初始结果向外扩展。
- **检索原语库（Primitive Library）**，论文冻结原语集合、只进化插入顺序和组合方式：
  - 搜索类：`entity_search`、`lexical_search`、`dense_search`；
  - 扩展类：`temporal_focus_expand`、`similarity_expand`、`relation_expand`；
  - 处理类：`llm_process`（用于查询改写、过滤、生成控制信号，如时间范围或偏好关系类型）。

### 2.3 检索技能与路由器
- **检索技能**定义为`κ=(c_κ, ρ_κ)`：`c_κ`记录技能描述与信息偏好，`ρ_κ`是一条按顺序执行的原语序列。技能产出“证据视图”，也是可复用、可解释且可被优化的程序。
- **技能路由器**`R_θ(κ|q,K)`：将查询和每个技能编码（使用冻结文本编码器，如 Qwen3-Embedding）后输入可学习的打分网络（线性投影+MLP），再用 softmax 在技能集上形成概率分布。该路由器可以泛化到新生成的技能，只要把新技能的文字描述编码进来即可。
- **推理过程**：路由器选择最高分技能`π_θ(q;K)`，执行该技能得到最终证据状态，再调用 LLM（`f LLM(q, s_L)`）生成答案。

### 2.4 技能-路由器协同进化
- **核心思路**：训练时反复从历史查询-技能回放中分析当前技能的覆盖空洞和冗余，生成新技能候选，同时更新路由器参数。
- **经验字典树（Experience Trie）**：由于技能是固定原语库上的序列，一个字典树可以统一存储所有出现过的原语前缀及其回放/验证/前沿状态。它允许模型“看到”已探索的路径，避免重复提出等价技能，也能把被拒绝的候选保留下来引导后续探索。
- **双前沿机制（Double-Frontier）**：
  - **能力前沿`C_t`**：只保留有“oracle 价值”的技能，即在假设可以选到最优技能时能提高任一查询的证据能力。它负责记录检索能力的边界。
  - **部署前沿`B_t`**：面向路由器选择，只放行经验证可由路由器可靠选择的技能，保证部署稳定。
  - 更新时先根据训练批生成临时能力前沿，过滤候选；再在验证集上重算最终能力前沿，最后仅在满足增益或紧凑性条件时更新部署前沿。
- **数学化的关键运算**：
  - 技能效用：`Util(κ;Q)=avg_q r(q,κ)`；
  - Oracle 覆盖：`OCov(K;Q)=avg_q max_{κ∈K} r(q,κ)`；
  - 前沿重算`Φ(K;Q)`：按效用排序，仅移除“不使任何查询的 oracle 分值下降”的技能；
  - 路由器训练：用回放得到的技能分数构造软标签，最小化软标签交叉熵；
  - 部署前沿接受条件：`Δ_route≥γ_route`，或`(Δ_route≥−ξ_drop 且部署集更紧凑)`，其中`Δ_route`为新旧部署前沿在路由评估下的验证集得分差。
- **理论保证**：论文证明两个前沿的验证集 oracle 覆盖率在每步进化中都不下降（Proposition 2.1）。

## 4. 主要结论与发现

- **主结果**：ERSkill 在两个骨干 LLM 上都取得最优的总体平均表现；相比最强基线，F1、BLEU-1 和 LLM-judge 三项的整体平均提升为 **31.3%（Qwen3-Next-80B-A3B-Instruct）** 和 **28.1%（GPT-5.4-nano）**。
- **细粒度差距**：在需要精确串联证据的 Single-Hop 和 Multi-Hop 类别上增益更大，说明“自适应的检索路径”确实能改进证据定位，而不仅是靠塞入更多上下文。
- **跨数据集迁移**：在 LoCoMo 上训练得到的 ERSkill 直接迁移到 LongMemEval，仍显著超过基线，说明学到的技能具备一定通用性。
- **成本-性能平衡优秀**：与 LLM 构建记忆的方法相比，ERSkill 的记忆构建开销最轻；在推理 token 上也处于较低量级，同时取得最高 L-J 分数。
- **消融结论**：所有组件都有贡献，其中去掉“技能进化”和“路由器”的掉点最明显，说明“发现新技能”和“按查询选技能”两个机制同等重要；双前沿与经验 trie 分别改善进化稳定性和探索效率。
- **稳定性**：5 次重复运行的变异系数较低，展示进化流程的鲁棒性。

## 5. 优点与亮点

1. **问题视角新颖**：把“检索侧行为”而非“记忆构建”或“推理提示”作为自进化的对象，填补了一个显著空白；强调“访问记忆”本身可以像技能一样被学习、组合与替换。
2. **设计清晰且机制明确**：原语-技能-路由器三层抽象便于复用/解释；经验 trie 有效压缩探索历史；能力前沿与部署前沿实现“探索能力”与“稳定部署”的解耦。
3. **训练设计务实**：回放窗口 + 软标签路由器训练使搜索到的技能可以直接转成可学习的路由信号；缓存/复用机制减少重复 roll-out，缓解自进化耗资源的问题。
4. **证据链完整**：主实验、细粒度分析、消融、超参、稳定性、成本分析、迁移实验与案例研究相互支撑。
5. **跨模型兼容**：在 Qwen 与 GPT 两类骨干上均验证了收益，说明方法并非依赖单一 LLM 特性。

## 6. 不足与限制

1. **训练成本偏高**：技能进化依赖大量 roll-out 和 LLM 裁判评估；虽然推理时轻量，但训练端成本不透明（未给量化数据）。
2. **原语库固定**：只进化“原语序列”，不进化“原语本身”，因此检索能力的上限被预定义的操作空间约束，论文也将其列为未来工作。
3. **评测范围窄**：实验均为长期记忆问答；对规划、工具使用、多轮交互决策、个性化推荐等更广泛应用没有覆盖。
4. **统计显著性缺失**：核心结论没有配合显著性检验或置信区间；分数差距是否稳定在多次评估中存在一定不确定性。
5. **低资源场景未验证**：训练需要 4 张高端 GPU，LLM 生成技能和评估成本较高，对中小团队复现门槛较高。

### 6. **潜在偏差风险**（续）
LLM-as-a-Judge 虽然采用 GPT-4o-mini 作为裁判，但裁判模型本身可能对长答案、特定措辞或结构化输出存在偏好，尤其当对比方法（如 A-Mem、MemoryOS）的答案格式与 ERSkill 的检索证据风格不一致时，这种偏好可能造成系统性的评分偏移。论文仅报告了 L-J 的总体准确率，未给出裁判与人类标注的一致性（如相关系数或 Cohen's κ），也未利用传统指标（F1、BLEU-1）对裁判分数进行交叉校准。此外，若 ERSkill 在训练中曾利用 LLM 生成技能描述与反馈，而测试时又使用同一类 LLM（同为 Qwen 或 GPT 系列）进行评估，则存在“自我偏好”导致的评分虚高风险——尤其是迁移实验中，训练使用 Qwen，评测裁判也是 OpenAI 系模型，这种耦合未在文中明确讨论。

### 7. 对未来研究的启示
- **检索策略的自适应上限**：ERSkill 证明了“固定存储 + 进化式访问”的可行性，为后续研究打开一个重要方向——不仅让技能序列进化，还应允许原语本身的语义（如检索粒度、索引类型、扩展半径）被动态调整，以突破当前操作空间边界。
- **跨任务与跨模态迁移**：当前技能主要在长时记忆问答上学习，但“路由器 + 技能库”的结构天然适合跨任务迁移（例如从问答迁移到推荐、任务分解或对话管理）。未来可探索预训练一个通用技能库，在不同下游智能体上微调路由器，从而降低每个新场景的训练成本。
- **无监督或弱监督自进化**：当前进化依赖人工标注的查询–答案对来评估 oracle 价值。现实中智能体日志中往往没有明确答案，利用最终任务成功率或用户反馈作为隐式奖励，将进一步提升该方法的实用性。
- **记忆访问的可解释审计**：由于技能是可解释程序，未来可以构建“检索行为日志”并分析路由器在何种查询下偏好哪些原语组合，从而为智能体纠错、用户信任和隐私控制提供接口。

## 7. 总结评价（综合)

ERSkill 是一项在方法构思上具有鲜明原创性、在工程实现上完整严密的工作。它将长久以来被视为“固定内部模块”的记忆检索，重构为一个“可学习、可进化、可解释”的决策问题，并通过技能原语化、双前沿进化、经验字典树与路由器学习四个组件的有机结合，给出了一个理论上站得住（单调不降的 oracle 保证）、工程上可训练（回放与缓存削减成本）的解决方案。实验覆盖多数据集、多骨干、细粒度分析与消融，充分说明了方法的有效性和鲁棒性。局限主要集中于训练资源要求、评估范围、裁判偏差与统计显著性缺失，但这些并不削弱其核心贡献。对于智能体长期记忆与自进化检索方向的研究者而言，这是一篇值得细读、也值得复现和扩展的方法论文。

**一句话概括**：ERSkill 通过让“记忆访问的过程”本身成为可组合、可演化的技能，并配合路由器软选择与双前沿进化机制，显著增强了大语言模型智能体在异构长期记忆查询上的证据检索能力 —— 它把“记住什么”和“如何想起”都变成了可以随经验进化的智能行为。
