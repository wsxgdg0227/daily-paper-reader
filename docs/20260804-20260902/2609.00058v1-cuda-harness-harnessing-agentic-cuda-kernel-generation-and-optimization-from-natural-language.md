## 摘要
开发高性能CUDA内核需要算法实现、正确性验证和硬件感知的并行优化方面的专业知识，这造成了巨大的专业壁垒，使得直接从自然语言生成CUDA内核（Text2CUDA）变得至关重要。同时，大型语言模型（LLMs）的通用代码生成能力催生了一系列探索基于LLM的CUDA内核生成的工作。这些工作主要集中于从高级框架（如PyTorch）到CUDA的转译（Torch2CUDA），而非Text2CUDA——后者要求模型理解高级输入语义并处理底层内核实现与验证。此外，由于依赖预定义测试输入，这些方法容易受到奖励黑客攻击。在本文中，我们提出了CUDA-Harness，一个用于从自然语言驾驭代理式CUDA内核生成与优化的框架。具体而言，我们引入了中间结构化生成，将高级语义理解与底层内核生成连接起来。为了稀释Text2CUDA中的奖励黑客风险，我们构建了基于综合的验证，提供隔离的测试数据和渐进式验证。此外，我们提出了反馈自适应进化，一种优先考虑正确性同时优化性能的内核进化策略。最后，通过大量实验，我们证明了CUDA-Harness的有效性，进一步评估展示了其在LLMs、硬件平台以及C到CUDA转译任务上的泛化能力。

## Abstract
Developing high-performance CUDA kernels demands specialized knowledge in algorithm implementation, correctness validation, and hardware-aware parallel optimization, creating a substantial expertise barrier and making generating CUDA kernels directly from natural language (Text2CUDA) essential. Meanwhile, the general-purpose code generation capability of Large Language Models (LLMs) prompts a series of works exploring LLM-based CUDA kernel generation. They mainly focus on transpilation from high-level frameworks such as PyTorch to CUDA (Torch2CUDA) rather than Text2CUDA, where models must understand the high-level input semantics and handle low-level kernel implementation and validation. Additionally, these methods are vulnerable to reward hacking due to reliance on predefined test inputs. In this paper, we propose CUDA-Harness, a framework for harnessing agentic CUDA kernel generation and optimization from natural language. Specifically, we introduce Intermediate-Structured Generation to connect high-level semantic understanding with low-level kernel generation. To dilute reward hacking in Text2CUDA, we construct Synthesis-Based Verification to provide isolated test data and progressive validation. Furthermore, we propose Feedback-Adaptive Evolution, a kernel evolution strategy that prioritizes correctness while optimizing performance. Finally, through extensive experiments, we demonstrate the effectiveness of CUDA-Harness, with further evaluations illustrating generalization across LLMs, hardware platforms, and to C-to-CUDA transpilation.

### 一、核心问题与研究动机

- **背景**：CUDA 是高性能并行计算的主导平台，支撑人工智能、量子计算与科学模拟等应用，但开发高性能 CUDA 内核门槛极高——要求开发者同时掌握算法实现、正确性验证、硬件架构理解与并行优化技巧。这构成了显著的专业知识壁垒。
- **关键缺口**：将 CUDA 内核生成从自然语言描述直接进行（Text2CUDA）虽极为必要，但现有基于大语言模型（LLM）的研究主要聚焦于从高级框架（如 PyTorch）到 CUDA 的转译（Torch2CUDA）。两种任务的本质差异在于：
  - **Torch2CUDA** 输入是程序代码，算法已指定、测试数据可从代码推导、语义明确；
  - **Text2CUDA** 输入是自然语言，算法不完全、测试数据不可得、语义含糊。
- **既有方法的问题**：
  - 基于训练的方法（SFT/RL）依赖高质量实现与优化轨迹作为训练数据，获取成本高昂；
  - 基于智能体的方法虽免训练，但依赖预定义测试输入进行验证与迭代，容易遭受**奖励黑客**（reward hacking）——过拟合测试输入而生成�出错误实现。
- **本文用途**：提出 CUDA-Harness，一个面向 Text2CUDA 的端到端智能体框架，系统性地连接高层语义理解与底层内核实现、验证和优化。

### 二、方法论

CUDA-Harness 框架包含三个核心组件，外加对自包含 CUDA 程序结构的分析：

**1. 自包含 CUDA 程序剖析**
- 指出一个可自验证的 CUDA 程序由头文件、设备端内核、主机端代码（输入准备、内存管理、启动配置）组成；
- 指出自包含程序执行依赖充分准备的测试输入；仅用 dummy 输入无法揭示真实性能瓶颈。

**2. Intermediate-Structured Generation（中间结构化生成）**
- **内核实现清单（Kernel Implementation Manifest）**：一种结构化、逐内核的规格说明。每条记录包含内核名称、输入输出描述、功能描述（揭示算法细节）、语言无关的参考代码片段，以及详细测试信息（shape、数据类型等）。生成清单时，智能体专注于高层语义理解与缺失细节补全，而不直接编写实现代码。
- **自包含 CUDA 脚手架（Self-Contained CUDA Scaffold）**：提供代码模板，将内核启动相关的操作（内存管理、数据传输、启动配置定义）聚合到独立的 launcher 函数中，另提供二进制文件读写辅助函数。关键设计：
  - 保证生成顺序：先内核、后 launcher；当启动配置与内核中隐含的内存访问模式冲突时，智能体执行反思（reflection）并回溯修正；
  - 禁止 dummy 输入，测试输入路径通过命令行参数传入，调用约定在编译期通过 `#pragma message` 发出——智能体实现内核时不了解测试输入细节，从源头抑制过拟合。

**3. Synthesis-Based Verification（基于合成的验证）**
- **解耦测试数据合成**：测试输入和参考输出通过标准数值库（NumPy/PyTorch）在隔离环境中生成，与内核生成使用不同上下文，防止交叉污染；
- **泛化数值范围**：要求测试输入服从均值 5.0、标准差 10.0 的高斯分布，抑制因小量级输出导致容差准则失效的奖励黑客途径。虽然较大的输入量级可能放大浮点累积误差、提高误报率，但这是为了降低更危险的漏报率；
- **渐进式多阶段验证（Progressive Multi-Stage Validation）**：按 fail-fast 顺序执行——先编译检查 → 再功能正确性 → 最后运行性能评测；
- 验证基于模型上下文协议（MCP）暴露工具接口，支持跨硬件可扩展验证。
- 关键公式：
  - 功能验证准则：\( V(K, x, y) = I[|K(x) - y| \leq \epsilon_{atol} + \epsilon_{rtol}|y|] \)
  - 编译检查：\( C(K; \phi) = I[K \text{ under } \phi \text{ compiles}] \)
  - 性能指标（以延迟为例）：\( P_{latency}(K, x) = 1/\text{Latency}(K, x) \)

**4. Feedback-Adaptive Evolution（反馈自适应演化）**
- **正确性优先细化（Correctness-First Refinement）**：根据失败阶段分流——编译失败时按错误细节定向修复；功能验证失败时退回更保守的实现，先保证正确性，避免在缺陷代码上继续堆叠激进优化；
- **奖励驱动的优化（Reward-Driven Optimization）**：采用带可验证奖励的强化学习（RLVR）范式，奖励为：
  \[ r(K) = -1 + C(K) + C(K)V(K)P(K) \]
  即编译失败受罚，编译+功能正确后奖励依据性能确定；
- 由于不存在可更新的模型参数，引入**优化洞察摘要**机制：智能体分析前后实现差异和奖励变化，提炼优化经验（哪些策略有效、哪些无效）并累积到下一轮，指导后续优化。

### 六、主要结论与发现

1. **有效性**：CUDA-Harness 在所有难度级别上均超越基线、通用智能体框架（OpenCode/Codex）以及已有的 Torch2CUDA 智能体（KernelSkill/CudaForge）——编译率、功能正确率和性能评分全面领先。

### 七、方法与实验的亮点

- **问题定位精准**：明确区分 Text2CUDA 与 Torch2CUDA 的本质差别，首次以 Text2CUDA 为核心任务提出端到端智能体框架；
- **中间结构化生成**：双中间蓝图（manifest + scaffold）的构思巧妙——将"理解语义"与"编写实现"分成两个时间步骤，天然贴合 LLM 的推理模式，降低语义歧义对内核实现的干扰；
- **测试数据与内核生成双向隔离**：既让生成端无法接触测试输入细节（通过 scaffold 约束），也让合成端在独立上下文完成，结合泛化数值范围统制，从三方面减缓奖励黑客风险；
- **正确性优先演化策略**：明确识别了业界常见的"在错误实现上持续优化导致错误固化"失败模式，并通过分支处理（编译修复 vs. 回退保守实现）加以规避；
- **RLVR + 洞察摘要**：在无参更新的 test-time 场景下巧妙类比 RLVR，将经验摘要作为可传递的"信用分配"载体，逻辑自洽；
- **验证协议工程化**：fail-fast 验证顺序 + MCP 工具化接口 + 编译期 `#pragma` 约定传递，考虑到了实际部署中的工程细节；
- **多维度泛化评估**：跨 LLM、跨硬件和跨任务（C-to-CUDA）三路泛化实验设计完整，且虚假输入/真实负载验证了框架的通用性。

### 八、不足与局限

- **未充分披露错误案例分析**：Synthesis-Based Verification 中 8.7% 的假阳性案例虽有归因，但未讨论 CUDA-Harness 如何减少此类错误或 6.9% 假阴性带来的代价（无谓算力消耗）。

- **无重复随机种子**：每个内核仅一次生成运行，无法量化框架在随机性下的稳定性和方差；
- **部分基线适配隐忧**：比较的某些基线（KernelSkill、CudaForge 等）本为 Torch2CUDA 设计，在 Text2CUDA 场景下可能未按最优配置运行；论文默认其开箱即用的表现可能不完全公平；
- **人工分析的主观性**：对假阳性的人工归类虽然提供了洞察，但未说明归类标准及审核人数，有一定主观风险评估；

- **C-to-CUDA 的层面**：CUDA-Harness 的方法在 C-to-CUDA 场景实验预算偏低（N=1→3），可能低估框架在该场景下的完整能力；
