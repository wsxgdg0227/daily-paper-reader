## 摘要
记忆对 AI 智能体至关重要。许多现有智能体记忆系统采用提前（Ahead-of-Time, AOT）设计，在具体请求到来之前就构建记忆。尽管这降低了在线服务成本，但这种与请求无关的记忆构建可能丢弃后续变得重要的细粒度信息。为解决这一局限，我们提出即时智能体记忆（Just-In-Time Agent Memory, JAM），一个可训练的框架，用于在运行时构建以查询为条件的上下文。记忆器（Memorizer）将完整原始历史保存在带有紧凑导航摘要的分层页面存储中，而研究者（Researcher）则针对每个请求迭代地检索、检查并整合证据。为训练这些记忆使用行为，我们提出 Memory-Gym，一个以证据为基础的数据合成流水线，涵盖六个领域中的九种任务类型，并通过已验证轨迹监督微调，随后进行提示引导的组相对策略优化（Hint-guided Group Relative Policy Optimization），来优化 Researcher。我们在智能体记忆和长上下文处理的多项基准上证明了 JAM 的有效性；其任务性能优于 AOT 式记忆系统，同时比先前训练过的智能体记忆方法显著更高效。为支持可复现性和未来研究，我们在 https://github.com/VectorSpaceLab/general-agentic-memory 发布了匿名化源代码。

## Abstract
Memory is critical for AI agents. Many existing agent-memory systems follow an Ahead-of-Time (AOT) design, constructing memory before a specific request arrives. While this reduces online serving cost, such request-agnostic memory construction can discard fine-grained information that later becomes important. To address this limitation, we propose Just-In-Time Agent Memory (JAM), a trainable framework for query-conditioned context construction at runtime. A Memorizer preserves complete raw histories in a hierarchical page-store with compact navigational summaries, while a Researcher iteratively retrieves, inspects, and integrates evidence for each request. To train these memory-use behaviors, we introduce Memory-Gym, an evidence-grounded data synthesis pipeline covering nine task types across six domains, and optimize the Researcher through verified-trajectory supervised fine-tuning followed by Hint-guided Group Relative Policy Optimization. We demonstrate the effectiveness of JAM across a variety of benchmarks on agent memory and long-context processing, where it achieves stronger task performance than AOT-style memory systems while remaining substantially more efficient than prior trained agentic memory approaches. To support reproducibility and future research, we release our anonymized source code at https://github.com/VectorSpaceLab/general-agentic-memory.

## 1. 核心问题与研究动机

- **背景**：LLM 智能体在深度研究、软件工程等长流程任务中持续产生长且不断演化的历史（观察、推理轨迹、交互），记忆系统成为构建下游任务上下文的关键。
- **现有范式缺陷**：主流记忆系统采用 **Ahead-of-Time（AOT）** 设计，即在具体请求到来前就把原始历史压缩/组织成摘要或记忆笔记。虽然降低在线开销，但：
  - 与请求无关的预处理会丢弃**细粒度细节**与**跨会话依赖**；
  - 当关键证据分散在庞大、动态、时间上相互依赖的历史中时，固定检索/摘要流水线难以拼装出查询特异的上下文。
- **核心主张**：记忆不应只是"存过去的信息"，而应是**运行时按查询构建上下文（query-conditioned context construction）**，即 Just-In-Time（JIT）范式：离线组织 + 在线构建分离。
- **形式化目标**：给定请求 q 与历史 H，记忆系统产出上下文 c* ← Memory(q, H)，目标为先最大化下游智能体性能、再最小化上下文规模：
  - `C*(q,H) = argmax_{c∈C(H)} Perf_A(q,c)`，`c* = argmin_{c∈C*(q,H)} |c|`
  - AOT 用请求无关的预压缩近似 c*，JIT 则在运行时以 q 为条件构造 c*。

## 2. 方法论

### 2.1 总体框架：双组件 JAM

- **Memorizer（离线）**：保存完整原始历史 + 构建紧凑导航结构，形成分层 workspace（page-store）。
- **Researcher（在线）**：以轻量记忆为导航，迭代检索、检查、整合证据，为每个请求组装优化上下文。
- 关键设计：把运行时记忆构建**显式化为可追踪、可训练的智能体过程**（思考、工具调用、充分性判断都可监督/可强化学习）。

### 2.2 Memorizer：分层工作区构建

- 两个轻量操作：
  - **memorize**：`memorize(s_i, W_<i) → μ_i`，为每个会话生成简明 memo（关键信息 + 导航描述子）。
  - **workspace writing**：`write(s_i, μ_i, W_<i) → W_≤i`，原始内容存为源文件，依据 memo 将语义相关会话归入一致目录。
- 每个目录维护由子文件/子目录 memo 生成的 **README**，构成该区域的紧凑导航摘要。
- 效果：原始文件保持完整、路径可追溯；memo 与 README 引导 Researcher 定位相关会话再做细粒度阅读。
- 同一流程支持**批量构建**与**增量追加**。

### 2.3 Researcher：运行时智能体研究

- **三个工作区访问工具**：`open(p)`（读目录 README 与列表）、`search(κ)`（BM25 + 稠密向量混合检索候选路径）、`browse(p, κ)`（读取指定文件并抽取与查询相关的信息）。
- **迭代 think–explore–reflect 循环**（第 i 步）：
  - 思考并生成动作集合：`A_i = {a^1_i,…,a^{K_i}_i} ~ π_θ(· | q, h_{i-1})`，每个动作 `a^k_i = (t^k_i, ρ^k_i)`，`t ∈ {open, search, browse}`。
  - 执行并得到观察：`O_i = {Exec(a^k_i, W)}`；轨迹更新：`h_i = h_{i-1} ⊕ (A_i, O_i)`。
  - 充分性反思：`y_i = Reflect_θ(q, h_i)`，为真或达到动作预算即停止。
  - 最终构造上下文：`c* = Finalize_θ(q, h_T)`，保留请求相关信息与来源溯源；预算耗尽则做"尽力而为"的汇总回答。

### 2.4 Memory-Gym：面向记忆智能体的数据合成

- **任务分类（3 族 9 类）**：
  - 单跳定位：属性抽取、概念解释、条件定位；
  - 多跳证据连接：比较、溯源追踪、交集选择；
  - 多会话摘要：状态演化、集合枚举、聚合摘要。
- **六个异构领域**：Web（Wikipedia + FineWeb）、书籍（BookSum + NovelQA）、对话（UltraChat + LoCoMo 生成管线）、新闻（MultiNews）、学术（Qasper）、长文档（Gov-report）。
- **四阶段构建流水线**：
  1. **锚点发现**：抽取任务相关锚点（实体/事件/概念/条件/演化状态），过滤欠定义、弱支撑的候选；
  2. **任务相关会话扩展**：单跳找局部会话并做全库歧义检查；多跳通过共享实体/事件/约束/时序关系链接会话；摘要类收集同主题/同状态的更大会话集合；
  3. **实例生成**：生成 (q, a) 并记录支撑会话来源；
  4. **验证与过滤**：单/多跳校验答案唯一性、证据支撑、无答案泄漏；摘要类额外校验覆盖度、完整性、忠实性。
- 规模：**28,276 候选 → 16,794 保留（接受率 59.4%）**；200 条留存实例人工审计通过率 **95.0%**（95% Wilson CI 91.0%–97.3%）；构造与验证使用 MiniMax-2.5，嵌入用 BGE-M3，聚类用 FAISS。
- 污染控制：训练语料与评测数据在用户、会话、查询、答案、支撑证据上均不重叠（LoCoMo 仅用官方生成管线重造新语料）。

### 2.5 级联优化：SFT + Hint-guided GRPO

- **第一阶段：已验证轨迹 SFT**
  - 由强教师模型在 JAM 工作流下解题，产出交互轨迹 τ；用 LLM-as-a-judge 过滤答案错误或过程低质（如浅层搜索、走捷径）的轨迹，形成 D_SFT。
  - 损失：`L_SFT(θ) = -Σ_{τ∈D_SFT} Σ_i log π_θ(A_i | q, h_{i-1})`，初始化思考、工具使用、充分性判断行为。
- **第二阶段：Hint-guided GRPO**
  - 动机：多步探索在稀疏任务级反馈下不稳定。
  - 每 K_h 步注入提示：`s̃_k = s_k ⊕ η_k if k mod K_h = 0`，提示只给高层方向（缺失信息、未探索方向、可用工具），不泄露答案与完整路径，**仅训练时使用，推理时移除**。
  - 奖励以**来源召回**为主：`R(τ) = Recall(E_τ, E*_q) = |E_τ ∩ E*_q| / |E*_q|`。
  - GRPO 目标：对每组 G 条轨迹归一化得优势 A_j，`J_GRPO(θ) = E[ (1/G) Σ_j min(ρ_j A_j, clip(ρ_j, 1-ε, 1+ε) A_j) - β D_KL(π_θ‖π_ref) ]`。
- **实现超参**：最多 20 轮动作；每次 search 取 BM25 top-5 + BGE-M3 top-5 合并去重；G=8；学习率 1e-6；β=0.001；ε=0.2；200 优化步；browse 与最终答案模型固定为未训练的 Qwen3.5-4B。

## 3. 实验设计

- **评测基准（4 个）**：
  - **LoCoMo**（长期对话记忆，F1）、**LongMemEval / LME**（交互式记忆，准确率）、**NarrativeQA**（长文档叙事推理，F1）、**HotpotQA**（分散证据多跳，F1，含 56k/112k/224k 三种上下文规模）。
  - 另有 **LongCodeQA**（代码理解，64K/128K/256K，共 233 条查询）用于**跨域迁移**测试，训练中完全不含代码任务。
- **对比方法**：
  - 免训练：Vanilla LLM、RAG、AOT 式记忆系统 A-MEM、Mem0、MemoryOS、LightMem；
  - 训练式：MEM1（7B）、MemAgent（14B）、Memory-R1-PPO/GRPO（8B，取自原论文报告）。
- **统一设置**：JAM 与所有 AOT 基线均使用 **Qwen3.5-4B** 作为骨干，默认检索器 BM25 + BGE-M3。
- **主要结果**：JAM 在 LoCoMo 总体 F1 **52.09**（SH 55.14 / MH 40.21 / TE 62.59 / OD 25.12）、LME **65.20**、NarrativeQA **45.72**、HotpotQA 平均 **60.84**，全面优于 AOT 基线与 7B–14B 训练式基线（如 MemAgent LoCoMo 46.13、HotpotQA 46.88）。
- **附加评测**：LLM-as-a-judge（GPT-4o-mini，LoCoMo/NarrativeQA/HotpotQA 上 JAM 相对最强基线分别高 12.54、20.00、11.20 个百分点）；3 个随机种子稳定性（标准差 0.31–1.34）。
