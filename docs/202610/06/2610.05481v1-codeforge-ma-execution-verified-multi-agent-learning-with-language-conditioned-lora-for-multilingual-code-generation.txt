Abstract —Large language models for code generation often fail on execution, multilingual coverage, and contamination control, especially under frozen backbone constraints. We present CodeForge-MA, a unified framework that improves code synthe-sis through a multi-agent data forge, execution verified reinforced instruction tuning, and a language conditioned mixture of LoRA adapters. Four specialized agents, Composer, Reviewer, Executor, and Curator, iteratively refine instruction code pairs, validate them with tests, and filter duplicates and benchmark leakage. During training, we combine masked supervised fine tuning with a test driven reinforcement objective to align generations with executable correctness. For the larger model, we use sparse expert routing over low rank adapters to improve cross language transfer while keeping the base model unchanged at inference. Experiments show that joint data, objective, and adapter design yields robust gains across programming languages. 

Index Terms —code generation, multi-agent learning, instruc-tion tuning, parameter-efficient fine-tuning, reinforcement learn-ing, multilingual programming 

I. I NTRODUCTION 

Generating correct code from natural language remains a critical challenge because success requires more than flu-ent text production, it demands syntactic validity, semantic correctness, and robust behavior across diverse programming languages. In practice, many systems produce answers that appear plausible but fail at compilation or unit testing, which makes execution grounded evaluation indispensable for real code tasks [1].Analogous reliability concerns arise in high-stakes LLM deployments such as financial anti-fraud systems, where hallucinations and unverifiable numerical or logical claims motivate layered verification and guardrail mechanisms [2]. Recent advances in prompting and large language model reasoning have improved code synthesis, yet they still strug-gle with long tail languages, prompt contamination, and the mismatch between reference style and executable correctness. Instruction tuning alone often optimizes surface form, while test time search and reasoning strategies add cost without directly fixing data quality or adapter efficiency [3]. At the same time, scaling model size is not always feasible when the backbone must remain frozen and inference overhead must stay low [4].These efficiency concerns are especially acute for edge-class Arm CPU deployment, where memory capacity, bandwidth pressure, low-precision throughput, and kernel-level optimization jointly constrain practical LLM infer-ence [5].This emphasis on architecture-level efficiency under realistic deployment constraints is consistent with recent evi-dence that different LLM reasoning architectures can exhibit markedly different accuracy, auditability, and cost trade-offs in resource-constrained settings [6]. To address these constraints, we introduce CodeForge MA, a framework that jointly improves training data, optimization objective, and parameter efficient adaptation. Our approach uses a multi agent data forge to create and verify code samples, an execution verified reinforced instruction tuning objective to reward passing tests, and a language conditioned mixture of low rank adapters to specialize efficiently across programming languages. The result is a frozen backbone pipeline that concentrates learning where it matters most, in the data, the reward signal, and the adapters. II. R ELATED WORK 

Work on core code generation has established that large language models can synthesize programs from natural lan-guage, but benchmark performance remains sensitive to dataset quality, language imbalance, and execution reliability [7]. Recent studies also show that model scaling alone does not resolve compilation errors or hidden test failures, especially in multilingual settings where training corpora are unevenly distributed [8]. Auxiliary approaches have therefore focused on strengthen-ing supervision through better prompting, self refinement, and arXiv:2610.05481v1 [cs.AI] 4 Oct 2026 execution feedback. Instruction tuning and reasoning centered decoding can improve outputs, yet they still depend heavily on the quality of the underlying synthetic or curated data, and they may not reliably eliminate contaminated examples or silent failures [9]. Parameter efficient adaptation methods further reduce training cost, but standard adapters or low rank modules can underutilize capacity when task diversity is high [10]. Our framework is closest to recent efforts that combine data curation, execution grounded learning, and modular adaptation for code oriented LLMs. In contrast to single stage tuning, we integrate a multi agent forge with verification, a reinforced in-struction objective tied to unit tests, and language conditioned expert routing over LoRA modules to reduce cross language interference. This design is motivated by broader findings that structured supervision and sparse adaptation can improve controllability and efficiency in large scale language models [11] [12].Related ideas about robustness through structured representations and causal disentanglement have also been explored in graph-based fraud detection, where suppressing spurious environmental correlations improves generalization under distribution shift [13].Similar efficiency-driven design principles have also appeared in cloud-native performance prediction, where multimodal generative modeling, long-range dependency mechanisms, and calibrated uncertainty estimation are combined to support online deployment under dynamic workloads [14]. III. M ETHODOLOGY 

Under a frozen-backbone, limited-compute setting, ar-chitectural novelty is unavailable, so gains must come from the data pipeline, the supervised objective, and the parameter-efficient adaptation layer. Built on the Qwen-1.8B and Qwen-72B backbones—decoder-only Transformers with RoPE, RMSNorm, SwiGLU, and tied embeddings—we pro-pose CodeForge-MA, a unified framework pairing a multi-agent data forge with a mixture-of-adapter tuning layer. On the data side, four specialized LLM agents—Composer, Reviewer, sandboxed Executor, and Curator—cooperate in a Reflexion-style loop that drafts instruction-code pairs, critiques them via self-consistency voting, compiles and tests them against auto-generated unit tests, and finally deduplicates and decon-taminates survivors against HumanEval, HumanEvalFix, and MBPP using MinHash LSH. This addresses three practical failures we observed: silent compile-time errors in single-shot synthetic data, the long-tail scarcity of Rust and Go samples, and prompt-level leakage in Evol-Instruct-style corpora. On the optimization side, we introduce an execution-verified rein-forced instruction-tuning objective that combines token-level cross-entropy on the assistant turn with a PPO-style surrogate whose reward is the unit-test pass ratio, gated by a warm-up schedule so fluency is acquired before execution signals are injected. For the 72B regime, where full fine-tuning is infeasible, we attach a language-conditioned mixture-of-LoRA module to the attention projections, in which six low-rank experts are blended by a top-k router conditioned on the mean-pooled prompt representation, regularized by a Switch-style load-balancing term and a soft language-identity prior to prevent expert collapse and encourage cross-lingual transfer. The Qwen architecture remains strictly untouched at inference, adding only negligible routing overhead, while all trainable capacity is concentrated in the agentic curation process and the low-rank adapters. Fig. 1 summarizes how the multi-agent data forge, the execution-verified reinforced instruction tuning stage, and the language-conditioned mixture-of-LoRA adapter stack on top of the strictly frozen Qwen backbone. IV. A LGORITHM AND MODEL 

In this section we describe CodeForge-MA, the end-to-end framework we designed for the Qwen AI Challenge. Because the competition forbids any modification to the backbone net-work itself, everything that can actually move the needle, i.e. the training data, the supervised objective, and the parameter-efficient adaptation, has to be reconsidered jointly rather than in isolation. We therefore organize the method around three tightly coupled components, preceded by a short description of the base model we build upon.

B. Multi-Agent Data Forge 

The first component of CodeForge-MA is a hierarchical multi-agent data forge. The rationale is that the scarcity of high-quality, execution-verified multilingual code instruc-tions, not model capacity, is the real bottleneck in this competition. Since every agent in the forge and every evaluation call is routed through Qwen’s ChatML interface, the prompts themselves are load-bearing pieces of the pipeline. Two design points individually shift pass@1 by a non-trivial margin and deserve explicit treatment. 

A. Role-Specialized ChatML Templates 

All four forge agents and the final fine-tuned model speak through the Qwen ChatML protocol, which delimits turns by ⟨im_start ⟩ and ⟨im_end ⟩. Instead of a single generic system prompt, we use a role-specialized family 

{P Cmp , PRev , PExe , PCur }, each declaring its agent’s respon-sibility, output schema, and refusal behavior. For seed problem 

s and target language ℓ, the Composer prompt expands as 

PCmp (s, ℓ ) = τ Cmp sys ⊕ τlang (ℓ) ⊕ τsig (s) ⊕ τfmt , (25) where ⊕ denotes ChatML-separated concatenation, and the four fragments fix the role, bind the emission language, carry the signature extracted from s, and enforce a JSON-fenced response schema. Before we imposed this schema, the Composer often embedded explanations inside code blocks, breaking downstream compilation in Go and Rust where stray top-level prose is rejected; fixing the schema at the prompt level eliminated a class of bugs the Curator would otherwise have had to repair. At fine-tuning time, assembly matters: we place the problem in the user turn, the reference solution in the assistant 

turn, and a compact declaration (“You are an expert program-mer. Write a complete, self-contained solution in ℓ.”) in the 

system turn. The loss mask of (12) then fires only on the assistant span, where the useful signal resides.

B. Packing, Truncation and EOS Hygiene 

Code samples span dozens to several thousand tokens, so naive padding wastes compute. We use greedy sequence packing at Lmax = 2048 : samples are concatenated with a reset attention boundary until appending the next would exceed 

Lmax . With padding fraction ηpad = ∆ /L max per block, the greedy packer empirically keeps ηpad below 4% , more than doubling effective throughput versus right-padding. A second hygiene issue is the EOS token: the base Qwen checkpoint and its ChatML-tuned counterpart use different end markers, and mixing them yields responses that either never terminate or cut off mid-function. We normalize every sample so both the assistant turn and the terminal token use ⟨im_end ⟩, and truncate from the left whenever a packed block exceeds Lmax ,so the assistant span carrying the training signal is never sacrificed for prompt context. B. Main Comparison and Ablation 

Table II consolidates all three evaluations under the four metrics of Section VII: functional correctness (pass@1, or Score final via (32) for the 70B block), reference similarity (CodeBLEU), syntactic soundness (compile rate CR), and cross-language balance (BMPS). The top block compares 1.8B-class backbones averaged over HumanEvalSynthesize, HumanEvalFixTests and MBPP; the middle block reports 70B-class results; the bottom block ablates CodeForge-MA on Qwen-1.8B. Three observations follow. At the 1.8B scale, C ODE FORGE -QWEN -1.8B surpasses all baselines on every metric, including larger code-specialized models built on general-purpose back-bones. At the 70B scale, C ODE FORGE -Q WEN -72B outper-forms both in-family LoRA controls and external code LLMs such as DeepSeek-Coder-33B-Instruct and CodeLlama-70B-Instruct across all four metrics, while updating less than one percent of backbone parameters. The ablation shows the multi-agent forge as the single largest contributor, with execution-grounded RL and LC-MoLoRA each adding meaningful gains on top; removing the MinHash contamination filter inflates CodeBLEU and CR but erodes pass@1 and BMPS, and the BMPS column confirms that balanced language sampling is disproportionately responsible for cross-language stability. IX. C ONCLUSION 

We presented CodeForge-MA, a framework for improving code generation with Qwen-1.8B and Qwen-72B under a strict no-architecture-modification rule, combining a multi-agent data forge, an execution-verified reinforced instruc-tion tuning objective, and a language-conditioned mixture-of-LoRA adapter.
