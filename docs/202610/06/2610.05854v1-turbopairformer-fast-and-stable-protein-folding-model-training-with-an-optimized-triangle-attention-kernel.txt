## ABSTRACT 

Triangular attention is a core computation in AlphaFold3-style biomolecular mod-els, with computational cost that grows cubically with token count. FlashAttention reduces attention memory traffic through IO-aware tiling and backward recomputa-tion. However, the shared pair bias in triangular attention adds a gradient reduction across attention slices to the usual reductions over queries and keys. The open-source backends we examine handle these reductions through repeated probability recomputation, floating-point atomics, or full score-gradient storage. Separately, computing the softmax backward correction from BF16-rounded forward outputs incurs a loss of numerical precision. We present TurboPairFormer, a triangular at-tention implementation for NVIDIA Hopper GPUs that addresses these two issues. Our key-tile-parallel backward algorithm recomputes each probability tile once and reuses it for the query, key, value, and pair-bias gradients, using ordered partial reductions to achieve deterministic accumulation without floating-point atomics or full score-gradient storage. Our output-residual compensation retains a BF16 approximation of the output-rounding residual and uses it to compute the backward correction more accurately in FP32, without changing the BF16 output. With BF16 inputs at crop sizes 384, 640, and 768 and head dimensions 16 and 32, TurboPair-Former achieves the lowest mean query, key, and pair-bias gradient RMSE against an FP64 reference among eight evaluated implementations; residual compensation mitigates the precision loss from output rounding, reducing these RMSE values by 28–47% in controlled ablations. All four gradients are bitwise identical across five repeated calls in all 600 input cases under fixed execution conditions. Integrated into OpenFold3 together with our triangle multiplication kernels, TurboPairFormer achieves the lowest GPU computation time per optimizer step among eight eval-uated backend configurations on 16 H100 GPUs, with speedups of 1.73 × over OpenFold3’s Triton backend and 1.13 × over cuEquivariance at crop size 768. 

## 1 INTRODUCTION 

AlphaFold3 predicts the joint structure of complexes containing proteins, nucleic acids, and small molecules (Abramson et al., 2024). OpenFold3 provides an open-source implementation of Al-phaFold3 with support for training and fine-tuning (The OpenFold3 Team, 2025). Both models use one token per standard amino acid or nucleotide residue and one token per heavy atom for other components. They maintain a pair representation, with one learned vector for each pair of tokens, and repeatedly update it through triangular attention and triangle multiplication. In triangular attention, fixing one token index, which we call the outer index, selects the pair vectors between that token and every token in the crop. These vectors form an attention slice with one query and one key per token, as in standard attention, and all slices share the same pair bias. There is one slice per token, and the cost of each slice grows with the square of the token count. The cost of triangular attention therefore grows with the cube of the token count: doubling the training crop makes it eight times as expensive.

The backward pass thus has three reduction directions (Figure 1a): the query gradient sums over keys, the key and value gradients over queries, and the pair-bias gradient over outer indices. All four gradients reuse the same probability tiles, but their reductions favor different work partitionings. TurboPairFormer evaluates P and dS only once: it keeps dK and dV in local registers, writes dQ and d bias into independent partial buffers, and reduces them in a deterministic FP32 order. Determinism does not guarantee accuracy. In the softmax backward pass, all score gradients in a query row depend on the same correction δ, the dot product of the output gradient and the forward output for that row (Dao et al., 2022). Kernels usually compute δ from the saved BF16 output, whose rounding error can shift these score gradients in the same direction. A deterministic kernel reproduces this error on every run. The forward pass matters as well: with 64-row query tiles and head dimension 32, a bias tile holds as many bytes as the key and value tiles combined, and recycling and checkpointing run two to five forward passes per backward pass. Our challenge is therefore threefold: to reuse each recomputed probability tile for all four gradients with fixed accumulation orders and sufficient parallelism, to compute δ accurately, and to stage the shared bias efficiently in the forward pass. Single recomputation with ordered partial reductions: Like DeepSpeed-Evo and ScaleFold, TurboPairFormer recomputes each probability tile once for all four gradients, but without floating-point atomics or full score-gradient storage. ## 2 TURBO PAIR FORMER 

TurboPairFormer implements triangular attention and triangle multiplication for OpenFold3 pair updates (TriMul details in Appendix J). The attention kernel combines one probability recomputation, fixed accumulation orders, and output-residual compensation. OpenFold3 learns features Z for each ordered token pair. Standard amino acids and nucleotides contribute one token each; other components use one token per heavy atom (Abramson et al., 2024). A crop selects N tokens, possibly across chains. Starting-node triangular attention fixes a token index o, called the outer index , and takes row o of Z as one slice. Each thread block, or cooperative thread array (CTA), owns one key tile and a group of four outer indices, called an outer group, for one example and head. It traverses query tiles in ascending order, using 64 keys and 32 query rows per tile. Different key tiles provide independent work. Within each owned slice, dK/dV accumulators stay in FP32 registers throughout the traversal (Figure 2). For each query tile, the thread block recomputes P = exp( S − LSE) from the scores and saved row log-sum-exp. It forms dP and dS as in Equation (2), with the compensated row correction bδ

of Section 2.4 in place of δ. The tile P supplies dV , while dS supplies dK , dQ , and the pair-bias gradient. Shared memory makes these intermediates available to their consumers before the next tile. Each thread block writes its query contributions as partials indexed by key tile and its bias contributions as partials indexed by outer group. Every partial has one writer. Separate reduction kernels sum these BF16 partials in FP32, without recomputing probabilities or storing the full score gradient. Proposition D.1 establishes the partitioning. Algorithm 1 omits batch and head indices; inside the slice loop, Q, K, V , dO , M , LSE , bδ, dK , and dV denote the current tiles of the current slice. Row statistics and the key mask broadcast along the other tile axis; fully masked rows and invalid outer positions have P = 0 . All matrix products use BF16 operands and FP32 accumulation, so P and dS are rounded when consumed by a matrix product; the bias sum instead uses FP32 dS .The main kernel uses two warpgroups (256 threads), WGMMA for S and dP , and mma.sync for the gradient products. Appendix D.3 gives the thread-block view with explicit slice and tile indices, including the fixed addition tree over the four slices, synchronization, and instruction order. 2.3 DETERMINISTIC REDUCTIONS AND WORKSPACE SCHEDULING 

Partitioning work across key tiles and outer groups exposes parallelism, but distributes contributions to dQ and the shared pair-bias gradient across thread blocks. We fix their floating-point addition order to make these reductions reproducible. TurboPairFormer separates the production of these contributions from their reduction: each block writes its partials to unique addresses, and a later kernel consumes them in a prescribed order. The addition sequence is therefore independent of block completion order. For each dQ element, the reducer adds BF16 partials sequentially in ascending key-tile order, using an FP32 accumulator. The pair-bias reduction follows the same principle along the outer axis: each outer group first forms one BF16 partial through a fixed FP32 addition tree, and the reducer adds these partials in ascending outer-group order. The dK/dV accumulations remain local to their owning block and follow ascending query-tile order. Final scaling and BF16 output conversion occur after the respective reductions. These fixed paths need no global floating-point atomics. The workspace planner changes how much work is resident in each launch while preserving these arithmetic paths. It partitions examples, query rows, and outer groups into consecutive chunks. After reducing a chunk of bias partials, the next launch reloads the FP32 running sum and continues

The row correction δ in Equation (2) comes from the forward output without another probability traversal. Computing it from the saved BF16 output loses information discarded during output conver-sion. Following analyses of attention precision and multiple-component BF16 representations (Qiu & Yao, 2026; Henry et al., 2019), we save a BF16 approximation to the difference between the FP32 forward result O32 and the public output O16 :

E16 = RN 16 (O32 − O16 ), bδ ≈ rowsum  dO ◦ (O16 + E16 ). (3) Here RN 16 rounds to BF16. The subtraction, reconstruction, and dot product execute in FP32; the approximation sign accounts for floating-point evaluation. In our controlled ablations, using bδ in the shared dS reduces the mean RMSE of dQ , dK , and the pair-bias gradient, while leaving the public output and dV bitwise unchanged (Section 3.2). The cost is one output-sized BF16 tensor and its memory traffic, without additional probability recomputation. Appendix D.5 specifies the evaluation and analyzes its precision. 

Forward pipeline. The forward kernel employs tiled online softmax (Milakov & Gimelshein, 2018), using double-buffered shared memory to overlap Tensor Memory Accelerator loads of keys, values, and pair bias with Tensor Core compute. Probability evaluation is interleaved with value aggregation, and the epilogue saves the rounding residual alongside the BF16 output (Algorithm 2; details in Appendix C).

## 4 RELATED WORK 

Triangular attention and kernel dataflow. AlphaFold2 and AlphaFold3 use triangular updates to pair representations (Jumper et al., 2021; Abramson et al., 2024); FastFold, ScaleFold, and MegaFold accelerate these models through kernel and system optimizations (Cheng et al., 2022; Zhu et al., 2024; La et al., 2025). FlashAttention and its successors establish tiled recomputation and hardware-specific pipelines (Dao et al., 2022; Dao, 2024; Shah et al., 2024; Zadouri et al., 2026). NeuralPLexer3 avoids explicit bias replication (Qiao et al., 2025), FlexAttention compiles PyTorch score modifications (Dong et al., 2025; Paszke et al., 2019), and FlashBias factorizes some structured biases exactly and approximates general biases (Wu et al., 2025). TurboPairFormer retains the dense shared bias. The inspected DeepSpeed-Evo and ScaleFold kernels already recompute probabilities once, but combine bias gradients through atomic accumulation and full score-gradient storage, respectively (Song et al., 2023; Zhu et al., 2024). Our distinction is combining key-tile parallelism with ordered query and pair-bias partials (Appendix F). 

Deterministic gradient reduction. Order-sensitive floating-point summation (Higham, 1993) motivates either order-independent accumulators (Ahrens et al., 2020; Collange et al., 2015) or prescribed reduction sequences. FlashAttention-2’s deterministic mode uses FP32 query-gradient buffers per split (Appendix I.2); FlashAttention-3 and FlashAttention-4 order in-place updates with semaphores (Qiang et al., 2026; Zadouri et al., 2026), and DASH improves the scheduling of these ordered updates (Qiang et al., 2026). TurboPairFormer materializes partials for both query and shared pair-bias gradients, allowing key-tile blocks to write independently before fixed FP32 reductions. This avoids waiting for accumulation turns, but requires partial storage; the query-partial buffer remains cubic in crop length (Appendices E and I). 

Precision of the backward correction. Mixed-precision training allocates precision selectively (Mi-cikevicius et al., 2018), while multi-component representations retain rounding information in BF16 arithmetic and training states (Henry et al., 2019; Yu et al., 2024). Qiu & Yao (2026) connect attention-output error to the backward correction δ = ⟨dO, O ⟩ and adjust the softmax shift to mitigate biased rounding. Attn-QAT computes an auxiliary output from unquantized probabilities for this correction in FP4 attention (Zhang et al., 2026). TurboPairFormer instead extracts a BF16 rounding residual from the existing FP32 output accumulator and reconstructs the saved output for δ. This preserves the public BF16 output and avoids another P V product; it targets output-conversion error, while other rounding errors remain (Appendix D.5). 

## 5 CONCLUSION 

TurboPairFormer combines one probability recomputation for all four triangular-attention gradients, fixed-order partial reductions, output-residual compensation, and shared-bias staging on NVIDIA Hopper GPUs. Under the tested conditions, it achieves bitwise gradient repeatability and the lowest mean query, key, and pair-bias gradient RMSE against an FP64 reference among eight attention implementations. Integrated with our triangle multiplication kernels, it achieves the lowest measured GPU computation time per optimizer step among eight OpenFold3 backend configurations on 16 H100 GPUs. Relative to our deterministic implementation, the fastest tested non-deterministic variants take 2.8–4.1% less backward time at the Pairformer head dimension D = 32 and 11.0–13.7% less at D = 16 . The query-partial buffer grows cubically with crop size; reducing this storage while preserving a fixed accumulation order is the main direction for future work. 9Preprint

## I CHOOSING THE DETERMINISTIC REDUCTION 

With one recomputation, a thread block emits each tile’s contributions to all four gradients, so any gradient that sums along an axis the block does not span needs a reduction across thread blocks. Under the work partitioning of Section 2.2, two remain: the query gradient over key tiles and the pair-bias gradient over outer groups. TurboPairFormer makes both deterministic with materialized partials summed in index order (Section 2.3). This appendix explains the choice and measures it on one H100. At D = 32 , the fastest tested non-deterministic variant of our kernel, which accumulates the pair-bias gradient with atomics, takes 2.8–4.1% less backward time, and the deterministic kernel is faster than assigning one thread block per slice at every shape. At D = 16 , which only the template stack uses, the fastest tested non-deterministic variant takes 11.0–13.7% less time. I.1 WHICH GRADIENTS NEED A CROSS -B LOCK REDUCTION 

Kernels that traverse the scores once per gradient need no cross-block reduction, because each traversal can span the axis along which its gradient sums; TriFast and Protenix work this way at the 29 Preprint price of three recomputations (Appendix F). With one recomputation, the work partitioning decides which gradients need such a reduction and how many blocks a launch contains (Table 11). The pair-bias gradient stays within a thread block only if the block spans all No outer indices (lower block of Table 11). A block that owns one query–key tile then leaves dQ , dK , and dV to cross-block reductions, and a block that owns a key tile leaves too few blocks: HJ K = 48 at N = 768 with four heads, fewer than the 132 SMs of an H100. We therefore partition the outer indices, a design choice that requires a cross-block pair-bias reduction; this reduction exists only because all slices share the bias. Among the partitionings that split the outer indices, assigning key tiles keeps dK 

and dV in registers and leaves dQ as the only slice-shaped cross-block reduction, whereas assigning whole slices, as DeepSpeed-Evo does, removes that reduction but launches JK times fewer blocks. I.2 THREE WAYS TO MAKE A CROSS -B LOCK REDUCTION DETERMINISTIC 

A reduction across thread blocks is bitwise repeatable only if its association order is fixed or its arithmetic is order-independent, as with binned accumulators (Ahrens et al., 2020) or superaccumula-tors (Collange et al., 2015). Attention kernels fix the order in three ways (Figure 11a). 

Semaphore-ordered atomic accumulation. Each thread block atomically adds its contribution to one FP32 buffer, and a semaphore grants the turns in a fixed order, so a block whose turn has not come waits. The deterministic mode of FlashAttention-3 accumulates the query gradient this way, in ascending key-tile order for non-causal attention (Shah et al., 2024), and DASH chooses the turn order together with the tile schedule so that, in its scheduling model, the waits do not lengthen the critical path (Qiang et al., 2026). 

One thread block per slice. A thread block that owns whole slices visits every key tile itself and accumulates the query gradient in program order. DeepSpeed-Evo obtains a deterministic query gradient this way (Song et al., 2023), and so does the deterministic mode of FlashAttention-2 for triangular attention. It keeps one FP32 query-gradient buffer per split and sets the number of splits to the SM count divided by the number of attention problems, rounded up, which yields one split per slice for the BN oH problems of triangular attention (3,072 at N = 768 with four heads). No block waits, but the launch has JK times fewer blocks than partitioning by key tile. 

Materialized partials and a reduction kernel. Each thread block writes its contribution as a partial that no other block writes, and after these blocks finish, a separate kernel sums the partials in index order. TurboPairFormer applies this to the query gradient, in the ascending key-tile order of FlashAttention-3’s turns, and to the pair-bias gradient, a reduction that standard attention does not have. No block waits; the partials cost memory, one additional pass, and, because they are stored in BF16, one rounding per partial before the FP32 sum.

and 1.6–1.7 × 10 −3, whereas FP32 accumulations that differ only in addition order agree within 

2.4 × 10 −5. The accuracy comparison of Section 3.2 includes this rounding. 

## J TRIANGLE MULTIPLICATION 

Triangle multiplication updates a pair by combining two transformed pair features that share a third token, contracting over that token separately for each channel. Our outgoing implementation (Figure 12) places two fused CUDA kernels around one cuBLAS batched matrix multiplication. The input kernel normalizes each pair and computes five projections: two branch values, two branch gates, and the output-gate logits. The output kernel normalizes the contraction result, projects it, and applies the saved output gate. Fusion removes the global-memory round trips of intermediates within each stage, while the branch tensors and the contraction result still pass through global memory. The backward pass evaluates the projection tiles again instead of storing them and combines weight-gradient chunks in a fixed FP32 order; the attention replay results do not cover TriMul. Unlike cuEquivariance 0.10.0, which evaluates the output gate in its output stage in FP32 registers, we compute the gate logits in the input kernel and store them in BF16. Against a PyTorch FP32 reference, the median relative L2 errors nevertheless match closely: 0.386% versus 0.384% for the output and 0.604% versus 0.607% for the input gradient, compared with 0.440% and 0.823% for PyTorch with BF16 inputs. This compares complete implementations and does not isolate the effect of BF16 gate storage.
