## 摘要
AI 编程智能体的性能高度依赖于其底层的编码规则。然而，现有编码规则通常是手工设计且固定不变的，这使得该过程劳动密集且往往次优。在本工作中，我们提出 RuleEvolve，一个面向编码规则的自演化框架。RuleEvolve 维护一个候选编码规则池，并迭代地改进它们。在每次迭代中，它使用一个由 LLM 驱动的变异器模块从现有候选中生成变体，然后使用一个评判器模块评估这些变体，并用表现最佳的变体更新规则池。在两个编程智能体框架、四个骨干 LLM 和三个基准上的大量评估表明，RuleEvolve 在生成代码的功能正确性、代码长度和/或生成成本（例如使用的 token 数）方面，均优于人工工程和现有提示优化基线。

## Abstract
The performance of AI coding agents is highly dependent on their underlying coding rules. However, existing coding rules are typically hand-crafted and fixed, making the process labor-intensive and often suboptimal. In this work, we propose RuleEvolve, a self-evolving framework for coding rules. RuleEvolve maintains a pool of candidate coding rules and iteratively improves them. In each iteration, it employs an LLM-powered mutator module to generate variants from existing candidates, and then uses a judge module to evaluate these variants and update the pool with the best-performing ones. Extensive evaluations across two coding-agent frameworks, four backbone LLMs, and three benchmarks demonstrate that RuleEvolve outperforms both manual engineering and existing prompt optimization baselines in terms of functional correctness of the generated code, code length, and/or generation cost (e.g., tokens used).

  - 现有自动提示优化方法（如 Prompt-Ops、DSPy 类）主要面向**几句话的短提示**，而编码规则是**长篇幅、文档化的结构化指导**，搜索空间大得多，直接套用效果不佳。
  - 编程智能体的执行过程涉及多轮交互与外部工具调用，**不可微**，无法直接做梯度优化；且每次评估都需完整跑一遍智能体，**评估代价极高**，传统随机变异策略在算力上不可承受。
- **整体含义**：论文首次系统性地将"编码规则"本身作为可自演化的优化对象，提出 **RuleEvolve** 框架，把"人工写规则"转变为"自动演化规则"，在**不牺牲正确性**的前提下显著压缩代码长度与生成成本。

## 2. 方法论

### 2.1 问题形式化

- 智能体 $A_\theta$ 依据任务 $x$ 与规则 $r$ 采样代码 $y \sim p_\theta(\cdot \mid x, r)$。
- 目标是一个**带约束的优化问题**：
  - 最大化代码简洁性得分 $E(y)$ 与低成本得分 $C(A_\theta, x, r)$ 的期望之和；
  - 约束为平均正确率 $\frac{1}{|X|}\sum_x \mathbb{E}[V(x,y)] \ge \tau$（$V$ 为执行测试用例的验证器）。

### 2.2 三大组件

- **规则池（Rule Pool）**：固定容量 $m$ 的候选规则集合。
- **变异器模块 $M$**：由 LLM 驱动，输入规则 $r$ 与自然语言变异指令 $g$（如"改进措辞、重排或合并步骤、改变风格"），输出变异候选 $r_m = M(r, g)$。
- **评判器模块 $J$**：在任务集 $X$ 上运行智能体、执行生成代码并打分，输出 $S = J(r, A_\theta, X)$。

### 2.3 打分函数

- **正确性惩罚项**（相对于"无规则"基线的相对下降，而非绝对正确率）：
  $\mathbb{E}_{x}[V(x, A_\theta(x,\varnothing)) - V(x, A_\theta(x,r))]_+$
- **效率项**：论文验证了生成代码字符数与 token 用量高度相关（图 2a），故用**生成代码字符数** $|A_\theta(x,r)|$ 统一近似代码长度与推理成本。
- **总分**：$S = -|A_\theta(x,r)| - \lambda \cdot \mathbb{E}_x[V(x,A_\theta(x,\varnothing)) - V(x,A_\theta(x,r))]_+$，$\lambda$ 平衡两项。
- 该设计的关键含义：**惩罚的是"比不加规则更差"的部分**，因此不会为压缩长度而牺牲原有正确性。

### 2.4 迭代变异—剪枝流程（Algorithm 1）

1. 用初始规则 $r_I$ 生成 $m$ 个变异体，初始化规则池 $P$ 并打分；
2. 每轮迭代 $t$：
   - 依据历史得分**策略性分配** $N$ 个变异额度 $\{n_1,\dots,n_m\}$；
   - 对池中每个候选生成 $n_j$ 个新变异体，**新候选继承父代的分数集合**（解决冷启动、保证观测数一致）；
   - 评判器评估全部新候选，将 $m+N$ 个候选**剪枝保留 top-$m$**；
3. $T$ 轮后返回平均得分最高的规则。

### 2.5 策略性变异分配（基于 OCBA）

- 采用**最优计算预算分配（Optimal Computing Budget Allocation, OCBA）**，目标是最大化"正确选出最优候选的概率"（PCS）。
- 设 $b$ 为当前平均分最高的候选，则其他候选的分配权重为：
  $w_i \propto \left(\dfrac{\hat\sigma_i}{\hat\mu_b - \hat\mu_i}\right)^2$
- 最优候选自身的权重用于维持比较稳定性：$w_b = \hat\sigma_b \sqrt{\sum_{i\neq b} w_i^2/\hat\sigma_i^2}$。
- 归一化后离散化为 $n_i$，使 $\sum n_i = N$。
- **直观解释**：与当前最优**差距小**（潜在竞争者）或**方差大**（不确定性高）的候选获得更多变异机会；附录 B 给出了基于正态假设的渐近最优性证明。
