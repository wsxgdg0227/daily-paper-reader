## 摘要
高性能 GPU 内核是现代机器学习系统不可或缺的基础，然而自动生成既正确又高效的内核仍然充满挑战。现有基于大语言模型的方法面临两大局限：与模型当前能力相匹配的高质量训练数据稀缺，以及内核正确性与性能之间固有的权衡。为应对这些挑战，我们提出 KernelZero，一个协同演化框架，通过两个专门化模型持续改进 GPU 内核生成：提议器（Proposer）从 API 集合生成 Torch 模块，编码器（Coder）将其转换为 CUDA 或 Triton 内核。KernelZero 采用前沿驱动的模块生成机制，根据编码器当前的薄弱环节持续生成与能力相匹配的训练模块。它进一步引入正确性感知的组相对策略优化（CA-GRPO），仅在正确性变得足够可靠之后才优化性能。通过交替优化提议器与编码器，KernelZero 形成了一种自动课程，从而实现有针对性且训练高效的能力提升。实验表明，KernelZero-7B 在 CUDA 上超越 Claude-4.5-Sonnet，在 Triton 上超越 DeepSeek-V4-Pro。在 KernelBench Level 1 和 Level 2 上，其 CUDA pass@1 分别达到 75.8% 和 69.6%，pass@10 分别达到 100% 和 97%。在 Triton 上，其 pass@1 分别达到 77.2% 和 72.5%。

## Abstract
High-performance GPU kernels are essential to modern machine learning systems, yet automatically generating kernels that are both correct and efficient remains challenging. Existing LLM-based approaches face two major limitations: the scarcity of high-quality training data aligned with the model's current capabilities, and the inherent trade-off between kernel correctness and performance. To address these challenges, we propose KernelZero, a co-evolution framework that continuously improves GPU kernel generation through two specialized models: a Proposer that generates Torch modules from API sets and a Coder that translates them into CUDA or Triton kernels. KernelZero uses a frontier-driven module generation mechanism to continuously produce capability-aligned training modules based on the Coder's current weaknesses. It further introduces Correctness-Aware Group Relative Policy Optimization (CA-GRPO), which optimizes performance only after correctness becomes sufficiently reliable. By alternating the optimization of the Proposer and Coder, KernelZero forms an automatic curriculum that enables targeted and training-efficient capability improvement. Empirically, KernelZero-7B surpasses Claude-4.5-Sonnet on CUDA and DeepSeek-V4-Pro on Triton. On KernelBench Level 1 and 2, it achieves CUDA pass@1 scores of 75.8% and 69.6%, respectively, with pass@10 reaching 100% and 97%. On Triton, it achieves pass@1 scores of 77.2% and 72.5%, respectively.

  - **正确性—性能权衡**：只优化正确性会得到保守内核（加速有限）；激进优化性能又会显著增加错误风险。
- **核心研究问题**：如何以目标导向的方式训练模型，从而高效提升 GPU 内核生成性能？
- **整体含义**：论文提出一种"协同演化"训练范式，让模型在每一轮迭代中动态识别并学习最贴合自身能力的样本，实现持续、定向、训练高效的能力提升，而无需人工为每个阶段构造任务。

## 2. 方法论

### 2.1 核心思想
- 将内核生成建模为**两个显式接口模型**的协同演化：
  - **Proposer（提议器）P**：输入 Torch API 集合 $a \in A$，生成可运行的 Torch 模块 $m \sim \pi_P(\cdot|a;\theta_P)$。
  - **Coder（编码器）C**：将模块 $m$ 翻译为 CUDA 或 Triton 内核 $k \sim \pi_C(\cdot|m;\theta_C)$。
  - 两阶段映射：$a \xrightarrow{P} m \xrightarrow{C} k$。
- **交替优化策略**：两者轮流更新，各自用自身奖励（$r_P$ 或 $r_C$）通过 GRPO 优化，另一方保持固定。Proposer 不断扩大模块分布至 Coder 能力前沿，Coder 则适应新分布提升质量，形成**自动课程（automatic curriculum）**。

### 2.2 Proposer：生成前沿 Torch 模块
- **API 列表采样**：从真实 Torch 模块中构建 API 共现分布，采样子集 $a \subset A$ 作为输入，兼顾真实性与多样性。
- **多阶段验证检查**（保证可靠、可运行、数值稳定）：
  1. **AST 检查**：静态分析验证生成模块的计算图与采样 API 集合语义一致。
  2. **可运行检查**：按 KernelBench 格式调用 `get_init_inputs` 与 `get_inputs`，在 CUDA 设备上执行，丢弃编译或运行时错误模块。
  3. **数值稳定性**：随机输入下过滤产生 NaN/Inf 的模块。
- **前沿奖励（Frontier Reward）**：对模块 $m$ 从 Coder 采样 rollout 组 $G=\{k_1,\dots,k_K\}$，计算平均正确率 $\bar{l}$，奖励定义为：
  - 有效模块：$R_p(m) = 1 - 2|\bar{l} - 0.5|$
  - 无效模块：$R_p(m) = \rho$（$\rho<0$ 惩罚）
  - 当正确率接近 0.5 时奖励最大，即模块既不过于简单也不过于困难。
- 对应算法为 **FO-GRPO（Frontier-Oriented GRPO）**。

### 2.3 Coder：生成高性能内核
- **冷启动蒸馏（Cold Start Distillation）**：嵌入四条编译器启发式优化原则：
  - **Tiling**（分块）：将张量划分为片上存储可容纳的块，提高数据复用。
  - **Fusion**（融合）：合并生产者—消费者算子链，减少 DRAM 流量与启动开销。
  - **Pipeline**（流水线）：重叠数据搬运与计算，隐藏内存延迟。
  - **Reordering**（重排序）：调整循环/线程映射，改善合并访问与局部性。
  - 用教师模型（gpt-oss-120B）基于这四条原则生成带 CoT 的内核推理轨迹，仅保留正确样本。
- **CA-GRPO（Correctness-Aware GRPO）**：
  - 对模块 $m$ 采样 rollout 组 $G=\{k_1,\dots,k_n\}$，计算组级正确率 $\text{Acc}_G = \frac{1}{|G|}\sum_i \mathbb{1}[\text{Corr}(m,k_i)=1]$。
  - 阈值函数 $T(G)=1$（当 $\text{Acc}_G \geq \alpha$），否则为 0，$\alpha$ 决定何时从正确性转向性能优化。
  - 对正确内核子集 $G_c$，归一化加速比得分：$S_G^i = \frac{S(k_i)-\min S(G_c)}{\max S(G_c)-\min S(G_c)}$（当极值相等时设为 0）。
  - 最终奖励：$R_G^i = 1 + T(G)\cdot\beta\cdot S_G^i$（若正确），否则为 0；$\beta$ 控制性能信号强度。
  - 核心机制：**正确性先学，性能后激活**，训练更稳定。

### 2.4 训练流程
- 每轮：Proposer 更新 20 步（用 $R_p$），随后 Coder 更新 20 步（用 CA-GRPO 奖励），共 4 轮，总计 80 步。

## 3. 实验设计

- **Benchmark**：KernelBench（250 个任务，3 个难度级别）。
  - Level 1：100 个单内核算子（如 Convolution）。
  - Level 2：100 个融合模式（如 Matmul + Sigmoid）。
  - 模型基于 PyTorch 参考实现，一次性提示（one-shot prompt）生成 CUDA 或 Triton 内核。
- **评估指标**：
  - `pass@k`：按 HumanEval 估计，$pass@k = 1 - \binom{n-c}{k}/\binom{n}{k}$。
  - `fast p@k`：仅统计正确且加速比超过 $p$ 倍的内核。
  - 输出 token 数（含推理与最终代码），衡量推理效率。
- **对比基线**：
  - **基础模型**：Claude-3.5/3.7/4.5-Sonnet、Gemini-2.5-Flash、GPT-oss-120B、GLM-5.1、Qwen3-32B/8B、Qwen2.5-Coder-32B/7B；Triton 额外加 DeepSeek-V4-Pro、GLM-5.2。

  - 正确性阈值 $\alpha \in \{0, 0.5, 0.9, 1.1\}$ 的对比。
  - 六个代表性算子的最快正确内核加速比对比（Tensor-MM、GroupNorm、Sum Reduce、Conv-BN-Scale、Conv3D Fusion、GEMM-BN-Swish）。
