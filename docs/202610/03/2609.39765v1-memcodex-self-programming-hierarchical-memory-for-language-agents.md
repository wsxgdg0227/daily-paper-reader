## 摘要
智能体记忆面临异构访问需求：单跳问题可能只需要一条证据，而多跳问题必须整合来自多个来源的证据。预定义的记忆工作流无法适应这些变化的需求。近期的自适应方法会在记忆组件及其组合上进行搜索或学习，但设计空间本身仍是预定义的。我们提出 MemCodex，一种自演化的分层记忆系统，它将经验组织为可执行的记忆程序，用于摘要、关系知识、可复用技能和潜在记忆。开放式程序演化通过重写每一层的构建、索引、检索和路由方式，搜索层程序的开放设计空间，从而同时适配层内实现和跨层组合。查询时，读取从粗到细遍历该层次结构，一旦找到足够证据就停止，并在需要时下探到原始历史。我们进一步开发了 MemArena，一个统一运行时，将异构数据和记忆系统置于公共接口之后。相比最强的自适应记忆基线，MemCodex 将平均任务成功率提高了 10.1%，同时使用的上下文 token 数减少 3.4 倍，推理速度提升 2.1 倍。

## Abstract
Agent memory faces heterogeneous access needs: a single-hop question may require one piece of evidence, whereas a multi-hop question must combine evidence from multiple sources. Predefined memory workflows cannot adapt to these varying needs. Recent adaptive methods search or learn over memory components and their compositions, but the design space itself remains predefined. We introduce MemCodex, a self-evolving hierarchical memory system that organizes experience into executable memory programs for summaries, relational knowledge, reusable skills, and latent memory. Open-ended program evolution searches the open design space of layer programs by rewriting how each layer is constructed, indexed, retrieved, and routed, thereby adapting both within-layer implementations and cross-layer composition. At query time, reads traverse the hierarchy from coarse to fine and stop once sufficient evidence is found, descending to the original history when needed. We further develop MemArena, a unified runtime that places heterogeneous data and memory systems behind a common interface. MemCodex improves average task success by 10.1% relative to the strongest adaptive-memory baseline, while using 3.4x fewer context tokens and achieving 2.1x faster inference.

## 2. 方法论

### 2.1 核心思想

- 将智能体记忆建模为**可执行记忆程序的层次结构**，层内实现与跨层组合均可演化。
- 通过**固定五方法层接口 + 运行时**约束程序交互，但内部行为对演化开放，从而在保持可验证性的同时打开设计空间。

### 2.2 形式化建模

- 任务智能体 π 回答关于记录 R 的问题，R 以带时间戳的写块 R₁…Rₙ 到达；每个问题 q 在其 question time 之前的记录写入后提出。
- 记忆系统架构 g 维持存储 M，提供写与读操作：
  - **写**：M ← write_g(M, Rᵢ)
  - **读**：C = read_g(M, q)，返回 ≤ B token 的上下文
  - **答**：a = π(q, C)
- 架构表示为 **g = (λ, ψ)**：
  - **λ**：层掩码，独立开关各派生层（raw 层始终激活）
  - **ψ**：层程序，实现每层的写与读
- 目标：在 token 成本不高于初始架构 g₀ 的前提下，获得最准确的架构。
- 准确率 acc(g) = E_{q∼Q}[π(q, C_g(q)) 正确]，成本 tok/q(g) = E_{q∼Q}[|C_g(q)|]。

### 2.3 分层结构

- 四个文本层按**从粗到细**排序：**L = (skill, graph, summary, raw)**，受 RAPTOR 启发。
- **raw 层**：不可变、只追加，保存所有原始 turn，保证原始证据始终可恢复。
- **summary 层**：将每个闭合的原始 turn 段落压缩为紧凑叙述。
- **graph 层**：存储带时间的断言 x = (h, r, t, τ)，实体 h 与 t 通过关系 r 在时间 τ 内关联，新断言可取代旧断言。
- **skill 层**：存储从跨会话重复流程中提炼的可执行过程；以程序而非文本笔记形式建模，因为可运行的过程能对照演示会话检验。
- **kv memory（潜在记忆）**：由 Metis-27B（带 stateful fast weights 的记忆基础模型）的 memory block 状态构成，固定大小、只写、不演化、不暴露 score/route。

### 2.4 证据保留与来源追踪

- 每个派生项 x 保留其**精确源 turn** src(x) ⊆ V，递归解析：
  - src(v) = {v}（v ∈ V）
  - src(x) = ⋃_{y ∈ in(x)} src(y)（x ∈ M \ V）
- 读操作可**不经派生路径直接到达**底层原始 turn，即使经过有损摘要。
- src(x) 记录的是精确派生来源，而非最小证据集；summary 与其抽取的断言共享同一段落 turn。

### 2.5 五方法层接口

- **层内方法**：
  - `admit_ℓ`：过滤候选
  - `index_ℓ`：保留至多 K_ℓ 个活跃项于索引 I_ℓ（被淘汰项仍留在存储中）
  - `score_ℓ(q, S)`：对搜索范围允许的项排序，返回 top 候选 x\* 与置信度 c
- **跨层方法**：
  - `propose_ℓ`：将派生项上传至上层
  - `route_ℓ(q, x\*, c)`：返回 **Stop / Narrow / Descend**
- 运行时负责 `assemble`，在预算 B 下打包上下文 C。

### 2.6 四条记忆约束（Validity Checks 的基础）

1. turn 只追加到 raw 层，永不修改；
2. 每个派生项标明构建它的精确 raw turn；
3. Narrow 只能把搜索范围限制到 top 候选的来源 turn，即 F ∩ src(x\*)；
4. 每个上下文必须不超过 B token。

这四条约束保证无论派生项多么有损，任何读都能回溯到 raw turn。

### 2.7 内容通道 vs 路由通道

- **内容通道 C_txt**：top 打分项的文本直接进入 C，取代其证据（类似 summary、profile、skill 记忆）。
- **路由通道 C_route**：检索命中导向其源 turn（类似 HippoRAG 将节点概率传给源段落）。
- **Caroline 例子（图 3）**：摘要只写 "Caroline plans to move"，遗漏 "Paris"；但通过 src(x) 路由可恢复命名 Paris 的原始 turn。证据保留使该路径始终可用。
- 通道是**架构级设置**而非逐查询选择，只有读深度逐查询自适应。

### 2.8 查询自适应读（Algorithm 1）

- 从粗到细遍历激活层；每层计算候选 S = {x ∈ I_ℓ : src(x) ∩ F ≠ ∅}，打分取 top 候选，由 route 决定动作：
  - **Stop**：结束读取，按通道组装上下文（C_txt 取 top-10 文本；C_route 取 src(x\*) ∩ F 按时间排序）；
  - **Narrow**：F ← F ∩ src(x\*)；
  - **Descend**：保持当前范围。
- 到达 raw 层时，取范围内得分最高的 k 个 turn。
- 路由通道确保任务智能体**始终从原始 turn 作答**，即使读取停在技能层。

### 2.9 写路径

- 自底向上处理每个追加块，依次经 propose、admit、index。
- 每个 proposal 结合下层新准入项与该层活跃项，运行时记录所有被读项作为输入。
- skill 层的 admit 要求**在每个演示会话上回放都能复现记录结果**才接受。
- 初始架构 g₀：index 依据 MemoryOS 的 access-and-recency heat；score 用余弦相似度；route 按每层阈值 stop 或 narrow。

### 2.10 程序演化（Algorithm 2）

- **可归因编辑**：每个子代只做**一个方法重写**或**一个层 toggle**，使改动效果可归因。
- **诊断 D(g)**：检查失败轨迹与被拒绝/淘汰项，把每个失败分配给**第一个丢失 gold turn 的方法**；兄弟节点按故障计数针对不同方法。
- **元智能体 ρ**：在任务智能体骨干上运行，读取目标层代码、诊断与拒绝日志，返回仅覆盖该方法的子类。
- **有效性检查 K**：拒绝违反记忆约束的子代（在 fixture 查询上测试）。
- **接受测试**：
  - Accept(g → g′) ⇐⇒ Δtok ≤ 0 ∧ Δacc ≥ 0 ∧ [(Δacc > 0 ∧ p < α) ∨ Δtok < 0]
  - 其中 p 为单侧精确 McNemar 检验 p 值，α = 0.05。
- **Archive**：接受架构构成一棵树，被拒子代进入父节点的 rejection log Jₙ；节点存储 evolve 准确率、每问题 token 与逐问题判定向量。
- **父节点采样权重**：w(n) ∝ σ((acc(gₙ) − acc)/σ̂) · 1/(1 + |ch(n)|) · (1 + dₙ)，偏向准确、少被扩展、位于 accuracy-cost Pareto 前沿的节点。

### 2.11 双接口

- **NL 接口**：文本上下文 C 放入 prompt，支持任意智能体。
- **KV 接口**：将 kv memory 注入开源权重智能体的 memory attention；API 智能体因无权重与激活而只能使用 NL 接口，无潜在记忆。

## 3. 实验设计

### 3.1 评测套件 MemArena

- **数据接口**：源适配器把不同语料映射为 episode e = (R, Q_e)；R 为带时间戳、说话人标注的会话序列；每个问题元组为 (q, a\*, G(q), y_q, t_q)，分别表示问题、参考答案、gold turn、问题类型、问题时间。
- **访问接口**：记忆包装器暴露 `write(M, Rᵢ) → M′` 与 `read(M, q) → C`；智能体包装器暴露 `answer(q, C) → a`，从而**分离记忆质量与任务智能体质量**。
- **评测协议**：每个记录写入全新存储，按 20-turn 分块写入；每个问题在 t_q 前最后一块写入后提出；存储不跨记录/用户共享，只有 g 共享；每次比较固定骨干与 judge。
- **指标套件**：
  - 任务成功率 **Acc**（GPT-4o-mini 按 Mem0 rubric 判定）
  - 证据召回 **Rec** = E_q[|G(q) ∩ C| / |G(q)|]
  - 上下文成本 **Tok/q**（每问题 prompt token 数）
  - 推理时间 **Lat**（从 read 到最后一个答案 token 的墙钟延迟）

### 3.2 数据集 / 基准

- **LoCoMo**：超长对话记忆
- **LongMemEval (LME, S split)**
-
