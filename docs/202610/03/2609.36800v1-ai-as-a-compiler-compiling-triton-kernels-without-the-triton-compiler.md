## 摘要
随着编程模型、工作负载和加速器不断演进，编译器后端的构建与维护成本高昂。我们研究大语言模型能否替代传统的优化与 lowering 流水线，我们将这一过程称为 AI lowering。我们研究从 Triton 到 NVIDIA PTX 的 AI lowering：一个 LLM 智能体将 Triton 内核直接翻译为 PTX。我们构建了一个用于评估候选 PTX 的环境，以及一个智能体框架，其中 LLM 将 Triton 内核翻译为 PTX。在 Ada、Hopper 和 Blackwell GPU 上的十二个常见内核以及来自近期机器学习论文的十个内核上，AI lowering 达到了自动调优 Triton 性能的 0.83 倍至 3.34 倍。最大的收益来自 Triton 的 lowering 流水线未执行的变换，例如将打包的二值权重直接解码为 Tensor Core 操作数（在 BitDelta 上为 3.34 倍）、在张量内存中为每个线程分配完整的 softmax 行（在 FlashAttention 上为 1.37 倍），以及复用重叠的卷积窗口（最高 2.23 倍）。这些结果依赖于具有全面验证支持的稳健评估框架。我们基于现有的 PTX 验证器 Volta，并通过引入对 Blackwell tcgen05 Tensor Core 接口的支持，大幅扩展其以支持现代 GPU 架构。这需要对三种架构特性进行建模：托管张量内存、基于描述符的操作数布局，以及通过提交、等待、内存屏障和代理栅栏协调的异步执行。我们讨论了形式化这些特性所涉及的挑战，以及当前的局限性。我们的结果表明了一个正在显现的未来：AI 编译器将取代自定义编写的中间表示和检查器，从而减少为新通用芯片和定制芯片完成软件初始支持所需的时间和工程投入。

## Abstract
Compiler backends are expensive to build and maintain as programming models, workloads, and accelerators evolve. We investigate whether large language models can replace the conventional optimizing and lowering pipeline, a process that we call AI lowering. We study AI lowering from Triton to NVIDIA PTX: an LLM agent translates Triton kernels directly into PTX. We build an environment that evaluates candidate PTX, and an agentic harness in which an LLM translates Triton kernels into PTX. Across twelve common kernels on Ada, Hopper, and Blackwell GPUs and ten kernels from recent ML papers, AI lowering achieves 0.83x-3.34x the performance of autotuned Triton. The largest gains come from transformations that Triton's lowering pipeline does not perform, such as decoding packed binary weights directly into Tensor Core operands (3.34x on BitDelta), assigning each thread a complete softmax row in tensor memory (1.37x on FlashAttention), and reusing overlapping convolution windows (up to 2.23x). These results rely on a robust evaluation harness with comprehensive verification support. We build on Volta, an existing PTX verifier, and substantially extend it to support modern GPU architectures by introducing support for Blackwell's tcgen05 Tensor Core interface. This requires modeling three architectural features: managed tensor memory, descriptor-based operand layouts, and asynchronous execution coordinated through commits, waits, memory barriers, and proxy fences. We discuss the challenges involved in formalizing them, as well as the current limitations. Our results suggest an emerging future in which AI compilers replace custom-written intermediate representations and checkers, reducing the time and engineering effort required to bring up software for new general-purpose and custom chips.

# 论文总结：AI as a Compiler — 不借助 Triton 编译器编译 Triton 内核

## 1. 核心问题与整体含义（研究动机与背景）

- **背景痛点**：高性能 GPU 内核开发依赖大量硬件专用知识，成本高、维护难。Triton、TileLang、CuTe DSL、ThunderKittens 等 DSL 虽降低了编程负担，却把复杂性转移到编译器后端：需要持续实现 lowering、调度、合法性检查与优化。
- **IR 中心的编译器难以跟上硬件演进**：LLVM、XLA、MLIR 等大型编译器依赖多层 IR，语义、变换和 lowering 路径需不断扩展，容易出现正确性或性能回退。而 GPU/TPU/Trainium/定制 ASIC 的架构快速分化（如 Hopper 的异步引用、Blackwell 的 tcgen05），现有 IR 难以自然表达。
- **现有绕行做法**：DeepGEMM 等性能关键实现直接用目标专用 intrinsic/汇编绕过 IR。
- **核心主张**：本文提出 **AI lowering** —— 用 LLM 直接替代传统"优化 + lowering"后端流水线。研究对象是 **Triton → NVIDIA PTX**：LLM 智能体把 Triton 内核直接翻译成 PTX，完全跳过 Triton 的中间表示栈。作者认为，对关键 GPU 内核而言，"绕过传统 lowering 流水线不仅可行，而且有益"。
- **整体含义**：若配合足够强的验证，AI 编译器有望取代手工编写的中间表示与检查器，降低新芯片（含定制芯片）软件栈的启动时间与工程成本。

## 2. 方法论

### 2.1 核心思想
- **AI lowering 的定位**（图 1）：不同于 (a) 传统编译器（固定手写 pass 流水线）和 (b) 超级优化器（以常规 lowering 结果为种子做随机变异搜索），AI lowering 是"直接生成 + 实测反馈"：LLM 从 Triton 源码直接合成 PTX，并用数值与性能反馈迭代修正。

### 2.2 问题形式化
- 内核 $K$ 的执行契约记为 $(c, I, h)$：$c$ 为编译期固定参数（维度、步长、constexpr），$I$ 为运行时启动接口（grid、线程数、参数 ABI），$h$ 为目标 GPU 架构。
- 正确性定义：候选 PTX $P$ 须暴露入口与 ABI，并在同一契约下满足数值等价
  $|P|_{c,I,h}(x) \approx_\epsilon |K|_{c,I,h}(x), \forall x \in D$
  其中 $\approx_\epsilon$ 允许容差内的浮点舍入差异；有形式验证时还额外检查"把浮点抽象为实数运算"后的精确相等。
- 有效 lowering 集合 $V(K,c,I,h)$ 要求：可为目标编译、内存安全且无竞争、ABI 一致、数值等价。
- 优化目标：在 $V$ 中最小化基准协议测得的延迟 $bL(P;h)$。
- 生成过程建模为迭代采样：$P_t \sim p_\theta(\cdot \mid q_t)$，其中提示 $q_t = \mathrm{Prompt}(K, c, I, h, F_{<t})$ 融合契约与历史反馈。

### 2.3 两大系统组件
- **TCE NV（Triton Compiler Environment）**：受控评估环境。把与 lowering 正交的配置（编译期常量、grid、线程数、目标 GPU）固定为输入；提供内核字典、元数据与 PTX 模板，负责汇编、启动、验证、基准测试与 profiling。为防"弱基线导致虚假增益"（一种 reward hacking），参考内核按官方教程最佳实践编写、在目标 GPU 上自动调优后再作为基线。
- **TAIC（Triton AI Compiler）**：执行 AI lowering 的智能体框架，具备三项通用技能——解读 NCU（Nsight Compute）指标、检索 PTX ISA 文档、应用 GPU 优化原则。

### 2.4 编译循环（图 2）
1. 生成初始 PTX；
2. 汇编 + sanitize；
3. 数值正确性测试；
4. 基准测试 + profiling；

7. 子智能体并行实现多个候选补丁；

### 2.5 验证基础设施
- 基于现有 PTX 验证器 **Volta** 扩展，引入对 Blackwell **tcgen05** Tensor Core 接口的支持，需建模三类架构特性：托管张量内存（TMEM）、基于描述符的操作数布局、通过 commit/wait/memory barrier/proxy fence 协调的异步执行。
- 扩展内容（附录 B）：立即数数学常量、更多指令（tanh、ldmatrix.trans）、异步拷贝、异步 Tensor Core 指令（tcgen05/wgmma/ldmatrix）、更多 barrier、shuffle 归约、打包格式（16x2、8x4）。可信计算基从 42 kLoC 增至 60 kLoC。

## 6. 主要结论与发现

- **性能区间**：AI lowering 达到自动调优 Triton 的 **0.83×–3.34×**（常见内核套件在 Ada/Hopper/Blackwell 上为 0.83×–2.23×）。
- **最大增益来自 Triton lowering 不做的变换**：
  - BitDelta：把打包二值权重直接解码为 Tensor Core 操作数，**3.34×**（batched 变体 2.51×）；
  - FlashAttention：为每线程在张量内存原生布局中分配完整 softmax 行，消除跨 lane 归约，**1.37×**；
  - Convolution 2D：复用重叠卷积窗口，最高 **2.23×**（B200 FP8），H100 FP16 为 1.90×；
  - 其他：FlashSinkhorn 1.55×、SageAttention 1.41×、Mamba-2 1.07×/1.10×。
- **架构覆盖**：生成 PTX 会使用各代现代机制——Ada 上 mma.sync+ldmatrix+cp.async，Hopper 上 wgmma+TMA+mbarrier，Blackwell 上 tcgen05+TMEM+2D TMA；SMEM 布局从 XOR swizzle 演进到 128B XOR / 64B offset swizzle。
- **架构/精度依赖**：GEMM 在 B200/L40S 的 FP16 达平，但 H100 FP16 仅 0.83×；FP8 在 H100 达 1.61×。元素级与归一化算子基本只是"恢复基线"（≈1.00–1.04×）。
- **可重复性**：SwiGLU、MatMul 方差极小（±0.001/±0.012）；Convolution（±0.197）与 FlashAttention（±0.106）方差中等，但均值均≥Triton。
- **验证现状**：受 Volta 支持范围约束时性能显著下降（如 GEMM 从 1.03× 降至 0.24×）；扩展后仍有三类构造无法支持——原子操作、输入依赖的控制流、位级值操纵。
- **语义理解**：TAIC 遵循实际实现而非名称/注释/常见模式，且在源码要求 IEEE-754 时避免使用 Tensor Core，说明其捕捉的是源码语义而非记忆的模板。
- **总体判断**：AI lowering 成本虽比毫秒级 Triton 编译高数个量级，但为一次性开销、可摊薄到重复执行；对新硬件尤为有吸引力。

## 7. 优点

- **问题立意新且切中要害**：把"LLM 能否取代编译器后端"具体化为可度量的 Triton→PTX 任务，明确区分于超级优化器（无编译器种子）和 IR 中心方法。
- **系统设计分工清晰**：TAIC（生成/优化）与 TCE NV（执行/验证）职责分离，且严格保留内核 ABI、启动配置、编译期常量与目标 GPU 契约，使对比可隔离到 lowering 层面。
- **公平的基线构造**：明确警惕弱基线导致的"reward hacking"，参考内核按官方最佳实践编写、在目标 GPU 上自动调优，并去除边界 mask。
- **Pareto 成本视角**：以"加速比 vs 累计 API 成本"呈现，区分"易恢复"与"需大规模搜索"的负载，比单一速度数字更有信息量。
- **严谨的语义恢复消融**：用随机无意义内核、误导性命名/注释、IEEE-754 约束三类测试，主动排除"训练数据记忆"这一最大偏差风险。
- **验证与生成协同**：把 Volta 验证器放进循环，并在扩展后给出支持/不支持特性的清晰边界，附录给出具体指令与建模难点，工程透明度高。
- **可重复性报告**：给出 5 次独立运行的均值、标准差与最优值，而非只报最好结果。

## 8. 不足与局限

- **性能并未全面超越**：多个负载仅达 0.83×–1.00×（如 H100 FP16 GEMM 0.83×、Dion 0.97×），元素级算子基本只是恢复基线，"AI 编译器取代传统后端"的结论仍需更强证据。
- **生成成本高**：单内核 $1.5–$12 的 API 成本远高于毫秒级编译；论文虽称可摊薄，但未给出摊销模型的定量分析，也未讨论大规模部署的总成本。
- **可重复性方差**：高增益内核（Convolution ±0.197、FlashAttention ±0.106）方差显著，意味着需要多次采样才能稳定获益，进一步抬高成本。
- **主实验样本量有限**：图 4 每配置仅单次运行；模型对比仅在单一 FP16 GEMM 上完成，不足以支撑"只有前沿模型可行"的普适结论。
- **验证覆盖严重不足**：扩展后的 Volta 仍不支持原子操作、数据依赖控制流、位级操纵；而这三类恰是性能优化的常用手段。作者明确声明扩展"不声称健全或完备"，其形式化留作未来工作，因此正确性主要依赖随机差分测试这一有限手段。
- **可信计算基膨胀**：Volta 从 42 kLoC 增至 60 kLoC，每新增指令都引入不可靠风险，验证器本身的健全性未被证明。
- **基线可比性边界**：基线限制在"标准 Triton 编程"（不用实验特性、不写内联汇编），而 AI lowering 无指令选择约束，两者自由度不对称，可能高估 AI 侧优势。
- **模型与数据时效性风险**：评估使用特定前沿模型（GPT-6 Astra），结论对模型版本高度敏感；同时部分内核可能出现在训练数据中，作者虽做了记忆

性消融，但无法完全排除训练语料污染的可能，尤其对 FlashAttention、Mamba-2 等广泛流传的实现，高增益是否源于"重新发现已知最优写法"与"真正超越编译器"难以彻底区分。

- **成本-收益的适用边界未被界定**：论文主张 AI lowering 适合"一次性开销可摊薄"的场景，但未刻画何时值得使用——例如内核需重编译的频次、目标硬件寿命、负载规模等条件均未量化，读者难以判断其相对于"继续维护 Triton 后端"的实际经济性。

- **架构覆盖的深度不均**：虽然展示了 Ada/Hopper/Blackwell 三代机制的生成能力，但性能收益高度集中于特定组合（如 B200 FP8 Convolution、BitDelta），部分配置（H100 FP16 GEMM 0.83×）反而落后，缺少对"何种内核/架构组合下 AI lowering 更可能胜出"的系统性归因分析。

- **缺少与传统编译器后端改造的对照**：论文的核心论点是"绕过 IR 栈优于扩展 IR 栈"，但未与"在 Triton/MLIR 中新增一条 lowering 路径"的直接工程方案做成本与性能对照，因而"有益"的结论缺少最直接的比较基准。

- **人类工程成本的量化缺失**：除 API 费用外，TAIC 的技能设计（NCU 解读、ISA 检索、优化原则）、提示工程、验证器扩展（+18 kLoC）本身的开发投入未计入总成本，而这些恰是传统编译器路线同样需要承担的部分。

- **通用性未验证**：实验全部限定在 Triton→NVIDIA PTX，未涉及其它 DSL（TileLang、CuTe DSL）或其它加速器（TPU、Trainium、定制 ASIC）。而作者在动机部分恰恰以"新芯片软件栈启动"为主要卖点，这一场景缺少实证。

## 9. 总体评价与启示

- **定位**：这是一篇**立场鲜明、问题定义清晰的前沿探索性工作**。它没有声称全面取代编译器，而是把"LLM 能否直接完成 lowering"压缩为一个可度量、可验证、可比较的具体任务，并给出了正向但非压倒性的初步证据。
- **方法论的贡献大于性能数字**：真正有价值的是三点——(1) 严格保留 ABI/启动配置/编译期常量以隔离 lowering 变量；(2) 把验证器放进优化循环而非事后检查；(3) 用随机内核、误导性线索、IEEE-754 约束三类消融主动攻击"记忆"这一最大偏差来源。这些做法对后续"LLM 作为编译器组件"的研究具有可复用的规范意义。
- **核心张力**：论文最有说服力的案例（BitDelta 3.34×、Convolution 2.23×、FlashAttention 1.37×）恰恰说明 AI lowering 的优势来源于**做传统 pass 流水线不做的事**（如打包权重直接解码为 Tensor Core 操作数、原生 TMEM 布局消除跨 lane 归约），而非把已有 lowering 做得更快。这暗示其定位更接近"补充/绕过既有编译器的特定瓶颈"，而非"替代编译器"。
- **风险与前提**：结论高度依赖前沿模型能力（仅 GPT-6 Astra 与 Triton 打平）、高额推理成本、以及一个可信计算基不断膨胀、明确声明不健全不完备的验证器。任何一项前提弱化，结论都会明显缩水。
- **对未来工作的指向**：若要支撑更强主张，需要 (1) 覆盖原子操作、数据依赖控制流、位级操纵的验证能力；(2) 摊销成本的定量模型；(3) 与"扩展 IR 栈"路线的正面对照；(4) 跨 DSL、跨加速器的泛化实验。在这些补齐之前，更稳妥的解读是：**AI lowering 是特定高性能内核上"值得一试的编译器替代路径"，而非已确立的通用方案。**
